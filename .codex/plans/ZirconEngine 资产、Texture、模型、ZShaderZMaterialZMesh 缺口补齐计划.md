# ZirconEngine 资产、Texture、模型、ZShader/ZMaterial/ZMesh 缺口补齐计划

## Summary
目标是把当前“已能导入/诊断”的资产能力推进到接近 Bevy 的公共资产完成度：统一 typed asset 生命周期、补齐 `MeshAsset/ZMesh` 一等资产、让 texture 容器格式可进入渲染上传路径、把 glTF/OBJ/STL/PLY/DXF 从“扁平 ModelAsset primitives”升级为 root + labeled subassets，并让 `ZShader/ZMaterial` 真正驱动 renderer/SRP 材质消费。

当前基线：
- 已有 `Asset` / `Handle<T>` / `Assets<T>` / `AssetEvent<T>` / `AssetLoadState` facade 和 `.zmeta` subasset/importer 流程。
- `TextureAsset` 已能解析常见图片和 DDS/KTX/KTX2/ASTC 容器头，但压缩容器还没有完整 GPU upload。
- 模型插件可导入 OBJ/glTF/STL/PLY/DXF，但输出主要是 `ModelAsset { primitives }`。
- `.zshader` / `.zmaterial` 已实现解析、依赖、诊断和部分 renderer 描述桥接。
- 没有独立 `ZMesh` / `MeshAsset` 一等资产。

## Key Changes
- 资产公共面补齐：
  - 保持现有 `ProjectAssetManager::load<T>()`、`assets<T>()`、`subscribe_asset_events<T>()` 风格，补全默认加载诊断、subasset event、typed capability report。
  - 对齐 Bevy `Assets<T>`、`Handle<T>`、`AssetServer::load_state` / `recursive_dependency_load_state` 的语义；参考本地 Bevy 源码 [assets.rs](<E:/Git/ZirconEngine/dev/bevy/crates/bevy_asset/src/assets.rs>)、[handle.rs](<E:/Git/ZirconEngine/dev/bevy/crates/bevy_asset/src/handle.rs>)、[server/mod.rs](<E:/Git/ZirconEngine/dev/bevy/crates/bevy_asset/src/server/mod.rs>)，以及 docs.rs [Assets](https://docs.rs/bevy_asset/latest/bevy_asset/struct.Assets.html)、[AssetServer](https://docs.rs/bevy_asset/latest/bevy_asset/struct.AssetServer.html)。
- 新增一等 `MeshAsset` 与 `.zmesh`：
  - Rust 运行时类型命名为 `MeshAsset`，作者/序列化文档命名为 `ZMeshDocument`，源文件扩展为 `.zmesh`。
  - `MeshAsset` 至少包含 topology、attribute map、indices、bounds、asset_usage、virtual_geometry，可投影为现有 `RenderMeshDescriptor`。
  - 属性模型采用 Bevy `Mesh` 的核心思想：position、normal、uv0、color、joint_weight、joint_index 作为内置属性，允许后续扩展自定义属性；参考本地 [mesh.rs](<E:/Git/ZirconEngine/dev/bevy/crates/bevy_mesh/src/mesh.rs>) 和 docs.rs [Mesh](https://docs.rs/bevy_mesh/latest/bevy_mesh/struct.Mesh.html)。
- Texture 补齐：
  - `TextureAsset` 保留现有图片 decode；DDS/KTX/KTX2/ASTC 从“只解析容器”推进到“可判断 GPU 支持、可上传支持格式、不可支持时给出确定诊断和 fallback”。
  - 采用 Bevy `Image` 的 `TextureFormat`、sampler、asset_usage、压缩格式 feature-gate 思路；参考本地 [image.rs](<E:/Git/ZirconEngine/dev/bevy/crates/bevy_image/src/image.rs>) 和 docs.rs [Image](https://docs.rs/bevy_image/latest/bevy_image/struct.Image.html)。
- 模型导入升级：
  - OBJ/STL/PLY/DXF 插件改为输出 root `ModelAsset` + labeled `MeshAsset` subassets，原 `ModelAsset.primitives` 保留到 renderer 完成 handle 消费后再收缩。
  - glTF/GLB 改为 Bevy 风格标签：`Scene{n}`、`Node{n}`、`Mesh{n}`、`Mesh{m}/Primitive{p}`、`Texture{n}`、`Material{n}`、`DefaultMaterial`、`Animation{n}`、`Skin{n}`、`Skin{n}/InverseBindMatrices`；参考本地 [label.rs](<E:/Git/ZirconEngine/dev/bevy/crates/bevy_gltf/src/label.rs>)、[assets.rs](<E:/Git/ZirconEngine/dev/bevy/crates/bevy_gltf/src/assets.rs>) 和 docs.rs [GltfAssetLabel](https://docs.rs/bevy_gltf/latest/bevy_gltf/enum.GltfAssetLabel.html)。
- ZShader/ZMaterial 渲染闭环：
  - 保持 `.zshader` schema/texture slot/WGSL capture 诊断，补上 renderer 对 shader property schema、texture slot key、fallback policy 的直接消费。
  - `ZMaterial` 继续兼容现有 PBR 字段，但 renderer 首选 shader-driven slots；PBR 字段只作为标准材质桥接层。
  - 对齐 Bevy `StandardMaterial` 的 texture dependency、material key、uniform/fallback 思路；参考本地 [pbr_material.rs](<E:/Git/ZirconEngine/dev/bevy/crates/bevy_pbr/src/pbr_material.rs>) 和 docs.rs [StandardMaterial](https://docs.rs/bevy_pbr/latest/bevy_pbr/struct.StandardMaterial.html)。

- M5: ZShader/ZMaterial renderer 消费
  - 实施切片：renderer material preparation 优先读取 `MaterialAsset.texture_slots` 和 shader property schema；PBR legacy 字段只同步标准槽位。
  - 实施切片：补齐 shader/material readiness report 到 GPU state 的诊断输出；fallback material、fallback texture、missing WGSL capture 必须可追踪到 asset URL/UUID/slot。
  - 2026-05-26 进展：renderer material preparation 已加载 shader contract 后优先同步 shader-driven texture slots，并新增 `MaterialAsset::shader_property_values_for_shader(...)` -> `MaterialRuntime.shader_property_values` 的 typed property value 投影。当前投影覆盖 bool、float、int、uint、string、vec2、vec3、vec4/color，先作为运行时准备态，不编码 WGSL uniform layout、不创建 bind group。
  - 2026-05-27 进展：在 typed property value 之上新增 `RenderMaterialPropertyUniformPayload`，由 `ResourceStreamer::ensure_material(...)` 写入 `MaterialRuntime.shader_property_uniform_payload`。bool/float/int/uint/vec2/vec3/vec4 会编码成确定的 CPU-side uniform bytes 与 field layout；string 等非 uniform 值进入 unsupported 列表，等待后续 GPU bind group 或非 uniform property 通道处理。
  - 2026-05-27 进展：renderer material preparation 已消费上述 payload，新增 `GpuMaterialUniformResource` 并让 `PreparedMaterial` 持有 uniform buffer/bind group；mesh 和 deferred geometry pipeline layouts 增加 group 3，`MeshDraw` 在绘制时绑定材质 uniform。当前仍是固定中性 uniform 槽，不做完整 shader reflection 或自定义 texture array 绑定。
  - 2026-05-27 进展：renderer material readiness 继续补齐 shader pipeline layout 诊断。`ResourceStreamer` 会在 shader 声明 bind groups 时检查固定 group 3 binding 0 材质 uniform ABI，并把缺失、类型不匹配、compute-only visibility、重复 descriptor 或额外 group 3 binding 记录到 `pipeline_layout.group3...` diagnostics；空 pipeline layout 仍走当前固定 renderer layout。
  - 2026-05-27 进展：`.zshader` TOML 现在可以持久化 `[pipeline_layout]`，compound shader importer 会把 bind groups、bindings、resource type、visibility 与 push constant labels 写入 `ShaderAsset.pipeline_layout`。这让上面的 renderer material ABI 诊断直接作用于真实 ZShader 资产包，而不是只作用于程序内构造的 shader fixture。
  - 2026-05-27 进展：新增真实资产路径回归：临时 `.zmeta` compound shader 项目导入错误 group 3 layout 的 `.zshader`，artifact reload 后注册到 `ProjectAssetManager`，再由 `ResourceStreamer::ensure_material(...)` 产出 `RendererMaterialAbi` readiness diagnostics。该测试覆盖 authoring -> importer -> artifact -> renderer readiness 的闭环。
  - 2026-05-27 进展：`ShaderAsset::readiness_report()` 现在额外返回 `ShaderPipelineLayoutReadiness`，把 authored pipeline layout 的 bind group/binding/push constant 形状、binding resource type 和 stage visibility 暴露给 asset/editor diagnostics。renderer material ABI 判定仍保留在 `ResourceStreamer` 的 group 3 检查中。
  - 2026-05-27 进展：`RenderMaterialReadinessReport` 新增非阻塞 `diagnostics` 列表，`MaterialAsset.validation_diagnostics` 会以 `MaterialAsset` source 和 `material.validation_diagnostics[N]` path 暴露，但不进入 `validation_errors`，所以 glTF/default material importer note 不会把材质标记为不可 ready。
  - 2026-05-27 进展：renderer material stats 现在通过 `RenderStats.last_material_diagnostic_count` 汇总上一帧 material readiness 的非阻塞 diagnostics。该计数独立于 `last_material_validation_error_count` 与 `last_material_fallback_count`，用于让导入/默认材质说明进入运行时统计而不改变 ready/fallback/error 判定。
  - 2026-05-27 进展：`RenderMaterialPropertyUniformPayload` 的 unsupported rows 现在可投影为 `MaterialUniform` 非阻塞 readiness diagnostics，`ResourceStreamer::ensure_material(...)` 会把 string 等暂不能进入 uniform buffer 的属性以 `uniform.<name>` 路径并入材质 report。这样非 uniform property 被保留但未上传的状态能进入 renderer stats/editor 诊断，而不会变成 fallback 或 validation error。
  - 2026-05-27 进展：新增 submit 层回归覆盖 string shader property。测试在材质仍 ready、无 fallback、无 validation error 的情况下，确认 `MaterialUniform` 非阻塞诊断会进入 `RenderStats.last_material_diagnostic_count`。
  - 2026-05-27 进展：新增 ResourceStreamer 明细回归覆盖同一 string shader property，直接断言 `material_readiness_report(...)` 中的 `MaterialUniform` source、`uniform.debug_label` path、ready 状态以及空 fallback/validation error 列表。
  - 2026-05-27 进展：新增 shader schema default 路径回归，确认 `.zshader` property schema 中的 string default 会和 material override string 一样进入 typed value map、uniform unsupported row、`MaterialUniform` readiness diagnostic。
  - 2026-05-27 进展：新增 DTO 层去重回归，锁定 `RenderMaterialReadinessReport::push_diagnostic_once(...)` 会把重复 `MaterialUniform` readiness diagnostic 合并为一条，避免同一 unsupported uniform row 被重复计入 editor/report/submit stats。

## Assumptions
- 默认走 Bevy 风格资产公共语义，但不直接复制 Bevy ECS/AssetServer 内部实现；Zircon 继续以现有 `ResourceManager` 和 `.zmeta` 为资产身份基础。
- `MeshAsset` 是运行时一等资产名，`.zmesh` 是作者/序列化格式名；这与当前 `MaterialAsset` / `ZMaterialDocument`、`ShaderAsset` / `ZShaderDocument` 命名保持一致。
- FBX/USD/DAE/3DS 在本计划中保持 diagnostic-only，不承诺真实导入；真实导入作为单独 importer 后续计划。
- animation/skin 在 M4 建立 label/type/依赖通道，完整动画播放和编辑器时间线不并入本计划。
- SRP RendererData 的大规模重构不并入本计划；M5 只完成当前 renderer 对 `ZShader/ZMaterial` 的可验证消费闭环。
