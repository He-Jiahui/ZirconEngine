# 布局系统

## 自动化布局AutoLayout

- 新增轴向约束类型，供 pane、region、solver 共用：
  - `StretchMode { Fixed, Stretch }`
  - `AxisConstraint { min, max, preferred, priority, weight, stretch_mode }`
  - `ResolvedAxisConstraint`
- 锚点和位置约束（布局容器条件生效）
  - `Pivot{ x, y }` 确定自身的锚点位置 `(0,0)为左上 (1,0)为右上`   范围都是0~1
  - `Anchor{ x, y }` 确定相对于父级的锚点位置`(0,0)在父级左上开始计算 (1,0)在父级右上开始计算`
  - `Position{ x, y }` 位置偏移
- 约束语义固定：
  - `min == 0` 表示无最小值
  - `max == -1` 表示无最大值
  - `preferred` 为显式字段；若覆盖层未提供，则回退到描述符默认值，再回退到现有内建 preset 的 extent
- `ViewDescriptor` 增加 pane 默认约束，分别提供宽/高两个轴的默认值。
- `WorkbenchLayout` 增加响应式覆盖层：
  - `region_overrides`，键为 `ShellRegionId { Left, Document, Right, Bottom }`
  - `view_overrides`，键为 `ViewInstanceId`
  - 现有 `drawer.extent` 保留，并定义为 drawer 主轴上的持久化 `preferred`
- 新增共享求解结果模型：
  - `WorkbenchShellGeometry { window_min_width, window_min_height, region_frames, splitter_frames, viewport_content_frame }`
  - `ShellFrame { x, y, width, height }`
- Slint 壳体接口改为消费几何结果：
  - 不再让 `WorkbenchShell` 自己算 `document_zone_x`、`right_stack_x`、`bottom_panel_y`
  - 改为接收 host 下发的 frame、最小窗体尺寸、splitter 命中区

## 更新机制

### 设脏与更新

当布局设脏（任意布局更新事件触发）后，例如过渡动画、拖拽事件、布局变化事件之后，当前一帧将会更新并解除脏标记。

设脏机制：根据影响范围设脏（根据变动的容器进行修正大小），容器是否会根据子组件内容变化而发生大小变化（如果会，则需要将脏标记向父级传播，直到被阻止），当容器大小不会受子组件内容变化时，将会阻止设脏标记继续向上传播。脏标记只会传播到根节点。

### 布局计算求解器

#### 反向求解

布局将会自内而外地求解`desiredSize`，如果布局组件大小固定，则`desiredSize`就是它本身大小，如果布局组件大小并非固定不变，例如文本和图片或可变大小容器，则会通过`desiredSize`计算需求大小。如果有`preferredSize` 也会参考它。

#### 正向传递

布局将会自外而内地传递预期值，求解器首先会根据子组件的AutoLayout分配预期值（此时如果容器包含之前的`desiredSize`, 同时AutoLayout大小会在计算中尝试保留该大小 取决于轴向约束类型）

## 组件系统

### 容器组件

容器组件通常可以包含若干功能性组件，并且形成某种布局模式。

#### Container

根据autoLayout改变大小，或者选择约束模式固定的情况下则大小固定，大小改变情况根据AutoLayout选项决定。

子组件会被约束`maxSize`为Container的最大大小，子组件通过锚点约束计算位置和大小，通常只要子组件不大于Container大小就不会被约束。

子组件X,Y可以让子组件自行修改位置 相对于锚点。

超出容器范围可以被裁剪

背景可以有颜色，如果需要图片则需要外层Overlay配合

可以开启滚动的布局（无、横向、纵向、双向），开启允许滚动后就允许子组件在范围内`maxSize`不受约束

允许同时横向纵向滚动，（滚动条配置：总是不显示、总是显示、溢出显示）超出本身MaxSize根据条件出现滚动条

#### ScrollableBox

优化的可滚动Box布局，不会渲染全部列表内元素，只会获取当前滚动到区域范围的元素（参考无限列表的局部计算模式）

只允许横向或者纵向滚动。（滚动条配置：总是不显示、总是显示、溢出显示）超出本身MaxSize根据条件出现滚动条

间隔: 类似Space作用在多个元素之间穿插间隔

#### GridBox

内部元素统一大小，按块进行分布，不会渲染列表内全部元素，只会获取当前滚动到区域范围的元素（参考无限列表的局部计算模式）

只允许横向或者纵向滚动。（滚动条配置：总是不显示、总是显示、溢出显示）超出本身MaxSize根据条件出现滚动条

间隔: 类似Space作用在多个元素之间穿插间隔

#### FlowBox

子组件只允许自动布局，FlowBox（横向模式）允许子组件从左往右布局后超出范围则从上往下到第二行继续从左往右布局 （纵向模式同理）。在AutoLayout未指定的时候，将会完全根据子组件大小排布，如果横向模式约束了最大Width，则会在即将超过Width的时候自动换行。纵向模式同理。此时子组件将尽可能以`preferredSize`布局。

间隔（X,Y）: 类似Space作用在多个元素之间穿插间隔

纵向对齐模式（上、中、下）

横向对齐模式（左、中、右）

横向拉伸模式（左对齐、右对齐、居中对齐、两端对齐）

纵向拉伸模式（上对齐、下对齐、居中对齐、两端对齐）

#### HorizontalBox

横向排布，根据子组件AutoLayout确定子组件纵向是占满还是保持子组件自身大小。最大大小也是通过AutoLayout决定是否跟随子组件计算，跟随时选择最大（最大高度）子组件的最大高度，最大（最小高度）子组件的最小高度

选项：

间隔: 类似Space作用在多个元素之间穿插间隔

对齐模式（上、中、下）

拉伸模式（上对齐、下对齐、居中对齐、两端对齐）

#### VerticalBox

纵向排布，同上

选项：

间隔: 类似Space作用在多个元素之间穿插间隔

对齐模式（左、中、右）

拉伸模式（左对齐、右对齐、居中对齐、两端对齐）

#### Overlay

多个组件同时在一个容器覆盖显示，子组件越高则渲染层级越高，AutoLayout决定是否跟随子组件计算，跟随时选择最大的容器

横向对齐模式（左中右）

纵向对齐模式（上中下）

## 输入事件系统

### 全局事件

输入行为会直接引发全局事件，与下方事件传递的全局需要区分开来。

GlobalInputEvent

### 事件传递

#### InputEvent

根响应 RootInputEvent(只有没有接受者时才响应)

#### 触控的冒泡事件系统：BubbledInputEvent

首先界面将会被划分分区，类似于四叉树，通过平面划分算法，快速定位到对应区域的鼠标点击事件到底属于哪个鼠标的节点，然后向上传递直到被处理（Handled）。堆叠UI处理：Prevent机制（如果鼠标事件在叶子结点或者冒泡时Prevent了，则在堆叠的UI对象位置中找到下一个节点触发）、穿透机制：同时触发下一个节点。没有接收者则直接根响应

#### 聚焦和导航的键盘事件系统：FocusedInputEvent And NavigationInputEvent

从聚焦对象开始的响应 Focus to Navigation。例如Focus也会给当前聚焦的元素派发事件，快键键，上下左右等导航键。冒泡、返回上层

根响应在聚焦对象和父级对象不捕获的时候触发。

### 机制说明

#### 处理机制

处理后事件将不会继续冒泡传递。即最终停留在被处理对象上

#### 阻止机制

阻止之后事件将寻找下一个同位置目标开始传递

#### 穿透机制

穿透允许下一个同位置目标也开始传递事件

#### 捕获机制

事件捕获后，就会认为聚焦到某个对象，后续事件主要为聚焦对象触发为主，直到释放
