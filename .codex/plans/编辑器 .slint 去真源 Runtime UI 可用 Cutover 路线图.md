# 编辑器 `.slint` 去真源 / Runtime UI 可用 Cutover 路线图

## Summary
- 终点已锁定为两条硬标准：第一，编辑器只能在“业务树、布局公式、事件语义、命中与路由结果全部来自 `TOML -> UiSurface -> host projection`，并且现有 `workbench.slint` 不再是业务真源”时，才可宣称完成 cutover。第二，运行时只能在“共享 UI 资产可直接支撑 HUD、暂停菜单、设置对话框、虚拟化列表等真实游戏界面，并由引擎自己的渲染/输入链路稳定消费”时，才可宣称 UI 已可用。
- 当前剩余 seam 以三处为主：`zircon_editor/src/host/slint_host/callback_dispatch/template_bridge/workbench.rs` 仍用 drawer extent 过渡桥；`zircon_editor/src/host/slint_host/floating_window_projection.rs` 仍有 shared source 与 `WorkbenchShellGeometry` 双源拼接；`zircon_ui/src/surface.rs` 的 `UiRenderExtract` 仍是几何级抽取，不足以支撑运行时可交付 UI。
- 执行顺序固定为“先冻结权威边界，再消灭 editor 过渡桥，再补 runtime 视觉抽取与 renderer，最后同时做 cutover 验收与删除旧路径”。迁移期间不允许新增任何直接依赖 legacy geometry、control-specific Slint frame setter/getter、或 editor-only 绘制语义的代码。

## Public Interfaces
- `zircon_ui` 保持共享权威，但要把 `UiRenderCommand` 升级为带 `kind` 的视觉命令；新增 `UiRenderCommandKind`、`UiResolvedStyle`、`UiTextMeasureService`、`UiVisualAssetRef`，并把 `UiDirtyFlags` 明确拆成至少 `layout/style/text/render` 四类脏标记。
- `zircon_ui` 的 layout/event 合同继续不变，但 `UiSurface::rebuild` 的产物必须从“frame/clip/z-index 列表”升级为“可直接被 renderer 消费的视觉 draw list”，覆盖 quad、border、text、image、clip、opacity、z-order。
- `zircon_editor` 用统一的 `BuiltinWorkbenchWindowProjectionBundle` 取代当前分裂的 `BuiltinWorkbenchTemplateBridge` 与 `BuiltinFloatingWindowSourceTemplateBridge` 权威角色；root shell、drawer shell、floating window、popup/dialog/transient overlay 全部由它产出共享 projection/source，不再由 helper stitching。
- `zircon_editor` 的 Slint 宿主收敛为通用 `UiHostWindow` 与通用 host component catalog；`SlintUiHostComponentKind` 不再承载 workbench 专用业务壳种类，业务结构只来自 projection。
- `zircon_graphics` 新增 screen-space UI pass，唯一消费 `UiRenderExtract`；它不感知 editor-only docking/page/window 语义，只处理视觉 draw list、字体/图片资源、裁剪、批处理与提交顺序。

## Implementation Plan

### Phase 1: 冻结 Cutover 合同
- 编辑器去真源：把 `.slint` 最终边界钉死为“仅允许 generic host window/bootstrap，不允许任何 workbench/menu/popup/drawer/document/floating 业务树、布局公式、control id 路由、frame setter/getter”；新增仓库级守卫测试，禁止再引入新的 `WorkbenchShell` 业务布局逻辑和 legacy geometry presentation seam。
- 运行时可用：把“游戏级可交付”具体锁成四个验收 fixture：HUD overlay、暂停菜单、设置对话框、虚拟化 inventory/list；这四个 fixture 必须全部来自 `.ui.toml` 资产和 shared core，而不是 editor host 特例。
- 完成门槛：实现者后续不能再自行决定 cutover 是否允许残留 `workbench.slint` 业务树，也不能把“运行时可用”降级成仅几何闭环或 editor preview 级能力。

### Phase 2: 收口 Editor 剩余几何过渡桥
- 编辑器去真源：把 left/right drawer width 与 bottom drawer height 从 `BuiltinWorkbenchDrawerLayoutInputs::from_chrome_snapshot` 迁到 builtin template/runtime source；drawer shell/header/content 直接由 builtin template 建模并求 frame，`chrome_snapshot` 只保留业务状态，不再输出 presentation extent。
- 编辑器去真源：把 `FloatingWindowProjectionBundle` 的 outer-frame authority 前推成 shared projection source；`resolve_floating_window_projection_base_outer_frame` 只允许用 requested frame、native host bounds、shared template source 计算外框，不再以 `WorkbenchShellGeometry::floating_window_frame` 作为 presentation 真源。
- 运行时可用：并行冻结 shared visual contract，把 style token、widget props、image/text/icon 引用的最终视觉落点定义到 `UiResolvedStyle` 和 `UiRenderCommandKind`，避免 editor host 与 runtime renderer 各自发明一套视觉字段。
- 完成门槛：drawer shell/header/content 与 floating window outer/content/tab strip frame 都能从 shared projection bundle 单独恢复；presentation correctness 不再依赖 legacy extent 或 geometry fallback。

### Phase 3: 把 Editor 输入与宿主呈现完全收口到 Shared Projection
- 编辑器去真源：menu、popup、dialog、transient overlay、activity rail、host-page、document-tab、drawer-header、tree/list/scroll surface 全部改为只读取 shared root/floating projection frames；`pointer_layout.rs` 中各类 `Some(&root_shell_frames)` 变成统一投影 bundle 输入，而不是不同 builder 自己补 legacy 几何。
- 编辑器去真源：所有宿主点击、滚轮、拖拽、dismiss、focus 切换都先进入 `UiSurface + UiPointerDispatcher`，Slint 只上传规范化输入事实；route id、binding id、typed command、reflection/nativeBinding 继续保留，但不再由 `.slint` 回调命名来决定语义。
- 运行时可用：同步把 runtime host 的 pointer/keyboard/gamepad 输入桥接定型为与 editor 同构的 dispatcher 入口，确保 HUD/menu/dialog/list 的输入规则不是另写一套 runtime-only 路由器。
- 完成门槛：editor 所有命中与 pointer route 都能通过 shared projection 重放；删除 control-specific frame getter/setter 后，menu/popup/tree/list/scroll 交互行为不回退。

### Phase 4: 用 Generic Host Window 替掉业务 `workbench.slint`
- 编辑器去真源：把现有 `workbench.slint` 从 build 主输入中移除，改成通用 `UiHostWindow` 宿主文件；root window 和 native floating window 都实例化同一 generic host window，业务结构完全由 runtime projection 驱动。
- 编辑器去真源：Slint 侧只允许保留通用 host primitives 与窗口 bootstrap，不再包含 `WorkbenchShell`、顶栏菜单、drawer header、document host、floating header、menu popup 等业务组件树；任何业务节点都必须由 TOML builtin template 实例化后投影出来。
- 运行时可用：开始把 shared draw list 接到 `zircon_graphics` 的 screen-space UI pass，先跑通 quad/border/text/image/clip 五类核心 primitive，再把 scrollbar、selection、focus ring、popup scrim、dialog chrome 这些 UI 常见视觉元素补齐。
- 完成门槛：`workbench.slint` 不再是业务真源，甚至不再作为 workbench 专用文件存在；editor 与 runtime 首次共用同一份“结构/布局/事件真源在 shared core、宿主只消费 projection”的架构闭环。

### Phase 5: 把 Runtime UI 提升到游戏级可交付
- 运行时可用：在 `zircon_ui` 中接入 `UiTextMeasureService`，让 Label、Button、TextField、List row、Dialog title/body 能依据字体、字号、padding、icon/image 内在尺寸得到稳定 desired size；文本测量、换行、截断、省略号规则以 shared service 为准，editor host 和 runtime renderer 共用同一测量输出。
- 运行时可用：在 `zircon_graphics` 中完成字体 atlas、图片/图标纹理引用、clip/scissor、批处理、draw-order 提交；`UiRenderExtract` 的每条命令都可映射到真实 GPU 绘制，而不是只供 preview 枚举 frame。
- 运行时可用：在 runtime 宿主层新增 UI manager/service，负责加载 `.ui.toml` layout/widget/style 资产、实例化 `UiSurface`、桥接输入、驱动更新、提交 render extract；screen-space UI 为 V1 必选，world-space UI 继续留到后续阶段。
- 编辑器去真源：在同一阶段补齐 generic host catalog，使 editor 也只消费 shared visual/state payload，不再有 `UiHostIconButton`/`UiHostLabel` 这类带业务假设的过渡件缺口。
- 完成门槛：HUD overlay、暂停菜单、设置对话框、虚拟化 inventory/list 四个 runtime fixture 都能在真实引擎渲染与输入链路下运行，不再依赖 Slint 或 editor preview 消费路径。

### Phase 6: 删除旧路径并做最终宣称
- 编辑器去真源：删除 legacy menu button frame fallback、drawer extent bridge、floating window geometry fallback、control-specific Slint callback/property glue，以及所有仅服务旧手写壳的 helper；保留的 `.slint` 文件只能是 generic host bootstrap，且不含业务 control id、layout math、event semantics。
- 运行时可用：删除“仅几何 render extract”假设与 editor-preview-only 消费路径，把所有 runtime UI 视觉与输入回归到 shared draw list + graphics pass + runtime UI manager；shared core 不再需要 editor host 参与才能验证 UI 可见行为。
- 双端共通：把 parity harness 与 gameplay fixture 全部转成强制验收门槛，只有在 editor cutover 与 runtime fixture 同时通过时，才允许对外宣称“编辑器业务树不再以 `.slint` 为真源”和“运行时 UI 已可用”。
- 完成门槛：编辑器侧编译和运行时不再依赖任何业务 `.slint` 树；运行时侧已经能独立加载 shared UI 资产、绘制、交互、滚动、导航、弹窗、文本输入，并承载真实游戏界面。

## Assumptions And Defaults
- 编辑器终点按你刚锁定的最严格口径执行：不是“Slint 只做宿主”就算完成，而是现有业务 `workbench.slint` 必须退出真源角色；最终只允许 generic host window/bootstrap 留在 Slint。
- 运行时终点按“游戏级可交付”执行，不接受“有 render extract 就算可用”的降级解释；最低验收是四个真实 UI fixture 在引擎渲染与输入链路下稳定运行。
- V1 仍只覆盖 screen-space UI；world-space UI、复杂动画、完整可视化主题编辑器、富文本排版、IME 深度支持可继续排在后续阶段，但不能阻塞本路线图的完成宣称。
- `WorkbenchLayout` 继续只是编辑器拓扑持久化权威；`UiSurface` 继续是布局、命中、焦点、滚动、渲染抽取的唯一运行时权威；`zircon_graphics` 继续只消费 shared draw list，不理解 editor-only 语义。
