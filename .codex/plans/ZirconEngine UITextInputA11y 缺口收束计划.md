# ZirconEngine UI/Text/Input/A11y 缺口收束计划

## Summary
- **目标**：把当前 UI 缺口整理成可执行里程碑，优先补齐 input manager、layout、render boundary、property binding、headless widgets、UI ECS、text/SDF、a11y，到接近 Bevy UI 完成度，但保持 Zircon-native runtime/interface/editor 分层。
- **架构默认**：`zircon_runtime_interface` 定义中立合同；`zircon_runtime` 拥有运行时行为、布局、文本、a11y、render extract、UI ECS bridge；`zircon_editor` 只做 authoring 与 styled widgets，不成为 runtime truth。
- **Bevy 参考**：UI/layout/focus 参考 [bevy_ui](/E:/Git/ZirconEngine/dev/bevy/crates/bevy_ui/src/lib.rs:1)、[bevy_input_focus](/E:/Git/ZirconEngine/dev/bevy/crates/bevy_input_focus/src/lib.rs:1)、[bevy_ui docs](https://docs.rs/bevy_ui/latest/bevy_ui/)；widgets/a11y/Feathers 参考 [bevy_ui_widgets](/E:/Git/ZirconEngine/dev/bevy/crates/bevy_ui_widgets/src/lib.rs:1)、[bevy_a11y](/E:/Git/ZirconEngine/dev/bevy/crates/bevy_a11y/src/lib.rs:1)、[bevy_feathers](/E:/Git/ZirconEngine/dev/bevy/crates/bevy_feathers/src/lib.rs:1)；text/render 参考 [bevy_text](/E:/Git/ZirconEngine/dev/bevy/crates/bevy_text/src/lib.rs:1)、[bevy_ui_render](/E:/Git/ZirconEngine/dev/bevy/crates/bevy_ui_render/src/lib.rs:1)、[bevy_text docs](https://docs.rs/crate/bevy_text/0.18.1)。

## Key Interface Changes
- **UI schedule contract**：在 runtime 内固定 `InputCollect -> Focus -> WidgetBehavior -> TextMeasure -> Layout -> PostLayout -> Picking -> A11yExtract -> RenderExtract -> BatchPrepare`，每阶段输出 dirty/report，避免 hover/click 触发整树重建。
- **UI ECS bridge**：新增 runtime-owned UI entity/component projection 层，把 `UiSurface` retained tree 与 ECS change detection 对齐；ECS 只拥有运行时事实，editor selection、viewport tool、authoring draft 不写入 runtime UI ECS。
- **Binding model**：把现有 retained attributes + `UiSurfaceComponentStateStore` + reducer 收束为 `UiBindingSource / UiBindingTarget / UiBindingUpdate` 合同，支持 state-backed、attribute-backed、ECS-backed 三类来源。
- **Layout backend report**：把现有 Taffy bridge 升级为 `UiLayoutEngineSelectionReport`，明确每个 container 是 Taffy native、Zircon fallback 或 unsupported，并记录 fallback 原因。
- **Text shaping boundary**：引入 `UiTextShaper` 抽象，当前 glyphon/SDF 作为 backend；后续 Parley/Swash/HarfBuzz 能替换 shaping 层而不改 `UiRenderExtract`。
- **A11y bridge**：中立 `UiAccessibilityTreeSnapshot` 继续作为 runtime 输出；AccessKit 只作为可选平台 bridge，不把 AccessKit 类型泄漏到 editor/widget 合同。

## Milestones
- **M1 Input Manager 收束**
  - 完成 pointer capture、pointer lock、高精度指针、IME、popup、tooltip、drag/drop 的统一 owner 校验和清理策略。
  - 补齐 drag distance / drag phase DTO，使 ScrollbarThumb、slider drag、text selection 不再伪造 pointer 行为。
  - 输入路由统一走 `UiDispatchReply` effects；keyboard/text/IME/navigation 都记录 `UiFocusedInput` 路由。
  - 验收：pointer capture release outside、IME owner cleared on blur、popup Escape、tooltip arm/show/cancel、drag begin/update/end owner mismatch。

- **M2 UI Layout 与 Taffy Surface Cache**
  - 保留混合架构：Flex/Grid/Wrap/Block 走 Taffy；Overlay、Canvas/Free、Scrollable、VirtualList、editor docking/splitter 继续 Zircon 自管。
  - 将局部临时 `TaffyTree` 改为 surface-level cached tree，增量更新 style/node/measure dirty。
  - 补齐 padding、margin、align、justify、aspect、grid placement、text/image measure callback 映射。
  - 验收：同一节点 arranged frame、hit entry、render command、pointer path 在 Taffy/Zircon backend 下保持一致。

- **M3 Property Binding 与 Runtime State Graph**
  - 把 `mutate_property`、widget alias、component-state typed values、a11y SetValue 合并进统一 binding update pipeline。
  - 支持 `value_property / checked_property / open_property / min/max/step_property / scroll_target` 的 attribute-backed 与 state-backed 双路一致性。
  - ECS-backed source 只用于 runtime facts；editor authoring state 通过 editor projection 消费，不反向污染 runtime world。
  - 验收：Button/Toggle/Range/Radio/TextInput/a11y SetValue 都通过同一 binding report 产生 dirty、event、state 更新。

- **M4 Headless Widget 完整化**
  - 补齐 ScrollbarThumb drag、Menu/MenuStack、Popover、Tooltip、TextInput selection/clipboard/IME/multiline/filter/max chars。
  - 保持 Bevy-style headless 行为层：styled editor widgets 只消费行为和 theme token，不 fork reducer。
  - 将 Button/IconButton、Checkbox、RadioGroup、Slider、Scrollbar、TextInput、Menu、Popover、Tooltip 纳入统一 disabled/focus/picking/a11y gate。
  - 验收：pointer 与 keyboard 触发同一 widget event；disabled 状态阻止 pointer、keyboard、a11y action；menu outside click 和 Escape 关闭正确 popup stack。

- **M5 UI ECS 与 Schedule**
  - 为 runtime UI 建立 ECS projection：UI node identity、layout dirty、interaction state、text dirty、a11y dirty、render dirty 都可被 schedule 查询。
  - ECS bridge 不替代 `UiSurface` 的 retained truth；它只提供 Bevy-like systems/change detection 和跨模块调度可见性。
  - runtime UI fixtures、editor retained host、viewport overlay 通过同一 schedule/report 汇聚。
  - 验收：单节点 value change 只污染必要 layout/text/render/a11y domain；hover/click 不重建 component structure。

- **M6 Text 到 Bevy-Level**
  - `UiTextShaper` 承接 rich runs、font fallback、grapheme/word boundary、bidi、selection/caret/composition geometry。
  - TextInput 补齐 grapheme delete、word move、selection replace、clipboard、IME composition commit/cancel、多行换行、过滤和最大长度。
  - layout measure 使用同一 shaped result，避免 layout/render/text hit 三套估算。
  - 验收：mixed LTR/RTL、emoji/grapheme、rich run、wrap/ellipsis、selection/caret、IME composition 在 render extract 与 hit testing 中一致。

- **M7 SDF 生产化**
  - 保留现有 renderer-local SDF atlas/font bake/GPU path，升级为可持久化 atlas/cache 策略。
  - SDF 与 native glyphon 共用 shaping/layout 输入；只在 raster/cache/render backend 分叉。
  - 补齐 atlas eviction、font fallback、quality parameters、clip/opacity/caret/selection parity。
  - 验收：Native/SDF/Auto 三种 render mode 对同一 text layout 只差 backend，不差 geometry；capture 证明 SDF 是真实 glyph footprint 而非占位块。

- **M8 Render Boundary 与 Batching 收束**
  - `UiRenderExtract` 覆盖 background、border、image、material、gradient、shadow、text、selection、cursor、debug overlay、clip/scissor、batch key、split reason。
  - WGPU surface、runtime screen-space UI、editor native painter 都消费同一 DTO。
  - 完成 sprite atlas UV validation、damage patch、direct-surface command stream 的稳定验证。
  - 验收：GPU/softbuffer parity、hit/render frame consistency、batch reduction metrics、damage-only redraw、atlas UV clipped sampling。

- **M9 Accessibility Runtime**
  - 完整生成 `UiAccessibilityTreeSnapshot`：role、name、description、state、actions、bounds、parent-child、focused node、diagnostics。
  - name 来源优先级固定为 explicit a11y name、label-for、文本内容、tooltip。
  - a11y action 回流到 widget/binding pipeline，不能绕开 disabled gate 和 property alias。
  - 验收：Button/Checkbox/Radio/Slider/TextInput/Menu/Scrollable roles/actions；hidden/disabled/despawn 清理；AccessKit bridge feature gate 可选通过。

- **M10 Feathers-like Styled Editor Widgets 与 Cutover**
  - 在 headless widgets 上构建 editor widget kit：toolbar、inspector、tabs、menus、dock header、property row、color controls、search/text input、tooltip/popover。
  - 迁移 workbench、asset editor、inspector、drawer、floating window、viewport toolbar、menus 到共享 focus/picking/widgets/a11y/render 合同。
  - 删除 editor 局部重复 hover/popup/focus 路由，只保留 authoring state 和 style/theme。
  - 验收：主 editor 工作流截图/交互 golden；styled widgets 不包含行为 fork；runtime/editor 边界没有 editor-to-runtime 反向 truth。

## Test Plan
- **Contract gates**：`cargo test -p zircon_runtime_interface --lib ui_contract_spine --locked --jobs 1`，覆盖 serde/default/schema/backward compatibility。
- **Runtime UI gates**：`cargo test -p zircon_runtime --lib focus_navigation widget_ text_layout accessibility ui_surface --locked --jobs 1`，按里程碑选择 focused filters。
- **Render gates**：`cargo test -p zircon_runtime --locked runtime_ui render_product_ui --jobs 1`，以及 `cargo test -p zircon_runtime --lib ui_surface --locked --jobs 1`。
- **Editor gates**：`cargo test -p zircon_editor --lib component_showcase gpu_presenter native_material_painter render_framework_boundary --locked --jobs 1`。
- **Acceptance evidence**：每个里程碑结束记录测试命令、失败修复、未决限制，并更新 `docs/ui-and-layout`、`docs/zircon_runtime/ui`、`docs/zircon_runtime_interface/ui`、`docs/zircon_runtime/rhi/ui_surface.md` 中对应模块文档。
- **Final gate**：在 Windows 构建面恢复后运行 `cargo test --workspace --locked --jobs 1 --message-format short --color never -- --test-threads=1`；若第三方 `wgpu-hal` DX12 编译问题复现，单独记录为外部依赖阻塞，不把 focused Zircon UI 验收混淆为失败。

## Assumptions
- “Bevy 完成度”指能力、边界和验证覆盖对齐，不复制 Bevy ECS/API 名称。
- 不新增第四个 root crate；UI 工作继续落在 `zircon_runtime_interface`、`zircon_runtime`、`zircon_editor` 三层内。

- Editor authoring state 不进入 runtime UI ECS；runtime UI ECS 只表达运行时事实和 schedule/change-detection。
- 每个里程碑按 ZirconEngine 里程碑优先策略执行：先完成实现切片和必要测试代码，里程碑末尾统一进入 testing/debug/docs 阶段。
