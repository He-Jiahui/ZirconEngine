# 多插件组合可选功能规则设计

## Summary
- 采用“主插件子功能”模型：组合功能显示在主插件详情页，但作为独立 runtime/editor 链接库参与导出和注册。
- 组合功能不自动启用依赖；依赖不全时阻止开启，并显示缺失列表与“一键开启依赖”的明确操作。
- 功能实现放在 `zircon_plugins/<owner>/features/<feature_id>/...`，不放回 `zircon_runtime/src/extensions`。

## Key Changes
- 在 `PluginPackageManifest` 增加 `optional_features: Vec<PluginFeatureBundleManifest>`：
  - 字段包括 `id`、`display_name`、`owner_plugin_id`、`dependencies`、`modules`、`capabilities`、`default_packaging`、`enabled_by_default=false`。
  - `dependencies` 使用 all-of 规则，只引用插件 id 和稳定 capability，不引用具体 crate 名。
- 新增 `ProjectPluginFeatureSelection`，挂在对应 `ProjectPluginSelection.features` 下：
  - 字段包括 `id`、`enabled`、`required`、`target_modes`、`packaging`、`runtime_crate`、`editor_crate`。
- 新增 `RuntimePluginFeature` / `RuntimePluginFeatureRegistrationReport`，复用现有 `RuntimeExtensionRegistry` 注册 module、manager、component、render feature 等贡献。
- 加载顺序固定为：基础插件注册报告 -> 可选功能注册报告；可选功能按依赖拓扑排序，发现缺失、重复 id、循环依赖时给结构化诊断。
- Runtime 仍以 `DependencySpec` 约束真实服务依赖；UI 的“插件已开启”只负责可用性门禁，不能替代 manager/driver/plugin 级依赖声明。

## Dependency Rules
- 一个组合功能必须有且只有一个 `owner_plugin_id`；owner 也必须出现在依赖列表中并标记为 primary。
- 功能可用条件：owner 插件启用、所有依赖插件启用、所有 required capability 由已启用插件或已启用功能提供、目标模式交集非空。
- capability 是公开契约，例如：
  - `runtime.plugin.sound`
  - `runtime.plugin.physics`
  - `runtime.capability.physics.raycast`
  - `runtime.feature.animation.timeline_event_track`
- v1 不支持 OR 依赖；如果未来需要“物理射线或专用声学射线后端”，应建两个功能或引入后续 dependency groups。
- optional 功能缺依赖时只是 blocked；required 功能缺依赖时在运行和导出阶段都视为 fatal。

## Examples
- `sound.timeline_animation_track`
  - owner: `sound`
  - depends on: `sound/runtime.plugin.sound`、`animation/runtime.feature.animation.timeline_event_track`
  - provides: `runtime.feature.sound.timeline_animation_track`
  - crates: `zircon_plugin_sound_timeline_animation_runtime`、`zircon_plugin_sound_timeline_animation_editor`
- `sound.ray_traced_convolution_reverb`
  - owner: `sound`
  - depends on: `sound/runtime.plugin.sound`、`physics/runtime.plugin.physics`、`physics/runtime.capability.physics.raycast`
  - provides: `runtime.feature.sound.ray_traced_convolution_reverb`
  - target modes: client runtime + editor host only, because sound 当前不支持 server runtime。

## Test Plan
- Manifest roundtrip：`plugin.toml` 能声明 optional features、dependencies、modules、capabilities。
- Catalog completion：主插件详情能列出默认关闭的可选功能，项目 manifest 保留 nested feature selection。
- Dependency status：依赖全开为 available；缺插件、缺 capability、target 不匹配、循环依赖分别产生明确诊断。
- Export/linking：只链接 active feature crates；missing optional 给 warning，missing required 给 fatal error。
- Runtime registration：基础插件先注册，feature 后注册；feature 的 manager/module 能通过 `DependencySpec` 解析真实 sound/animation/physics 服务。

## Assumptions
- 已选择“主插件子功能”形态，而不是独立普通插件包。
- 依赖缺失时采用“阻止并引导”，不隐式修改项目配置。
- v1 不做版本范围约束；以后可在 `PluginFeatureDependency` 上补 `min_version` / `version_req`。
