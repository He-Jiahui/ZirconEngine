# 编辑器资源管理器与运行时资源分层重构计划

## Summary
- 目标是把当前“`zircon_asset::AssetManager` 同时承担 project/import/resource façade、editor 只显示 locator 列表”的状态，升级成 `运行时资源管理 + 编辑器资产目录/Meta/引用/预览管理` 分层架构。
- 采用 `方案A`：在 `zircon_asset` 内拆成两个 manager。
  - `AssetManager` 保留为运行时资产管理器，负责 `Resource` 生命周期、引用计数、加载/卸载、typed handle + lease。
  - `EditorAssetManager` 新增为编辑器资产管理器，负责目录扫描、`*.meta.toml`、UUID/path 双保险引用、引用图、预览调度和缩略图缓存。
- `zircon_editor` 不直接拥有资产数据库实现，只通过 `zircon_server` façade 消费 `EditorAssetServer + ResourceServer + AssetServer`。
- 默认策略固定：
  - 持久化引用为 `UUID主，last_known_locator/path辅`
  - 文件变化后先标脏；资源当前可见时后台刷新预览，否则继续显示缓存缩略图
  - 预览缓存放 `Project/library`
  - 缺失 `*.meta.toml` 首次扫描自动生成
  - 引用管理维护“完整直接引用图”
  - 运行时公开 `typed handle + lease`，不直接暴露底层 `Resource` 对象
  - UI 先升级现有 `Project/Assets` 面板，`AssetBrowser` 暂不做第二入口

## Public Interfaces
- `zircon_resource` 增加运行时基础抽象：
  - `AssetUuid`
  - `AssetReference { uuid, locator }`
  - `Resource` trait 作为运行时基类契约，公开公共元信息和装载状态访问
  - `ResourceLease<T>`，用于引用计数 acquire/release
  - `RuntimeResourceState::{Unloaded, Loading, Loaded, Error, Reloading}`
  - `ResourceTypeDescriptor` / `ResourceInspectorAdapterKey`，用于“后缀 + meta”决定资源属性与编辑器面板适配
- `ResourceId` 规则调整：
  - 项目资源不再只由 locator 派生；改为由 `AssetUuid + #label` 稳定派生
  - `builtin://` 仍可走稳定内建映射
  - `mem://` 仍为进程内临时 id
- `zircon_server` 调整 façade：
  - `AssetServer` 收窄为 project/import/watch 生命周期 façade
  - `ResourceServer` 扩展 `acquire/release/by_uuid/by_locator/status/revision`
  - 新增 `EditorAssetServer`，提供资源树、meta、引用、预览状态、预览请求、脏标记和引用查询
- `zircon_asset` 新增/固定：
  - `EditorAssetManager`
  - `AssetMetaDocument`
  - `AssetCatalogRecord`
  - `ReferenceGraph`
  - `PreviewCache`
  - `PreviewScheduler`
  - `PreviewArtifactKey`
- 资源文件 sidecar 格式固定为 `foo.ext.meta.toml`，至少包含：
  - `format_version`
  - `asset_uuid`
  - `primary_locator`
  - `kind`
  - `import_settings`
  - `editor_adapter`
  - `source_mtime_unix_ms`
  - `source_hash`
  - `preview_state`
- `SceneAsset`、`MaterialAsset`、后续可序列化资产中的资源引用统一改成 `AssetReference`，不再只写 locator 字符串

## Implementation Changes
- 运行时资源层：
  - 在 `zircon_asset` 内把当前 `AssetManager` 重构为纯运行时 manager，职责只保留解析、加载、卸载、缓存和 refcount
  - 建立 `ResourceSlot` 表，按 `ResourceId` 维护 `descriptor + state + resident payload + ref_count + revision`
  - `ResourceLease<T>` drop 时递减计数；计数归零后允许转 `Unloaded` 并释放 resident payload/GPU 侧依赖
  - `ResourceServer` 查询和 acquire 全部接受 `uuid` 与 `locator` 两种入口
- 编辑器资产层：
  - 新增 `EditorAssetManager` 作为同一 AssetModule 下的 sibling manager，不放进 `zircon_editor`
  - 启动 project 后先扫描 `assets/`，为缺失资源自动补写 `*.meta.toml`
  - 变更检测采用“两段式校验”：先用文件时间做廉价 dirty 判断，再用内容 hash 确认；meta 中同时保存二者
  - 建立 `AssetCatalogRecord` 作为 editor 权威索引，内容包含 `uuid + locator + meta + preview status + direct references`
  - 建立 `ReferenceGraph`，维护直接边：scene→asset、material→shader/texture、model/subresource→source、meta→source
- 引用与持久化：
  - 所有项目资源引用序列化写出 `uuid + last_known_locator`
  - 加载时先按 UUID 命中 catalog；locator 只用于回显、断链诊断和自动修复
  - `rename/move` 时更新 locator，不改 UUID；直接引用图和 scene/material 不需要批量重写才能继续加载
- Meta 与类型适配：
  - 后缀决定基础 kind；`meta.toml` 决定导入设置、预览策略、editor adapter、子资源标签映射
  - `ResourceTypeDescriptor` 统一注册“图片/材质/场景/模型/shader”的 inspector 和 preview 行为
  - 后续新增资源种类时只能扩 descriptor/adapter，不允许在 editor 里再加裸字符串分支
- 预览与缩略图：
  - `Project/library/editor-previews/` 保存图片缩略图、材质离屏预览、场景缩略图
  - watcher 变化后只把对应预览标记 dirty
  - 资源当前在 `Project/Assets` 面板、Inspector 预览区或资源详情页可见时，`PreviewScheduler` 立刻后台刷新
  - 不可见资源继续显示旧缓存，下一次进入可见状态时再刷新
  - 图片预览可走轻量 CPU 路径；材质/场景预览复用运行时 `AssetManager + ResourceServer + Graphics` 链路，使用 preview world/camera/light
- 编辑器 UI：
  - 升级现有 `Project/Assets` 面板为资源管理器，不新开第二个主入口
  - 面板至少支持：资源树、缩略图/列表切换、dirty/error/status 标记、详情面板、预览面板、直接引用/被引用面板
  - 面板数据全部来自 `EditorAssetServer`
  - editor 需要实时预览资源时，通过 `EditorAssetServer` 查 catalog，通过 `ResourceServer` 获取运行时 handle/lease
- 兼容迁移：
  - 首次打开旧目录项目时自动回填全部 `*.meta.toml`
  - 旧只含 locator 的 scene/material 在迁移阶段允许读取，但保存时统一写成 `AssetReference`
  - 这是有意 breaking change；项目资产的稳定 identity 从“locator-only”切到“UUID + locator”

## Test Plan
- 单元测试：
  - `AssetMetaDocument` roundtrip
  - `AssetReference` roundtrip 与 UUID 优先解析
  - `ResourceId` 从 `AssetUuid + label` 的稳定派生
  - mtime/hash 双校验命中与失效
  - `ResourceLease` acquire/release 引用计数与 unload
  - `ResourceTypeDescriptor` 后缀 + meta 适配结果
- 资产/编辑器集成测试：
  - 首次扫描缺失 meta 的项目，自动生成 `*.meta.toml`
  - rename/move 后 UUID 引用仍可加载，locator 被更新
  - scene/material 保存后写出 `uuid + locator`
  - 直接引用图正确列出“我引用谁/谁引用我”
  - 文件变化后预览先标 dirty；可见资源自动刷新，不可见资源保持缓存
  - 图片/材质/场景缩略图缓存命中与失效
- 运行时测试：
  - `AssetManager` 在 refcount 归零后卸载 resident resource
  - 同一资源多 lease 共享一次加载
  - 材质/场景预览复用运行时加载链，不引入 editor-only 特判
- 编辑器验收：
  - 打开目录项目后 `Project/Assets` 面板显示资源树、缩略图、UUID、locator、dirty/error 标记
  - 查看图片/材质/场景时能看到缓存预览，文件修改后符合“可见即刷新，否则下次查看刷新”
  - 引用面板能正确显示直接引用与被引用
- 验收命令：
  - `cargo test -p zircon_resource -p zircon_asset -p zircon_scene -p zircon_graphics -p zircon_editor`
  - `cargo test --workspace --locked`

## Assumptions
- `*.meta.toml` 是项目权威文件，应随项目一起保存和版本控制；`Project/library` 里的预览与中间产物始终是可删可重建缓存。
- `EditorAssetManager` 与 `AssetManager` 都属于 `zircon_asset` 模块，由 `zircon_server` façade 暴露给 editor；`zircon_editor` 本身不拥有资产数据库实现。
- 本轮只升级现有 `Project/Assets` 面板；`AssetBrowser` 保持注册但不作为第二套完整入口。
- 预览与引用图先覆盖图片、材质、场景、模型、shader 五类资源；更细分的 prefab/script/animation 后续按同一 meta/descriptor/preview 契约接入。
