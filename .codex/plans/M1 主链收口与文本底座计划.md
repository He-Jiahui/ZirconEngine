# M1 主链收口与文本底座计划

## Summary
- 下一步先执行 `M1`，目标是把当前主链收成“runtime 只负责运行时世界与中性渲染数据，editor 只负责作者态语义与交互状态”，同时把 runtime UI 文本从占位渲染补到真正可用。
- `M1` 完成后，后续音频、网络、物理、资源池、HZB、AA 等工作都建立在稳定边界上推进，不再继续把 editor 语义混进 runtime/graphics。
- 当前关键起点是公共 overlay DTO 已经存在于 framework 层 [overlay.rs](/E:/Git/ZirconEngine/zircon_runtime/src/core/framework/render/overlay.rs)，editor 已经在单独构造 viewport packet [render_packet.rs](/E:/Git/ZirconEngine/zircon_editor/src/scene/viewport/render_packet.rs)，而 runtime UI 的文本仍是矩形带占位而非字形渲染 [render.rs](/E:/Git/ZirconEngine/zircon_runtime/src/graphics/scene/scene_renderer/ui/render.rs)。

## M1 Key Changes
- **渲染合同固定为“中性 DTO，editor 负责作者态生成”**
  - 保留 framework 里的 `RenderSceneGeometryExtract`、`PreviewEnvironmentExtract`、`RenderOverlayExtract` 作为公共 DTO，不把这些类型迁到 editor。
  - 明确规则：framework 只定义数据形状，runtime/editor 都能产出这些 DTO，但作者态 overlay 的默认生产者只能是 editor。
- **runtime scene / render extract 去作者态**
  - `World::build_viewport_render_packet` 与 `RenderExtractProducer for World` 只输出运行时世界几何、灯光、相机、以及宿主可控的基础 preview 默认值；默认 `overlays` 为空。
  - runtime 不再构造 selection highlight、selection anchor、scene gizmo、grid、handle、camera override 这类作者态内容。
  - graphics 保留 overlay 渲染能力，但职责收窄为“消费 `RenderOverlayExtract` 并绘制”，不再从 scene/world 派生 editor 语义。
- **editor viewport 成为作者态唯一入口**
  - `zircon_editor::scene::viewport` 成为 selection、gizmo、grid、preview sky/lighting、camera override、handle overlay 的唯一生产面。
  - `SceneViewportSettings`、`SceneViewportController`、`build_render_packet` 保持 editor 所有权；所有作者态设置都只存在于 editor，不写回 runtime world。
  - editor 输出 `RenderSceneSnapshot` 时，先取 runtime scene geometry，再叠加 editor-owned overlay/preview packet。
- **runtime UI 文本从占位升级为可用底座**
  - 在 `UiResolvedStyle` 与模板解析层补齐字体与排版字段：`font`/`font_family`、`font_size`、`line_height`、`text_align`、`wrap`，继续复用现有 `foreground_color`。
  - 新增 runtime UI 文本子层，负责文本测量、分行、glyph run 生成、glyph atlas/cache；`UiRenderExtract` 输出真实文本绘制数据，而不是仅凭 `kind=Text` 进入占位矩形带。
  - `graphics::scene::scene_renderer::ui` 用 glyph quad/atlas 走真正的文本绘制路径；保留现有 `Quad`/`Image` 路径不变。
- **公共接口调整**
  - `RenderOverlayExtract` 继续保留在 framework，作为“中性 overlay packet DTO”。
  - `UiResolvedStyle` 扩展 typography 字段；runtime UI 内部新增文本布局与 glyph cache 类型，但不把复杂排版状态暴露到 editor 公共 API。
  - asset 管线增加最小字体资源入口，供 runtime UI 使用一个默认字体并允许显式引用字体资产。

## M1 Test Plan
- runtime scene extract 回归：
  - `World` 生成的 render packet 不包含 selection/gizmo/grid/handle 等作者态 overlay。
  - runtime world 序列化与 render extract 不因 editor 状态变化而变化。
- editor overlay 所有权回归：
  - selection、gizmo、grid、camera override、handle 仅在 editor packet 构造路径中出现。
  - editor 关闭 gizmo/grid/preview lighting/preview sky 时，packet 输出同步变化，runtime world 不受影响。
- graphics overlay 消费回归：
  - overlay renderer 仅根据 `RenderOverlayExtract` 输出结果绘制，不要求 scene/world 额外作者态上下文。
- 文本系统回归：
  - 模板样式能解析 `font_size`、`line_height`、`text_align`、`wrap`。
  - 多行文本、裁剪、对齐、颜色、透明度都能进入 UI render extract。
  - 文本渲染输出真实 glyph 几何/采样结果，不再是当前的矩形占位带。
- 集成验收：
  - editor workbench 继续由 Slint 承担 UI；M1 不替换 Slint 文本。
  - runtime UI 与 editor viewport/runtime-style overlay 至少共享同一套 runtime 文本底座。
  - `cargo check --workspace`、相关 scene/ui/graphics 测试通过，并新增边界与文本回归测试。

## Later Milestones
- **M2 基础子系统补齐**
  - 目标：把 `sound`、`net`、`physics` 从“合同或占位”补成真实最小可用子系统。
  - 方向：音频先做资源加载与播放闭环；网络先做 socket/基础消息闭环；物理补默认可运行后端，不再停留在同步/query 合同层。
- **M3 资源与运行时基础设施**
  - 目标：把资源系统从“能导入”补到“能规模化运行”。
  - 方向：CPU/GPU 资源池、atlas、纹理压缩/编码、缓存/释放生命周期、UI/graphics 共用资源策略。
- **M4 现代渲染标配**
  - 目标：把当前 render framework 补到现代引擎基础水位。
  - 方向：HZB/可见性、空间结构、ToneMapping、AA、LightMap/Baking；全部建立在既有 render framework 上，不另起主链。
- **M5 表现力增强**
  - 目标：补动画渲染、材质增强与专题表现。
  - 方向：skinning/动态网格、法线/贴花/阴影等常用材质能力，再往后才进入雾、水、SSS、天空、体积、Path Tracing、多图形 API。

## Assumptions
- `M1` 不替换 Slint editor UI；文本系统范围是 runtime UI 与 editor-owned runtime-style overlays，不是重写 editor 整体界面。
- `M1` 保持 overlay DTO 位于 framework 层；只改变“谁负责生产作者态 overlay”，不改变 graphics 对 DTO 的消费方式。
- `M1` 文本能力以“单字体默认可用 + 可显式引用字体资产 + 基础换行/对齐/裁剪”为完成线，不包含富文本、双向文字、复杂脚本整形、全套字体 fallback。
