# GPU Command Stream 接管 Editor UI 渲染计划

## Summary
- 目标：编辑器原生窗口默认使用 GPU presenter 渲染完整 retained host UI；`softbuffer` 只作为无 GPU、初始化失败、测试/截图的 fallback。
- 当前缺口：presenter factory 仍默认 `Softbuffer`，`GpuChromePresenter` 只是上传/诊断 stub，runtime RHI 缺真实 surface/render pass/draw/present，`ChromeCommandStream` 只覆盖少量 skeleton/viewport 指令。
- 架构边界：`zircon_editor` 只负责 retained UI 状态、damage、command stream 生成；surface、swapchain、pipeline、buffer/texture、draw/present 全部放在 `zircon_runtime` RHI/wgpu 实现内，编辑器源码不直接依赖 `wgpu`。

## Key Changes
- 将 `ChromeCommandStream` 提升为唯一权威 UI draw list：覆盖 root chrome、菜单/dock/pane/template 节点、文本 glyph runs、图标/图片、viewport image、浮窗、关闭提示、debug overlays、clip/scissor、z-order、damage/full rebuild/patch。
- 从现有 CPU painter 中抽取“生成绘制命令”的逻辑，避免 GPU stream 与 CPU painter 各自维护一套 UI 表达；GPU presenter 和 softbuffer fallback 都消费同一份 command stream。
- 扩展 runtime RHI：新增 native surface 创建、swapchain 配置/resize、frame acquire、render pass、pipeline bind、vertex/index draw、texture upload、present 等中立接口；在 `zircon_runtime::rhi_wgpu` 实现 Windows `Win32` surface。
- 实现 runtime 侧 UI 2D GPU pipeline：批量绘制 quad/border/image/viewport texture，使用 glyph/icon atlas；CPU 只允许做 glyph/icon/image 小纹理栅格化与上传，不允许正常 GPU 路径整帧 CPU UI 绘制。
- 更新 presenter 选择：`HostPresenterBackend` 增加 `Gpu`，默认优先 GPU；初始化失败时自动 fallback 到 softbuffer 并记录诊断计数，正常 profile 中 fallback 计数视为失败。
- 保持 hover/viewport image 为 paint-only patch：hover 不触发 chrome snapshot、workbench model build、presentation rebuild；viewport image 只触发 texture upload + 区域 damage。
- 更新 profiling/hotspot：保留现有 counters，并补强 GPU 默认接管断言，包括 `software_fallback_present_count == 0`、`gpu_draw_calls > 0`、GPU upload/draw batch 可观测。
- 更新 retained host 性能文档，明确 command stream、GPU presenter、softbuffer fallback、runtime/editor 边界和验证方式。

## Implementation Milestones
- M1 Command Stream 权威化：统一现有 painter command 与 `ChromeCommandStream`，让全 UI 元素都能表达为 backend-neutral commands，并补齐 full rebuild/patch 生成测试。
- M2 Runtime Surface + Draw API：补 runtime RHI surface/present/render pass/draw 接口与 wgpu Windows 实现，保持 editor 无 raw `wgpu` import。
- M3 GPU Presenter 接管：让 `GpuChromePresenter` acquire frame、上传 atlas/viewport/image texture、按 command stream 绘制并 present；factory 默认走 GPU，softbuffer 只作为 fallback。
- M4 Dirty/Damage/Profile 闭环：确保 hover、viewport image、resize、菜单/面板交互使用正确 command patch 与区域 damage，不回退到 presentation slow path。
- M5 Parity + Docs：用截图/像素容差和 profiling 场景确认 GPU 与 CPU fallback 视觉一致，并更新 `docs/` 中 retained host 性能与模块文档。

## Test Plan
- Unit：command stream 覆盖 shell、menu、dock、pane/template nodes、text、image、viewport、floating/close/debug layers；patch 不重复静态层；glyph/icon atlas packing 与 texture upload 行为稳定。
- Runtime：RHI surface 生命周期、resize、frame acquire/present、render pass/draw command、fallback failure path 测试；headless 环境不要求真实 present。
- Editor：backend 默认 GPU，fallback 可控；`zircon_editor` 不出现 raw `wgpu` imports；softbuffer 与 GPU 共用 command stream。
- Integration/profile：运行 workspace check/test 后，用 `tools/ui-profile-capture.ps1` 覆盖 startup、idle_hover、viewport_image、click/drag/resize 场景。
- Acceptance：正常 GPU 会话中 `software_fallback_present_count=0`、`gpu_draw_calls>0`；idle hover 的 `chrome_snapshot_count=0`、`workbench_model_build_count=0`、`presentation_rebuild_count=0`；viewport image 不 dirty layout/presentation；区域 redraw 不退化为 full-frame repaint；关键页面截图与 fallback 渲染在容差内一致。

## Assumptions
- 首版真实 surface 以 Windows `Win32` 为目标，因为当前 runtime surface descriptor 已是 Win32，其他平台保留 softbuffer/headless fallback。
- 全 UI 覆盖是首版验收标准；不接受复杂 pane/template 内容长期以整帧 CPU texture 层过渡。
- 当前活跃 `.zui` loader/session 改动不作为本任务重构目标；只有 command stream 消费已投影出的 template/pane 数据时才触碰相关路径。
- `paint_host_frame` 可暂留给测试、截图和 fallback 迁移期使用，但默认原生窗口 present 路径不能再依赖它整帧绘制。
