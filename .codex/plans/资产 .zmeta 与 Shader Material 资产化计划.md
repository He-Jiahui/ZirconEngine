# 资产 `.zmeta` 与 Shader/Material 资产化计划

## Summary

把资产身份、路径、复合资产和 shader/material 描述收束到现有 `zircon_runtime::asset` + `zircon_runtime::core::resource` 主链，不建立第二套资产数据库。

选定规则：
- 单资产：`assets/textures/hero.png` + `assets/textures/hero.png.zmeta`
- 复合资产：`assets/shaders/unlit_shader.zmeta` + `assets/shaders/unlit_shader/`
- 项目路径：`res://path/to/asset` 映射到 `{project_root}/assets/path/to/asset`
- 包路径：`package://com.zircon.navigation/xxx/yyy` 映射到包根 `assets/xxx/yyy`
- 对外引用固定为 `{ url, uuid }`，`uuid` 是身份权威，`url` 是可读定位与修复线索
- `.zshader` 使用 TOML，描述 WGSL 文件、entry point、依赖重定向、材质属性 schema 和编辑器辅助字段

参考依据：
- 当前 Zircon 资产栈已有 `AssetMetaDocument`、`AssetReference`、`ResourceLocator`、multi-asset entries 和 artifact restore。
- Bevy `AssetPath#label` 支持 subasset label。
- Godot `ResourceUID`/`.import` 证明 UID 与路径分离的资源模型。
- Unity Graphics 包内 `.meta`/package name 形态支持包资产和 GUID sidecar 方向。

## Public API / Type Changes

- 扩展 `ResourceLocator`：
  - 新增 `ResourceScheme::Package`
  - 支持 `package://{package_id}/{path}#label`
  - 保持 `res://`、`lib://`、`builtin://`、`mem://` 既有语义
- 改造 `AssetReference` 序列化：
  - 写出 `{ uuid = "...", url = "res://..." }`
  - 内部仍可使用 `ResourceLocator`
  - 解析时按 `uuid` 查找；`url` 不一致时给 stale-url 诊断；`uuid` 未命中但 `url` 命中不同 UUID 时返回结构化错误
- 升级 `AssetMetaDocument` 到新格式版本：
  - 对外字段使用 `uuid`、`url`、`asset_kind`、`unit = "single" | "compound"`
  - 增加 `included_files`
  - `entries` 中每个 root/subasset 都有独立 `uuid`、`url`、`asset_kind`、`artifact_locator`、`dependencies`
  - 保留 importer/version/hash/artifact/preview state，继续支持增量导入和热重载
- 扩展 `PluginPackageManifest`：
  - 新增显式包身份 `package_prefix`、`package_company`、`package_name`
  - 组合成 `com.zircon.navigation` 这类 package id
  - `asset_roots` 默认使用 `["assets"]`

## Implementation Changes

- **Milestone 1: `.zmeta`、引用、路径基础**
  - 将旧 `*.meta.toml` 硬切为 `*.zmeta`：更新 meta path 计算、watcher 忽略规则、项目扫描、测试 fixture 和文档。
  - 扫描器从“文件列表”升级为 `AssetSourceUnit`：单文件资产和复合目录资产都能进入同一导入管线。
  - `AssetMetaEntry` 增加 per-entry UUID；root entry 使用 document UUID，subasset 新建时生成随机 UUID 并持久化，重导入时按既有 entry URL/label 保留 UUID。
  - `ProjectManager` 同时维护 UUID 索引和 URL 索引，资源 ID 改为从 entry UUID 派生。

- **Milestone 2: package 资产根**
  - 从插件/包 manifest 建立 `PackageAssetRegistry`。
  - 项目扫描保留 `res://`，包扫描生成 `package://{package_id}/...`。
  - `source_path_for_uri` 支持 package URI，并拒绝未知 package、逃逸路径、空 package path。
  - 包内 `.zmeta` 与项目 `.zmeta` 使用同一 schema、同一 importer、同一 dependency graph。

- **Milestone 3: 复合资产与 shader/material**
  - 新增 `.zshader` TOML document 类型，包含 WGSL 文件列表、entry points、imports/redirects、material properties、editor hints。
  - 新增 compound shader importer：读取 `unlit_shader.zmeta` 指向的 `unlit_shader/` 目录，导入 `.zshader` 和关联 `.wgsl`，输出 root `ShaderAsset` 与必要 subasset entries。
  - 扩展 `ShaderAsset`：记录 source files、imports、property schema、validation diagnostics。
  - 扩展 `MaterialAsset`：保留现有 PBR 字段，新增 `property_values`，按 shader property schema 做类型/缺失/未知属性诊断。
  - material/shader/texture 依赖统一写入 `.zmeta.entries[*].dependencies`，并继续同步到 `ResourceRecord.dependency_ids`。

- **Milestone 4: editor、fixtures、docs 收束**
  - Asset Browser/diagnostics 显示 UUID、URL、package id、compound unit、included files、subassets。
  - 更新示例资产：`unlit_shader.zmeta + unlit_shader/*.zshader/*.wgsl`，以及一个 material 引用该 shader 的 fixture。
  - 更新 `docs/zircon_runtime/asset/*` 和 `docs/assets-and-rendering/*`，记录 `.zmeta` schema、package URI、compound asset、shader/material 规则。

## Assumptions

- 不保留旧 `*.meta.toml` 长期兼容路径；这是硬切换。
- `.zmeta` 继续保存 import/artifact 状态，不另建 `.zimport`。
- subasset 对外仍通过 `url#label` 表示，但每个 entry 都有独立 UUID。
- `.zshader` 只描述 shader 包和材质属性 schema；WGSL 仍是实际 shader source。
- 本计划不重做完整 shader graph，只为后续 graph/custom material 留 schema 扩展位。

## Follow-up State (2026-05-26)

后续 shader/material 管理切片已经继续推进到 renderer 消费层：`MaterialAsset::shader_property_values_for_shader(...)` 按加载到的 `ShaderAsset.property_schema` 选择 material override 或 shader default，并把支持的 bool、float、int、uint、string、vec2、vec3、vec4/color 值投影为 `RenderMaterialPropertyValue`。`ResourceStreamer::ensure_material(...)` 会把这些 typed value 保存在 `MaterialRuntime.shader_property_values`，与 shader-driven texture slot readiness 一起成为 GPU material state 的准备态。

这仍然不是完整 shader reflection 或 uniform/bind-group 编码；它只是避免 renderer 后续阶段重新解析 `.zmaterial` TOML，并让 property schema 管理进入和 texture slot 相同的运行时消费闭环。

## Follow-up State (2026-05-27)

renderer 消费层又向前推进了一步：`RenderMaterialPropertyUniformPayload::from_values(...)` 会把已投影的 typed material property map 编码为 CPU-side uniform bytes，并记录每个字段的 name、kind、offset、size、alignment。`ResourceStreamer::ensure_material(...)` 在准备 `MaterialRuntime` 时同步生成 `shader_property_uniform_payload`，所以后续 WGPU uniform buffer/bind group 切片可以直接消费运行时 payload。

当前只编码 bool、float、int、uint、vec2、vec3、vec4/color；string 会进入 payload 的 unsupported 列表而不是被丢弃。这个状态仍不等于完整 shader reflection、GPU buffer 分配或 bind group 创建。

同日后续切片已经把上述 payload 接入 renderer-owned GPU state：`PreparedMaterial` 现在保留 `GpuMaterialUniformResource`，由 `ResourceStreamer` 为每个材质创建 WGPU uniform buffer 和 bind group，并在 `MeshDraw` 中作为 group 3 绑定到 base mesh pass 与 deferred geometry pass。当前 group 3 是固定的中性材质 uniform 合约，尚未覆盖自动 shader reflection、非标准 texture bind array 或 string/非 uniform property 通道。

同日后续诊断切片补上了 authored shader pipeline layout 与固定 group 3 材质 uniform 合约之间的 runtime readiness 检查。`ResourceStreamer::ensure_material(...)` 现在会在 shader 声明 bind groups 时验证 group 3 binding 0 是否为 uniform buffer，并把缺失 group/binding、错误资源类型、compute-only visibility、重复 descriptor 或额外 group 3 binding 记录为 `pipeline_layout.group3...` readiness diagnostics。空 pipeline layout 仍然允许走当前 renderer-owned 固定 layout。

同日后续资产化切片将 `.zshader` 的 `[pipeline_layout]` 持久化到 `ShaderAsset.pipeline_layout`。compound shader importer 现在把 bind groups、bindings、resource type、stage visibility 和 push constant labels 从 TOML 带入 shader asset；renderer material ABI 诊断因此能覆盖真实作者 shader package，而不只覆盖测试里手工构造的 shader value。

同日后续 e2e 验证切片新增 `render_product_zshader_import_tests`，从临时 `.zmeta` compound shader 项目导入带错误 group 3 layout 的 `.zshader`，再通过 `ResourceStreamer::ensure_material(...)` 验证 `RendererMaterialAbi` readiness diagnostics。这样 `.zshader` authoring、artifact reload、asset manager 注册和 renderer material readiness 已形成一条可回归的真实资产路径。

同日后续 shader readiness 切片把 `ShaderAsset::readiness_report()` 从只有 `has_pipeline_layout` 扩展为 `ShaderPipelineLayoutReadiness` 摘要：记录 bind group 数、binding 数、push constant range 数、group/binding label、binding resource type 和 stage visibility。这个摘要是 shader-owned inspection data，不替代 renderer-owned group 3 material ABI 诊断。

同日后续 material readiness 切片把 `MaterialAsset.validation_diagnostics` 接入 `RenderMaterialReadinessReport.diagnostics` 的非阻塞列表。glTF/default material importer note 这类本地诊断会保留 `MaterialAsset` source 和 `material.validation_diagnostics[N]` path，但不会进入 `validation_errors`，也不会让 `is_ready()` 变为 false。

同日后续 renderer stats 切片把上述非阻塞 readiness diagnostics 汇总到 `RenderStats.last_material_diagnostic_count`。该计数和 `last_material_validation_error_count`、`last_material_fallback_count` 分离，用于显示 glTF/default material importer note 等说明性信息，而不影响材质 ready/fallback/error 语义。

同日后续 material uniform 诊断切片把 `RenderMaterialPropertyUniformPayload.unsupported` 从内部记录提升为 `MaterialUniform` 来源的非阻塞 readiness diagnostics。`ResourceStreamer::ensure_material(...)` 现在会把 string 等暂不能编码到固定 group 3 uniform buffer 的属性记录为 `uniform.<name>` 诊断；属性值仍保留在 typed material map/payload 中，等待后续非 uniform property 通道或完整 shader reflection。

同日后续 submit 统计切片新增 string shader property 回归，确认 `MaterialUniform` readiness diagnostics 会穿过 `ResourceStreamer` 和 renderer submit 路径进入 `RenderStats.last_material_diagnostic_count`。该回归同时锁定 ready/fallback/validation-error 计数不变，避免把“已保留但未上传”的非 uniform 属性误报成材质失败。

同日后续 readiness 明细切片在 `render_product_material_property_tests` 中补了更靠近资源流的回归：同一 string shader property 会在 `ResourceStreamer::material_readiness_report(...)` 中保留为 `MaterialUniform` 诊断，路径为 `uniform.debug_label`，同时材质仍保持 ready 且没有 fallback 或 validation error。这样 editor/runtime 调试面板不需要只依赖 submit 统计计数，也能读取具体诊断行。

同日后续 schema default 切片补上 `.zshader` 默认值路径：当 shader property schema 自己提供 string default、`.zmaterial` 没有 override 时，`MaterialAsset::shader_property_values_for_shader(...)` 仍会生成 typed string value，uniform preparation 会把它记录为 unsupported row，并在 readiness report 中给出 `MaterialUniform`/`uniform.debug_label` 诊断。

同日后续 DTO 去重切片补上 `RenderMaterialReadinessReport::push_diagnostic_once(...)` 的 `MaterialUniform` 回归：同一 unsupported uniform 诊断重复推入时只保留一条，避免 editor/runtime readiness 明细和 submit 统计被重复行放大。

## Follow-up State (2026-05-28)

renderer material uniform 管理继续补齐调试可见性：`ResourceStreamer` 除 payload byte length 和 backing buffer byte length 外，现在还能直接返回已编码 uniform field count 与 unsupported row count。对应回归在材质准备前确认 accessor 返回 `None`，准备后确认 shader property schema 产生 3 个已编码字段和 1 个 string unsupported row，让 editor/runtime 面板可以读取紧凑 readiness 摘要，而不需要拆 `MaterialRuntime.shader_property_uniform_payload`。

同日后续切片把这组调试值收束成 `RenderMaterialPropertyUniformSummary`，并通过 `ResourceStreamer::material_uniform_summary(...)` 单次暴露 payload byte length、encoded field count 与 unsupported row count。分散 accessor 继续保留给 backing buffer length 和已有调试调用，但 editor/runtime 面板可以优先消费 summary DTO。

同日后续切片补上了 uniform 编码前的 `RenderMaterialPropertyValueSummary`。它直接统计 `MaterialRuntime.shader_property_values` 的 total/per-kind/uniform-eligible/non-uniform count，让调试面板可以先确认 shader property schema 投影出了预期的 bool/float/vector/string 值，再查看 uniform payload 摘要里的 encoded/unsupported 行。

同日后续切片把 `RenderMaterialPropertyUniformSummary` 挂到资源流产出的 `RenderMaterialReadinessReport.uniform_summary` 上。材质 readiness 明细现在既保留 `MaterialUniform` 非阻塞诊断行，也直接携带 payload byte length、encoded field count 和 unsupported row count；`ResourceStreamer::material_uniform_summary(...)` 继续作为只读 compact accessor 保留。

同日后续切片把 uniform 编码前的 `RenderMaterialPropertyValueSummary` 也接到 `ResourceStreamer::material_property_value_summary(...)`。这样 editor/runtime 调试面板可以通过 resource streamer 同时读取 shader property 投影摘要和 uniform payload 摘要，不再需要直接拆 `MaterialRuntime.shader_property_values`。

同日后续切片把同一个 `RenderMaterialPropertyValueSummary` 挂到 `RenderMaterialReadinessReport.property_value_summary`。材质 readiness 明细现在同时携带 shader property 投影摘要与 uniform payload 摘要，给 editor/runtime 面板一个单 DTO 的调试入口。

同日后续测试维护切片把 oversized `render_product_streamer_tests.rs` 拆成 `render_product_streamer_tests/material_runtime.rs` 与 `render_product_streamer_tests/readiness_diagnostics.rs` 两个聚焦子模块。非标准 shader texture slot 的缺失引用现在有专门 ResourceStreamer 回归覆盖：当 `[textures.mask_map]` 指向不存在的 texture locator 时，runtime readiness 的 validation/fallback 记录保留 `mask_map` slot key，`MaterialRuntime.non_standard_texture_slots` 也保留 `mask_map -> None`，让后续 bind-group/reflection 工作能区分“槽位存在但走 fallback”和“槽位未声明”。

同日后续管理面切片新增 `RenderMaterialTextureSlotSummary`。`ResourceStreamer::ensure_material(...)` 现在会在非标准 shader texture slot resolution 后生成 total/resolved/fallback count，并把它写入 `RenderMaterialReadinessReport.texture_slot_summary`；`ResourceStreamer::material_texture_slot_summary(...)` 暴露同一摘要。这样 editor/runtime 面板可以和 property/uniform summary 一样读取 texture slot 概览，而不用直接拆 `MaterialRuntime.non_standard_texture_slots`。

同日后续管理面切片新增 `RenderMaterialReadinessSummary`。它由 `RenderMaterialReadinessReport::summary()` 派生，汇总 ready/fallback/diagnostic 布尔值、validation/fallback/diagnostic count，以及 property/uniform/texture slot 三个已准备摘要；`ResourceStreamer::material_readiness_summary(...)` 暴露同一 compact 视图，`ensure_scene_resources(...)` 的材质统计也改为从该视图读取计数，避免 editor/runtime 面板为了显示概览而拆完整 readiness report。

同日后续标准纹理槽管理切片把固定 PBR texture readiness 也接入 compact 管理面。`RenderMaterialReadinessReport.standard_texture_slot_summary` 和 `ResourceStreamer::material_standard_texture_slot_summary(...)` 现在统计 authored `base_color`、`normal`、`metallic_roughness`、`occlusion`、`emissive` 槽位的 total/resolved/fallback；非标准 shader 槽位继续由 `texture_slot_summary` 表示。这样材质 readiness summary 能同时携带 property、uniform、standard texture、non-standard texture 四类 prepared 摘要。

同日后续 texture slot 明细切片新增 `RenderMaterialTextureSlotState`，把 authored slot key 与可选 resolved `ResourceId` 作为中立 DTO 放入 readiness report。标准 PBR 槽位通过 `standard_texture_slot_states` / `ResourceStreamer::material_standard_texture_slot_states(...)` 暴露，非标准 shader 槽位通过 `non_standard_texture_slot_states` / `ResourceStreamer::material_texture_slot_states(...)` 暴露；summary 仍然只承载 total/resolved/fallback count。

同日后续 uniform payload 明细切片把已编码字段和 unsupported 行也提升到 readiness 管理面。`RenderMaterialReadinessReport.uniform_fields` 保存 name/kind/offset/size/alignment，`uniform_unsupported` 保存 name/reason；`ResourceStreamer::material_uniform_fields(...)` 与 `material_uniform_unsupported(...)` 暴露同一组明细。这样 editor/runtime 面板可以从 readiness report 或 resource streamer 直接展示 uniform payload 布局和非 uniform 属性原因，而不用拆 `MaterialRuntime.shader_property_uniform_payload`。

同日后续 shader property value 明细切片新增 `RenderMaterialPropertyValueState`。它按 property name 保存 typed value，并提供 uniform-eligible 判定；`RenderMaterialReadinessReport.property_value_states` 与 `ResourceStreamer::material_property_value_states(...)` 暴露同一组明细。这样 shader property 投影、uniform payload、texture slot 三个管理面都能用 summary 读取概览，用 detail rows 展示具体作者字段。

同日后续 prepared-state 聚合切片新增 `RenderMaterialPreparedState`。它由 `RenderMaterialReadinessReport::prepared_state()` 派生，把 shader property value、uniform payload、标准 PBR texture slot、非标准 shader texture slot 的 summary 与 detail rows 汇总为一个只读 DTO；`ResourceStreamer::material_prepared_state(...)` 暴露同一快照，方便 editor/runtime 面板一次读取完整 prepared material 管理面，同时完整 readiness report 仍然是诊断、fallback 和 validation 的事实来源。

同日后续 issue-state 聚合切片新增 `RenderMaterialIssueState`。它由 `RenderMaterialReadinessReport::issue_state()` 派生，只汇总 validation errors、fallback usages 和非阻塞 diagnostics；`ResourceStreamer::material_issue_state(...)` 暴露同一快照，方便 editor/runtime 面板把问题列表和 prepared-state 管理面分开读取，同时 readiness report 仍然是唯一事实来源。
