# Scaffold a skill or reference

1. Identify the distinct task trigger. Reuse an existing skill when the new guidance belongs to its workflow.
2. For an independent skill, create a concise `SKILL.md` with valid `name` and `description` frontmatter.
3. Put optional techniques in `references/` or focused Markdown. Categories and supporting branches use `index.md`, not frontmatter-free `SKILL.md`.
4. Preserve metadata and discovery policy unless the user has authorized a change.
5. Use [the layout template](layout-template.md), then run the canonical skill validator, local-link checks, and the catalog helper.

Do not force hierarchy onto a small skill or make every reference discoverable.
