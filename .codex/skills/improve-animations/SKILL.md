# UI Motion And Polish

Follow the requested design, audit, plan, or implementation scope. An implementation request authorizes relevant fixes and verification; explicit approval checkpoints remain in force.

1. Inspect the affected component, existing motion tokens, interaction frequency, and motion stack.
2. Evaluate purpose, timing, origin, interruption, performance, and accessibility against [shared standards](../review-animations/STANDARDS.md). Read only the relevant sections.
3. Fix supported issues within scope, or return concrete locations, effects, and recommendations for an audit.
4. Verify affected interactions visually when the claim depends on feel or frames. Report any uncertainty left by source inspection.

## Select the relevant technique

| Requested work | Reference |
| --- | --- |
| Find useful places for motion | [Opportunities](../find-animation-opportunities/guide.md) |
| Apple-style gestures, springs, materials, or typography | [Apple design](../apple-design/guide.md) |
| Component and interaction details | [Design engineering](../emil-design-eng/guide.md) and its conditional references |
| Review existing motion | [Review guide](../review-animations/guide.md) |
| Name an unfamiliar effect | [Vocabulary](../animation-vocabulary/SKILL.md) |

A separate plan is useful only when requested or needed for substantial staged work; [the template](PLAN-TEMPLATE.md) is optional. There is no required findings quota or delegation sequence.
