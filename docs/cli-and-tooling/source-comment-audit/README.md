# 源码注释审查规范

本流程补充仓库开发约定中的 GEN-Q3、GEN-Q5 和 GEN-D4。审查对象是全部第一方源码、测试、工具脚本、着色器、脚本语言源码和可执行文本资源。`dev/` 参考仓库、第三方代码、生成物、缓存及构建产物不属于写入范围；生成物的意图应回溯到生成器。无法嵌入注释的 JSON 等资源仍需审查其加载和消费路径，问题标签放在可注释的调用端。

## 注释写什么

- 新增正文使用中文。`//!` 说明模块在调用链中的职责和边界；`///` 说明公共类型、接口和函数的用途、适用调用方、调用时机、所有权或失败约束；`//` 说明私有不变量、状态迁移和非显然设计决定。
- 只写代码本身无法可靠表达的事实。不逐行转述实现，不给显然的赋值、转发和断言添加注释，也不把所有调用方路径抄进注释以免随重构失效。
- 保留准确的现有注释；发现其陈述失真时，以当前源码、调用方和测试为证据修正。公共 Rust 契约使用 rustdoc；`unsafe` 块的 `SAFETY:` 必须写明已验证的具体前提，不能以“调用方保证安全”代替可检查的条件。
- 注释不能为了让基于 `include_str!` 或字符串搜索的结构测试通过而引入其查找的标识符。写入前先查该文件是否被源码文本测试读取。

## 逐项审查顺序

1. 为模块列出当前内容哈希、定义、导出、调用点和相关测试。逐一阅读直接调用上下文，并检查 trait 实现、宏展开入口、回调注册、FFI、资源加载、UI 绑定及配置驱动的间接调用。
2. 对每个函数、类型或接口确定调用者为何使用它，以及前置状态、所有权、生命周期、错误路径和设计目的。对语句块追踪其进入路径、状态变化和后续影响。没有内部调用点时，还要检查公共消费者、测试和动态入口；不能仅凭 `rg` 无命中认定死代码。
3. 记录“需注释”“无需注释”“存在确认问题”“意图待证实”中的审查结论。证据不足时用具体 `TODO:` 留下问题和验证动作，不把推测写成设计事实或 `BUG:`。
4. 主审复核 agent 的调用链证据和最终 diff。agent 可跨模块只读追踪，但只能编辑分配并取得写入归属的路径；有外来未提交改动的文件延后处理。

## 问题标签

标签放在最接近错误调用或约束缺口的位置。固定的是 `BUG:` / `TODO:`、编号和证据内容；外层须使用该文件所属语言的合法注释语法。例如 Rust 使用 `//`，Python、PowerShell 和 TOML 使用 `#`，SQL 使用 `--`：

Rust 问题标签必须写成普通的 `// BUG:` 或 `// TODO:`，不能写成 `///` 或 `//!`；审计器只收录普通注释标签。标签与 rustdoc 同处一段时，先写标签，再让 `///` 连续紧贴被说明的声明，避免标签进入公开 API 文档。

```text
// BUG: [CR-<模块>-0001] <可证明的触发条件>导致<可观察影响>；证据：<调用点或测试>。
// TODO: [CR-<模块>-0002] 确认<具体问题>；缺少<证据>；下一步检查<调用点或测试>。
# BUG: [CR-<模块>-0003] <可证明的触发条件>导致<可观察影响>；证据：<调用点或测试>。
-- TODO: [CR-<模块>-0004] 确认<具体问题>；缺少<证据>；下一步检查<调用点或测试>。
```

`BUG:` 只用于已复现或可从代码路径证明的问题。潜在风险、意图疑问和覆盖缺口使用 `TODO:`。审查编号在所属模块内递增且不复用；问题账本保存证据、影响或疑问、后续动作、现有问题所有者和源码标签位置。发现既有问题时链接原所有者，不建立重复修复任务。本轮只标注和登记，不混入行为修复。

## 覆盖账本和验收

`inventory.jsonl` 保存 Git 可见的第一方文本候选、分类、排除原因及扫描时哈希；`coverage/<模块>.jsonl` 对每个审查完成的文件记录最终内容哈希、审查者、结论和调用证据；`issues/<模块>.jsonl` 记录带编号的问题。每个账本分片指定一位写入者并取得精确路径租约；同一源文件只分配给一位 owner。`mark` 和 `mark-batch` 对同一账本目录持跨进程独占写锁，跨分片登记也会串行；竞争者收到退出码 2 后，主审须先确认另一登记结果再重试。单批次只原子替换所属分片；其他会话的源码改动仍须靠精确路径租约和哈希复核。内容改变后，原审查记录立即视为过期，必须重新核对受影响的调用关系。新增文件、未知后缀、生成物判定不明和无归属文件不得静默略过。

文件哈希只证明被审文件本身未变，不能自动证明调用方没有改变。调用证据须写明关键调用端；每批次修改调用端时，主审反查其被调定义并重审受影响的记录。最终全仓核验再以当前调用端复核跨文件关系；不得只凭 `reviewed_current` 数量宣称调用链审查仍然有效。

每个模块批次检查标签与问题账本的一一对应、仅含本任务改动的 diff、相关语言的格式或解析检查，以及仓库要求的结构检查。纯注释变更按里程碑验证政策选择最小门槛；协调器要求的验证、独立复核和精确快照归属仍须完成。模块提交后复核清单和哈希；只有全部纳入范围的文件均有当前审查记录、待处理项清零时，才能声称全仓完成。
