# 第二轮源码注释审查规范

## 范围与账本

本轮审查当前 Git 可见的第一方产品、插件、工具、示例、测试、着色器及可执行文本资源。排除 `dev/` 参考仓库、第三方内容、生成物和缓存。JSON 等不能插入注释的资源须追踪加载器与消费者；问题标签放在可注释的调用处。SVG 等文本资源按来源和实际消费路径判定，不按文件后缀冒称二进制。

`inventory.jsonl` 记录文件分类与扫描时 SHA-256；`coverage/*.jsonl` 记录当前审查内容哈希、结论和调用证据；`issues/*.jsonl` 将审查编号对应到源码标签、证据及后续动作；`batches.jsonl` 记录精确分工和主审复核、验证与提交状态；`deferred.jsonl` 记录待归属、缺失及需补证据的文件。状态是账本对当前内容的比较结果，文件变动即失效。

旧账本的有效记录可以复用，须保留原 reviewer、时间与证据来源，并核对受影响的调用方；不将原始扫描哈希当作审查后的哈希，不仅凭文件哈希断言跨模块调用关系未变。旧记录未被核对时只作候选证据。

## 注释内容

- 新增解释使用中文。Rust `//!` 说明模块职责和边界；`///` 说明公共类型、接口和函数的用途、调用时机、所有权及必要约束；`//` 说明私有不变量、非显然调用顺序、状态变化和设计理由。其他语言使用合法的对应注释语法。
- 保留所有原有注释。历史说明与当前证据冲突时保留原文，在邻近位置补充明确的当前说明并登记证据。用途已清楚的对象仍须审查，可以登记 `no_comment_needed`；不复述函数名、赋值、逐行实现，不靠注释数量证明覆盖。
- 每个定义、trait 实现、宏生成路径、动态注册与 FFI 入口均须定位。阅读直接调用上下文、相关测试和契约，明确调用者为何使用它及其前提。语句块须核对进入路径、状态变化与后续影响。
- 证据引用包含实际路径、符号、必要行号和调用链；优先记录定义、调用者、测试或契约各自的作用。查不到静态引用不等于没有调用，要继续核查动态入口及外部契约。
- 不用注释满足文本守卫，不改字符串或可执行资源含义；注释插入前检查 `include_str!`、源码扫描与资源加载是否读取原始文本。

## 问题与安全前提

```text
// BUG: [CR-R02-<owner>-0001] 触发条件；可观察影响；证据：可证明的调用路径或复现。
// TODO: [CR-R02-<owner>-0002] 待确认问题；缺少的证据；下一步验证。
// SAFETY: 此处已证实的具体安全前提及保证它的调用路径。
```

`BUG:` 必须有复现或代码路径证明。意图疑问、未证实风险和覆盖缺口使用具体 `TODO:`。Rust 问题标签用普通 `//`，避免变成公共 rustdoc 文字；Python、PowerShell 等使用 `#`，SQL 使用 `--`。编号唯一，问题记录包含 `id`、`kind`、`state`、`path`、`anchor_path`、`evidence`、`impact`、`next_action` 和必要负责人。未证实的 unsafe 前提不能写成笼统的 `SAFETY:`。

当前实现已消解的历史问题可登记 `state=resolved`。如果旧标签已移除，记录 `source_label_status=absent`；如果按本任务要求保留原标签，记录 `source_label_status=retained_historical`，保存原标签文本、当前源码哈希、邻近澄清说明和 `resolution_evidence`。标签核对须同时验证原文未改、说明未把历史问题表述为现存缺陷、当前消解路径有证据。旧审查工具的“resolved 不得保留标签”规则不覆盖这一保留历史标签的情形，本轮单独记录其核对结果，不改旧工具行为。

## 所有权、复核与验证

主审先取得精确路径租约，再分配互不重叠的文件。agent 只编辑获分配且获授权的文件，其余路径只读；大子树按子模块拆分。既有未提交改动保留，注释建议与原始字节、前后 SHA-256 分开记录，不能整文件混入提交。所有写入保留 BOM、换行与已有内容。

agent 输出逐文件证据和局部检查结果，主审独立阅读调用证据并检查增量 diff。对 Rust 使用局部 rustfmt 解析检查，Python 用 AST，其他语言使用已有解析或格式工具；检查只验证实际覆盖的范围。纯注释批次不例行运行宽泛 Cargo。受管门槛要求的票据必须达到终态通过；待处理、dry run 和旧环境结果均不算通过。

提交前重新归属最终内容哈希，核对精确候选包含的每个路径与审查快照一致。首次提交先诊断索引锁，由协调器完成阶段提交及用户已授权的自动企业微信通知。清单、最终哈希、调用证据、问题标签和回执全部收口后才报告全仓完成。

外来产品后像的精确排除策略见 [product-exclusions.json](ownership/product-exclusions.json)。列出的路径保留原注释字节与历史覆盖出处；新业务后像不得进入本轮注释提交，也不得改称为本轮新注释证据。文件释放或租约可用本身不构成作者归属交接。

协调器已保存的精确阶段候选与终态结构票据记录在 [integration/derive-20260930.json](integration/derive-20260930.json)。`integration_ready` 表示快照已封存；索引锁尚未处置时，Git 提交与验收仍为待处理。
