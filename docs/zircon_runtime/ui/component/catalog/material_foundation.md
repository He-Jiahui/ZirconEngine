# Material Editor Foundation Catalog

`UiComponentDescriptorRegistry::material_editor_foundation()` is the first component catalog for the new editor UI direction. It is intentionally separate from `editor_showcase()` so existing showcase tests and legacy showcase consumers keep their exact component set while the new workbench path gains a clean Material-first contract.

## Component Layers

The catalog is organized around the implementation plan's four layers:

- primitive controls: button, icon button, text field, checkbox, switch, dropdown, slider, tabs, menu, tooltip, scrollbar, splitter, panel, modal;
- layout controls: flex group, horizontal group, vertical group, grid group, overlay, scroll view, scroll box, split view, and panel group;
- data/view controls: list view, virtual list, tree view, property grid, inspector section, property row, and vector row;
- Fyrox panel role controls: search field, context menu, field editor, folder tree, asset grid/list, preview and metadata panes, viewport host, pane toolbar, gizmo controls, filter bar, severity chips, categorized list, status action controls, graph canvas, source editor, timeline, and visual designer;
- shell controls: window, view, drawer, view tab, window frame, document node, tab stack, floating window, dock host, workbench shell, slot, and composite.

Every descriptor receives the `material_dark`, `material`, and `material-dark` default classes. Each descriptor also declares the same visual state schema used by the Material skin: hovered, pressed, selected, disabled, focused, error, and warning.

Data-display descriptors are split by responsibility so the catalog remains folder-backed as it grows. `data_display.rs` owns direct MUI data-display components such as Chip, Divider, Icon, List, Table, Typography, Avatar, Badge, and ImageList. `data_display_subcomponents.rs` and `data_display_table.rs` own local MUI child components. `data_display_editor.rs` owns editor-facing collection roles such as FolderTree, AssetGrid, AssetList, and CategorizedList, keeping editor panel descriptors out of the core MUI data-display owner.

- `PropertyGrid` and `InspectorSection` keep inspector-style section/field slots and property-edit events.

- `Select` and `Autocomplete` popup lifecycle events now have a first runtime-owned reducer path: `OpenPopup` and `ClosePopup` mutate retained `popup_open` state through `state_reducer/overlay.rs`. It also handles `BeginEdit`, `Cancel`, and `Commit { property = editing_text|editingText }` for retained rename state and semantic rename payload writeback. Default TreeView pointer interactions route primary drag from a reorderable tree row through `BeginDrag`/`EndDrag`, reorder top-level `nodes` or MUI `items`, and now reparent nested source subtrees under the drop target when the retained tree has child arrays. Remaining collection work is broader executable TreeView tests, 1k virtual-tree render/window evidence, and editor hierarchy bridge removal.

These are still neutral component descriptors. They do not create native windows or bind editor state directly; they let v2 assets and editor presenters agree on which values and events are valid before a concrete skin or host renders them.

Text-backed Material descriptors live in the `text_inputs` child module instead of the broader input-control module. That subtree owns `TextField`, `Input`, `InputBase`, `FilledInput`, `OutlinedInput`, `TextareaAutosize`, `SearchField`, `FieldEditor`, and `SourceEditor` because they share the `TextInput` host capability and edit/commit event family. These descriptors now advertise `KeyboardText` and expose `caret_offset`, `selection_anchor`, `selection_focus`, composition mirror props, and shared validation props such as `required`, `min_length`, `max_length`, `validation_timing`, `validation_message`, `validation_dirty`, and `validation_touched`. The M1 reducer bridge routes printable payloads through the shared text edit-state insertion helper, appends at the end when no edit-state metadata exists, replaces an explicit selection when present, writes the collapsed caret/selection state back, mirrors MUI input-family `value_text`/`value`, ignores control or whitespace-only payloads, sets focus, honors read-only aliases, and now keeps validation ownership in `state_reducer/text_input.rs`. Query-backed `SearchField` and `Autocomplete` nodes also infer `query` as their host editable-text property, so physical edit actions such as Backspace/Delete use the retained search text instead of falling back to `value` or overwriting Autocomplete's committed selection value. Focused MUI `TextField` host coverage now verifies ArrowLeft, Delete, End, and active-selection Backspace against the same retained value/caret route: caret-only moves emit no value event, Delete writes `value`, `caret_offset`, and a `ValueChanged { property: "value" }` report, and Backspace removes the selected range before collapsing `caret_offset`, `selection_anchor`, and `selection_focus`. `TextInput` validation timing is reducer-owned: `change` validates after each text/value mutation, `commit` defers until commit while marking dirty edits, and `blur` validates on focus loss while preserving dirty/touched metadata. `TextField` currently records the MUI wrapper split as metadata: `variant = outlined|filled|standard`, `label`, `value_text`, `placeholder`, `helper_text`, `multiline`, and `select_mode`. The Material Lab prototype freezes one representative route-bearing row plus non-dispatchable visual children for outlined focus, filled helper text, standard underline, error helper, and disabled no-edit, while live helper-label layout, platform candidate-window validation, real Chinese input, full multiline/autosize validation, and select-mode behavior remain later runtime support work. `TextareaAutosize` uses the same owner module and adds layout-affecting row metadata: `variant`, `value_text`, `placeholder`, `helper_text`, `multiline`, `autosize`, `min_rows`, and `max_rows`. Its prototype keeps one change route on the sample row and uses visual-only child examples for minimum rows, maximum row clamp, focused autosize, error helper, and disabled no-edit so later layout tests can distinguish row-clamp metadata from render-only field styling.

Surface descriptors that override a shared Material prop default must keep descriptor schema reflection and authored default instancing aligned. `AppBar` and `Paper` inherit the shared `elevation` schema from `with_material_defaults(...)`, then update that schema default before recording their authored `default_prop(...)` value. This keeps catalog queries such as `descriptor.prop("elevation")` consistent with the MUI source defaults while preserving the existing template compiler merge order where authored `default_props` win over generic schema defaults during instancing.

`Badge` keeps `badgeContent` as a string default so descriptor instancing has a stable optional-content field, but the runtime style bridge and retained projection must treat the empty default as absent non-dot content. That matches local MUI `Badge.js`, where non-dot badges with null content are invisible, and `useBadge.ts`, where numeric `badgeContent = 0` is invisible unless `showZero` is true. The focused Badge style guard therefore checks four paths: hidden numeric zero content emits `MuiBadge-invisible`, `showZero = true` keeps numeric zero visible, string `"0"` also stays visible because MUI uses strict numeric equality for zero suppression, and the empty descriptor default emits the invisible slot class and retained `invisible` token.

`NumberField` remains in the numeric/input owner module because it shares drag and clamp behavior with runtime numeric state rather than the `TextInput` host capability. The Material foundation descriptor uses the field-sized numeric schema (`value` range `0..100`, step `1`) and exposes typed numeric `value`, `min`, `max`, `step`, and `large_step` defaults, plus `Focus`, `BeginDrag`, `DragDelta`, `LargeDragDelta`, `EndDrag`, `ValueChanged`, and `Commit`. Its Material Lab prototype keeps one route-bearing sample row for `MaterialLab/NumberField/Change`; the visible child examples are non-dispatchable `NumberField` nodes for stepper, clamped max, drag-active chip, error, and disabled states. The slice intentionally does not add string-only `value_text` to the numeric children, so retained projection continues to read `value_number` from the numeric `value` prop.

`RangeSlider` is now a first-class numeric/input descriptor instead of an implicit `Slider` visual variant. It exposes typed `range_min`, `value`, `min`, `max`, `step`, `large_step`, `range_min_percent`, `value_percent`, `focused_thumb`, `disable_swap`, `show_value_label`, and `marks` props, plus `Focus`, `BeginDrag`, `DragDelta`, `LargeDragDelta`, `EndDrag`, `ValueChanged`, and `Commit`. The generic numeric reducer keeps the descriptor role as the range-mode switch: lower-thumb writes clamp `range_min` at or below `value`, upper-thumb writes clamp `value` at or above `range_min`, and keyboard increment/decrement now chooses lower versus upper from `focused_thumb`/`active_thumb`/thumb-index metadata while defaulting to the upper `value` thumb for compatibility. `state_reducer/slider.rs` also keeps `range_min`/`value` and `range_min_percent`/`value_percent` synchronized in both directions, so a renderer-facing percent write is converted back into a clamped retained thumb value and value writes refresh the painter-facing percent mirror. With the default `disable_swap = true`, lower/upper crossing clamps to the other thumb. With `disable_swap = false` or authored `disableSwap = false`, crossing swaps the active retained property and writes sorted endpoints, matching MUI's non-disabled swap behavior without adding a second public event family. The Workbench primitive `workbench_range_slider.zui` composes the `RangeSlider` component directly, while `sliders.rs` already routes `RangeSlider` through the shared Slider painter family for dual-thumb track, fill, tick, and value-box render extraction.

`Switch` remains in the basic input owner module because it is a local checked toggle with track/thumb presentation rather than grouped selection or popup state. The descriptor exposes `text`, `checked`, `switch_size`, `switch_color`, `label_click_toggles`, `track_click_toggles`, and `thumb_draggable`, plus `Focus` and `ValueChanged`. The current policy records label and track clicks as toggle owners while thumb dragging stays disabled until drag semantics are implemented. Its Material Lab prototype keeps one route-bearing sample row for `MaterialLab/Switches/Toggle`; the visible child examples are non-dispatchable `Switch` nodes for on, off, small, disabled, and error states. Child examples freeze the size/color and toggle policy metadata so later runtime behavior can prove disabled no-toggle and local checked-state mutation without changing the prototype schema.

Selection-backed Material descriptors live in the `selection_inputs` child module instead of the broader input-control module. That subtree owns `Select`, `Dropdown`, `DropdownPopup`, `Autocomplete`, and `ToggleButtonGroup` because they share popup/option or grouped-selection ownership rather than text-edit or numeric-drag ownership. `Select` now records the Material field variant, display value, selected option ids, option ids, disabled/focused/hovered/pressed option id sets, `multiple`, `display_empty`, and `popup_open` metadata. It exposes `Focus`, `OpenPopup`, `SelectOption`, `ClosePopup`, and `ValueChanged`; `OpenPopup` and `ClosePopup` already update the retained popup flag through the runtime overlay reducer, while option commit stays owned by the selection reducer. `DropdownPopup` now carries the popup-shell half of the selection contract: open flags, selected/disabled/focused/hovered/pressed option id sets, focused index, keyboard navigation, retained typeahead, submenu hover metadata, anchor/placement/offset props, modal dismissal props, overlay portal props, paper/listbox/transition/option/group slots, and keyboard/text/typeahead/value/focus/select/close events. The Workbench `workbench_dropdown_popup.zui` primitive binds that descriptor directly and keeps the same popup shell props under `.zui` governance. `UiWidgetBehavior::infer_from_component` now maps `DropdownPopup` to `Popup` for authored assets without an explicit widget behavior; `pointer_popup_routes.rs` verifies outside pointer release close/writeback, and `keyboard_popup_routes.rs` verifies Escape close/writeback for the same component shell. `DropdownPopup` also reuses `state_reducer/keyboard/menu.rs` for roving option focus and retained typeahead without committing `selected_options`, and the shared menu timer predicate lets `UiInputManager` read authored `typeahead_timeout_ms` and `submenu_hover_delay_ms` from the shell. `popup_options.rs` now renders real `DropdownPopup` shells from `selected_options`/`selectedOptions`, `disabled_options`, `focused_index`, and `hovered_option_id`, and `popup_rows.rs` treats a no-anchor `DropdownPopup` as the popup surface itself instead of a dropdown trigger. `ToggleButtonGroup` records `options`, `value`, `selected_index`, `focused_index`, `disabled_options`, `selection_state`, `selection_follows_focus`, and `keyboard_navigation`, exposes `KeyboardAction`, reuses the indexed keyboard reducer for exclusive focus/selection movement while skipping disabled options, and in multiple mode uses `Activate` to toggle the current focused option in the retained `value` array without moving `selected_index`. Its Material Lab prototype keeps one route-bearing sample row for `MaterialLab/Selects/Change`; the visible child examples are non-dispatchable `Select` nodes for closed placeholder, open popup, selected option, multi-chip selection, and disabled option states.

`Autocomplete` stays in `selection_inputs` but adds the search-query side of the popup contract. Printable `KeyboardText` is emitted only for enabled/focusable host targets with an explicit binding, then performs focus search from option `label`/`text`/`title`/`value_text`/`value`/`id` metadata with the same wrap and disabled-option rules; single-character payloads keep first-letter cycling, multi-character payloads match case-insensitive label prefixes, and successive single-character events extend `typeahead_buffer` until `typeahead_buffer_expired` requests a reset. `TypeaheadExpired` marks `typeahead_buffer_expired = true` without clearing the existing buffer, so the next printable text event owns the reset boundary. ## Host Capabilities

Editor shell descriptors require `UiHostCapability::Editor`, which keeps them out of runtime-basic host palettes. `VirtualList`, `TreeView`, `MaterialTreeView`, `Table`, and `DataGrid` require both `UiHostCapability::VirtualizedLayout` and `UiRenderCapability::VirtualizedLayout`, preserving the existing validation invariant that virtualized rendering must be backed by a virtualized host.

Editor panel controls also require `UiHostCapability::Editor`. `PropertyRow`, `VectorRow`, `PanelGroup`, `ContextMenu`, `CommandPalette`, `ConfirmDialog`, `NotificationCenter`, and `DragOverlay` are editor-only descriptors because their meaning depends on inspector paths, dock grouping, workbench panel ownership, editor context targets, the editor command registry, editor action confirmation semantics, editor notification stream ownership, or editor drag/drop payload semantics. Text-backed controls such as `SearchField`, `FieldEditor`, `SourceEditor`, and `CommandPalette` require `TextInput` and expose the shared printable `KeyboardText` event lane. `Snackbar` remains a general feedback descriptor and now advertises the runtime Toast queue contract: `toast_queue`, `current_toast_id`, `expired_toast_id`, `queue_length`, and `action_label` props plus `ValueChanged`/`Commit` events. `state_reducer/toast.rs` owns queue promotion, timeout expiry, stale timer rejection, and close-current/promote-next behavior; `UiInputManager` now arms auto-hide deadlines from queue payloads or retained state and dispatches `UiInputEvent::ToastTimer`, while `surface/input/toast_timer.rs` routes the matching current toast into `Commit { expired_toast_id }`. M3.S3 splits editor-owned feedback overlays out of `feedback.rs` into `feedback_editor_overlays.rs`: `CommandPalette` declares query, command list, filtered/recent/disabled command lists, focused index, selection id, command source, modal dismissal, portal, anchor props, and popup layout role plus open/text/keyboard/value/select/commit/close events; `state_reducer/command_palette.rs` now owns command-source filtering, printable query updates, disabled-command focus skipping, selection rejection, and committed command id writeback. `ConfirmDialog` declares centered modal overlay props, title/message, confirm/cancel action ids, severity/default action/destructive state, title/content/action slots, explicit action state, and open/close/commit/value/keyboard events. General `Dialog` now also exposes `popup_open`, title/message text, `dialog_action_id`, `Commit`, and `KeyboardAction` so the shared overlay reducer can close on Escape and record action commits through the same state path. `NotificationCenter` declares popup/open flags, structured notification entries, unread count, focused index, selected notification id, visible limit, keyboard navigation, title/empty text, header/item/empty/action slots, and open/close/select/value/keyboard/reference events; `state_reducer/notification_center.rs` owns row selection, read-state mutation, unread-count resync, disabled-row rejection, stale-selection cleanup, and visible-row keyboard navigation, while `surface/render/notification_center.rs` renders the panel/list baseline through the Toast painter family and `workbench_notification_center.zui` plus retained-host native projection/painter files cover the editor Workbench path. M3.S4 adds `DragOverlay` with drag payload kind/label/reference, source/target control ids, cursor offsets, preview sizing, drop target geometry, allowed-state, drop indicator edge, preview/indicator slots, and drag/drop event kinds; `workbench_drag_overlay.zui` plus retained-host drag projection/native painter files now cover the editor Workbench path for preview chips and drop indicators. `workbench_command_palette.zui`, `workbench_notification_center.zui`, `workbench_drag_overlay.zui`, `workbench_alert.zui`, `workbench_dialog.zui`, and `workbench_confirm_dialog.zui` keep the Workbench feedback assets under primitive and overlay governance while the real command registry/execution route stays queued for 08 M4. Canvas-backed controls such as `ViewportHost`, `GraphCanvas`, and `VisualDesigner` require `CanvasRender`; preview panes require `ImageRender`.

## Layout Roles

The catalog uses `UiComponentLayoutRole` rather than renderer-specific type checks:

- flex, horizontal, vertical, scroll view, and scroll box remain flex-family layouts for the Taffy bridge;
- split view uses the size role because its main output is a resizable two-pane allocation;
- grid group maps to grid;
- overlay stays Zircon-owned;
- virtual list stays explicitly virtualized;
- command palette uses the popup role because it is an overlay command-search surface even though its category remains input;
- viewport, graph, and designer surfaces use the canvas layout role;
- dock host and panel group use the editor dock role for future JetBrains/Unreal workbench shell assembly.

## Enum Option Ownership

MUI catalog helper modules build enum props by passing string option arrays into `enum_option_descriptor`. The shared helper accepts `&str` and immediately materializes owned `UiOptionDescriptor` values, so local wrappers can pass their array items without forcing a caller-side `'static` lifetime through every descriptor module.

This is a shared catalog invariant rather than an app-entry workaround: package-level app tests compile `zircon_runtime` first, so enum option helper lifetime errors in the MUI catalog can block unrelated `zircon_app` guards before the app test harness starts. Keeping ownership at the shared helper boundary preserves the normal bottom-up path: catalog descriptors compile, then app-entry source guards can validate their own module boundaries.
