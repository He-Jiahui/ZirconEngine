# Material Editor Foundation Catalog

`UiComponentDescriptorRegistry::material_editor_foundation()` is the first component catalog for the new editor UI direction. It is intentionally separate from `editor_showcase()` so existing showcase tests and legacy showcase consumers keep their exact component set while the new workbench path gains a clean Material-first contract.

## Component Layers

The catalog is organized around the implementation plan's four layers:

- primitive controls: button, icon button, text field, checkbox, switch, dropdown, slider, tabs, menu, tooltip, scrollbar, splitter, panel, modal;
- layout controls: flex group, horizontal group, vertical group, grid group, overlay, scroll view;
- data/view controls: list view, virtual list, tree view, property grid, inspector section;
- Fyrox panel role controls: search field, context menu, field editor, folder tree, asset grid/list, preview and metadata panes, viewport host, pane toolbar, gizmo controls, filter bar, severity chips, categorized list, status action controls, graph canvas, source editor, timeline, and visual designer;
- shell controls: window, view, drawer, view tab, window frame, document node, tab stack, floating window, dock host, workbench shell, slot, and composite.

Every descriptor receives the `material_dark`, `material`, and `material-dark` default classes. Each descriptor also declares the same visual state schema used by the Material skin: hovered, pressed, selected, disabled, focused, error, and warning.

Data-display descriptors are split by responsibility so the catalog remains folder-backed as it grows. `data_display.rs` owns direct MUI data-display components such as Chip, Divider, Icon, List, Table, Typography, Avatar, Badge, and ImageList. `data_display_subcomponents.rs` and `data_display_table.rs` own local MUI child components. `data_display_editor.rs` owns editor-facing collection roles such as FolderTree, AssetGrid, AssetList, and CategorizedList, keeping editor panel descriptors out of the core MUI data-display owner.

## Behavior Contracts

The foundation descriptors now carry the first behavior-level props and events needed by the planned Workbench shell:

- `VirtualList` declares `item_count`, `item_extent`, `overscan`, and `SetVisibleRange`.
- `TreeView` declares `query`, `expanded`, `focused_index`, `selected_index`, `disabled_options`, `selection_follows_focus`, and `keyboard_navigation` props plus selection, expand/collapse, context-menu, and `KeyboardAction` events.
- `PropertyGrid` and `InspectorSection` keep inspector-style section/field slots and property-edit events.
- `SearchField`, `FilterBar`, and `SeverityChips` declare query/severity props and selection/value-change events for Hierarchy, Asset Browser, Console, and Diagnostics.
- `FolderTree`, `AssetGrid`, `AssetList`, and `CategorizedList` declare collection slots plus selection, expand/collapse, context-menu, locate, and open-reference events.
- `PreviewPane`, `MetadataPane`, `FieldEditor`, and `StatusActionControls` give Inspector, Asset Browser, Plugin Manager, and export views reusable editor-only composite surfaces.
- `ViewportHost`, `GraphCanvas`, and `VisualDesigner` are canvas-layout components for Scene/Game, Material, UI, and animation authoring surfaces.
- `PaneToolbar`, `GizmoControls`, `SourceEditor`, and `Timeline` cover viewport/editor toolbars, transform controls, text-source editing, and animation scrubbing.
- `DocumentNode`, `TabStack`, and `FloatingWindow` expose the Workbench split/tab/detach model as authorable shell components.
- `Drawer`, `View`, `ViewTab`, `Window`, `WindowFrame`, `DockHost`, and `WorkbenchShell` declare stable ids, active-selection/focus props, preset ids, and shell interaction events.
- `Button`, `IconButton`, and `FloatingActionButton` expose the button-family interaction event set: `Focus`, `Hover`, `Press`, and `Commit`. The runtime state reducer owns retained focus/hover/press flags in `state_reducer/button.rs`, while `Commit` still uses the generic property-mutation path.
- `KeyboardAction` is now the semantic keyboard event advertised by the first behavior slices. `Button`, `IconButton`, `FloatingActionButton`, `ButtonBase`, `NumberField`, `Checkbox`, `Radio`, `RadioGroup`, `Switch`, `Slider`, `RangeSlider`, `ToggleButton`, `ToggleButtonGroup`, `Tabs`, `Tab`, `Menu`, `MenuList`, `Select`, `Dropdown`, `Autocomplete`, `ListView`, `TreeView`, `Table`, MUI X `MaterialTreeView`, and `DataGrid` expose it. `Menu`, `MenuList`, `TextField`, `Input`, `InputBase`, `FilledInput`, `OutlinedInput`, `TextareaAutosize`, `SearchField`, `FieldEditor`, and `SourceEditor` also expose `KeyboardText` for printable component text, and `Menu`/`MenuList` expose `TypeaheadExpired` for timer-driven typeahead expiry. Runtime input hosts map physical keys to semantic actions and printable text to component text events, the explicit printable-text route uses the same disabled/ancestor-disabled interaction gate as semantic actions, and `UiInputManager` arms Menu/MenuList expiry deadlines after delivered `KeyboardText` reports before injecting synthetic `TypeaheadTimer` events on `tick(...)`; `state_reducer/keyboard.rs` applies activation, cancel, tab and grouped-selection focus/selection movement, multiple ToggleButtonGroup focused-option activation, menu-list focus movement, menu first-letter and multi-character prefix focus movement with retained typeahead buffer state, typeahead expiry marking, recursive menu search filtering, Menu/MenuList submenu pending/open keyboard focus-scope cycling, query-backed SearchField/Autocomplete editable-property routing, MUI TextField ArrowLeft/Delete/End retained edit-state routing plus active-selection Backspace collapse, ListView/TreeView/Table/DataGrid indexed focus movement, and numeric step/clamp behavior without platform keycode branching in the component catalog. Text-input-specific reducer ownership now lives in `state_reducer/text_input.rs`, which handles printable insertion writeback plus `validation_timing = change|commit|blur`, dirty/touched flags, and required/min/max-length validation.
- `RangeSlider` also participates in headless Range widget inference: `UiWidgetBehavior::infer_from_component("RangeSlider")` returns `Range`, and `default_interactions/range.rs` chooses the nearest retained thumb (`range_min` or `value`) on pointer press, stores that property in the pointer-drag state for move/release, and applies the descriptor swap policy while keeping the non-RangeSlider range path on the configured value property. The catalog declares `disable_swap = true` by default for no-swap crossing clamps; authored metadata can also use MUI-style `disableSwap = false` to opt into active-thumb swapping.
- `ButtonGroup` is a structural composite: it declares group orientation, attached-radius, segment-count, and disabled-propagation metadata plus the child button style schemas/defaults (`button_variant`, `button_color`, `button_size`, and `icon_placement`). The group itself stays non-dispatchable; child buttons own click, press, focus, and selection routes.
- `UseMediaQuery` remains a layout utility descriptor and now declares both raw query props (`query`, `min_width`, `max_width`, `defaultMatches`, `default_matches`, `matches`) and MUI breakpoint shorthand props (`up`, `down`, `between`, `breakpoint`). Runtime evaluation stays owned by the responsive layout pre-pass so catalog metadata and actual resize behavior share the same schema.
- `Select` and `Autocomplete` popup lifecycle events now have a first runtime-owned reducer path: `OpenPopup` and `ClosePopup` mutate retained `popup_open` state through `state_reducer/overlay.rs`. Anchored context-menu opens use the same overlay family through `OpenPopupAt`, which records `popup_anchor_x` and `popup_anchor_y`; full popup placement, keyboard navigation, and outside-click close policy remain later overlay/dropdown work.
- `VirtualList`/`DataGrid` visible-window events and `Pagination`/`TablePagination` page events now route through the runtime `state_reducer/windowing.rs` family. The visible-range path keeps the existing MUI/react-window alias support (`rowCount`, `rowHeight`, `overscanCount`, `disableVirtualization`), while the page path clamps invalid page sizes and out-of-range page indices before writing retained page window fields.
- `ListView`, `TreeView`, `Table`, `MaterialTreeView`, and `DataGrid` now carry the shared indexed collection keyboard contract. The runtime keyboard reducer reads ordered entries from `nodes`, `rows`, `items`, or `options`, moves `focused_index` with direction/Home/End actions, skips disabled rows/nodes, and only writes `selected_index`/`value` when `selection_follows_focus` is enabled. Full tree expand/collapse, multi-select/range selection, rename, drag reorder, table column resize/sort, and virtualized scroll coupling remain later Tree/Table slices.

These are still neutral component descriptors. They do not create native windows or bind editor state directly; they let v2 assets and editor presenters agree on which values and events are valid before a concrete skin or host renders them.

Text-backed Material descriptors live in the `text_inputs` child module instead of the broader input-control module. That subtree owns `TextField`, `Input`, `InputBase`, `FilledInput`, `OutlinedInput`, `TextareaAutosize`, `SearchField`, `FieldEditor`, and `SourceEditor` because they share the `TextInput` host capability and edit/commit event family. These descriptors now advertise `KeyboardText` and expose `caret_offset`, `selection_anchor`, `selection_focus`, composition mirror props, and shared validation props such as `required`, `min_length`, `max_length`, `validation_timing`, `validation_message`, `validation_dirty`, and `validation_touched`. The M1 reducer bridge routes printable payloads through the shared text edit-state insertion helper, appends at the end when no edit-state metadata exists, replaces an explicit selection when present, writes the collapsed caret/selection state back, mirrors MUI input-family `value_text`/`value`, ignores control or whitespace-only payloads, sets focus, honors read-only aliases, and now keeps validation ownership in `state_reducer/text_input.rs`. Query-backed `SearchField` and `Autocomplete` nodes also infer `query` as their host editable-text property, so physical edit actions such as Backspace/Delete use the retained search text instead of falling back to `value` or overwriting Autocomplete's committed selection value. Focused MUI `TextField` host coverage now verifies ArrowLeft, Delete, End, and active-selection Backspace against the same retained value/caret route: caret-only moves emit no value event, Delete writes `value`, `caret_offset`, and a `ValueChanged { property: "value" }` report, and Backspace removes the selected range before collapsing `caret_offset`, `selection_anchor`, and `selection_focus`. `TextInput` validation timing is reducer-owned: `change` validates after each text/value mutation, `commit` defers until commit while marking dirty edits, and `blur` validates on focus loss while preserving dirty/touched metadata. `TextField` currently records the MUI wrapper split as metadata: `variant = outlined|filled|standard`, `label`, `value_text`, `placeholder`, `helper_text`, `multiline`, and `select_mode`. The Material Lab prototype freezes one representative route-bearing row plus non-dispatchable visual children for outlined focus, filled helper text, standard underline, error helper, and disabled no-edit, while live helper-label layout, platform candidate-window validation, real Chinese input, full multiline/autosize validation, and select-mode behavior remain later runtime support work. `TextareaAutosize` uses the same owner module and adds layout-affecting row metadata: `variant`, `value_text`, `placeholder`, `helper_text`, `multiline`, `autosize`, `min_rows`, and `max_rows`. Its prototype keeps one change route on the sample row and uses visual-only child examples for minimum rows, maximum row clamp, focused autosize, error helper, and disabled no-edit so later layout tests can distinguish row-clamp metadata from render-only field styling.

Surface descriptors that override a shared Material prop default must keep descriptor schema reflection and authored default instancing aligned. `AppBar` and `Paper` inherit the shared `elevation` schema from `with_material_defaults(...)`, then update that schema default before recording their authored `default_prop(...)` value. This keeps catalog queries such as `descriptor.prop("elevation")` consistent with the MUI source defaults while preserving the existing template compiler merge order where authored `default_props` win over generic schema defaults during instancing.

`Badge` keeps `badgeContent` as a string default so descriptor instancing has a stable optional-content field, but the runtime style bridge and retained projection must treat the empty default as absent non-dot content. That matches local MUI `Badge.js`, where non-dot badges with null content are invisible, and `useBadge.ts`, where numeric `badgeContent = 0` is invisible unless `showZero` is true. The focused Badge style guard therefore checks four paths: hidden numeric zero content emits `MuiBadge-invisible`, `showZero = true` keeps numeric zero visible, string `"0"` also stays visible because MUI uses strict numeric equality for zero suppression, and the empty descriptor default emits the invisible slot class and retained `invisible` token.

`NumberField` remains in the numeric/input owner module because it shares drag and clamp behavior with runtime numeric state rather than the `TextInput` host capability. The Material foundation descriptor uses the field-sized numeric schema (`value` range `0..100`, step `1`) and exposes typed numeric `value`, `min`, `max`, `step`, and `large_step` defaults, plus `Focus`, `BeginDrag`, `DragDelta`, `LargeDragDelta`, `EndDrag`, `ValueChanged`, and `Commit`. Its Material Lab prototype keeps one route-bearing sample row for `MaterialLab/NumberField/Change`; the visible child examples are non-dispatchable `NumberField` nodes for stepper, clamped max, drag-active chip, error, and disabled states. The slice intentionally does not add string-only `value_text` to the numeric children, so retained projection continues to read `value_number` from the numeric `value` prop.

`RangeSlider` is now a first-class numeric/input descriptor instead of an implicit `Slider` visual variant. It exposes typed `range_min`, `value`, `min`, `max`, `step`, `large_step`, `range_min_percent`, `value_percent`, `focused_thumb`, `disable_swap`, `show_value_label`, and `marks` props, plus `Focus`, `BeginDrag`, `DragDelta`, `LargeDragDelta`, `EndDrag`, `ValueChanged`, and `Commit`. The generic numeric reducer keeps the descriptor role as the range-mode switch: lower-thumb writes clamp `range_min` at or below `value`, upper-thumb writes clamp `value` at or above `range_min`, and keyboard increment/decrement now chooses lower versus upper from `focused_thumb`/`active_thumb`/thumb-index metadata while defaulting to the upper `value` thumb for compatibility. `state_reducer/slider.rs` also keeps `range_min`/`value` and `range_min_percent`/`value_percent` synchronized in both directions, so a renderer-facing percent write is converted back into a clamped retained thumb value and value writes refresh the painter-facing percent mirror. The default range pointer path infers `RangeSlider` as a `Range` widget, computes the click value from track geometry, writes the nearer retained thumb (`range_min` for lower, `value` for upper with ties favoring upper), stores that property for the active drag session, and emits the existing drag/value reports. With the default `disable_swap = true`, lower/upper crossing clamps to the other thumb. With `disable_swap = false` or authored `disableSwap = false`, crossing swaps the active retained property and writes sorted endpoints, matching MUI's non-disabled swap behavior without adding a second public event family. The Workbench primitive `workbench_range_slider.zui` composes the `RangeSlider` component directly, while `sliders.rs` already routes `RangeSlider` through the shared Slider painter family for dual-thumb track, fill, tick, and value-box render extraction.

`Checkbox` remains in the basic input owner module because its runtime behavior is a local toggle value rather than a popup selection list. The descriptor exposes `text`, `checked`, `indeterminate`, `label_click_toggles`, and `indeterminate_resolves_to_checked`, plus `Focus` and `ValueChanged`. The current policy records that clicking an indeterminate checkbox resolves to checked. Its Material Lab prototype keeps one route-bearing sample row for `MaterialLab/Checkboxes/Toggle`; the visible child examples are non-dispatchable `Checkbox` nodes for unchecked, checked, indeterminate, error, and disabled states. Child examples keep `label_click_toggles = true` so later headless behavior tests can assert that label and box activation share the same disabled-aware owner.

`Radio` remains in the basic input owner module, and the catalog also declares a `RadioGroup` descriptor for indexed grouped selection. `Radio` carries per-option metadata such as `group_value`, `option_id`, `options`, `disabled_options`, `label_click_selects`, `exclusive_group`, and `keyboard_navigation`. `RadioGroup` carries the group-level `value`, `value_text`, `selected_index`, `focused_index`, `disabled_options`, `selection_follows_focus`, `keyboard_navigation`, and `KeyboardAction` contract. The keyboard reducer now handles direction/Home/End movement for `RadioGroup`, updating focus, selection, `value`, `value_text`, and `group_value` together while skipping disabled options from retained `disabled_options` or descriptor option metadata; label-click routing remains a later behavior slice. The Material Lab prototype keeps one route-bearing sample row for `MaterialLab/RadioButtons/Change`; the visible child examples are non-dispatchable `Radio` nodes for selected, unselected, disabled, and error options. Each child freezes the same option list and selected group value so the runtime implementation can prove exclusive selection clears previous options and disabled options are rejected without changing the prototype schema.

`Switch` remains in the basic input owner module because it is a local checked toggle with track/thumb presentation rather than grouped selection or popup state. The descriptor exposes `text`, `checked`, `switch_size`, `switch_color`, `label_click_toggles`, `track_click_toggles`, and `thumb_draggable`, plus `Focus` and `ValueChanged`. The current policy records label and track clicks as toggle owners while thumb dragging stays disabled until drag semantics are implemented. Its Material Lab prototype keeps one route-bearing sample row for `MaterialLab/Switches/Toggle`; the visible child examples are non-dispatchable `Switch` nodes for on, off, small, disabled, and error states. Child examples freeze the size/color and toggle policy metadata so later runtime behavior can prove disabled no-toggle and local checked-state mutation without changing the prototype schema.

Selection-backed Material descriptors live in the `selection_inputs` child module instead of the broader input-control module. That subtree owns `Select`, `Dropdown`, `Autocomplete`, and `ToggleButtonGroup` because they share popup/option or grouped-selection ownership rather than text-edit or numeric-drag ownership. `Select` now records the Material field variant, display value, selected option ids, option ids, disabled/focused/hovered/pressed option id sets, `multiple`, `display_empty`, and `popup_open` metadata. It exposes `Focus`, `OpenPopup`, `SelectOption`, `ClosePopup`, and `ValueChanged`; `OpenPopup` and `ClosePopup` already update the retained popup flag through the runtime overlay reducer, while option commit stays owned by the selection reducer. `ToggleButtonGroup` records `options`, `value`, `selected_index`, `focused_index`, `disabled_options`, `selection_state`, `selection_follows_focus`, and `keyboard_navigation`, exposes `KeyboardAction`, reuses the indexed keyboard reducer for exclusive focus/selection movement while skipping disabled options, and in multiple mode uses `Activate` to toggle the current focused option in the retained `value` array without moving `selected_index`. Its Material Lab prototype keeps one route-bearing sample row for `MaterialLab/Selects/Change`; the visible child examples are non-dispatchable `Select` nodes for closed placeholder, open popup, selected option, multi-chip selection, and disabled option states.

`Autocomplete` stays in `selection_inputs` but adds the search-query side of the popup contract. Its descriptor records `query`, display value, selected option ids, all option ids, filtered option ids, disabled/focused/hovered/pressed/matched option id sets, `multiple`, `free_solo`, and `popup_open` metadata. It exposes `Focus`, `ValueChanged`, `OpenPopup`, `SelectOption`, `ClosePopup`, and `RemoveElement`; the remove event is reserved for chip deletion while query edits and option commits remain distinct. Host editable-text actions now choose `query` for Autocomplete even when committed `value` is present, so Backspace/Delete/caret edits filter text without overwriting selection value. Its Material Lab prototype keeps one route-bearing sample row for `MaterialLab/Autocomplete/Change`; the visible child examples are non-dispatchable `Autocomplete` nodes for query-filtered results, open popup, selected option, multi-chip selection, and disabled option states. Free-solo and async loading are still future runtime behavior, but the descriptor carries the `free_solo` flag now so assets can declare the supported mode without changing the schema later.

Navigation-backed menu descriptors split the popup shell from the roving-focus list. `Menu` records popup/open metadata plus `options`, `focused_index`, `disabled_options`, `keyboard_navigation`, `disableListWrap`, `disabledItemsFocusable`, `typeahead_buffer`, `typeahead_buffer_expired`, `typeahead_timeout_ms`, `allow_search`, `search_bar_enabled_on_item_count`, `search_query`, `filtered_option_ids`, `filter_no_results`, `hovered_option_id`, `submenu_pending_option_id`, `submenu_open_option_id`, `submenu_hover_ready`, `submenu_hover_delay_ms`, `submenu_focus_scope`, `submenu_active_parent_index`, and `submenu_focus_loop`; `MenuList` carries the same indexed focus, retained typeahead, retained search-filter, and retained submenu contract without the overlay shell. Both descriptors expose `KeyboardAction`, `KeyboardText`, `TypeaheadExpired`, `ValueChanged`, and `Focus`. The keyboard reducer applies direction/Home/End movement to `focused_index`, skips disabled options unless `disabledItemsFocusable` is true, wraps by default, honors `disableListWrap`, and intentionally does not mutate `selected_index`, `value`, or `state.flags.selected`; the Menu/MenuList-specific focus, typeahead, search filtering, and submenu pending/open implementation now lives in `state_reducer/keyboard/menu.rs` instead of expanding the main keyboard reducer. Printable `KeyboardText` is emitted only for enabled/focusable host targets with an explicit binding, then performs focus search from option `label`/`text`/`title`/`value_text`/`value`/`id` metadata with the same wrap and disabled-option rules; single-character payloads keep first-letter cycling, multi-character payloads match case-insensitive label prefixes, and successive single-character events extend `typeahead_buffer` until `typeahead_buffer_expired` requests a reset. `TypeaheadExpired` marks `typeahead_buffer_expired = true` without clearing the existing buffer, so the next printable text event owns the reset boundary. Repeated identical characters keep first-letter cycling semantics, while non-expired prefixes prefer the current focused option when it still matches. `UiInputManager` reads `typeahead_timeout_ms` from enabled Menu/MenuList nodes, arms per-node deadlines after delivered `KeyboardText`, and dispatches synthetic `TypeaheadTimer` input on `tick(...)` to emit `TypeaheadExpired`. `ValueChanged { property: "search_query" }` updates recursive `filtered_option_ids` by case-insensitive substring match over option text/id metadata, writes `filter_no_results`, and reconciles `focused_index` to the first visible focusable result while keeping disabled matches visible but unfocused unless `disabledItemsFocusable` is true. Nested submenu data under `children`, `items`, `options`, `submenu`, `sub_menu`, or `subMenu` is searched recursively; descendant matches retain their ancestor ids in the visible path, so root focus can move to the parent row that opens the matching submenu. `ValueChanged { property: "hovered_option_id" }` now arms a child-bearing row as `submenu_pending_option_id`, `submenu_hover_ready = true` promotes that row to `submenu_open_option_id` and `submenu_focus_scope = "submenu"`, and `KeyboardAction::Activate`/`Cancel` open or close the active submenu loop before the generic popup branch runs. Host timer dispatch for `submenu_hover_ready`, outside-click close, and complete overlay focus-loop policy remain later popup/menu slices.

`FyroxPanelComponentRole::component_id()` maps editor panel roles onto these descriptor ids. The editor-side default stack test walks every panel preset role and verifies that the Material foundation catalog contains the matching descriptor. Adding a new Fyrox panel role now requires either reusing an existing component id or adding a catalog descriptor with matching host/render capabilities.

## Host Capabilities

Editor shell descriptors require `UiHostCapability::Editor`, which keeps them out of runtime-basic host palettes. `VirtualList` requires both `UiHostCapability::VirtualizedLayout` and `UiRenderCapability::VirtualizedLayout`, preserving the existing validation invariant that virtualized rendering must be backed by a virtualized host.

Editor panel controls also require `UiHostCapability::Editor`. Text-backed controls such as `SearchField`, `FieldEditor`, and `SourceEditor` require `TextInput` and expose the shared printable `KeyboardText` insertion/edit-state bridge; canvas-backed controls such as `ViewportHost`, `GraphCanvas`, and `VisualDesigner` require `CanvasRender`; preview panes require `ImageRender`.

## Layout Roles

The catalog uses `UiComponentLayoutRole` rather than renderer-specific type checks:

- flex, horizontal, vertical, and scroll views remain flex-family layouts for the Taffy bridge;
- grid group maps to grid;
- overlay stays Zircon-owned;
- virtual list stays explicitly virtualized;
- viewport, graph, and designer surfaces use the canvas layout role;
- dock host uses the editor dock role for future JetBrains/Unreal workbench shell assembly.

## Enum Option Ownership

MUI catalog helper modules build enum props by passing string option arrays into `enum_option_descriptor`. The shared helper accepts `&str` and immediately materializes owned `UiOptionDescriptor` values, so local wrappers can pass their array items without forcing a caller-side `'static` lifetime through every descriptor module.

This is a shared catalog invariant rather than an app-entry workaround: package-level app tests compile `zircon_runtime` first, so enum option helper lifetime errors in the MUI catalog can block unrelated `zircon_app` guards before the app test harness starts. Keeping ownership at the shared helper boundary preserves the normal bottom-up path: catalog descriptors compile, then app-entry source guards can validate their own module boundaries.
