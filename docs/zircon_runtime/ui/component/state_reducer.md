# Component State Reducer

`zircon_runtime::ui::component::state_reducer` applies component-level UI events to `UiComponentState`. The public entry point remains `apply_component_event(...)`, while family-specific behavior lives in child modules under `state_reducer/`.

## Family Dispatch

`state_reducer/button.rs` is the first family reducer extracted from the monolithic entry function for plan 06 M1.S2. It recognizes `Button`, `IconButton`, `FloatingActionButton`, and `ButtonBase` by descriptor id or role, then owns the transient button interaction flags:

- `Focus` writes `state.flags.focused`.
- `Hover` writes `state.flags.hovered`.
- `Press` writes `state.flags.pressed`.

Other button-family events fall back to the generic reducer. This preserves the existing `Commit { property, value }` path, including descriptor-based value validation and reference-source cleanup, instead of duplicating generic property mutation in the button module.

The Material foundation descriptors for `Button`, `IconButton`, and `FloatingActionButton` now expose `Focus`, `Hover`, `Press`, and `Commit`. `ButtonGroup` stays structural; child buttons own interaction state and commit routing.

`state_reducer/keyboard.rs` owns semantic keyboard actions exposed through `UiComponentEvent::KeyboardAction`. The event is intentionally action-based rather than physical-key based: host input code maps Enter/Space/Escape/arrow/Page-style keys into `Activate`, `Cancel`, `Next`, `Previous`, `First`, `Last`, `Increment`, `Decrement`, `LargeIncrement`, or `LargeDecrement`; the reducer only mutates component state. The host mapping lives in `surface/input/keyboard_action.rs`, and `dispatch_keyboard_input(...)` tries this semantic component route before generic arrow-key focus navigation, legacy button commit, or legacy popup dismissal. It only handles the event when the focused node has a binding that explicitly targets the `KeyboardAction` token, so ordinary nodes keep the existing navigation and default-action behavior. The same keyboard host path also exposes `UiComponentEvent::KeyboardText` for printable component text, currently used by menu typeahead: it requires an explicit `KeyboardText` binding, accepts pressed/repeated printable `UiKeyboardInputEvent.text`, permits Shift, rejects Control/Alt/Super and control/whitespace-only payloads, reuses `widget_interaction_enabled(...)` so disabled nodes or disabled ancestors cannot emit component text, and runs before generic navigation fallbacks. Menu/MenuList roving focus text search, retained search-bar filtering, and typeahead expiry state now live in `state_reducer/keyboard/menu.rs`, while the parent keyboard reducer keeps shared action dispatch, indexed selection, indexed collection, numeric, and text-input orchestration. `UiComponentEvent::TypeaheadExpired` is the timer-facing menu expiry semantic event: descriptors and default interaction token mapping can advertise it, the reducer records only the expired marker while leaving buffer clearing to the next printable text event, and `UiInputManager` now schedules plus dispatches it through synthetic `UiInputEvent::TypeaheadTimer` on `tick(...)`. The first reducer slices cover:

- `Activate` for button-family controls, checked controls, radio, popup controls, and multiple-selection `ToggleButtonGroup` focused-option toggles.
- `Cancel` for popup-capable controls, clearing retained popup and transient press/drag flags.
- `Next`/`Previous`/`First`/`Last` for indexed keyboard-selection controls. `Tabs` write `focused_index` and, when `selection_follows_focus`/`selectionFollowsFocus` is true, `selected_index`, `value`, and `value_text`. `RadioGroup` defaults to selection-following-focus and also keeps `group_value` aligned. `RadioGroup` and `ToggleButtonGroup` skip options listed in `disabled_options` or disabled descriptor option metadata. `ToggleButtonGroup` uses the same indexed focus path, but only commits selection when opted in and not in multiple-selection mode; multiple mode keeps movement focus-only, then `Activate` toggles the current focused option in the retained `value` array without changing `selected_index`.
- `Next`/`Previous`/`First`/`Last` for indexed collection controls. `ListView`, `TreeView`, `Table`, MUI X `MaterialTreeView`, and `DataGrid` derive their ordered keyboard entries from `nodes`, `rows`, `items`, or `options`, write `focused_index`, skip disabled entries, wrap by default, and only commit `selected_index`/`value` when `selection_follows_focus` is explicitly enabled. This is the M1 focus baseline; expand/collapse, range selection, rename, column resize/sort, drag reorder, and virtualized scroll coupling stay in the later tree/table family slices.
- `Next`/`Previous`/`First`/`Last` for indexed keyboard-focus menu controls. `Menu` and `MenuList` write `focused_index` without changing `selected_index`, `value`, or `state.flags.selected`; they wrap by default, honor `disableListWrap`, skip `disabled_options` and disabled descriptor option metadata, and allow disabled focus only when `disabledItemsFocusable` is true.
- `KeyboardText` focus search for indexed menu controls. `Menu` and `MenuList` derive searchable text from option `label`, `text`, `title`, `value_text`, `value`, or `id`. Single-character payloads preserve first-letter cycling; multi-character payloads are normalized to a case-insensitive prefix. Search starts after the current `focused_index`, wraps unless `disableListWrap` is true, skips disabled options unless `disabledItemsFocusable` is true, and updates only `focused_index`. The same reducer now maintains retained typeahead state: `typeahead_buffer` accumulates successive single-character printable events, repeated identical characters collapse back to one-character cycling, non-expired prefixes prefer the current item when it still matches, and `typeahead_buffer_expired = true` causes the next printable event to start a fresh buffer while clearing the expired flag. `TypeaheadExpired` is the semantic event that sets that expired marker without destroying the previous buffer.
- `ValueChanged { property: "search_query" }` filtering for indexed menu controls. `Menu` and `MenuList` now retain `search_query`, `filtered_option_ids`, `filter_no_results`, `allow_search`, and `search_bar_enabled_on_item_count`. A query update writes the query through the generic value validator, then the menu reducer derives visible option ids by case-insensitive substring matching over option text/id metadata, writes `filter_no_results` for non-empty no-match queries, moves `focused_index` to the first visible focusable result, and treats non-matching ids as hidden for subsequent menu focus navigation. Nested submenu metadata under `children`, `items`, `options`, `submenu`, `sub_menu`, or `subMenu` participates in the search; a descendant match keeps its ancestor path in `filtered_option_ids` and focuses the root row that can open the matching submenu. Disabled matches remain visible in `filtered_option_ids` but stay unfocused unless `disabledItemsFocusable` is true. The same menu reducer now owns a retained submenu state baseline: `hovered_option_id` arms `submenu_pending_option_id` when the hovered option has children, `submenu_hover_ready = true` promotes that pending option to `submenu_open_option_id`, and `submenu_focus_scope`/`submenu_active_parent_index` record whether keyboard focus is inside the submenu loop. `KeyboardAction::Activate` opens the currently focused submenu option before falling back to generic popup activation, and `Cancel` closes the active submenu loop before closing the main popup. Host timer dispatch for `submenu_hover_ready`, outside-click close, and complete overlay focus-loop behavior remain later popup/menu slices.
- `KeyboardText` insertion for text-input controls. `TextField`, `Input`, `InputBase`, `FilledInput`, `OutlinedInput`, `TextareaAutosize`, `SearchField`, `FieldEditor`, and `SourceEditor` drop control characters, ignore whitespace-only payloads, honor descriptor/state `readOnly` aliases, set focus, and route printable text through the shared `apply_text_edit_action(..., Insert)` helper. Descriptors expose `caret_offset`, `selection_anchor`, `selection_focus`, composition mirror props, `required`, `min_length`, `max_length`, `validation_timing`, `validation_message`, `validation_dirty`, and `validation_touched`; when edit-state props are absent the reducer defaults to end-of-text append, and when an explicit selection exists the printable payload replaces that selection and collapses the caret. ## Selection Semantics

`apply_selection(...)` resolves selection mode from the component descriptor and current state:

- A property whose descriptor declares `UiValueKind::Flags` is a flag set and stores `UiValue::Flags(Vec<String>)`.
- A component whose `multiple` setting is true stores selected values in `UiValue::Array`.
- Every other selection is single-select and stores either `UiValue::Enum(option_id)` or `UiValue::Null`.

The mode decision is made before inspecting any stale value currently stored on the property. This matters because old state, partially migrated data, or previous bugs can leave a single-select control with `UiValue::Flags` or `UiValue::Array`. A single-select event must not preserve that stale container and append into it. It must replace the value with the one selected enum, or clear it to null when the option is unselected.

## Stale Value Conversion

For flag properties, `selection_flags_value(...)` removes the previous value and converts known option-shaped values into a clean `Vec<String>`. Existing `Flags` values are preserved, arrays keep enum/string entries, and a non-empty enum/string becomes a one-item flag vector. Other values normalize to an empty flag list.

For multi-select properties, `selection_array_value_mut(...)` keeps the existing array path and converts a previous scalar enum/string into a one-item array before adding or removing the requested option.

For single-select properties, no previous container is reused. Selecting an option writes `UiValue::Enum(option_id)`. Unselecting writes `UiValue::Null`. This keeps the public invariant simple: a single-select value is unique or absent, even when the previous state was malformed.

`state.flags.selected` is still updated from the event's selected flag after the value mutation. That flag reflects the most recent event outcome; it is not the source of truth for the selected option list.
