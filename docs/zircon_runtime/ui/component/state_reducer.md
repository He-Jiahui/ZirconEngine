# Component State Reducer

`zircon_runtime::ui::component::state_reducer` applies component-level UI events to `UiComponentState`. The public entry point remains `apply_component_event(...)`, while family-specific behavior lives in child modules under `state_reducer/`.

## Family Dispatch

`state_reducer/button.rs` is the first family reducer extracted from the monolithic entry function for plan 06 M1.S2. It recognizes `Button`, `IconButton`, `FloatingActionButton`, and `ButtonBase` by descriptor id or role, then owns the transient button interaction flags:

- `Focus` writes `state.flags.focused`.
- `Hover` writes `state.flags.hovered`.
- `Press` writes `state.flags.pressed`.

Other button-family events fall back to the generic reducer. This preserves the existing `Commit { property, value }` path, including descriptor-based value validation and reference-source cleanup, instead of duplicating generic property mutation in the button module.

The Material foundation descriptors for `Button`, `IconButton`, and `FloatingActionButton` now expose `Focus`, `Hover`, `Press`, and `Commit`. `ButtonGroup` stays structural; child buttons own interaction state and commit routing.

`state_reducer/keyboard.rs` owns semantic keyboard actions exposed through `UiComponentEvent::KeyboardAction`. The event is intentionally action-based rather than physical-key based: host input code maps Enter/Space/Escape/arrow/Page-style keys into `Activate`, `Cancel`, `BeginEdit`, `Next`, `Previous`, `First`, `Last`, `Increment`, `Decrement`, `LargeIncrement`, or `LargeDecrement`; the reducer only mutates component state. The host mapping lives in `surface/input/keyboard_action.rs`, and `dispatch_keyboard_input(...)` tries this semantic component route before generic arrow-key focus navigation, legacy button commit, or legacy popup dismissal. It only handles the event when the focused node has a binding that explicitly targets the `KeyboardAction` token, so ordinary nodes keep the existing navigation and default-action behavior. Focused `TreeView`/`MaterialTreeView`/`FolderTree` targets now use a target-aware physical key mapping: ArrowRight emits `Increment` for expand, ArrowLeft emits `Decrement` for collapse, F2 emits `BeginEdit` for inline rename, and ArrowUp/ArrowDown keep the collection `Previous`/`Next` semantics. The same keyboard host path also exposes `UiComponentEvent::KeyboardText` for printable component text, currently used by menu typeahead: it requires an explicit `KeyboardText` binding, accepts pressed/repeated printable `UiKeyboardInputEvent.text`, permits Shift, rejects Control/Alt/Super and control/whitespace-only payloads, reuses `widget_interaction_enabled(...)` so disabled nodes or disabled ancestors cannot emit component text, and runs before generic navigation fallbacks. Menu/MenuList roving focus text search, retained search-bar filtering, and typeahead expiry state now live in `state_reducer/keyboard/menu.rs`, while the parent keyboard reducer keeps shared action dispatch, indexed selection, indexed collection, numeric, and text-input orchestration. `UiComponentEvent::TypeaheadExpired` is the timer-facing menu expiry semantic event: descriptors and default interaction token mapping can advertise it, the reducer records only the expired marker while leaving buffer clearing to the next printable text event, and `UiInputManager` now schedules plus dispatches it through synthetic `UiInputEvent::TypeaheadTimer` on `tick(...)`. The first reducer slices cover:

- `Activate` for button-family controls, checked controls, radio, popup controls, and multiple-selection `ToggleButtonGroup` focused-option toggles.
- `Cancel` for popup-capable controls, clearing retained popup and transient press/drag flags.
- `Next`/`Previous`/`First`/`Last` for indexed keyboard-selection controls. `Tabs` write `focused_index` and, when `selection_follows_focus`/`selectionFollowsFocus` is true, `selected_index`, `value`, and `value_text`. `RadioGroup` defaults to selection-following-focus and also keeps `group_value` aligned. `RadioGroup` and `ToggleButtonGroup` skip options listed in `disabled_options` or disabled descriptor option metadata. `ToggleButtonGroup` uses the same indexed focus path, but only commits selection when opted in and not in multiple-selection mode; multiple mode keeps movement focus-only, then `Activate` toggles the current focused option in the retained `value` array without changing `selected_index`.
- `Next`/`Previous`/`First`/`Last` for indexed collection controls. `ListView`, `TreeView`, `Table`, MUI X `MaterialTreeView`, and `DataGrid` derive their ordered keyboard entries from `nodes`, `rows`, `items`, or `options`, write `focused_index`, skip disabled entries, wrap by default, and only commit `selected_index`/`value` when `selection_follows_focus` is explicitly enabled. TreeView expand/collapse, selection, inline rename, and top-level drag reorder now use the tree family/default-interaction path: focused tree targets map physical ArrowRight/ArrowLeft/F2 to `Increment`/`Decrement`/`BeginEdit`, `state_reducer/tree_view.rs` mutates the focused node id in the expanded list, `SelectOption` updates `selected_items`/`selectedItems` plus `selection_anchor_index` for multi/range selection, and `BeginEdit`/`Cancel`/`Commit` manage retained rename state plus commit payload. Table/DataGrid sort metadata and column-width metadata now use `state_reducer/table.rs`; Table/DataGrid virtual-window state uses `state_reducer/windowing.rs` through `SetVisibleRange` plus the surface wheel route. Cross-parent TreeView reparent and virtualized drag coupling remain later tree/table family slices.
- `Next`/`Previous`/`First`/`Last` for indexed keyboard-focus menu controls. `Menu`, `MenuList`, `PopupMenu`, `MenuPopup`, `ContextMenu`, `ContextActionMenu`, and `DropdownPopup` write `focused_index` without changing `selected_index`, `selected_options`, `value`, or `state.flags.selected`; they wrap by default, honor `disableListWrap`, skip `disabled_options` and disabled descriptor option metadata, and allow disabled focus only when `disabledItemsFocusable` is true.
- `KeyboardText` focus search for indexed menu controls. The same menu-like descriptor set derives searchable text from option `label`, `text`, `title`, `value_text`, `value`, or `id`. Single-character payloads preserve first-letter cycling; multi-character payloads are normalized to a case-insensitive prefix. Search starts after the current `focused_index`, wraps unless `disableListWrap` is true, skips disabled options unless `disabledItemsFocusable` is true, and updates only `focused_index`. The same reducer now maintains retained typeahead state: `typeahead_buffer` accumulates successive single-character printable events, repeated identical characters collapse back to one-character cycling, non-expired prefixes prefer the current item when it still matches, and `typeahead_buffer_expired = true` causes the next printable event to start a fresh buffer while clearing the expired flag. `TypeaheadExpired` is the semantic event that sets that expired marker without destroying the previous buffer.
- `ValueChanged { property: "search_query" }` filtering for indexed menu controls. `Menu` and `MenuList` now retain `search_query`, `filtered_option_ids`, `filter_no_results`, `allow_search`, and `search_bar_enabled_on_item_count`. A query update writes the query through the generic value validator, then the menu reducer derives visible option ids by case-insensitive substring matching over option text/id metadata, writes `filter_no_results` for non-empty no-match queries, moves `focused_index` to the first visible focusable result, and treats non-matching ids as hidden for subsequent menu focus navigation. Nested submenu metadata under `children`, `items`, `options`, `submenu`, `sub_menu`, or `subMenu` participates in the search; a descendant match keeps its ancestor path in `filtered_option_ids` and focuses the root row that can open the matching submenu. Disabled matches remain visible in `filtered_option_ids` but stay unfocused unless `disabledItemsFocusable` is true. The same menu reducer now owns a retained submenu state baseline: `hovered_option_id` arms `submenu_pending_option_id` when the hovered option has children, `submenu_hover_ready = true` promotes that pending option to `submenu_open_option_id`, and `submenu_focus_scope`/`submenu_active_parent_index` record whether keyboard focus is inside the submenu loop. `KeyboardAction::Activate` opens the currently focused submenu option before falling back to generic popup activation, and `Cancel` closes the active submenu loop before closing the main popup. `UiInputManager` now also reads `submenu_hover_delay_ms` from menu-like component shells after delivered `hovered_option_id`, dispatches synthetic `SubmenuHoverTimer` input on `tick(...)`, and the surface default action emits `ValueChanged { property: "submenu_hover_ready", value: true }` for still-valid child-bearing targets. Empty hover values or targets without submenu hover support clear/drop the deadline; popup anchor placement and broader outside-click execution evidence remain later popup/menu slices.
- `CommandPalette` query and command selection. `state_reducer/command_palette.rs` owns `query`, `commands`, `filtered_commands`, `disabled_commands`, `selected_command_id`, `focused_index`, `command_source`, and `committed_command_id` for the editor command overlay. `ValueChanged` on command/query/source state recomputes `filtered_commands` from string or map command entries, matching id/label/source/shortcut/category/keywords and filtering by `command_source` when present. `KeyboardText` appends printable text into `query`, navigation moves through the filtered command ids while skipping disabled commands, `SelectOption` rejects disabled commands without mutating the previous selection, and `Commit` records `committed_command_id` before closing through the descriptor-aware overlay reducer.
- `KeyboardText` insertion for text-input controls. `TextField`, `Input`, `InputBase`, `FilledInput`, `OutlinedInput`, `TextareaAutosize`, `SearchField`, `FieldEditor`, and `SourceEditor` drop control characters, ignore whitespace-only payloads, honor descriptor/state `readOnly` aliases, set focus, and route printable text through the shared `apply_text_edit_action(..., Insert)` helper. Descriptors expose `caret_offset`, `selection_anchor`, `selection_focus`, composition mirror props, `required`, `min_length`, `max_length`, `validation_timing`, `validation_message`, `validation_dirty`, and `validation_touched`; when edit-state props are absent the reducer defaults to end-of-text append, and when an explicit selection exists the printable payload replaces that selection and collapses the caret. MUI `Input` family values still mirror between `value_text` and `value` when both props exist. `state_reducer/text_input.rs` now owns the text-input branch so the main keyboard reducer stays below the module size warning threshold; it defers validation during `KeyboardText`/`ValueChanged` for `validation_timing = "commit"` or `"blur"`, validates on `Commit` or focus loss respectively, validates live for `"change"`, and reflects the result through `UiValidationState`, `validation_level`, and `validation_message`. Platform candidate-window validation, real Chinese input, and full multiline/autosize validation remain later text-edit chain work.
- `Increment`/`Decrement`/`LargeIncrement`/`LargeDecrement` for numeric controls through the existing numeric step/clamp path. Range sliders default to the upper `value` thumb for compatibility, but `focused_thumb`/`active_thumb`/thumb-index metadata can target the lower `range_min` thumb, and the shared numeric clamp still preserves `range_min <= value`.

The Material descriptors for `Button`, `IconButton`, `FloatingActionButton`, `ButtonBase`, `NumberField`, `Checkbox`, `Radio`, `RadioGroup`, `Switch`, `Slider`, `RangeSlider`, `ToggleButton`, `ToggleButtonGroup`, `Tabs`, `Tab`, `Menu`, `MenuList`, `ContextMenu`, `Select`, `Dropdown`, `DropdownPopup`, `Autocomplete`, `ListView`, `TreeView`, `Table`, MUI X `MaterialTreeView`, `DataGrid`, `Dialog`, and `ConfirmDialog` now advertise `KeyboardAction`; `Menu`, `MenuList`, `ContextMenu`, `DropdownPopup`, `TextField`, `Input`, `InputBase`, `FilledInput`, `OutlinedInput`, `TextareaAutosize`, `SearchField`, `FieldEditor`, `SourceEditor`, and `CommandPalette` advertise `KeyboardText`. `TreeView` and `MaterialTreeView` also declare retained rename state (`editing`, editing node id/text/index, renamed node id/text, and committed flag) using snake_case for generic TreeView and camelCase aliases for MUI X. `Menu`, `MenuList`, `ContextMenu`, and `DropdownPopup` also carry `typeahead_buffer`, `typeahead_buffer_expired`, `typeahead_timeout_ms`, `TypeaheadExpired`, and submenu timing props; `Menu` and `MenuList` additionally carry retained search filtering props. The reducer owns buffer mutation, expiry marker mutation, recursive search-query filtering for the base menu list family, no-results state, focus reconciliation, pending/open submenu promotion, keyboard submenu close-before-popup behavior, and Dialog/ConfirmDialog Escape/explicit-action state mutation, while the input manager owns host scheduling/dispatch of timed typeahead expiry and submenu hover-ready events for menu-like component shells. Open nodes whose resolved widget behavior is `Popup` now participate in the surface focus-loop contract, so retained `popup_open` changes can autofocus the first popup descendant, trap Tab/Shift+Tab, redirect outside programmatic focus unless enforcement is disabled, and restore the previous focus on close. IME cancel/commit now reaches the shared editable-text route for the MUI TextField coverage slice, retained IME context now reports soft-wrap-aware cursor/composition rects for `wrap`/`multiline` nodes, TextField render extraction now injects composition metadata into `UiResolvedTextLayout` preedit spans, and TextInput validation timing now has a reducer-owned commit/blur/change policy. `RangeSlider` also declares `disable_swap`, with surface pointer dispatch owning the MUI-style no-swap/swap policy while the reducer-owned value/percent mirror remains the canonical retained value synchronizer. Platform candidate-window validation, broader popup/outside-click execution evidence, and deeper tree/table behavior remain later family slices.

`state_reducer/command_palette.rs` owns editor command-palette filtering separately from menu typeahead. Command entries can be authored as maps or compact strings, and the reducer normalizes ids, labels, source tags, shortcuts, categories, keywords, and disabled flags before deriving `filtered_commands`. It intentionally leaves disabled matches visible so the overlay can explain unavailable commands, but roving focus and commit skip or reject them. This module closes the popup by calling the shared overlay reducer after a successful command commit, keeping open-state mirroring in the overlay owner while preserving command-specific validation in the command-palette owner.

`state_reducer/interaction.rs` owns generic retained interaction flags shared by non-button rows, drag targets, and future composed controls: focus, hover, press, drag begin/end, drop hover, and active drag target.

`state_reducer/disclosure.rs` owns the retained disclosure flag used by `ToggleExpanded`; it updates both `state.flags.expanded` and the `expanded` value property so selector state and data binding stay aligned.

`state_reducer/selection.rs` owns the existing `SelectOption` behavior. Moving this family out of the entry file is a structural split: single-select, multi-select, flags, disabled-option rejection, stale-value conversion, and `state.flags.selected` semantics are unchanged.

`state_reducer/collection.rs` owns the existing ArrayField/MapField mutation family: add/set/remove/move array elements, add/set/rename/remove map entries, row-level validation errors, and reference-source cleanup for replaced collection values. Moving this family reduced the dispatcher file to a thin routing layer for collection events while keeping existing `ArrayIndexOutOfBounds`, `DuplicateMapKey`, and `MissingMapKey` behavior unchanged.

`state_reducer/numeric.rs` owns numeric drag math for `DragDelta` and `LargeDragDelta`. It validates that the target property is numeric, reads the current/default value, applies either `step` or `large_step`, clamps through the descriptor/state `min` and `max` settings, and writes the normalized `Int` or `Float` value through the shared value route so reference-source cleanup and component-specific mirrors remain consistent.

`state_reducer/slider.rs` owns RangeSlider numeric mirror behavior. When `value` or `range_min` changes, it refreshes `value_percent` or `range_min_percent` from the current `min..max` range; when `value_percent` or `range_min_percent` changes, it computes the corresponding thumb value, clamps it against the other thumb, and normalizes the percent mirror back to the clamped value. This keeps keyboard, drag, commit, and future track-percent writes aligned with the renderer, which reads the percent fields first.

`state_reducer/overlay.rs` owns the popup flag, pointer-anchor behavior, and Dialog/ConfirmDialog action reducer used by selection popups, context menus, and modal feedback surfaces. `OpenPopup` sets `state.flags.popup_open` and mirrors the accepted open state into descriptor-backed `popup_open`, `popupOpen`, or `open` values; `ClosePopup` performs the inverse unless a `ConfirmDialog` requires an explicit action. `OpenPopupAt` also records `popup_anchor_x` and `popup_anchor_y` through the shared value path so stale reference metadata is cleared if those property names were ever reused. `KeyboardAction::Cancel` closes a normal `Dialog` unless `disable_escape_key_down` is true, but it leaves an explicit-action `ConfirmDialog` open. `Commit` for dialog controls records `dialog_action_id`, derives and writes `confirmed` when that state exists, respects disabled confirm actions, and then closes through the same unchecked overlay path. Surface focus handling observes the accepted `open`/`popup_open` mutation and owns the overlay focus-loop side effects separately from this reducer, while render extraction consumes anchor/placement/offset metadata for dropdown and context-menu popup geometry. This keeps state mutation, focus restoration, and popup placement in their existing runtime owners.

`state_reducer/reference.rs` owns the retained reference field behavior: accepted asset drops write `UiValue::AssetRef`, accepted scene instance/object drops write `UiValue::InstanceRef`, optional drag source metadata is retained per property, sourceless accepted drops clear stale source metadata, `ClearReference` writes `UiValue::Null`, and locate/open actions validate that a non-empty reference exists. Rejected drops still leave the previous value and source metadata untouched while setting validation feedback.

`state_reducer/windowing.rs` owns virtualized visible-range and page-window math. `SetVisibleRange` derives canonical `total_count`, viewport bounds, requested overscan bounds, and scroll offsets from both Zircon and MUI/react-window alias props. `SetPage` clamps invalid page sizes and out-of-range page indices, then stores `page_size`, `page_count`, `page_index`, `page_start`, `page_end`, and `empty`.

`state_reducer/text_input.rs` owns the component-level text-input value and validation policy. It shares the existing editable-text insertion helper for printable `KeyboardText`, mirrors MUI `value_text`/`value` where both props exist, keeps `query` as the primary property for search-backed controls, and applies declarative text validation without rejecting a type-correct string value. `validation_timing = "commit"` clears stale errors while editing and validates on `Commit`; `"blur"` validates on focus loss after marking the field touched; `"change"` validates live after each `KeyboardText` or `ValueChanged` event.

`state_reducer/tree_view.rs` owns the TreeView expanded-node, selection, and inline rename reducer. It treats `TreeView`, `MaterialTreeView`, and `FolderTree` as tree containers, flattens ordered node ids from `nodes`, `items`, or `options`, and applies semantic `KeyboardAction::Increment`/`Decrement` plus `ToggleExpanded` to the currently focused node. `surface/input/keyboard.rs` now recognizes focused tree targets by component id or tree role metadata, so physical ArrowRight/ArrowLeft route into this reducer as expand/collapse before generic directional focus navigation can run, and F2 routes to `KeyboardAction::BeginEdit`. Generic TreeView state writes `expanded_items`; MUI X state writes controlled `expandedItems` while seeding from `defaultExpandedItems` when no controlled list exists. `SelectOption` updates `selected_items` or MUI `selectedItems`, derives multi-select from `multi_select`/`multiSelect`/`checkboxSelection`, preserves a `selection_anchor_index` during range selection, writes `focused_index`/`selected_index`, and rejects disabled tree nodes without mutating selection. Range selection currently replaces the prior selected-id list with the inclusive anchor-to-target range, skipping disabled nodes in the range. `BeginEdit` records the focused node id, label text, and index as retained editing state when `editable` is true; `Cancel` clears that editing state before generic popup cancellation; `Commit { property = editing_text }` emits a retained rename payload through `renamed_node_id`, `renamed_text`, and `rename_committed` before clearing the active edit fields. The boolean `expanded` value and `state.flags.expanded` remain a summary of whether any node id is expanded, so existing disclosure-style state consumers do not become the tree source of truth.

`state_reducer/table.rs` owns the Table/DataGrid retained sort and column-width metadata baseline. It recognizes generic `Table` and MUI `DataGrid` descriptors, intercepts `ValueChanged` for `sort_column`/`sortField`/`sort_field`, `sort_direction`/`sortDirection`, and `column_width`/`columnWidth`, then returns to the generic reducer for unrelated value updates. ## Selection Semantics

`apply_selection(...)` resolves selection mode from the component descriptor and current state:

- A property whose descriptor declares `UiValueKind::Flags` is a flag set and stores `UiValue::Flags(Vec<String>)`.
- A component whose `multiple` setting is true stores selected values in `UiValue::Array`.
- Every other selection is single-select and stores either `UiValue::Enum(option_id)` or `UiValue::Null`.

The mode decision is made before inspecting any stale value currently stored on the property. This matters because old state, partially migrated data, or previous bugs can leave a single-select control with `UiValue::Flags` or `UiValue::Array`. A single-select event must not preserve that stale container and append into it. It must replace the value with the one selected enum, or clear it to null when the option is unselected.

## Stale Value Conversion

For flag properties, `selection_flags_value(...)` removes the previous value and converts known option-shaped values into a clean `Vec<String>`. Existing `Flags` values are preserved, arrays keep enum/string entries, and a non-empty enum/string becomes a one-item flag vector. Other values normalize to an empty flag list.

For multi-select properties, `selection_array_value_mut(...)` keeps the existing array path and converts a previous scalar enum/string into a one-item array before adding or removing the requested option.

For single-select properties, no previous container is reused. Selecting an option writes `UiValue::Enum(option_id)`. Unselecting writes `UiValue::Null`. This keeps the public invariant simple: a single-select value is unique or absent, even when the previous state was malformed.

`state.flags.selected` is still updated from the event's selected flag after the value mutation. That flag reflects the most recent event outcome; it is not the source of truth for the selected option list.
