# Runtime UI Text

## Purpose

Runtime UI text owns the shared layout, edit, hit-test, and shaping boundary used by render extraction, TextInput behavior, accessibility text geometry, and future SDF/native text backends.

The active measurement path now uses the shared runtime text service in `graphics/text/layout`, which consumes `graphics/text/shaping` shaped runs. UI text still owns source-run wrapping, rich-run ranges, low-fidelity bidirectional visual order, ellipsis construction, caret/selection geometry, and hit testing, but width, line-height, baseline, cache buckets, hit-test grapheme widths, and resolved-line glyph advances come from the shared shaping/metric owner instead of a fixed equal-width estimate.

## Shaper Boundary

`UiTextShapeRequest` carries the source text, resolved style, layout frame, and optional clip frame. `UiTextShaper` provides two operations:

- `shape_text(...)` returns `UiResolvedTextLayout`, the shared geometry DTO consumed by render extract and hit testing.
- `measure_text(...)` returns `UiSize`, the same measurement used by layout callbacks.

`UiSharedTextShaper` is the current default implementation. It delegates UI line organization to `layout_engine.rs`, while `layout_engine.rs` delegates measurement to `graphics/text/layout/measure.rs`; that measurement owner now derives width and per-grapheme advances from `graphics/text/shaping::shape_horizontal_line(...)` and the neutral `ShapedGlyphRun` contract. The shaping owner also projects UAX#14 break opportunities into cluster flags, and Word wrapping now consumes the first LB-M2 layout owner function, `graphics/text/layout::line_break_chunks(...)`, so CJK text without spaces can wrap from shared cluster break data. `core/framework/render/mod.rs` re-exports neutral DTOs such as `ShapedGlyphRun` and `ShapedGlyphScript` for implementation leaves, but remains a DTO facade rather than a glyphon/cosmic-text API. `graphics/text/layout/kinsoku.rs` owns the first CJK line-start and line-end prohibition slices, including small kana `ゕゖヵヶ`, and marks protected chunks with `allow_glyph_fallback = false`; `layout_engine.rs` only follows that chunk metadata. Soft hyphen is also chunk metadata now: `graphics/text/layout/line_break/soft_hyphen.rs` strips U+00AD from visual chunk text, records the optional visible `-` suffix with the source soft-hyphen range, and leaves `layout_engine/candidate_line.rs` to append that suffix only when an actual width wrap pushes the next chunk to a new line. The same `allow_glyph_fallback` metadata lets ordinary overwide words fall back to grapheme wrapping while NBSP and ZWJ emoji glue groups overhang instead of being split; `graphics/text/layout/line_break/glyph_fallback.rs` owns the measured-width plus Unicode grapheme-count predicate behind that fallback decision. `graphics/text/layout/line_break/greedy.rs` owns the current-line plus next-chunk fit predicate used by Word and Glyph wrapping, so UI wrapping no longer rebuilds candidate strings or owns the line-fit epsilon itself. ASCII wrap-space edge trimming now comes from `graphics/text/layout/line_break/wrap_space.rs`, so `layout_engine/candidate_line.rs` owns only the UI-side `CandidateLine` text/run/source/visual range mutation after receiving shared offsets or byte counts. LB-M3 now keeps logical `start` / `end` and `justify` in `UiTextAlign`; `layout_engine/direction.rs` resolves `Auto` and external `Mixed` requests to a concrete first-strong base direction before placement, and render extraction/native/SDF batches carry `text_direction` so draw backends preserve the same semantics. `layout_engine/line_box.rs` owns measured/tab-aligned grapheme advances, Justify gating, logical Start/End x alignment, and the fallback text-advance minimum used by the root orchestrator. `graphics/text/layout/align.rs` owns justify advance distribution for word spaces and CJK inter-character gaps and now trims leading/trailing edge spaces before choosing opportunities; UI layout consumes it for non-final lines and SDF draw planning reuses the same helper for word-gap vertex placement. `graphics/text/layout/overflow.rs` owns end/start/middle and word-trim ellipsis grapheme selection; word-trim keeps only complete word boundaries, retreats half-word candidates, and emits only the ellipsis when the first word cannot fit whole. `layout_engine.rs` now applies that shared overflow owner to horizontally overwide visible lines as well as height-clipped lines, so no-wrap Ellipsis* text is resolved into the frame instead of remaining overwide. Ellipsized non-last lines also skip Justify expansion by checking `line.ellipsized`, preventing start/middle/end ellipsis results from being stretched back to paragraph width. `graphics/text/layout/tab.rs` owns the first tab stop advance expansion pass; measurement and UI layout pass measured grapheme advances plus resolved `tab_size`, then consume the returned tab-aware advances instead of implementing `\t` math in UI. `layout_engine.rs` now only orchestrates wrapping, overflow clipping/application, visual-order handoff, resolved-line assembly, and delegates shrink-to-fit plus clamp font-size effective-style resolution to `layout_engine/overflow_style.rs`, which derives font size/line height from shared measurement before wrapping. `UiTextOverflow::ClampFontSize` honors parser min/max bounds and never searches below the requested minimum. The current SH-M2 interim BiDi scaffold in `layout_engine/visual_order.rs` mirrors a small table of single-codepoint RTL punctuation while preserving source ranges. Full greedy paragraph line breaking, broader emoji/ZWJ glue policy, complete CJK kinsoku tables, kashida justify, broader tab/overflow/shrink/clamp interaction rules, full UAX#9 level/isolate resolution, backend-level mirroring, and vertical layout remain later LB-M2/LB-M3/LB-M4 work. Future richer shaping services must preserve the `UiResolvedTextLayout` contract before diverging into native or SDF raster/cache backends.

## Current Guarantees

`layout_text(...)` now routes through `UiSharedTextShaper`, while `measure_text_size(...)` routes through the same backend. Owner text render extraction and focused TextField text commands construct `UiTextLayoutRequest` values and call `resolve_text_layout(...)`, so render extraction consumes the same request-level source hash and optional preedit span model used by the text pipeline tests.

The existing `layout_engine` still handles grapheme cluster wrapping, rich text run splitting, ellipsis range preservation, and the low-fidelity BiDi scaffold. It asks `graphics/text/layout` for line width, line metrics, ellipsis fit, public measurement, one advance per visual grapheme, tab stop expansion, and UAX#14/kinsoku/soft-hyphen-aware line-break chunks for Word wrapping; those values now originate from `ShapedGlyphRun` rather than direct UI-side backend calls. `layout_engine.rs` does not own CJK punctuation, Arabic/RTL punctuation, Unicode standalone interrobang punctuation, Unicode double/interrobang punctuation, U+00AD, or `\t` spacing tables: it only skips glyph fallback when a shared `LineBreakChunk` says fallback is not allowed, appends the shared `break_suffix` when it actually wraps at that chunk, and delegates tab stop placement to `graphics/text/layout/tab.rs`. The shared kinsoku owner now covers first-pass closing/opening punctuation, fullwidth white parenthesis `｟`/`｠`, spacing voicing marks `゛`/`゜`, JLREQ hyphens `‐〜゠–`, JLREQ cl-08 pairs such as `……`, halfwidth forms, small ka/ke, Japanese non-starters, and CJK white bracket/quote variants such as `〗` and `〖`; UI tests prove those chunks overhang or move with following text without copying the table. ## Font Registry

`UiFontRegistry` is the UI-facing owner for font family registration before the real shaping backend lands. It records `FontAsset` sources, inferred or explicit family names, effective render-mode preference, and a fallback chain whose default values come from `graphics/text/font` instead of a UI-local hardcoded list. Asset registration now uses `FontAsset::effective_render_mode()` so legacy `render_mode`, `render_strategy.default_mode`, and `allow_native` / `allow_sdf` constraints are interpreted once at the asset boundary. Registered families and manifest `fallback_families` are merged into the UI fallback chain with empty entries filtered and existing families deduped case-insensitively. The registry deliberately stores neutral records instead of exposing a shaping library type. A later cosmic-text integration can populate its `FontSystem` from the shared runtime `FontDatabase` without changing the call sites that register editor/runtime font assets.

Screen-space UI native glyphon and SDF render paths now share that runtime database for project font assets. Native loading registers the font file once and injects the registered face into glyphon `FontSystem`; SDF bake resolves the same font asset to `FontFaceId` and constructs fontsdf faces from shared `Arc<[u8]>` bytes. The text system also loads system font faces into the same Zircon `FontFaceId`/family index during initialization, while keeping the third-party `fontdb::Source` hidden inside `graphics/text/font`.

The database owner now delegates source metadata projection to `graphics/text/font/descriptors.rs` and pure family/match scoring helpers to `graphics/text/font/matching.rs`. This keeps UI text code insulated from TTF/fontdb parsing details while preserving the same `FontDatabase` API for `UiFontRegistry`, native glyphon loading, and SDF bake/render paths.

## Layout Request And Cache

`UiTextLayoutRequest` wraps the existing `layout_text(...)` path with the extra information the editor UI plan needs: style key extraction, optional clip frame, source hashing, and an optional preedit span. `UiPreeditSpan` replaces a byte range in the temporary layout input only; it does not mutate the source text. This preserves the IME invariant that preedit text is visual state until commit. TextField render extraction now converts retained composition metadata into this span before shaping, so a command can keep its retained `text`/`editable.text` as the document value while the `UiResolvedTextLayout` line text shows the active preedit replacement. The input-method context is the exception: after `SetComposition`, editable state already contains the current preedit text, so IME cursor/composition geometry resolves `state.text` directly and does not call `with_preedit(...)` again.

The public retained/editor consumer boundary is `zircon_runtime::ui::surface::{layout_text, measure_text_size, measure_text_source_range_width}`. `measure_text_size(...)` delegates to this text owner while keeping `ui::text` internal, so editor retained-host components can measure button, status, and table labels through the same grapheme/tab/overflow-aware path used by runtime layout without importing private text modules. `measure_text_source_range_width(...)` exposes a shaped source-byte range width for editor/runtime consumers that need substring metrics without importing `graphics/text/layout`; it is intentionally kerning-included only until the shaping backend exposes true unkerned advances for `include_kerning=false`.
