# RHI UI Surface

## Current Physical Ownership

`zr_rhi` owns `UiSurfaceDescriptor`, `UiSurfaceDrawList`, `UiSurfacePresenter`, the native surface
target and all backend-neutral UI surface data. `zr_rhi_wgpu` is the single concrete WGPU owner.
The Runtime facade function `zircon_runtime::rhi::create_default_ui_surface_presenter(...)` is the
only backend-selection seam exposed to app/editor code; neither Editor nor the neutral crate names
or constructs `WgpuUiSurfacePresenter`. The former Runtime `rhi_wgpu` module was deleted rather than
retained as a private shim.

`zircon_runtime::rhi` is the runtime-owned contract for presenting retained editor UI without exposing raw `wgpu` or a concrete backend provider to `zircon_editor`. The editor converts `ChromeCommandStream` into `UiSurfaceDrawList`; runtime owns the surface descriptor, native target extraction, concrete presenter factory, surface resize, texture upload, draw execution, and present lifecycle.

`UiSurfaceDrawList` carries the surface size, optional damage, ordered commands, and an optional producer-owned generation. The command vocabulary is backend-neutral: quads, borders, text runs, images, and clips. Quad and border commands retain `corner_radius` so editor Material-style controls do not lose rounded geometry when the command stream crosses from the retained host into runtime RHI. Image payloads can include RGBA bytes and upload byte counts, so the GPU presenter can update viewport/image textures without asking the editor to render a full CPU frame. Their resource identity is always the exact pair `(resource_key, resource_generation)`: compaction may move bytes to a draw-list resource table, but it must retain simultaneous generations of one key. Only commands with the same pair may share an image draw or upload source; resident checks, WGPU bind-group lookup, cache admission, and eviction use that same pair. The WGPU cache remains bounded by both entry count and byte size. Legacy `UiSurfaceDrawList::new(...)` leaves the generation unset and is deliberately never cacheable. Producers with a stable complete command payload use `UiSurfaceDrawList::with_generation(...)` and must advance that generation whenever command content or payload changes.

`UiSurfacePresenter` is the neutral presenter trait. Native implementations must resize, present a draw list, and expose the last present stats. The stats are intentionally small and profiling-facing: surface size, actual GPU batch draw calls, actual native render-pass count, retained-cache raw-copy bytes, visible command count and dynamic payload bytes, visible draw item count, compiled solid/image vertex counts, image upload bytes, image count, clip count, batch layer/dependency/merge/overlap-candidate counts, compiled-plan build/hit counts, vertex-buffer creates/upload bytes, text shapes, text-renderer builds/cache hits, and presented frame count. `UiSurfaceDrawList::stats()` still provides the backend-neutral visibility and upload baseline; the WGPU presenter replaces `draw_calls`, `render_pass_count`, and `retained_cache_copy_bytes` with work actually encoded after culling and resource resolution, while the batch fields retain the compiled-plan topology.

The owned retained-host path uses `UiSurfaceDrawList::with_compact_styles(...)` or `with_generation_and_compact_styles(...)`. These constructors intern compatible quad, border, and text state into a draw-list-owned `UiSurfaceStyle` table and leave each ordered command with a `UiSurfaceStyleHandle` plus only its dynamic payload. `resolved_kind(...)` is the single compatibility view consumed by statistics, WGPU geometry, and text preparation. `new(...)` and `with_generation(...)` retain the inline command vocabulary for legacy callers; consumers must not branch on storage form when resolved paint behavior is required. Visible payload statistics count an interned font family once per visible handle and publish the visible compact-style count.

The WGPU presenter compiles ordinary quads and non-rounded border leaves into 32-byte `SolidInstance` records. Each solid draw carries an explicit `instance_start..instance_end` range and the vertex shader expands one instance into six triangle vertices through `vertex_index`; therefore repeated guides, ticks, and rows avoid six retained/uploaded `SolidVertex` records per primitive. Rounded rectangles, rounded borders, and clipped tessellation continue through the existing vertex range so corner and clip semantics remain unchanged. Submitted and compiled instance counts are reported alongside vertex invocations and upload bytes.

`UiSurfaceDescriptor::from_winit_window(...)` is the editor-facing native-window conversion point when `platform-winit` is enabled. It translates a host `winit` window into the neutral `RenderNativeSurfaceTarget` and surface size without requiring the editor to name `wgpu` or `rhi_wgpu`. `create_default_ui_surface_presenter(...)` is the runtime-owned factory that selects the current concrete UI surface provider and returns `Box<dyn UiSurfacePresenter>`. This keeps backend selection inside `zircon_runtime::rhi` while preserving the existing `GpuChromePresenter<P: UiSurfacePresenter>` test seam.

`zr_rhi_wgpu::WgpuUiSurfacePresenter` has two modes:

- Native descriptors create a real wgpu instance, adapter, device, queue, Win32 surface, non-sRGB swapchain configuration, direct solid/image pipelines, glyphon text renderer, and retained UI target. Full frames render once to the retained target and copy raw texels to the acquired swapchain when that surface advertises `COPY_DST`; surfaces without that capability retain the direct-surface replay fallback.
- Headless descriptors keep the same contract and stats without creating a native surface. Unit tests use this mode so CI does not require a window.

The native WGPU path intentionally keeps UI color in non-sRGB byte space. `ChromeCommandStream` colors, embedded image bytes, softbuffer screenshots, and retained-host reference snapshots are already display-space byte RGBA values; rendering them through an sRGB target would apply hardware encoding and make the GPU capture visibly brighter than the software path. The presenter therefore requires `Bgra8Unorm` or `Rgba8Unorm` as the swapchain render target, uses `Rgba8Unorm` for uploaded image textures, clears the first direct surface pass to opaque black, and prefers `CompositeAlphaMode::Opaque` when the swapchain supports it. If a native surface only exposes sRGB formats, WGPU UI presenter initialization fails and the editor can use the existing fallback path instead of silently accepting color-space drift. `wgpu_ui_surface_uses_non_srgb_formats_for_byte_exact_editor_parity` and `wgpu_ui_surface_prefers_opaque_swapchain_alpha` pin that visual-parity contract.

The native renderer supports damage without relying on the swapchain's previous contents. `WgpuRetainedSurfaceCache` owns a non-sRGB texture matching the current swapchain format and size. A full frame renders the draw list to that retained target once; if the swapchain supports `COPY_DST`, a raw texture copy writes the same bytes to the acquired surface, otherwise the direct-surface replay fallback preserves the existing presentation contract. Damage frames require a matching initialized cache: a `COPY_DST` surface records only the damage-intersecting draw ops into the retained target, then copies the complete updated cache to the acquired surface. This is the single authoritative plan record because an acquired swapchain texture cannot be assumed to contain the prior frame. The no-copy fallback restores the cache into the current swapchain view and records the patch into both targets. Cache maintenance remains internal to the direct-present path; its image sampling restore is used only by that fallback.

`GpuChromePresenter` protects the cache preconditions at the editor boundary. The first native GPU present, any present without damage, and the first present after resize build a full command stream so runtime can seed the retained cache with complete UI contents. Once a successful present has initialized that cache, subsequent damaged host presents build patch command streams and carry `UiSurfaceDrawList::damage` through to runtime. Headless presenter stats remain damage-aware for tests, while native presenter `draw_calls`, `render_pass_count`, and `retained_cache_copy_bytes` report only actual encoded work: unavailable image textures, missing text batches, and culled draws do not increase any counter; raw cache copies increase only the copy-byte counter; a cache restore draw and pass exist only on the no-copy patch fallback.

`zr_rhi_wgpu::ui_surface::geometry` owns the draw-list geometry layer: stable `(z_index, command_index, sub_index)` ordering, quad/image vertices, rounded solid tessellation, rounded border rings, image UV trimming, square border expansion, and the shared effective command rectangle. Solid and image commands are clipped on the CPU before batching, so the renderer no longer needs per-primitive scissor calls for ordinary quad/image clipping. Rounded quads and borders produce larger solid vertex lists but still remain in the normal solid batch path; they do not trigger a software fallback or a separate material. `zr_rhi_wgpu::ui_surface::batching` turns those visible items into a partial-order draw plan: earlier items only constrain later items when their clipped rectangles intersect, independent items share a depth layer, and each layer groups solid geometry, same `(resource_key, resource_generation)` images, and text into as few draw ops as current materials allow. `zr_rhi_wgpu::ui_surface::pipeline` owns WGSL shader strings, solid/image pipeline creation, shared image samplers, and bind-group layout creation for direct swapchain rendering. `zr_rhi_wgpu::ui_surface::text` owns glyphon buffer preparation, style mapping, glyph atlas lifetime, and render-pass submission for text batches. Keeping these layers outside the presenter file keeps the wgpu presenter focused on resource lifetime, render passes, and surface presentation while making clip and batching parity directly unit-testable.

The Material shader keeps the alpha contract explicit. Solid and image fragment outputs pass through tint-ready helper functions and are premultiplied before the shared UI blend state, then blend directly into the non-sRGB swapchain target. Rounded fill and border shape still comes from CPU geometry today, but `ui_material.wgsl` keeps the rounded-SDF helper as the stable handoff point for future GPU-side rounded primitive work.

Text uses glyphon inside runtime. The editor provides text, frame, color, font size, line height, and style; runtime intersects the command frame, command clip, and surface bounds before preparing glyph buffers for the direct surface pass. Empty or whitespace-only text is omitted before shaping because it cannot emit visible glyphs. Image commands use cached runtime textures keyed by the exact `(resource_key, resource_generation)` pair. The compiled image projection retains one ordered source group per exact resource identity, so upload preparation visits only that small resource table and can reuse a stable generation without a second full command-list scan or per-frame resource de-duplication. The first usable source preserves the prior payload-selection behavior when an earlier command references a resident texture and a later command supplies its RGBA bytes. The runtime treats `resource_key` as the source identity and `resource_generation` as its content revision, so editor command producers must derive the key from the real asset identity or the RGBA content, never only from dimensions, and must advance the generation when that content changes. Atlas-backed UI images therefore use the atlas texture identity as `resource_key` and carry their subimage as `atlas_uv: Some(UiSurfaceImageUvRect)`. `atlas_uv: None` keeps the existing full-texture UV path; valid atlas UVs must be finite, normalized, and strictly ordered on both axes. WGPU geometry first computes local clipped-image UVs from the visible command rect, then composes those local values into the atlas rect. Invalid `Some` atlas UVs are skipped instead of silently sampling the wrong pixels. The wgpu presenter tracks the last present that touched each cached image identity and caps the cache with least-recently-used pruning, which prevents content-derived viewport keys from growing GPU memory without bound during continuous viewport updates. Overlapping solid, image, and text items keep the same visible order as the softbuffer command-stream executor because the batching planner adds depth dependencies only for intersecting rectangles in stable z/index order. Non-overlapping items are incomparable in that partial order and may be reordered within a layer to batch solid geometry, same-identity images, and text. Same-identity image batching is intentionally governed by that partial order rather than by an atlas-specific branch: disjoint images sharing `(resource_key, resource_generation) = ("atlas://editor/icons", 4)` collapse to one image draw in one layer, while a different generation is a distinct draw/upload/cache entry; overlapping same-identity images split into dependency layers, an overlap chain through a middle item preserves painter order, and independent same-identity images around an overlapping solid still share the independent image layer. `gpu_draw_calls` reports the actual WGPU draw commands encoded after culling and resource resolution; `gpu_solid_vertices` and `gpu_image_vertices` report the unique compiled payloads used by those commands; `gpu_visible_command_payload_bytes` records the visible dynamic command payload without cloning it; native image preparation exposes `gpu_image_upload_writes`, `gpu_image_cache_key_allocations`, and `gpu_image_cache_prune_visits` alongside upload bytes so stable generations can prove image-cache work is zero; `gpu_visible_commands`, `gpu_visible_draw_items`, `gpu_batch_layers`, `gpu_batch_dependencies`, `gpu_batch_merges`, and `gpu_overlap_candidates` expose the compiled command-stream topology and spatial-planner work that made those submissions possible.

Milestone 5 keeps atlas batching in the normal image path. Retained-host atlas producers resolve generated editor SpriteAtlas manifests into an atlas texture `resource_key`, full atlas dimensions/RGBA, a content generation, and per-entry `atlas_uv`; runtime still sees an ordinary image command keyed by that exact atlas identity. Draw-list stats and WGPU upload preparation de-duplicate visible image upload bytes by `(resource_key, resource_generation)`, so two visible atlas subimages from the same atlas generation count and upload the shared atlas texture once while a replacement generation is prepared independently. The ideal profile term for image batching is therefore the exact image-identity count per independent layer rather than source-image count.

The current implementation intentionally keeps platform support narrow: `RenderNativeSurfaceTarget::Win32` maps to wgpu raw Win32 handles on Windows. Other platforms must use headless/softbuffer fallback until native targets are added to the runtime contract.

## Current Performance Boundary

PERF-MVP-225 replaces unconditional pairwise overlap discovery with an adaptive-axis interval index. The planner still computes the exact painter-order dependency depth: interval lookup only prunes rectangles that cannot overlap on the selected axis, and the full effective rectangles remain the final dependency test. All-overlap scenes therefore retain the same dependency count; sparse rows and columns avoid N(N-1)/2 checks. The index stores nodes and its start/end crossing order in three preallocated contiguous vectors rather than allocating a box and two vectors per node. Layer materialization likewise sorts one item-index vector by dependency depth and painter order instead of allocating one vector per layer. The 1/100/1,000/10,000 row/column matrix locks sparse candidates to at most N, exact zero dependencies, one instanced draw, N instances, and linear pooled index storage.

Normal FullRedraw borrows the input draw list and does not clone text/image/RGBA payloads. A damage-scoped cache bootstrap still renders the complete scene by passing `None` as the independent render-damage value; the source draw list remains intact. For a generation-tagged draw list, WGPU retains one complete compiled batch projection, solid/image GPU buffers, glyphon text renderer batches, and each image resource's uploaded revision. A later damage projection with the same generation reuses those facts and applies a clamped GPU scissor to the retained-cache write; when the surface supports `COPY_DST`, the complete updated cache is then copied to the swapchain texture so the plan is recorded only once. Surfaces without `COPY_DST` allocate no retained cache and issue one direct, complete redraw to the swapchain; damage input is intentionally ignored for that frame because a patch cannot be restored correctly. Draw batches whose full-projection bounds cannot intersect the scissor are skipped entirely, without rebuilding clipped geometry or reshaping text. Each native submit encloses those UI commands in the `zircon::UI` RenderDoc debug group. `visible_command_count` remains the damaged-list visibility metric, while `visible_draw_item_count` reports the cached complete GPU projection submitted through that scissor. Stable full and damage frames therefore report zero plan builds, vertex-buffer creates/upload bytes, text shapes, text-renderer builds, and native image-upload bytes. Invalidated and legacy inputs remain conservative: they rebuild their current projection, but reuse retained buffer capacity when it suffices and only grow geometrically when required. Render17 still owns scale validation and RenderDoc/Softbuffer parity for the shared projection path through `render/17/failure-2026-07-18-ui-surface-pairwise-overlap-batching.md`.
