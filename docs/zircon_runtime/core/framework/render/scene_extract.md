# Scene Mesh Extract Contract

`scene_extract.rs` is the renderer-neutral scene snapshot contract. It can describe meshes, lights, particles, preview environment, and virtual geometry data, but it must not carry WGPU handles or renderer-owned cache entries.

## Mesh Snapshot

`RenderMeshSnapshot` is the mesh row consumed by the graphics scene renderer. It contains the stable scene entity id, transform, model handle, optional direct mesh handle, material handle, optional LOD selection, morph weights, tint, mobility, static-state contract, and render layer mask.

Direct mesh snapshots use `mesh: Some(...)` and bypass model primitive expansion. Model snapshots use `mesh: None` and let the renderer expand the prepared model into per-primitive draw slices.

## Stable GPUScene Identity

Plan 03 adds two renderer-neutral fields to every mesh snapshot:

- `stable_instance_key`: a packed key generated by `render_mesh_stable_instance_key(entity, primitive_ordinal)`. The lower 16 bits hold the primitive ordinal under the source entity, and the remaining high bits hold the entity id.
- `transform_revision`: a deterministic FNV-1a hash of translation, rotation, and scale float bit patterns.

`World::render_mesh_snapshots_for_camera` now fills both fields while expanding direct primitive bindings and model-backed snapshots. The key is stable across frames as long as the entity and primitive ordinal remain stable. `build_mesh_draws` consumes that same identity lineage by registering each expanded pending draw into `GpuScene` with the source entity plus draw ordinal, which gives the data side-channel a stable owner before the renderer starts replacing per-draw model uniforms with instance indices.

The revision is content-derived rather than tied to mutable ECS internals. That keeps the extract contract serializable and reproducible for tests while still letting the renderer detect transform changes for later incremental GPUScene uploads.

## Static State

`RenderMeshStaticState` is the extract-level contract used by the MD-M2 mesh draw command cache:

- `transform_static`: the scene/extract side asserts that the object is eligible for static command caching from a transform perspective.
- `geometry_revision`: a renderer-neutral revision lane for geometry identity.
- `material_revision`: a renderer-neutral revision lane for material and shader-visible binding identity.

The contract intentionally stays conservative. `has_authoritative_revisions()` only returns true when the transform is static and both revision lanes are nonzero. Command caching rejects snapshots without authoritative revisions instead of guessing.

World extraction currently seeds `transform_static` from `Mobility::Static`. The WGPU scene renderer then fills geometry/material revision signatures from prepared resource revisions exposed by `ResourceStreamer`. That keeps asset-revision knowledge in the resource layer while keeping the framework contract free of resource streamer internals.

## Cache Use

The static state is not itself a command cache key. The renderer combines it with per-expanded-draw identity:

- entity id from `RenderMeshSnapshot::node_id`
- draw ordinal assigned while expanding model primitives or raster draw slices
- render phase emitted by the mesh pass processor

The cache entry stores the last `RenderMeshStaticState` it was built from. A changed geometry revision, material revision, or loss of `transform_static` makes the lookup miss and rebuild only that command entry.

## Validation State

The MD-M2 cache tests cover matching-state reuse, material-revision invalidation, and rejection of dynamic, transparent, and indirect batches. The broader `cargo check -p zircon_runtime --lib --locked --jobs 1 --target-dir E:\cargo-targets\zircon-render-main-chain --message-format short --color never` validation passed on 2026-06-12 after the unrelated UI initializer and moved-value blockers in `zircon_runtime/src/ui/style.rs` and `zircon_runtime/src/ui/v2/style.rs` were corrected; it also passed again after the GPUScene stable key, transform revision fields, frame-path GPUScene sync, and stats propagation were added.
