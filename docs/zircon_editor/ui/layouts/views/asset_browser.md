# Asset Browser View Projection

This view projection builds the Asset Browser pane from `AssetWorkspaceSnapshot` into retained template nodes. It is intentionally split by ownership so content-mode work can continue from small components toward complex containers without growing `asset_browser.rs`.

`asset_browser.rs` is the assembly owner. It resolves snapshot text, selection state, table cell text, toggle state, active utility tabs, and then delegates mode-specific layout to sibling owners. It should stay a coordinator, not a place for new card, toolbar, or compact-layout algorithms.

`toolbar_layout.rs` owns the compact toolbar/search/quick-import composition. The current toolbar slice treats search, kind chips, view buttons, and Quick Import as one Slate-like compound row: 32 px toolbar frame, 30 px controls, 8/6/4 px gaps, search as the dominant flexible field, and Quick Import as a trailing input group. The import path field collapses below the regular-width breakpoint instead of forcing a second row, while the Import command remains visible after the view buttons.

`stack_layout.rs` owns the standard-height main-stack reclaim that follows toolbar compaction. It moves `AssetBrowserMainPanel` to the toolbar bottom plus a 6 px gap, stretches the sources/content/details surfaces down toward the utility panel, and keeps the root assembly file from accumulating per-panel y/height repair logic. This owner runs before `compact_layout.rs`; compact mode can then apply short-viewport source/details collapse and thumbnail/list switching on top of a normalized stack.

`compact_layout.rs` owns short-viewport pane adaptation: source/details collapse, table stack sizing, preview summary placement, utility collapse, and the table-vs-thumbnail content-mode switch. In thumbnail mode, the selected summary is now an inline inset `asset-preview` card that follows the visible thumbnail card rows and caps to a 360-460px width band at regular/wide sizes; narrow content can still use almost the available width. Table/List mode intentionally keeps the older full-width bottom summary.

`table_nodes.rs` owns compact table row text projection and row selection/focus stamping. Keeping this separate prevents the view assembly root from owning both list/table formatting and card-grid behavior.

`thumbnail_nodes.rs` owns thumbnail-mode node generation. It appends the grid panel and a bounded set of card, visual, info-band, selection-marker, name, name-continuation, type-badge, type-label, and status metadata nodes only when `AssetViewMode::Thumbnail` is active. Long tile names are split locally into `AssetBrowserThumbNameNN` and `AssetBrowserThumbNameContinuationNN` around separator or camel-case boundaries, while short names keep an empty continuation node. The primary name is a 9 px / 500 weight tile label; the continuation is an 8 px / 400 muted label; type/status metadata is 8 px muted text, so the tile name area has a stable small-control hierarchy instead of three equal-weight rows. Thumbnail cards now use the transparent `asset-thumbnail-card` surface as a frame-only tile shell: neither unselected nor selected cards paint a full panel fill, full-card focus ring, or card border by default. Selected cards also stay `focused=false`; selection identity belongs to the `asset-thumbnail-name-area` information band plus the 2 px marker node, while true keyboard focus remains a separate state. Thumbnail visual nodes now carry `component_role=asset-thumbnail-visual` and a `component_variant` derived from `ResourceKind`, such as `asset-texture`, `asset-material`, `asset-scene`, `asset-mesh`, `asset-shader`, `asset-ui-layout`, `asset-ui-widget`, or `asset-ui-style`. The UI layout/widget/style resource kinds intentionally have distinct semantic aliases instead of sharing the script icon. `thumbnail_layout.rs` owns thumbnail grid frame computation. It derives columns, card size, visual height, 52 px information-band, selection-marker, two-line title area, type-badge, type text, and status frames from the content panel frame, using padding, gaps, width-derived ratios, and type-text width estimates rather than screenshot absolute coordinates. Card height is derived from card width through a Slate-like tile ratio and then capped by available row height, so regular and wide panes preserve a stable `AssetTileItem` proportion while short panes still cap relatively. The thumbnail visual area is clamped to a 72-88 px band and is asserted to dominate the 52 px name area, matching UE's `ThumbnailAreaBackground` / `NameAreaBackground` split instead of rendering each asset as a squat label block. The name area uses a 12 px primary line, a 10 px continuation line, and moves the metadata row below the continuation when it exists, preserving bottom padding inside the band. The type/status row intentionally splits the old `Type | Ready` string into an `asset-type-badge` low-emphasis panel, an 8 px accent type label, and a muted status label. This keeps the grid adaptable at the same 900x620 M3 acceptance size, and the focused 420px test locks that cards wrap instead of staying as a screenshot-only one-row layout.

`summary_nodes.rs` and `summary_layout.rs` own the selected inline summary card title hierarchy and metadata row. The assembly root appends semantic summary nodes after thumbnail nodes, while the compact layout only delegates the card internals to `summary_layout.rs`. `summary_nodes.rs` reuses `thumbnail_nodes.rs::asset_display_name_lines` to split long selected display names into `AssetBrowserContentPreviewName` and muted `AssetBrowserContentPreviewNameContinuation`; `summary_layout.rs` collapses empty continuation height and otherwise moves the meta row below the second name line. In compact thumbnail mode, the legacy `AssetBrowserContentPreviewMeta` label is collapsed to zero and replaced with the same `asset-type-badge` language used by thumbnail cards, followed by a muted state label and a right-aligned revision label. This keeps the selected summary consistent with the card grid without adding more card-specific behavior to `asset_browser.rs` or `compact_layout.rs`.

The selected preview and detail preview visuals reuse the same `ResourceKind` mapping from `thumbnail_nodes.rs` instead of keeping a second icon table in the assembly root. The retained placeholder painter consumes the `asset-thumbnail-visual` role and resolves the semantic variant through `visual_assets/candidates/aliases.rs`, so visual placeholders use real SVG asset-type icons while still allowing future real thumbnail image resources to replace them. Typed thumbnail visuals now paint a recessed preview canvas first, then lightweight type-specific content marks, and then a 14 px semantic SVG icon inside a small top-right badge. The preview canvas border stays on the muted `separator_soft` role for normal and selected preview visuals; only an explicitly focused visual may use `focus_ring`. Type tint is reserved for content marks inside the preview canvas; the corner semantic icon plate uses `surface_inset` plus `separator_soft` so every resource tile does not look like it has a selected or focused badge outline. The generic `image` fallback remains a smaller 20 px single-tint placeholder so unknown assets do not look more important than typed project resources.
