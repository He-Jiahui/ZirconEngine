# Asset Browser View Projection

This view projection builds the Asset Browser pane from `AssetWorkspaceSnapshot` into retained template nodes. It is intentionally split by ownership so content-mode work can continue from small components toward complex containers without growing `asset_browser.rs`.

`asset_browser.rs` is the assembly owner. It resolves snapshot text, selection state, table cell text, toggle state, active utility tabs, and then delegates mode-specific layout to sibling owners. It should stay a coordinator, not a place for new card, toolbar, or compact-layout algorithms.

`toolbar_layout.rs` owns the compact toolbar/search/quick-import composition. The current toolbar slice treats search, kind chips, view buttons, and Quick Import as one Slate-like compound row: 32 px toolbar frame, 30 px controls, 8/6/4 px gaps, search as the dominant flexible field, and Quick Import as a trailing input group. At the 900 px acceptance width, filter chips and view buttons have priority over the optional import path field; the path field collapses below 1040 logical px instead of forcing a second row or crowding the filter/view group, while the Import command remains visible after the view buttons. `asset_browser.zui` provides the low z-index inset `AssetBrowserToolbarKindPrimaryRow` surface, but `toolbar_layout.rs` computes that group frame from the visible filter chips and view buttons, so the group bounds follow the actual controls rather than spanning the whole toolbar.

`stack_layout.rs` owns the standard-height main-stack reclaim that follows toolbar compaction. It moves `AssetBrowserMainPanel` to the toolbar bottom plus a 6 px gap, stretches the sources/content/details surfaces down toward the utility panel, and keeps the root assembly file from accumulating per-panel y/height repair logic. This owner runs before `compact_layout.rs`; compact mode can then apply short-viewport source/details collapse and thumbnail/list switching on top of a normalized stack.

`compact_layout.rs` owns short-viewport pane adaptation: source/details collapse, table stack sizing, utility collapse, and the table-vs-thumbnail content-mode switch. In thumbnail mode, it collapses the table/list nodes and lets the thumbnail grid reclaim the content height; selected feedback stays inside the tile name band and its left 2 px marker rather than drawing a second inline summary card. Table/List mode intentionally keeps the older full-width bottom summary.

The utility tab strip keeps its compact `compact_layout.rs` geometry, while `utility_tabs.rs` owns the local typography projection for the four authored utility-tab button nodes (`Preview`, `References`, `Metadata`, `Plugins`). After active-state stamping, all four buttons receive the readable 12 px UI tab font size; the active tab receives `font_weight = 600` and inactive tabs receive `font_weight = 400`. This keeps the view assembly root from collecting another typography rule and gives the retained button text path a concrete `font_weight` signal to convert into a strong UI text run. Font family is not selected here; it stays behind the global `EditorTypographyTokens -> HostTextPreferences -> fontdb` route so user preferences can replace the UI/code families without editing Asset Browser controls. `asset_browser_utility_tabs_use_compact_slate_tab_strip_geometry` locks the 22 px row, tab widths/gaps, locator alignment, 12 px font size, and selected/idle font weights. `table_nodes.rs` owns compact table row text projection and row selection/focus stamping. Keeping this separate prevents the view assembly root from owning both list/table formatting and card-grid behavior. List/Table selected rows intentionally do not set `focused=true`; selected resources use the row selected affordance, while keyboard focus remains a separate state for future navigation/focus-visible work. The table name projection preserves readable asset filenames instead of converting them into generic category aliases such as `Asset`, `Base`, or `Folder`. Short file-like names, including `workbench_page_chrome.zui` and `folder-open-outline.svg`, remain complete. Names that exceed the measured table-name width now use shared `name_compaction.rs` runtime text measurement to choose `prefix...tail.ext` truncation, so the extension remains visible and same-character-count narrow/wide labels are not forced through the same char-count budget.

`labels.rs` owns `ResourceKind` display text for the Asset Browser. It deliberately keeps four display contexts separate: 2-3 letter thumbnail dense badge codes such as `UI`, `STY`, `TEX`, `WDG`, `MAT`, `SCN`, `SHD`, and `PFB`; selected-summary readable labels such as `UI Layout` and `Material Graph`; compact table labels such as `Texture`; and full detail labels such as `UI Widget`.
