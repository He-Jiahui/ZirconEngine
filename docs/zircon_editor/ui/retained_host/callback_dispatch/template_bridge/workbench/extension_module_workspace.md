# Extension Module Workspace Evidence

## Purpose

The extension module workspace path records scoped native retained/Taffy evidence for individual More Editors surfaces without promoting the full 44-module extension set into the native-covered core module contract.

Each recorded surface stays under `WorkbenchExtension/*`, uses a split `.zui` workspace file, and routes through dedicated extension bindings, preview actions, navigation, and feedback. Preview action payloads use dotted functional paths such as `workbench.extension.level_variant.apply.invoke`; the `WorkbenchExtension/*` binding namespace and `WorkbenchExtension.<NativeId>.*` routes remain the event contract. The core `WorkbenchModule/*` binding file must remain free of extension actions.

Retained extension navigation is intentionally split by responsibility. `extension_module_navigation.rs` remains the query entry used by callback dispatch, `extension_module_navigation/specs.rs` owns the workspace-spec index, `specs/types.rs` owns the data shape and const constructors, and the concrete action/control maps live in `specs/gameplay_animation.rs`, `specs/gameplay_state.rs`, `specs/simulation_physics.rs`, `specs/online_sessions.rs`, `specs/runtime_state.rs`, `specs/render_asset_vfx.rs`, `specs/data_production.rs`, `specs/ui_diagnostics.rs`, `specs/ui_diagnostics/observability.rs`, and `specs/world_building.rs`. This keeps the retained route layer componentized as more More Editors workspaces are recorded.

The query entry builds one process-local action index from those static specs. Callback dispatch therefore resolves workspace, tab, row, command, field, and group routes with one hash lookup instead of rescanning all workspace/action slices. The specs remain the source of truth, first-match semantics are preserved for duplicate route fields, and validation checks representative routes plus index reuse.

Extension template binding registration follows the same boundary. `workbench_extension_module_template_bindings.rs` remains the installer entry consumed by the Workbench window template binding registry, `workbench_extension_module_template_bindings/types.rs` owns the binding spec shape, `install.rs` converts specs into `EditorUiBinding` records under `WorkbenchExtension`, and `gameplay_animation.rs`, `gameplay_state.rs`, `simulation_physics.rs`, `online_sessions.rs`, `runtime_state.rs`, `render_asset_vfx.rs`, `ui_diagnostics.rs`, `ui_diagnostics/observability.rs`, plus `world_building.rs` own the concrete click/change/submit binding tables. The authored ZUI binding events keep the `WorkbenchExtension/*` event namespace, while preview action payload ids use dotted functional paths such as `workbench.extension.world_state.validate.invoke`.

Retained extension feedback follows the same split. `extension_module_feedback.rs` remains the bridge entry that updates shared status controls, while `data_production.rs`, `gameplay_state.rs`, `simulation_physics.rs`, `online_sessions.rs`, `runtime_state.rs`, `ui_diagnostics.rs`, and `ui_diagnostics/observability.rs` own scoped output rows and status text for their functional families.

## Validation

`verify-native-extension-module-contract.mjs` is the source-level gate for this evidence. It checks that every extension event has a matching template binding, every binding resolves to a registered preview action, every preview action is consumed by a binding, preview action ids use dotted functional paths, opener controls live in the expected native-covered module workspace, and retained navigation/feedback mention the surfaced action ids.

`verify-web-native-handoff.mjs` then checks that the handoff matrix records the evidence while keeping the affected More Editors rows prototype-only.
