# Host Contract Paint Text

`paint_text.rs` is the retained-host text paint entry. It keeps the legacy import surface stable for chrome command replay, template render commands, and primitive text markers while moving concrete text drawing responsibilities into focused child modules.

## Draw Ownership

`paint_text/draw.rs` owns the text draw pipeline after entry normalization and the draw-order handoff to the focused clip, layout, recording, and glyph children.

`paint_text/draw/entry.rs` owns the public text draw entry chain, default font metrics, and default text-style selection before forwarding into the pipeline owner.

`paint_text/draw/clip_rect.rs` owns effective text-clip resolution plus frame-to-pixel clip conversion for draw calls.

`paint_text/draw/layout.rs` owns the retained-host bridge from runtime text layout to host glyph rasterization. It calls `zircon_runtime::ui::surface::layout_text` to compute the single-line displayed text, alignment frame, grapheme advances, overflow, and ellipsis projection with the runtime font family selected from `HostTextFontFace`. Fontdue is then used only for glyph indices, glyph bounds, and y placement on the selected host face. The final x positions are `RuntimeTextGlyph` values produced by projecting runtime grapheme advances back onto the fontdue glyphs, so measurement/projection and actual retained-host drawing do not fall back to separate advance rules. The 2026-07-03 spacing guard now has two gates: runtime total advance must stay close to the selected host face's natural run width, and each runtime grapheme advance must stay within the host face's local advance tolerance. If the total still matches but neighboring graphemes trade pixels, retained-host drawing falls back to natural `GlyphPosition.x` spacing for the selected host face instead of projecting jitter into tab labels. The shaped-position path has the same fail-closed local-advance gate: matching shaped glyph ids, visual ranges, and total width are not enough unless `shaped.x + shaped.offset_x` also preserves the selected host face's local advances, so compact labels with local origin borrowing fall back while tiny legal shaped offsets still survive.

`paint_text/draw/recording.rs` owns font-size and line-height clamping plus retained recording handoff. It converts the clipped pixel bounds back into a frame-space recording rectangle before forwarding the existing text/style payload to `HostRgbaFrame::record_text(...)`.

`paint_text/draw/glyphs.rs` owns glyph traversal, cached-raster lookup, per-row clip gating, and row dispatch.

`paint_text/draw/glyphs/row.rs` owns row/column clipping, supersampled alpha-mask or native-scale subpixel-mask coverage sampling, style-based emphasis offset, coverage-scaled alpha, and the final per-pixel dispatch into the blend owner. Alpha-mask glyphs still use arithmetic average coverage for normal UI pixels with the narrow high-sample floor only for true one-pixel strokes. Subpixel glyphs consume the native RGB coverage channels directly when raster scale is 1x, and only average channels when a fallback raster actually carries a higher scale. Strong UI text no longer receives a synthetic extra horizontal pass here; strong weight is represented by the selected font face from `paint_text/font.rs`.

The public boundary remains intentionally narrow: callers keep using `draw_text(...)`, `draw_text_with_size(...)`, or `draw_text_with_size_and_style(...)` through the root module, while the root file no longer owns layout or pixel loops and `draw.rs` no longer owns fontdue setup, retained recording rectangle construction, or glyph pixel loops directly.

## Clip Ownership

`paint_text/clip.rs` owns active paint-clip and explicit text-clip resolution. It intersects the frame clip with the call-site clip when both exist and returns `None` for disjoint clipping so the draw owner can stop before layout or raster work.

## Font And Raster Ownership

`paint_text/font.rs` owns retained-host font-face selection, lazy `fontdue::Font` construction, retained font bytes for swash rasterization, and the retained-host bridge to runtime text measurement. It no longer names a concrete product font as the normal UI policy. `HostTextPreferences` are projected from `EditorTypographyTokens`, whose defaults are logical families (`system-ui` for UI/strong UI and `monospace` for code). `fontdb` resolves those preferences to the current platform or user-selected face for host rasterization; embedded Fira assets remain only the last-resort fallback when a requested/system face cannot be loaded. `font_face_for_paint_style(...)` routes `UiTextRunPaintStyle::code` to the mono face first and routes non-code `strong` text to the UI strong face, so selected tab/button labels can request a strong UI run without becoming code/monospace text. Runtime-facing measurement and draw-list export now use `runtime_text_style_for_face(...)`, which writes `font_request_for_face(face).family` and the requested weight into `UiResolvedStyle`. The physical family selected by `fontdb` is not a component or runtime style input; it is a host implementation detail and test-only guard. Component width measurement goes through `measure_runtime_text_width(...)` or `measure_runtime_text_width_with_style(...)`, which set the requested runtime family and font weight before delegating to `zircon_runtime::ui::surface::measure_text_size(...)` so button labels, status chip values, and right-aligned table cells share the runtime text stack.

Asset Browser toolbar chips and utility tabs do not own concrete font choices. Their button content code only chooses text semantics (`UI`, `strong`, or `code` when a future component explicitly asks for code semantics) and label-slot padding. The concrete face remains globally switchable through typography preferences, matching the same path that will allow editor preferences to switch fonts, color themes, and style packs.

The 2026-07-02 appearance-preference hardening moved the startup owner for retained-host design tokens into `zircon_editor/src/ui/preferences.rs`. `retained_host/app.rs` now installs host text preferences through `EditorAppearancePreferences` instead of constructing the workbench token set inline. `paint_text/font.rs` still owns `fontdb` resolution and embedded fallback bytes, but the runtime family reported to measurement keeps the requested user or logical family. Embedded fallback files are therefore an implementation fallback, not a hardcoded UI font policy. The retained font-weight contract follow-up closes the next mismatch visible in the user's mixed-font editor screenshot. `measure_runtime_text_width_with_style(...)` and `draw/layout.rs::runtime_single_line_text(...)` now derive a `HostTextFontRequest` for the selected face and pass its `weight` into `UiResolvedStyle.font_weight`; the runtime side carries that value through `UiTextStyleKey`, glyphon `Weight`, `UiTextPaint`, paint runs, and the text font resource id. Retained-host code still only chooses UI semantics and the current host face; it does not hardcode concrete UI families or own a separate measurement rule.

The 2026-07-03 runtime-style projection follow-up narrows that rule further. `paint_text/font.rs::runtime_text_style_for_face(...)` is now the single retained-host helper that turns the current global `HostTextPreferences` and selected face into runtime `UiResolvedStyle`. Measurement, single-line overflow projection, and focused tests all call that helper, so controls can remain semantic consumers while the future engine preferences panel switches fonts, color themes, density, and style packs globally. This slice does not name a concrete UI font as product policy; platform or embedded font files are resolution/fallback details only.

The render-command conversion bridge remains outside `paint_text`, but it is one of the text ingress points that feeds `HostPaintCommand::text(...)`. The 2026-07-02 style-preservation follow-up keeps that bridge from resetting text semantics at the last retained-host hop: fallback text commands map `UiRenderCommand.style.font_weight` through `render_command_conversion/style/text.rs`, and runless shaped text commands split shaped clusters into per-cluster host text commands using `UiTextRunPaintStyle::from_run_kind(cluster.kind)`. This is a command bridge fix only; font face resolution, raster choice, and cache identity remain owned by `paint_text/font.rs` and `paint_text/raster.rs`.

`paint_text/raster.rs` owns glyph raster caching by font face, glyph index, logical pixel size, and requested fallback raster scale. It tries swash first with `Format::Subpixel` at native 1x logical size so ClearType-like coverage is not rendered at 3x and then averaged back into blocky pixels. If swash cannot place/render the glyph, or if the native swash bitmap has too little maximum coverage for a small thin stroke, the owner falls back to the existing 3x fontdue alpha-mask path. Each cached raster carries its own `raster_scale`, and `draw/glyphs.rs` uses that scale for logical extent and row sampling, so native subpixel glyphs and supersampled fallback glyphs do not share one downsampling rule.

The 2026-07-03 global text-smoothing follow-up turns the earlier grayscale/subpixel decision into an explicit appearance preference. `EditorTypographyTokens.font_smoothing` is projected through `HostTextPreferences.smoothing`, and `paint_text/raster.rs` includes that value in the glyph raster cache key. The default `HostTextSmoothing::Grayscale` requests swash `Format::Alpha` and emits `CachedGlyphRasterFormat::AlphaMask`, which avoids RGB color fringe in the current retained software framebuffer. `HostTextSmoothing::Subpixel` requests swash `Format::Subpixel` and preserves `Content::SubpixelMask` RGB coverage as `CachedGlyphRasterFormat::SubpixelMask`. Font family, weight, and style selection remain owned by `HostTextPreferences` and `fontdb`, so this smoothing choice does not hardcode a concrete UI font.

## Blend Ownership

`paint_text/blend.rs` owns RGBA write, alpha blending, and channel-specific subpixel coverage blending for text pixels. The draw owner only calculates coverage-adjusted color and pixel coordinates; channel overwrite and alpha composition stay in the blend child.

## Root Boundary

The root `paint_text.rs` declares child modules, re-exports the existing text draw entry points, and attaches the external test module. It should not regain font bytes, fontdue imports, glyph cache state, clip math, pixel blending, layout traversal, or inline tests.

## Test Ownership

`paint_text_tests.rs` owns local regressions for glyph raster cache reuse and disjoint active/explicit clip suppression. The tests stay outside production files so the root can remain a structural owner boundary.
