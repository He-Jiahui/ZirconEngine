# Paint Template Nodes

`paint_template_nodes/` is the neutral retained-host software-paint family for template-node backed Workbench UI. It replaced the old `host_contract/painter/` directory during the 08 M3.S2 hard cutover. The module still paints editor template nodes in software, but it no longer owns the broad Workbench frame, primitive replay, text, theme, diagnostics, or presenter boundaries.

`mod.rs` is the only folder entry. It exposes `draw_template_nodes(...)` and `has_template_nodes(...)` to `paint_workbench_impl.rs`, and exposes the test-only template-node/render-command helpers used by retained-host parity tests. `template_node_pipeline.rs` owns template-node model traversal, effective paint clipping, command collection, command submission, and the test-only RGBA entry helpers. `template_material_feedback.rs` owns Material backdrop and progress feedback primitives. `template_node_images.rs` owns image/icon payload extraction, target-rect fitting, tint resolution, and image paint-command emission. `template_node_text.rs` owns the generic text fallback path: label filtering, text rect layout, leading-icon avoidance, font-size clamping, and `HostPaintCommand::text(...)` emission. `template_node_surface.rs` owns the generic surface fallback path: frame-only filtering, surface eligibility, elevation shadow, border, surface quad, and Material state-layer/ripple dispatch. `template_alert_glyphs.rs` owns inline-alert and toast status/close glyph segment drawing, while `template_alerts.rs` keeps alert/toast recognition, tone parsing, style selection, surface/text/action command sequencing, and toast sizing;
