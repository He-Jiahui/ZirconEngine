# 15 组件视觉标准化（从原子基元到领域组合）

## 0. 为什么需要本计划

`01-14` 把设计语言、停靠架构、声明接口、渲染/绑定/约束契约**结构性**地立了起来,但 `docs/tests/editor/` 下最近一轮真实 retained-host 截图暴露出**视觉成品仍然很糙**,与 `editor-workbench-designs/` 参考图差距明显:

- **页签条过密被硬裁剪**:主页面页签挤成 `Sce / Eff / Abil / Ta / Perce …`,因为页签数量超出可用宽度后被压到远小于最小宽度,文本在 `fontdue` 布局里按 `max_width` **硬切字形**(切成 "Sce"),既不省略也不溢出收纳。
- **密度/间距不统一**:Asset Browser 列头 `Name Type Siz Rev`、`NaT SR` 被裁;行高、内边距、间隙在不同绘制族里各写各的常量,缺单一事实源。
- **控件度量分散**:`BUTTON_RADIUS=4`、`BUTTON_FONT_SIZE=10`、`TAB_FONT_SIZE=10`、`SEGMENT_RADIUS=4` 等散落在各 `metrics.rs`/`geometry.rs`,无法"改一处全局生效",也无法保证与参考风格一致收敛。
- **配色未喂入单源**:retained painter 自带 `paint_theme/tokens.rs::PALETTE` 与 `workbench_chrome/palette.rs`,尚未由 `01` 的中央 `EditorDesignTokens` 喂入(`01.S2` 后续项),导致色板事实源有两套。

本计划承接 `01`(色板单源)、`12`(组件三层 + slot/prop 契约)、`13`(约束 token 化)、`10`(确定性渲染 + 截图验收),把它们**从结构落到像素**:按用户要求**自下而上、从具体到抽象**——先把**通用原子控件**的视觉度量/形状/响应标准化并自适应,再组合成**复合控件**,最后自适应拼装成**抽屉/窗口**,每层都用 `docs/tests/editor/` 截图作为验收闸。

## 1. 视觉权威与"取什么/不取什么"

度量与响应权威 = `dev/UnrealEngine` Slate(Starship)源码的**具体数值**;色彩身份权威 = Zircon 自有设计契约(近黑阶调 + teal `#3cc7d6`,见 `STYLE-NOTES.md` 与 `design-language-contract.md`);结构密度权威 = `editor-workbench-designs/*-layout-spec.png`。

| 参考物 | 取什么(度量/形状/响应) | 不取什么 |
| --- | --- | --- |
| UE `StarshipCoreStyle.cpp` / `CoreStyle.h` | 控件圆角 4px、边框 1px、按钮内边距 `12/1.5/12/1.5`、按下内边距 `12/2.5/12/0.5`(下沉 1px)、字号 Normal=10/Small=8/Large=14、复选框 16×16 圆角 3px、输入框内边距 `8/8/3/4` 圆角 4px、页签内边距 `4/10/3/4`、滚动条厚 8px 圆角 4px、列表行选中/悬停色角色 | **不取** UE 蓝 `#0070E0` 作主强调色(Zircon 用 teal),不取 Slate 对象模型,不取 `.png`/笔刷资源 |
| UE `StyleColors.cpp` | **仅取色彩"角色"语义**(Background/Panel/Header/Recessed/Input/Hover/Foreground/ForegroundHover/Select 的层级关系) | 不取 UE 的具体 hex;映射到 Zircon 近黑阶调 + teal |
| `STYLE-NOTES.md` / `design-language-contract.md` | 近黑面板四阶 `#111416`/`#171a1d`/`#1b1f23`/`#252b31`、teal `#3cc7d6` 仅激活/选中/焦点;扁平、1px 边框、低圆角、28–32px 控件高;**禁**渐变/辉光/阴影/嵌套卡片/英雄字号 | 不取参考图任何绝对坐标 |
| `main-tabs-layout-spec.png` / `asset-browser-workbench.png` | 页签条单独成行、标签全称 + 副标题、列头密度、行选中态 | 不取像素坐标;改 Taffy + token |

> 关键裁决:用户要求"按钮样式/文本渲染/背景颜色风格照搬 UE"。本计划裁决为**照搬 UE 的度量/形状/响应(圆角、边框、内边距、字号、按下下沉、状态优先级)**,但**保留 Zircon 的色彩身份(teal + 近黑)**——因为 `index.md §4.2/§4.3` 把"色板单源 = 近黑 + teal,teal 仅关键态"列为全目录硬约束,UE 蓝若进来会破坏一致性。色彩只借 UE 的**层级角色关系**,不借 hex。

## 3. 分层:原子 → 复合 → 领域(从具体到抽象)

```
原子层 (S15.1 度量 token 单源 + S15.2 文本省略)
  按钮 / 图标按钮 / 文本(标签) / 容器(面板/分隔) / 图像(图标·缩略) / 间隙(gap·padding)
        ↓ 组合(不新增原子,差异靠 slot 填充——遵 12)
复合层 (S15.4)
  搜索栏 / 工具栏 / 状态栏 / 多选段控 / 按钮组 / 弹出框·上下文菜单 / 列表行·列头·可交互选择列表 / 内容容器
        ↓ 自适应拼装(Taffy 约束 + 约束 token——遵 13)
领域层 (S15.3 页签条 + S15.5 抽屉/窗口)
  主文档页签条 / 左右抽屉 / 底部输出 / 浮动窗口
        ↓ 上屏(确定性渲染 + 脏区增量——遵 10/09)
截图验收 (docs/tests/editor/*.png 人工 + 契约比对)
```

每一层"完成"判据:① 度量来自 S15.1 单源;② 色彩来自 `01` 中央 token(S15.6 收口);③ 在 640/900/1260 三档宽度下自适应不破版(截图);④ 不违反 `engine-code-structure-convention.md` 硬闸。

## 5. 文本原子省略(S15.2)

当前 `layout_text_run` 把 `rect` 宽喂给 `fontdue` 的 `max_width`,溢出字形被直接丢弃(=硬裁剪)。改为文本原子统一的"测量→必要时末尾省略":

1. 先 `measure_fallback_text_width(text)`;若 ≤ 可用宽,原样绘制。
2. 否则二分/线性逐字裁到 `可用宽 - 省略号宽`,追加 `…`(U+2026),保证至少 1 个有效字形 + 省略号。
3. 对"不可裁单元"(单字形已超宽)退化为仅省略号或单字形,不 panic。
4. 纯函数、可单测(给定宽度与字符串→期望输出串),测试随生产 owner 落 `paint_text` 下,不超 800 行。

效果:`Scene Editor` 窄列降级为 `Scene…` / `Scene E…` 而非 `Sce`。这是**原子层**改进,被所有标签/页签/列头/行复用。
