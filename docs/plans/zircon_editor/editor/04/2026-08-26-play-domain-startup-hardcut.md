## Current-Source 与参考复审

- `RetainedEditorHost::new_with_viewport` 原先在任何 Play backend 启动前执行 `attach_play_gateway(runtime_gateway.clone())`。该 gateway 来自 App 创建的 projectless `editor` profile session，不是副 game session，也没有本次 Play 的 scene payload，因此它不能成为 `WorldDomain::Play` 的事实源。
- `EditorContext.gateway()` 已是稳定 authoring facade；`PlayDomainLink` 已拥有独立的 replaceable play handle。启动时把 editor session 塞进后者会重新混合两个生命周期，并使 `backend_attachable=true` 即使没有 backend-owned gateway 也可能启动 runtime consumer。
- 正常 Exit Play 与 crash pump 原先停止 backend 和 consumer，却不走工程/宿主关闭已有的 identity-qualified detach；停止后的 gateway 可继续从 stable play handle 可达。
- Unreal `PlayLevel.cpp:2332-2417` 的 `CreatePIEWorldByDuplication` 建立独立 `EWorldType::PIE` world，`PlayLevel.cpp:730-934` 在结束时按 play world context 执行 teardown/cleanup。Zircon 不复制 UObject world，但必须保留同一原则：只有独立副 session 能进入 play domain，且终态先撤销所有 play 路由，再销毁该副本。
- Unreal `PlayLevel.cpp` 的 `GetSimulateInEditorViewTransform` 与 `SLevelViewport.cpp` 的 `SetPlayInEditorIsSimulate`/`SwapViewportsForSimulateInEditor` 表明 SIE 继续使用 Level Editor viewport、释放 game viewport 输入，并用编辑器视角观察独立 PIE world。Zircon 因而不能让 Simulate focus Game，也不能把编辑相机写入玩法 ECS；编辑相机必须成为 play-world render extract 的 presentation override。
- Unreal `SceneOutliner/ActorBrowsingMode.cpp:316-340` 先解绑旧 `RepresentingWorld` 再重建，`:1055-1134` 的 selection 同步显式识别 `PKG_PlayInEditor` actor 并让 PIE selection 不产生普通编辑事务，`:1447-1459` 又把删除命令发送给当前 represented world。Zircon 因而必须让 selection 携带同一实例化 world identity，不能用另一个无实例 `Play` enum 猜测目标。
- M4 current-source 复核确认旧 `CoreEditContext` 只持 authoring `EditorRuntimeGatewayHandle`，且 `resolve_history_context` 尚无生产调用者。若只增加 `PlaySession` 并复用旧 `begin(history)`，运行时实体 ID 会被错误送入编辑世界。Unreal 同一 outliner 路径对 PIE actor 避开普通 editor transaction，进一步证明必须先完成 world-routed context，再开放 Play 写入，而不能用历史标签冒充世界路由。本切片据此硬切 `EditContext` 合同并删除旧拒绝分支，不保留单网关兼容入口。

## 实现决策

- retained host 启动不再 attach App 的 editor-profile runtime gateway；生产源码中 `attach_play_gateway(runtime_gateway...)` 为 0。
- `PlayBackendStartReport` 删除独立 `attachable` 状态；`attachable()` 只由是否实际携带 gateway 推导。没有明确交付 play gateway 的 noop/process/test backend 不会被当成可 attach runtime。
- `PlaySessionController::detach_terminal_play_gateway` 成为 normal stop、startup compensation、crash poll、project close 和 host shutdown 的共同 owner；它在 transition gate 内检查终态并 reservation 当前 `PlayInstanceId + GatewaySessionIdentity`，释放 gate 后执行 history/finalize，再重新持 gate 调用 `PlayDomainLink::detach_matching_identity`。reentrant detach 返回 `TerminalDetachInProgress`，backend retirement 在 reservation active 或 gateway 仍 attached 时返回 typed `InvalidTransition`，既避免 extension finalizer 回调 controller 的同线程死锁，也不会在清理中途销毁 App session。
- crash pump 对终态但仍 attached 的 link 重试 detach，避免首次 identity race 后永久遗留 stopped gateway；pending decision 与 editor-state restore 仍只在 gateway 成功退役后继续。
- `EmbeddedPlayBackend` 以 `Idle/Starting/Running/Stopped/Retiring` 保存事实状态；启动先物化 project-relative scene，再向 App factory 领取 opaque lease。停止只进入 `Stopped`，不会越过 consumer/gateway 生命周期直接 destroy。
- `AppPlaySessionFactory` 从克隆的 `RuntimeLibraryPreflight` 重新校验同一 BuildSet，创建带 project root 与 scene 的 `runtime` profile session；Editor 合同不暴露 create/destroy ABI。GUI 即使从欢迎页启动也预装此 factory，后开工程不再退回旧 backend。
- terminal 顺序统一为 consumer/watch stop -> backend stop -> identity-qualified gateway detach -> App lease retire。`Arc::try_unwrap` 或 `try_destroy` 失败会把 lease 恢复到 `Stopped` 并进入 typed `BackendRetirement` 重试状态。
- retained host 的 Scene 与 Game 图像所有权硬切为 `HostViewportImageSet` 双槽，painter 按 pane kind 取图，不再让 Game 复用 authoring Scene 帧。Playing tick 在 runtime consumer pump 之后，仅当 Game pane 实际可见时通过默认 runtime viewport capture，复制为 host-owned `Arc<[u8]>` 后立即 release provider allocation；隐藏时跳过回读，退出、崩溃或停止会清除 Game 槽。CPU 回读量与隐藏跳过量分别由 `play.preview.copy_bytes`、`play.preview.hidden_capture_skipped_count` 记录，native surface 只能在真实 profiling 证明需要且所有权闭环后替换该 MVP fallback。
- attachable Play 在 consumer 成功启动后 focus 已存在的 Game view，不会把浮动 Game view 重新挂载；normal Exit 与 backend crash 都在编辑器状态退出 Play 后恢复原 view。布局 focus/restore 失败只降级状态行，不回滚仍健康的 runtime，也不把已停止 runtime 伪装为 Playing。
- native hit-test target 与 pane callback 已将 `SceneViewport`/`GameViewport` 身份硬切，删除旧统一 viewport callback；Scene 事件只进入 authoring dispatcher，Game pointer move/button/wheel 与焦点 Game view 的 keyboard press/repeat/release 只通过 `PlaySessionController::route_preview_input` 发往副 session 的默认 runtime viewport。Play 白名单以 transition gate 串行化 input 与 detach，Simulate/Edit/Building/CleanupFailed 返回未路由，避免运行输入回落到编辑命令；进入 Play 只在状态边沿清一次文本焦点。Workbench 缓存 Game descriptor，焦点判断在单次 session lock 下直接查当前实例，不再物化全部 `ViewInstance`；tick 只在 Game -> 非 Game 边沿发送 background/`InputEvent::FocusLost`。当前聚焦 Game view 的 native window 失焦也走同一路由，避免切面板或 Alt-Tab 后卡键。获焦未转发，因为现有 callback 不携带窗口 identity，多窗口下不能安全证明来源。已增加 `play.preview.input_routed_count` 计量。
- Simulate 启动不再 focus Game；retained tick 在 runtime tick 前读取 authoring Scene 的 world-space `ViewportCameraSnapshot`，只在快照变化时通过 4 KiB 上限的版本化 `VIEWPORT_CAMERA` 事件同步。`PlaySessionController::route_simulate_camera` 仅接受 `PlayKind::Simulate`，与 Game 输入白名单严格互斥。runtime 校验有限值、非奇异 scale、单位 quaternion、投影几何后，只覆盖缓存 `RenderFrameExtract` 副本中主相机的 transform/projection，保留玩法相机 pipeline、曝光、动态分辨率等字段且不修改 ECS。host 图像改为 authoring Scene / SIE Scene override / Game 三槽；Simulate 仅在 Scene pane 可见时捕获 play world，退出后清 override 即回显持续更新的 authoring Scene 帧。相机未变化和隐藏 Scene 分别由 `play.simulate.camera_unchanged_skipped_count`、`play.simulate.hidden_capture_skipped_count` 计量。
- M3 current-source 复核证明，现有 hierarchy publication/fragment/reflow 全部读取 authoring `EditorState.world`，仅把 watch 切到 Play gateway 会形成“Play 失效通知驱动 Edit 快照”的错误双世界混合。通用 reflected `WorldQuery` 的裸 `Rows` 又没有 generation，且会让 editor 重算 runtime 已维护的 hierarchy depth/hash/active/children。基础协议因此硬切为 typed `Components/Hierarchy` projection；两类 materialized result 都携带 generation，`WorldHierarchyRow` 由 interface 单一拥有并被 runtime inspection 直接复用。bounded hierarchy producer 在 owned clone 前校验 bytes/items/deadline。旧 untagged request 与裸 `Rows(Vec<EntityRow>)` 不保留。
- Edit/Play world sync 拆成独立 pump/watch owner，watch 身份以 `(WorldDomain, GatewaySessionIdentity, WatchToken)` 限定。tick 先消费 runtime 事件，再按终态选择 active domain；Play 期间 authoring hierarchy publication 只 drain/discard，retained hierarchy 只接受副 session 的 identity-qualified typed query。初次、身份变化及 topology 变化执行 authoritative reflow，同 topology 的值变化执行 sparse patch；失败查询保留 pending 并重试，退出时先退役 Play watch/cache，再强制 Edit authoritative reflow。
- Inspector query 新增 typed `InspectionFields { entity, generation_hint }`，结果明确区分 `InspectionFields`、`NotModified` 与 `EntityMissing`；`WorldInspectionFieldRow` 由 interface 单一拥有，runtime inspection 直接复用，并在 owned clone 前执行 bytes/items/deadline 校验。Play Inspector 只从当前 attached identity 与选中实体查询，100 ms cadence 以 generation hint 短路；快照身份或实体不匹配时不暴露，缺失实体清空。运行时内建字段与插件字段均投影到 retained Inspector，M3 一律只读；可见值未变化时不触发布局重建，Edit 与无选中状态不回落展示 authoring snapshot。
- Selection domain 删除 `scene/selection/world_domain.rs` 的匿名 `Edit/Play` owner，统一复用 `core::play::WorldDomain::Play(PlayInstanceId)`；`SelectionModel` 以 `BTreeMap<PlayInstanceId, DomainSelection>` 隔离实例，只有真实 attach 后才从 Edit seed 并激活对应实例，显式退役回 Edit。`PlayInstanceId` wire decode 拒绝保留值 0。retained tick 在 runtime 终态收敛后、hierarchy/Inspector 前对齐 selection domain，覆盖 immediate、after-build、crash 与 retry；退出恢复进入前的完整 Edit selection，不保留匿名 Play 桶或兼容类型。`FocusMessage` 同步硬切：`SelectionDomain::Scene(WorldDomain)` 与 `FocusObject { domain, entity }` 必须携带具体 Edit/Play 实例，Latest retention key 按实例隔离，删除匿名单位 `Scene`。
- M4 history owner 新增 `HistoryContextId::PlaySession(PlayInstanceId)` 与 canonical `world_domain/is_volatile`；routing 第 0 步显式接收 `WorldDomain`，Edit/Play 或 Play 实例不匹配返回 typed `CrossWorldHistory`。volatile status 无 `saved_top`、`is_dirty` 恒 false、dirty batch 不发布，save token 与 journal 构造/解码均拒绝持久化。`EditContext` 已硬切为 `capture_world_route/activate_world_route/retire_world_route`，`CoreEditContext` 同时持有 authoring/play 稳定 handle 与按 `WorldDomain` 分区的 selection slot；Builder 把同一个 play handle 交给 transaction context 和 `PlayDomainLink`，attach authority 仍只有后者。根事务捕获 `WorldDomain + GatewaySessionIdentity`，嵌套事务继承，`TransactionRecord` 持有精确 route；undo/redo 使用目标 record 的旧 generation，gateway 被同实例替换时返回 typed `WorldRouteStale`，不会把旧命令重定向到新世界。`discard_play_history(instance)` 在 gateway 仍可达时按实例整栈 finalize、移除 store/generation、恢复 Edit route并退休 Play selection slot；宿主唯一 terminal detach owner 使用两阶段 reservation 保证 extension cleanup 锁外执行，再 identity-qualified detach，覆盖 normal stop、crash、project close 与 host shutdown。导航等外部命令通过 `runtime_operations()` 获得持有单一 `GatewayOrigin` 的 `EditorRuntimeOperationRoute`，submit/poll/harvest 不会跨 generation。旧 `runtime_gateway` trait 和 `VolatileHistoryRouteUnavailable` 已删除，不保留兼容入口。
- M4.2 产品入口按当前 active selection domain 选择历史：Play Inspector 字段批次在已固定的 Play transaction context 内捕获 before value，只修改批次携带字段；单轴 transform 写入保留其余运行时轴，动态字段按运行时 reflected type 解析，不读取或回写 authoring draft。Ctrl+Z/Redo 在 active Play selection 时只路由 `PlaySession(instance)`，Play 中的 Edit selection 不回落 authoring history。通用 `OperationCommandFactoryRegistration` 构造时强制接收 editing-owned `EditOperationTarget`，没有 workspace 默认值或事后 setter；navigation/neural 产品注册显式声明 `EditWorkspace`。宿主必须先 `defer` 并调用 `route_edit`，只有 `ApplyNow` 才执行 factory capture；queued 路径发布 `EditQueued` 且不创建命令、不写 history。旧 Play-owned target 文件和类型名均删除。
- Play Gizmo 源码按显式 world route 开放，不复用 authoring hit：副 session 已有 identity-qualified V8 pick request/poll/cancel、session ticket owner、renderer-neutral bridge、WGPU exact-frame HitProxy product 与 SIE press selection consumer。handle build/pick/drag 已硬切为 selected entity+typed `Transform` 的 world-neutral 输入；SIE local handle route 优先消费 Gizmo axis，scene primitive 仍只走副 session HitProxy。128-byte 定长 transform payload 通过完整 gateway identity 分发，runtime 用 replacement epoch、expected/target CAS、checked sequence 与单活动 owner 实现 begin/preview/commit/cancel，undo/redo 走独立 apply phase。Unreal `LevelEditorViewport.cpp` 在交互前显式选择 `PlayWorld`/`EditorWorld` 的原则因此已进入 Zircon 源码；受管行为、真实 WGPU 和性能/功耗证据仍未取得。
- current-source 复核同时确认现有 watch payload 只有 component type 级失效，无法可靠证明新增组件或某实体字段变化；因此 100 ms 节奏拉取是当前正确性兜底，不把它伪装成最终性能方案。entity-exact invalidation 与 page/cursor/cancel 必须先取得真实 trace，再作为 M3 后续结构性优化，不在缺少 profiling 数据时盲改。SIE press 已改为消费显示帧携带的完整 gateway identity 与 exact frame generation，authoring CPU hit/Scene Mode 左键路径在 Play 中关闭；Game viewport 仍只向副 session 输入。8 ms pending poll 与 50 ms error retry 是集中式 MVP 调度边界，不是性能或功耗结论，必须由受管产品 trace 再评估。
- 启动前拒绝遗留的 attached route；若极端 attachment rollback 连 backend stop 都失败，controller 保持 `Playing` 且 Workbench 不退出 Play，从而保留 stop 重试入口。
- `editor_host_event_controller.rs` 已为 1002 行，但本轮没有向 root 增加 lifecycle helper；新协议留在既有 `runtime_shutdown.rs` child，root 只增加调用编排。后续若继续扩展 controller，优先把其大型 `#[cfg(test)]` 树迁到 folder-backed tests owner。

## M4.3 Keep Changes 架构复审（实现前）

- Unreal `LevelEditorActions.cpp:2683-2785` 的 Keep Simulation Changes 只接受已选 PIE actor，通过 editor counterpart 建立一笔 `FScopedTransaction`，只复制可编辑/插值属性并过滤只读属性；附件关系与运行期新建 actor 明确不在该路径中。本切片采用同一边界，不做停止 Play 时的全场景覆盖，也不把 UI 文本重新解析为运行时值。
- Zircon 的 `PlaySceneSource::from_world` 使用 `DynamicScene` 快照，runtime snapshot 路径以 `World::new()` 为目标执行 `spawn_into`；该路径在空世界中保留 source entity id，但必须以行为测试固定，不能仅依赖当前实现细节推断 counterpart。
- Keep Changes 仅允许 active `WorldDomain::Play(instance)` 中的单一选中实体。查询必须固定 `GatewaySessionIdentity`，使用 `query_world_at_identity(identity, WorldQuery::inspection_fields(entity, None))` 获取一次新鲜 typed snapshot；identity 陈旧、实体缺失、响应实体不匹配或 `NotModified` 均作为 typed failure，不回落 authoring cache。
- 字段准入只接受 `writable && serializable`，并排除 `Hierarchy.parent`。运行期新增实体或 authoring counterpart 缺失整体拒绝；任何字段捕获失败都发生在事务开始前，避免部分回写。组件增删、父子层级、附件和运行期新建实体留给后续显式 diff/merge 系统，不混入 MVP 属性回写。
- 通过作者 world 捕获 `SetReflectedSceneFieldCommand`，跳过值相同字段；非空命令集合绑定 Edit selection，并进入 active scene `HistoryContextId::Document(document)` 的单一 transaction。提交后 Play selection 仍保持 active，作者 Undo/Redo 只在退出 Play 后生效；Playing 期间的 Edit selection 仍不回落 authoring history，也不污染 volatile Play history。
- 旧 `EditorPlaySession` 的整场景备份/退出覆盖与双 gateway 架构冲突：Play 写入已经只到副 session，作者 world 不再需要“恢复”，而该覆盖会直接丢失 Keep Changes。本切片硬切为只保存选择/Gizmo/session mode，退出 Play 不替换作者 world；这属于正确性迁移，不保留旧恢复兼容路径。
- 该切片不属于性能优化；仍遵守“先 profile 后优化”。当前只用一次有界 Inspector query 和一次作者事务建立正确性闭环，不在缺少 trace 时引入全世界 diff、后台扫描或停止时自动合并。

## M4.4 副 Session Picking / Editor Overlay 架构复审（实现前）

- current-source 复核确认 authoring point picking 已经在 pointer event 期执行一次 renderer-visible spatial query，只投影查询返回的 owner；现有埋点覆盖 visited node、candidate、hit、projected candidate、projection build/reuse 与 owner-map payload。当前没有受管 1/1k/10k 产品样本，不能宣称该路径已达到 P95、GPU 或功耗目标，但已足以排除“再建一套 Editor 全场景线性扫描”这种结构性回退。
- 真正阻断 Play Gizmo 的不是 authoring CPU broad phase 局部实现。`EditorRuntimeGateway`、唯一 `ZrRuntimeApiV8`、dynamic runtime 与 WGPU exact-frame HitProxy product 已接通源码；剩余边界是 Play viewport receipt/selection/hover consumer、Gizmo transaction owner 和受管 WGPU 产品验收。把 authoring `Scene` 的命中结果套到 Play 实体仍会跨 world 污染，继续禁止。
- Unreal `FEditorViewportClient::GetHitProxy` / `ProcessClick` / `InputWidgetDelta` 让 world primitive 与 widget axis 消费同一 viewport hit-proxy 产品；`FLevelEditorViewportClient::GetElementsToManipulate` 在 SIE 时显式选择 `PlayWorld`，`ConditionalSetWorld` 在交互前切换 Play world。Zircon 吸收的是“同 view hit identity + 显式 world 选择 + transaction owner”，不复制 UObject 全局 world 或旧兼容 API。
- Unreal `SceneHitProxyRendering.cpp` 进一步证明命中代理必须是独立 color+depth pass：清空后按 HitProxy/HitProxyOpaqueOnly visibility pass 绘制，depth test/write 开启、blend 关闭，透明是否进入由显式策略控制，foreground/editor simple elements 与 widget 使用专门深度行为。Unity URP/HDRP 的 selection-picking pass 与 alpha-tested picking 测试同样要求复用 material visibility/alpha clip；因此 Zircon 禁止从 final color 解码身份、禁止 CPU raycast 冒充渲染可见性，也禁止另写不理解材质的简化 mesh pass。
- 通用 `submit_operation -> JSON -> queued snapshot -> worker prepare -> owner tick apply -> poll/harvest` 适合导航烘焙，不适合 hover/press 的交互热路；本计划禁止用该通道伪装 renderer picking。旧 `ZrRuntimeApiV7` 已删除，唯一 exact `ZrRuntimeApiV8` 把 request/poll/cancel 固定在 table 尾部；loader、runtime、app、editor 与测试不保留 prefix probing、可选尾字段或 V7/V8 双轨兼容。
- 目标 renderer 合同为无 JSON、无全帧 pick-buffer 跨进程复制的异步 ticket/readback：请求固定 runtime session origin、viewport、render frame generation、input sequence、physical pixel 与 pick policy；结果回传同一 ticket/session/view/frame identity、world generation、entity/instance/subobject、depth/position/normal、applied policy 与 typed terminal disposition。Pending 可跨一帧；NoHit/Stale/Unavailable/Rejected/Hit 都必须可区分，任何 identity/generation 不匹配 fail closed。
- overlay 分层不把 Editor 语义塞进 runtime scene serialization。选中高亮继续通过 generation-bound `HighlightSet`；transform handle、hover、pivot 与 tool capture 仍归 Editor。SIE 的 Editor 相机和 Play entity typed inspection 构造本地 handle overlay，local handle route 优先于 renderer scene hit；Scene primitive 精确命中只采用副 session readback。最终 pointer receipt 同时记录 local-overlay 与 renderer backend provenance，禁止两套 owner 真值互相覆盖。

### M4.4d Play Transform Transaction 结构复审（实现前）

- current-source 复核发现 `CoreEditContext::with_scene/with_scene_mut` 最终依赖 `EditorRuntimeGateway::with_world/with_world_mut`，而真实 DLL `SessionGateway` 只实现序列化 query 与 ABI 操作，借用式 World 入口固定返回 `RequiresSerializedAccess`。因此现有 Play Inspector/history 在进程内 gateway 测试可走通、真实副 session 却不能写入；这不是 Gizmo 局部缺陷，而是 Play 写半程的底层合同缺失。不得通过给 DLL gateway 伪造借用闭包或回落 authoring World 掩盖。

## M2 已完成的生命周期前置

`EmbeddedPlayBackend` 没有复用旧的单阶段 `stop == destroy`。本切片已落地以下不变量：
