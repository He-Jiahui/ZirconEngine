# Editor17 M3.2 Notification Current-Source Manifest

## Scope Delivered

This candidate hard-cuts the retained `WorkbenchNotification` DTO and its queue/history publishers from the M3.2 notification path. Typed Toast, Progress, and Decision authority remain in `core/notifications`; the retained activity view projects only core snapshots and routes Play pending-edit selections through the one Decision receipt path. Job admission and terminal events now feed a bounded core Progress center through a job-system observer, so Progress is a live notification projection rather than test-only construction.

The current Decision failure repair adds bounded immutable message facts to the core model. `present_decision` captures one locale, resolves the localized template, and formats only those declared facts. The Play adapter no longer owns English prompt text or a second option payload: it rebuilds rows from the core projection while retaining ticket and option identity.

## Current-Source Evidence

- The exact current manifest is 37 paths. It includes the Decision owner facade/center and its Python contract that the prior 35-path candidate omitted; its existing Rust sources pass `rustfmt --edition 2021 --check --config skip_children=true`, and scoped `git diff --check` passes with only repository line-ending notices. The deleted retained-history path is an explicit manifest candidate, not an unowned missing file. The formatting-only retained dispatch file is deliberately excluded.
- Complete-symbol checks found no `WorkbenchNotification` DTO or removed queue/history publisher in `zircon_editor/src`. Existing `WorkbenchNotificationCenter` component identifiers are intentionally outside that removed API.
- Static guards confirm bounded decision message arguments, the single-locale projection boundary, complete en/zh-CN placeholders, no legacy `WorkbenchNotification` DTO or legacy pending-edit localization keys, no `RetainedNotificationHistory`, no partial bridge sync API, and no invalid `control_bool` option comparison. Play adapter tests cover direct core receipt consumption, failed-effect retry until cursor commit, foreign-only expiry advancement, retained post-cutoff receipt consumption, and explicit replacement only when an owned receipt was actually evicted.
- Progress capture is bounded to 64 active notification bindings, snapshots only the bound job IDs, and captures both notification ID and Job ID before reconciliation. Lifecycle delivery uses a 1024-event hard bound, collapses overflow to one authoritative resynchronization, and isolates observer panics before repairing from the progress source. This preserves a replacement producer that reuses a stable ID while an earlier snapshot is resolving.
- The automatic job-progress binding is intentionally replaceable by a source-specific producer; terminal job transitions retire its binding without retaining a result receiver.
- No Cargo command was run locally. This manifest exists to bind the coordinator-owned current-source validation snapshot.
- Coordinator run `c5ee167c2a6d4ca791598c8f2109f001` was prepared before this record used the required JSON `Files` syntax and therefore bound only this record path. No validation action was created. The corrected record requires a fresh Coordinator01 run before managed validation; the immutable malformed binding must not be reused.

## Review

The first independent review found the adapter's private-field construction and loss of the core Decision message facts. Both were repaired forward: selection uses a controlled model constructor, and the core model carries bounded typed facts consumed by the localized projection. A later review found missing live Progress production, unbounded snapshot work, overflow history churn, and two replacement races. The forward repair wires job lifecycle observation, bounds Progress state, treats overflow as a retained-host change, supports atomic source-specific replacement, and records `(NotificationId, JobId)` capture identity.

The earlier review sequence repaired missing production Play receipt consumption, retained-history drift, and the first `CursorExpired` recovery gap. The 2026-08-10 independent review then rejected the 35-path candidate with `Critical/Important/Minor = 1/2/1`: its manifest omitted required Decision owner files, recovery confused a no-op with an actual replacement publication, and Progress callbacks could observe `finished` before `admitted`. Subsequent review found mixed foreign hunks, mandatory-republish livelocks, observer panic loss, and an unbounded observer backlog. The current 37-path forward repair strips those foreign dependencies, advances only to the Decision center's retained resume boundary, preserves live/post-boundary owned receipts, refuses to discard a lost owned choice when no replacement prompt exists, and bounds/panic-isolates Progress delivery with authoritative resynchronization. The latest review rejected snapshot `1565` with `Critical/Important/Minor = 2/2/0`; the forward fix removes the remaining logging/autosave/hierarchy/viewport dependencies, repairs the shadowed delivery guard, retries a resynchronization stranded by two observer panics from the normal event pump, and commits the receipt cursor before fallible post-effect prompt reconciliation. The subsequent live re-review exposed a reintroduced hierarchy hunk and a synthetic post-effect test; current source removes that hunk and replaces the test with a real controller capacity-failure/recovery chain. Final independent re-review is clean with `Critical/Important/Minor = 0/0/0`. Source-bound managed Cargo validation remains required; no accepted result is claimed here.
