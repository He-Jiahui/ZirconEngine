# 06 · AI 插件完善计划（行为树 / Blackboard / Perception）

> 状态：工程化细化版 v2 · 优先级：P2 · 前置：[01 插件架构核心](01-plugin-architecture-core.md) M1–M2；[05 Navigation](05-navigation.md) M3（MoveTo 节点）
> 现状文档：`docs/zircon_plugins/ai/runtime.md`
> 参考实现：Unreal BehaviorTree（Composite/Decorator/Service/Task 四分类 + Blackboard key 观察者 + 条件中断）、Unreal AIPerception（Sight/Hearing 刺激模型）

## 1. 目标

把 `zircon_plugins/ai` 从 Experimental 推进到可生产使用：完整行为树节点库与资产化、类型安全 blackboard、观察者驱动的条件中断、视觉/听觉感知系统、与 navigation/animation 的标准交接节点、行为树可视化编辑与运行时调试。

## 2. 现状基线（实查）

成熟度 Experimental / Partial。

- **契约层** `zircon_runtime/src/core/framework/ai/`：`behavior_tree.rs`（`AiBehaviorNodeKind`：Selector/Sequence/Parallel/Decorator/Service/Task/Subtree 粗分类、`AiBehaviorNodeDescriptor`/`AiBehaviorTreeDescriptor`/参数 DTO）、`blackboard.rs`（**类型化 schema DTO 已在**：`AiBlackboardValueType`/`AiBlackboardValue`/`AiBlackboardEntry`/`AiBlackboardKeyDescriptor`/`AiBlackboardSchemaDescriptor`）、`perception.rs`、`snapshot.rs`、`tick.rs`、`ids.rs`、`manager.rs`（`AiManager` trait）。
- **runtime** `zircon_plugins/ai/runtime/src/manager/`：behavior_tree/blackboard/execution/parameters/perception/service/snapshot/state/tick/validation（validation 较厚，校验规则成体系）；注册经 `register_module`。无 editor crate。

缺口（按严重度）：

| # | 缺口 | 证据 |
|---|------|------|
| B1 | 节点库：`AiBehaviorNodeKind` 只有粗分类，具体节点（Cooldown/TimeLimit/RandomSelector/Wait/MoveTo…）靠参数字符串区分，无注册化节点目录 | `framework/ai/behavior_tree.rs:7` |
| B2 | 执行内核：轮询式逐 tick 遍历，无 observer aborts（任意子树打断 + 状态清理）——需要换内核 | `manager/execution.rs` |
| B3 | Blackboard：schema DTO 在，运行期无 dense slot 存储、无世代号、无 key 观察者 | `manager/blackboard.rs` |
| B4 | Perception 近乎占位（无视锥/遮挡/遗忘/预算） | `manager/perception.rs` |
| B5 | 无 navigation/animation/VM 标准集成节点 | — |
| B6 | 无 `ai.behavior_tick` 系统锚点（Module 轮询）；无 editor | `module.rs` |

## 3. 架构设计

中立契约维持在 `zircon_runtime::core::framework::ai`；执行实现在 `zircon_plugins/ai/runtime`。

### 3.1 行为树资产与编译（解决 B1，`runtime/src/behavior_tree/` [manager/behavior_tree.rs 收编]）

- `.btree.toml` 资产 → 契约 `AiBehaviorTreeDescriptor`（现 DTO）→ 加载期编译：

```rust
/// dense 节点数组，索引寻址，树结构全 agent 共享；每 agent 仅持轻量运行态。
pub struct CompiledBehaviorTree {
    pub nodes: Box<[CompiledNode]>,          // 前序排列，子节点区间 [first_child, last_child]
    pub services: Box<[CompiledService]>,    // 按宿主 composite 分组
    pub blackboard_schema: BlackboardLayout, // §3.2
}
pub struct CompiledNode {
    pub node: NodeImplId,                    // 节点目录 dense id（见下）
    pub params: ParamBlockRef,               // 预解析参数块（含 blackboard key → slot）
    pub children: core::ops::Range<u32>,
    pub observer: Option<ObserverDecl>,      // decorator 的 abort 声明
}
pub struct TreeInstanceState { /* 每节点 1 字节状态 + 活跃路径栈 + cooldown 计时数组 */ }
```

- 节点目录：`register_bt_node(BtNodeDescriptor)` 走 01 的 `TypedExtensionPoint` 实例（key = 节点名，value = 工厂 + 语义元数据），Rust 插件与 VM（[08 ZrVM](08-zr-vm.md) §3.2 `register_bt_node` 通道）都可注册；标准库节点同样经此目录注册（dogfooding）。
- 标准节点库（v1 必交付，Unreal 形态四分类）：
  - **Composite**：`Selector`、`Sequence`、`Parallel { policy: AnySucceeds|AllSucceed }`、`RandomSelector`（权重参数）。
  - **Decorator**：`BlackboardCondition`（key 条件 + observer abort）、`Cooldown`、`TimeLimit`、`Loop { count|infinite }`、`Inverter`、`ForceResult`。
  - **Service**：`UpdateBlackboardDistance` 等周期回调（间隔 + 抖动参数）。
  - **Task**：`Wait`、`MoveTo`、`PlayAnimation`、`SetBlackboard`、`EmitEvent`、`RunSubTree`（契约 Subtree kind）、`ScriptTask`（VM 回调）。

### 3.2 Blackboard 运行期（解决 B3，`runtime/src/blackboard/` [收编]）

```rust
/// 编译期由 AiBlackboardSchemaDescriptor 排布：按类型分区的 dense slot。
pub struct BlackboardLayout { /* key 名 → BlackboardSlot { type, offset }，加载期一次解析 */ }
#[derive(Clone, Copy)] pub struct BlackboardSlot(u32);
pub struct BlackboardStore {
    bools: Box<[bool]>, ints: Box<[i64]>, floats: Box<[f32]>,
    vectors: Box<[Vec3]>, entities: Box<[Option<EntityId>]>, strings: Box<[String]>, assets: Box<[Option<AssetRef>]>,
    generations: Box<[u32]>,                 // 每 slot 写入世代号
    observers: Box<[SmallVec<ObserverRef>]>, // slot → 订阅的 decorator
}
impl BlackboardStore {
    pub fn write<T: BlackboardValueKind>(&mut self, slot: BlackboardSlot, value: T) -> WriteOutcome; // 值变更才 bump 世代并通知
}
```

- 观察者中断（解决 B2 的内核需求）：key 写入 → 通知订阅 decorator → 按 `AbortPolicy { None, Self_, LowerPriority, Both }` 打断——执行内核（`execution.rs` **重写**为 `runtime/src/behavior_tree/executor.rs`）改为显式状态机：活跃路径栈 + 打断请求队列，tick 入口先处理打断（自高优先级向下清理被打断子树的运行态：cooldown 保留、Wait/MoveTo 等 Task 收到 `on_abort` 回调），再继续正常推进。`manager/validation.rs` 既有校验规则全部迁移保留。

### 3.3 Perception（解决 B4，`runtime/src/perception/` [收编]）

- 组件：`AiPerceptionSource { channels: SIGHT|HEARING 位集, strength }`、`AiPerceptionReceiver { sight_fov_degrees, sight_range, hearing_radius, forget_seconds }`。
- `ai.perception_tick` ∈ Update（before `ai.behavior_tick`，显式约束）：分帧预算扫描（`AiTickBudget` 资源：每帧最多 N 对 receiver×source）；sight 遮挡走 physics raycast 可选依赖（`finish` 探测 `runtime.capability.physics.raycast`，无 physics 退化为距离+视锥）；结果写 `PerceivedStimuli` 快照（契约 `snapshot.rs` 扩展），blackboard service 消费。
- 事件刺激适配器：`AnimationEvent`/`SoundPlaybackEvent` 等总线事件可注册为 hearing 刺激源。

### 3.4 ECS 集成（解决 B6，对接 01 定稿 API）

- `ai.behavior_tick` ∈ Update（01 锚点表；`navigation.agent_tick` 在其后由 navigation 侧声明）；`ai.perception_tick` ∈ Update before `ai.behavior_tick`。
- agent tick LOD：按距相机距离分档降频（每 agent 帧间隔 1/2/4），档位计算在 behavior_tick 内联。
- `register_event::<BtNodeResultEvent>`（调试流，M5 编辑器消费）；`register_resource::<AiTickBudget>`。

### 3.5 与 Navigation 的交接（与 [05 Navigation](05-navigation.md) §3.4 对偶，双方逐字一致）

`MoveTo` Task 只写 `NavMeshAgent.target` 字段并订阅 `OffMeshTraverseEvent`/到达失败事件，不直接调用 NavWorld 查询；运行结果三态映射：到达 → Success，repath 失败/不可达 → Failure，途中 → Running。

## 7. 风险

- observer aborts 要求"任意子树打断 + 状态清理"，`execution.rs` 直接换内核而非增补（激进重构原则）；`validation.rs` 既有校验规则全部迁移保留，作为重写回归网。
- ScriptTask 依赖 [08](08-zr-vm.md) M2 回调通道，M3-T3 排期在其后；M3-T1/T2 不受影响。
- 打断语义的边界（Parallel 分支中断、Service 在打断后的停止时机）按 Unreal 语义裁决并写节点语义矩阵测试固化，避免后续编辑器联调期重谈语义。
