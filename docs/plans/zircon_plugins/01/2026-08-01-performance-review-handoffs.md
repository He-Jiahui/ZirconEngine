## 2026-07-18

- particle runtime-prepare性能交接：neutral fallback在persistent particle owner缺席时每帧clone frame并创建七类GPU buffer。Plugins01须把fallback与真实backend统一到per-device/viewport owner生命周期，禁止插件collector私建第二套稳态buffer权威；按capacity复用、dirty写入、static binding IDs，empty/stable create=0。见PERF-MVP-348与`docs/plans/performance/01/2026-07-18-runtime-core-framework-render-sideband-relevance-static-review.md`。
- runtime-prepare调度交接：renderer当前在submission线程依注册顺序同步调用所有collector，并允许回调持有Device/Queue/Encoder、完整frame、重建external-binding Vec及返回大owned payload。Plugins01联动Render03/12/18把合同拆为有界异步CPU prepare artifact与render-thread record/apply，按generation single-flight发布immutable handles；stable heavy prepare/copy/binding rebuild=0，饱和走neutral/last-good并暴露age/drop。见PERF-MVP-379与scene-renderer-core静态证据。
- render executor slot交接：render registry已有register/revoke generation与compiled validation cache，但产品pass仍以String ID查`BTreeMap`。Plugins01联动Render01让finalize/freeze发布immutable dense `ExecutorSlot`表；plugin register/revoke/hot reload原子发布新generation并只使相关compiled binding失效，旧slot不得执行，稳定pass禁止回退String resolve或全表锁。记录table builds、slot resolves、String/tree probes、rebind scope与reload latency；见PERF-MVP-399及graph-execution静态证据。
- advanced-lighting prepare交接：cookie/irradiance/fog-volume/SSS等筛选与打包须服从统一有界prepare artifact合同，按scene/camera/asset/feature generation single-flight；render callback不得再收集全mesh positions、建BTreeMap/profile table或返回第二份大owned payload，只record ready/last-good handles并暴露age/drop。插件reload只失效相关advanced generation，stable heavy prepare/copy/binding rebuild=0；见PERF-MVP-403。
- plugin material/resource residency交接：插件提供的shader、material、texture与resource collector须进入Runtime04同一有界single-flight artifact合同，register/reload/revoke原子发布dependency generation并只失效affected prepared handles；render callback禁止同步I/O/decode/ABI parse或建立第二resident cache。stable plugin resource prepare=0，饱和复用last-good并记录age/drop。见PERF-MVP-404。
- graphics extension catalog启动交接：Plugins01将render features、geometry/shading、executors、collectors与runtime providers冻结为单一generation-owned immutable catalog，module descriptor、lazy factory与WGPU framework只传Arc/dense handles，不再逐层`clone`/`to_vec`整表；reload原子发布新generation且init single-flight。见PERF-MVP-409及graphics runtime-builtin静态证据。
- provider feedback ticket交接：Hybrid GI/VG/particle provider输出当前可同时存在renderer与prepared sideband owner，submission每camera再merge/clone大Vec。Plugins01把prepare/record feedback合同收敛为generation-tagged immutable ticket，producer边界唯一merge，runtime/debug/stats借用同一payload；reload/revoke使旧ticket可丢弃且age/drop可观测，不允许plugin私建无界队列。见PERF-MVP-415并复用379。
- runtime provider ABI补充：registration当前以String id/priority/Arc trait object表达，热路径已clone provider Arc而非整份registration；HGI/VG/Solari动态调用仍可与framework state锁重叠，automatic VG还允许同步asset load closure。本轮只把HGI/VG filtered readback known-input growth清零。Plugins01按PERF-MVP-409冻结generation+dense provider slot，按379拆CPU prepare与render apply，禁止callback持有全局state锁或做同步I/O；按415让reload/revoke原子淘汰旧ticket。
- VG culling artifact ABI补充：runtime production plan仍在CPU以owned DTO执行ordinal/count重复扫描、frontier排序与lineage多重遍历。Plugins01联动Render03/04按PERF-MVP-421把compiled dense hierarchy/index与bounded cull/request/feedback handles纳入provider generation；reload/revoke原子失效相关artifact，插件不得返回第二份全量CPU plan或无界request queue。
- renderer descriptor generation补充：plugin feature当前在apply/filter/validation/compile/report间重复返回owned name与完整descriptor。Plugins01按PERF-MVP-422让冻结catalog发布interned feature ID、immutable pass/resource ranges和generation；register/reload/revoke只失效affected compiled artifact，稳定plugin descriptor clone/全表filter=0，并由Render01的dense analysis消费。
