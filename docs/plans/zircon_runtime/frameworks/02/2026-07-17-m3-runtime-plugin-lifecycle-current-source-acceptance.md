## Scope Delivered

- `RuntimePluginDescriptor` 只内嵌一份内核 `ModuleDescriptor`；`RuntimePlugin` 的 lifecycle 访问直接投影该 descriptor，`RuntimePluginRegistrationReport::from_plugin` 只注册一份 module row。
- 当前第一方插件结构审计覆盖 28 个 RuntimePlugin descriptor roots：0 descriptor single-source violations、0 free-function registration sites、0 registration compatibility shim sites。
- `plugin_interface_imports` 加入后，`RuntimeExtensionRegistry` 已有 21 个 typed extension points；本轮把 finalize coverage guard 的显式基数从 20 同步到 21，并继续要求 typed fields、`freeze()` 与 `is_frozen()` 三集合完全相等。
- Plugin SDK 的 38 个 package declaration owner 已统一使用 `declare_plugin!`；runtime descriptor 与 native ABI v3 entry/registration manifest 由同一 `PluginDeclaration` 投影。runtime descriptor 只投影 `runtime_registration` / `runtime_editor_registration` 能力，拒绝把 `editor_registration` 或 `requested_only` 误报为 runtime provider。SDK runtime 回归锁定默认 `InitLevel::Post`、空 module dependency 与 package manifest module row 一致。
- 当前 28 个 RuntimePlugin descriptor roots 均由声明投影；原先 15 个直建 `RuntimePluginDescriptor::builder` 的根已硬切到 `PluginDeclaration::runtime_declaration(...).into_descriptor()`，package `default_packaging` 不再手工追加 `NativeDynamic`。结构审计同时拒绝 direct builder、缺失声明投影和重复 packaging push，不保留兼容构造路径。
- native loader 的 capability grant 同时遍历 package 顶层 module 与匹配 entry kind 的 feature-extension module/dependency；Sound 的两个 native feature provider 因此可从真实 package manifest 获得其声明请求，editor/runtime kind 仍严格隔离。SDK runtime declaration wrapper 补齐 provided-interface 的类型化转发，不暴露第二套 builder。
- Checked-in `plugin.toml` 继续是 Rust 声明生成物快照并可由 dist `include_str!` 打包；完整字段的声明→快照同步与一致性门属于 Frameworks 04 M1/M2，当前 M3 不把 header/self-include 断言冒充完整 manifest 单源验收。
- 退役 `native_plugin_manifest_v3!` 的 module mount 和源文件已物理删除；`native_dynamic_fixture` 已硬切到 `declare_plugin!`，ABI descriptor 只嵌入带 generated header 的 manifest snapshot，不保留旧宏、alias 或 shim；快照全字段同步仍由 Frameworks 04 的 generator closeout 负责。
- 不恢复旧 PluginLifecycle、兼容 alias/shim、第二套 module descriptor 或第二次 module registration。
