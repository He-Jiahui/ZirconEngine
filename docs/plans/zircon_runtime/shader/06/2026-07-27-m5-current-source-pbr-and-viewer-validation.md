## Scope Delivered

This record retains the pre-direct-present current-source evidence for the environment-only PBR profile. It is not an acceptance record for the active M5: subsequent direct-present timing, Base-pipeline prewarm, and deferred on-demand changes require the newer M5 follow-up gates before any milestone commit.

- Standard PBR direct lighting consumes clamped, per-pixel metallic, F0, and Lambert diffuse factors in forward, deferred, and fallback paths instead of recomputing material terms for every light.
- Ambient occlusion applies only to ambient, environment IBL, and baked indirect terms. Direct directional and punctual radiance in forward, deferred, and fallback paths is unaffected by AO.
- Environment reflection uses the PMREM roughness-to-LOD path whenever source cubemap or realtime IBL data exists. The no-PMREM procedural-sky fallback samples only the reflected direction and does not synthesize a rough lobe from the normal direction.
- When probes exist but a selected probe has zero blend weight, environment reflection now skips that probe's cubemap sample instead of fetching a value that is multiplied by zero. The primary and secondary gates preserve the existing probe/sky weighted-composite formula.
- When the existing environment occlusion contract clamps to zero, `zr_environment_pbr_components` now returns zero diffuse/specular before normal normalization, SH/IEM, PMREM, and BRDF work. This is equivalent to the previous final multiplication by zero while removing all environment sampling for fully occluded pixels.
- Reference-engine cross-check: cmft's radiance filter decreases glossiness monotonically with mip and cmftStudio exposes roughness/glossiness as an explicit material choice. Zircon's PMREM producer deliberately uses its own nonlinear `1.2` roughness scale. The source-cubemap contract maps runtime roughness with `max_mip - 1.0 + 1.2 * log2(clamped_roughness)` and bakes with its canonical inverse; full roughness therefore selects `max_mip - 1`, while the terminal 1x1 mip remains the six-face average. This changes PMREM content and sampling LOD, so `IBL_BAKE_ALGORITHM_VERSION` is `2026_07_31_0004` and invalidates older artifacts rather than mixing generations.
- The viewer keeps its loading state until an immutable IBL load report is available; it cannot display a `Ready` title while IBL is unavailable.
- Realtime IBL now leaves its two cubemap buffer sets, capture recorder, and timestamp collector unallocated until the first procedural-sky frame. HDRI-only PBR construction therefore does not pay that resource or capture-pipeline setup cost; the scheduler still initializes before bind-group sampling on the first procedural frame.
- Coordinator topology refresh records ordinary plan-text updates as a new immutable content version and advances only the active-version pointer; it preserves existing milestone nodes, dependencies, and gate history while allowing the M5 plan status record to enter the next validation context.
