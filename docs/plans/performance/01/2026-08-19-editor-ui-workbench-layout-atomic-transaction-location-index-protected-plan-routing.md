# Protected plan routing: Workbench layout atomic transaction and location index

## Reason for routing

The Performance01 ledgers and numbered owner plans are shared authorities. Optimize13 and the
reviewed layout source/tests also contain foreign in-progress changes. This record routes current
39/39-file evidence without overwriting or rebasing those owners. Detailed evidence source:
`2026-08-19-editor-ui-workbench-layout-atomic-transaction-location-index-architecture-review.md`.

## Requested Performance01 updates

### PERF-MVP-077

Upgrade from generic full-layout recompute to the following explicit P0 contract:

- Open/Move/Attach/CreateSplit detach before target validation, so an `Err` can delete the source
  placement and leave the legacy drawer mirror stale.
- One local command global-scans all placements, normalizes every drawer, deep-clones active drawers,
  then the host repeats the mirror and full metadata/window/native synchronization.
- `LayoutDiff { changed: bool }` discards affected identities and forces downstream rediscovery.

Required solution: one `LayoutAuthority`, stable node/stack IDs, instance placement index,
prepare/commit/abort transaction, generation precondition and typed bounded delta. Every typed error
is a byte-for-byte live-state no-op. Same-state input must perform zero transaction, normalization,
metadata, event, native and persistence work.

### PERF-MVP-097

Correct the partial-green wording. Canonical `activity_windows()` borrowing is useful, but
`active_activity_window_drawers()` still deep-clones the active drawer map, the serialized legacy
`drawers` field remains a second authority, and manager plus host synchronize it repeatedly.
Acceptance requires schema-v2 one-way migration and current writes containing only canonical
activity-window drawers; it is not satisfied by a borrowed read path.

### PERF-MVP-131, PERF-MVP-602 and PERF-MVP-603

Make all layout batches depend on the same atomic transaction and typed delta:

- grouped resize commits both affected slots once;
- floating-window close removes K views in one all-or-nothing decision/commit;
- tab drop validates source, target, anchor, policy and generation before one placement edit.

Each logical action may publish at most one generation, metadata delta, event, native sync and
persistence request. Failure or cancel publishes none.

### Pending/review accounting

Record `zircon_editor/src/ui/workbench/layout/**` as `39/39 static reviewed, dynamic pending`, with
the evidence document above. Do not move any file to `review.md`: current-source Cargo, failure
invariants, scale counters, F4 and WPR/ETW/power gates are all open.

## Requested Optimize13 updates

Optimize13 already identifies the broader command, restore, schema, dirty-document and native-window
correctness failures. Add the performance contract without creating a parallel owner:

- M0 counters: source/target lookup probes, visited windows/drawers/nodes/tabs, subtree/mirror clone
  bytes, host metadata/registry/native sync calls, commit generations and delta cardinality;
- M1: stable placement index and typed affected-ID delta are part of `LayoutAuthority`, not a later
  UI cache;
- M2: legacy drawers are migration input only and are never regenerated by current serialization;
- M3/M4: committed generations feed coalesced persistence and staged restore; consumers never
  rescan the full layout to infer a known edit;
- M7: include `1/100/1k/10k/100k` tabs/views, depth `1/8/64`, batch `1/8/128/1k`, no-op storms and
  WPR/ETW allocation/lock/latency/RSS/package-power measurements.

Preserve Optimize13's hard boundary: dirty decisions stay with Editor02, plugin owner leases with
Editor06, and current-product presentation diff with Editor01/EditorUI08.

## Requested EditorLayout07 updates

Own the domain API and invariants:

- canonical versioned layout schema, stable node/stack/placement IDs and unique instance placement;
- local stack/subtree operations and explicit relocation/open/close lifecycle;
- bounded typed commit delta and generation;
- schema budgets, deterministic migration/repair, unknown-owner placeholder and exact topology;
- no compatibility mirror or Boolean-only diff in the current runtime model.

Use Unreal `SDockingTabStack.cpp:252-315,1410-1527` and
`TabManager.cpp:3171-3208` as the primary lifecycle/locality evidence. Do not claim Unreal relocation
is globally O(1); the required Zircon property is bounded affected-stack/subtree work with indexed
placement lookup.

## Requested EditorUI08 updates

Consume the layout commit delta instead of rebuilding metadata from the full layout:

- patch affected page/drawer/tab/window/focus identities only;
- update window registry and native targets from topology/placement delta;
- publish at most once per transaction generation and skip all work for unchanged input;
- keep command/session/registry locks out of model build, persistence and native callbacks;
- reuse PERF-MVP-131/602/603 batch transactions rather than adding per-interaction layout caches.

The existing full-reflection failure remains open until layout delta, UI generation and frame
coalescing are jointly proven by scale counters and product traces.
