# Generated MikkTSpace tangents must match the mesh vertex basis

**Draft — tests and source evidence only.** This asset-generation failure is separate from the mirrored instance TBN test oracle. The unchanged ZE fixture reports `T=(0,1,0)`, `w=+1` where the mirrored UV triangle requires `w=-1`.

1. **Difference.** UE's static mesh paths use a MikkTSpace adapter (`Engine/Source/Runtime/StaticMeshDescription/Private/StaticMeshOperations.cpp:1736–1799`) and an explicit vertex-factory convention for reconstructing the bitangent (`Engine/Shaders/Private/LocalVertexFactory.ush:650–659`). ZE's [generated path](../../../zircon_runtime/src/asset/assets/mesh/tangents.rs#L576-L611) negates the library sign on output even though ZE's unchanged positions, normals, UVs and [shader convention](../../../zircon_runtime/src/graphics/shader/template/material_surface.rs#L234-L240) require the encoded sign for the tested triangle.
2. **Effect.** `(P0,P1,P2)=(0,+X,+Y)`, `N=+Z`, `(UV0,UV1,UV2)=(0,+V,+U)` gives `dP/du=+Y`, `dP/dv=+X`. ZE stores `+1`, which reconstructs `-X`, opposite the intended normal-map V direction. This is a measured CPU asset discrepancy, not a measured rendered artifact or performance regression.
3. **Cause and UE evidence.** UE does store `-BitangentSign` in its callback, but its computed face normal for that corner order is `cross(P2-P0,P1-P0)` for its left-handed mesh winding (`StaticMeshOperations.cpp:36–48`). ZE [computes the opposite cross order and passes authored tangents through](../../../zircon_runtime/src/asset/importer/ingest/indexed_mesh_projection.rs#L194-L245). Compare the reconstructed direction, not raw UE serialization bits. The available UE source gives the build and shader contracts; there is no executed UE binary or same-input UE automation result.
4. **Rust approach.** Preserve the `bevy_mikktspace` encoded sign for a computed corner; preserve ZE's existing `+1` fallback when the library returns no corner basis. The library/version, tangent splitting, target-frame projection and shader are not being replaced. Freeze an analytic material-facing comparison against authored tangent data before changing production.
5. **Interface/ECS boundary.** Tangent `xyz,w`, vertex channel layout, materials, GPU instance mirror sign, morph representation and Prefab stay unchanged. Already cooked generated tangents require regeneration, not a global sign change of loaded assets. Review both existing glTF import descriptors' reuse boundaries before landing a fix; UE static mesh derived data includes its builder version in the key (`Engine/Source/Runtime/Engine/Private/StaticMesh.cpp:3744–3756,3792–3797`).
6. **Concrete ZE change.** The [mirrored UV regression](../../../zircon_runtime/src/asset/tests/assets/mesh/tangent_generation.rs#L107-L199) observes the output direction against the same authored frame. The existing regular UV, splitting, authored and degenerate fallback controls remain. The initial local candidate changes the Mikk adapter and uses the existing importer version contract for cache invalidation; no change to the asset/runtime format is proposed. UE explicitly versions mesh-builder output (`Engine/Source/Developer/MeshUtilities/Private/MeshUtilities.cpp:136–140`). The candidate is not in this Draft branch.

## Morph compatibility: one endpoint cannot produce a tangent basis

1. **Difference.** ZE regenerates tangents for each morph target if the importer had to generate the base stream; then it compares each target sign to the base sign. UE's Interchange glTF code decodes an authored tangent displacement as XYZ with `W=0` (`Engine/Plugins/Interchange/Runtime/Source/Parsers/GLTFCore/Private/GLTF/GLTFMesh.cpp:152–167`) and adds that displacement to the base tangent rather than storing a new target sign (`Engine/Plugins/Interchange/Runtime/Source/Parsers/GLTFCore/Private/GLTFMeshFactory.cpp:289–338,593–619`). These UE paths are a representation reference, not an identical generated-morph oracle.
2. **Potential effect.** A generated mirrored mesh can collapse to a point or expand from one at a target endpoint. Treating the undefined endpoint as a real `+1` basis may turn a previously accepted import into `MorphTangentHandednessMismatch` after the sign correction. This is a source-derived risk, not an observed import failure yet.
3. **Cause.** A solitary collapsed triangle cannot obtain tangent space from a neighbor; the Mikk callback returns no basis. The local candidate preserves the fallback `+1` but changes the valid mirrored endpoint to `−1`. The existing ZE [guard](../../../zircon_runtime/src/asset/assets/mesh/tangents.rs#L111-L134) can compare those as if both were computed results. UE's XYZ displacement cannot author a second sign.
4. **Rust test.** Two existing-harness [admission probes](../../../zircon_runtime/src/asset/tests/assets/mesh/tangent_generation.rs#L382-L455) use exact P=(0,X,Y) versus three coincident positions, constant +Z normals and the same mirrored UVs, in both directions. They preserve existing non-failing import behavior if the source hypothesis is borne out. They are not evidence that shading at the healthy endpoint is correct.
5. **Interface/ECS boundary.** Keep the base sign and morph XYZ channel contract. A follow-up must distinguish missing values from valid sign changes and must not hide a genuinely unrepresentable change or make the expanded endpoint use a wrong valid basis. No shader, ABI, ECS or Prefab change.
6. **Gate.** Run the same new admission probes on unchanged runtime and on the retained initial candidate, then verify any follow-up reconstructs the correct basis where geometry is valid. Treat an uncomputed base sign as undecided only if all valid target bases agree, if that approach proves viable; do not drop the valid-vs-valid sign check. Until this is resolved, keep #141 tests-only and do not merge or ship the local production candidate.
