# Generated MikkTSpace tangents must match the mesh vertex basis

**Draft — generated tangent orientation and morph compatibility.** This asset-generation defect is separate from mirrored instance TBN. The old ZE fixture reports `T=(0,1,0)`, `w=+1` where the mirrored UV triangle requires `w=-1`. The production change keeps the selected Mikk basis and does not add a per-target handedness channel.

1. **Difference.** UE's static mesh paths use a MikkTSpace adapter (`Engine/Source/Runtime/StaticMeshDescription/Private/StaticMeshOperations.cpp:1736–1799`) and an explicit vertex-factory convention for reconstructing the bitangent (`Engine/Shaders/Private/LocalVertexFactory.ush:650–659`). The old ZE generator negated the library sign on output even though its unchanged positions, normals, UVs and [shader convention](../../../zircon_runtime/src/graphics/shader/template/material_surface.rs#L234-L240) require the encoded sign for the tested triangle. The [adapter now preserves the encoded result](../../../zircon_runtime/src/asset/assets/mesh/tangents.rs#L749-L759).
2. **Effect.** `(P0,P1,P2)=(0,+X,+Y)`, `N=+Z`, `(UV0,UV1,UV2)=(0,+V,+U)` gives `dP/du=+Y`, `dP/dv=+X`. Old ZE stores `+1`, which reconstructs `-X`, opposite the intended normal-map V direction. This was measured at the CPU asset and actual Deferred G-buffer boundaries; it is not a claim about lighting performance or an editor screenshot.
3. **Cause and UE evidence.** UE does store `-BitangentSign` in its callback, but its computed face normal for that corner order is `cross(P2-P0,P1-P0)` for its left-handed mesh winding (`StaticMeshOperations.cpp:36–48`). ZE [computes the opposite cross order and passes authored tangents through](../../../zircon_runtime/src/asset/importer/ingest/indexed_mesh_projection.rs#L194-L245). Compare the reconstructed direction, not raw UE serialization bits. The available UE source gives the build and shader contracts; there is no executed UE binary or same-input UE automation result.
4. **Rust approach.** Preserve the `bevy_mikktspace` encoded sign for a computed corner; preserve ZE's existing `+1` fallback when the library returns no corner basis. The library/version, tangent splitting, target-frame projection and shader are not being replaced. Freeze an analytic material-facing comparison against authored tangent data before changing production.
5. **Interface/ECS boundary.** Tangent `xyz,w`, vertex channel layout, materials, GPU instance mirror sign, morph representation and Prefab stay unchanged. Already cooked generated tangents require regeneration, not a global sign change of loaded assets. Review both existing glTF import descriptors' reuse boundaries before landing a fix; UE static mesh derived data includes its builder version in the key (`Engine/Source/Runtime/Engine/Private/StaticMesh.cpp:3744–3756,3792–3797`).
6. **Concrete ZE change.** The [mirrored UV regression](../../../zircon_runtime/src/asset/tests/assets/mesh/tangent_generation.rs#L107-L199) checks actual output direction against the same authored frame. The existing regular UV, splitting, authored and degenerate fallback controls remain. The patch changes the Mikk adapter and bumps both glTF importer identities from 4 to 5 under the existing cache contract, without changing asset/runtime formats. UE explicitly versions mesh-builder output (`Engine/Source/Developer/MeshUtilities/Private/MeshUtilities.cpp:136–140`).

## Morph compatibility: one endpoint cannot produce a tangent basis

1. **Difference.** ZE regenerates tangents for each morph target if the importer had to generate the base stream; then it compares each target sign to the base sign. UE's Interchange glTF code decodes an authored tangent displacement as XYZ with `W=0` (`Engine/Plugins/Interchange/Runtime/Source/Parsers/GLTFCore/Private/GLTF/GLTFMesh.cpp:152–167`) and adds that displacement to the base tangent rather than storing a new target sign (`Engine/Plugins/Interchange/Runtime/Source/Parsers/GLTFCore/Private/GLTFMeshFactory.cpp:289–338,593–619`). These UE paths are a representation reference, not an identical generated-morph oracle.
2. **Effect.** The same two isolated triangle admission cases ran on Windows/MSVC: old `2abe3885a` admitted both; the first sign-only candidate `4d368b204` rejected both with `MorphTangentHandednessMismatch { target_index: 0, vertex_index: 0 }`. Stable glTF's actual healthy output on the old path has `N=+Z, T=+Y, w=+1, B=−X` after expansion, expected `B=+X`. Old admission is not proof of correct direction.
3. **Cause.** A solitary collapsed triangle cannot obtain tangent space from a neighbor; the Mikk callback returns no basis. The sign-only candidate preserved the fallback `+1` but changed the valid mirrored endpoint to `−1`. Its old guard compared those as if both were computed results. The final [guard](../../../zircon_runtime/src/asset/assets/mesh/tangents.rs#L563-L620) distinguishes missing corners from computed constraints; an XYZ displacement still cannot author a second sign.
4. **Rust test and proposed approach.** The original [admission probes](../../../zircon_runtime/src/asset/tests/assets/mesh/tangent_generation.rs#L382-L455) stay unchanged. The [stable importer regression](../../../zircon_plugins/gltf_importer/runtime/tests/generated_tangent_contract.rs#L92-L200) also checks the authored +Z normals, mirrored UV Jacobian and resulting `cross(N,T)*w` at the healthy endpoint. Keep temporary `Some`/`None` provenance until all target constraints are checked. An uncomputed generated base sign can take the unanimous valid target sign; a valid or authored base is fixed. Do not infer provenance from the fallback's numeric value.
5. **Interface/ECS boundary.** Keep one base sign and morph `xyz` only; no shader, asset/ABI, ECS or Prefab change. Two viable target signs that differ on a shared output vertex cannot be encoded. The two-target fixture varies which triangle is healthy and uses opposite UV determinants, rather than flipping only position winding with identical UVs.
6. **Gate.** The unchanged stable integration produced three wrong healthy directions. The two-opposite-target test reached the importer but reported a premature `target=0, vertex=0`; the regression requires the second valid target's `target=1, vertex=0` conflict, so arbitrary early errors or removing all conflicts are not success. All six frozen integration cases were behavioral RED on the old input. The separate old two-call direction checks remain mandatory even when the combined production importer works. The earlier lit diagnostic did not distinguish its controls and is not evidence.

## Provenance on the historical stacked comparison

- Both production importers call a combined Rust generation/rebuild entry point so `None` is not materialized as a handedness constraint. Only a missing generated base can adopt its valid targets' unanimous sign. A valid or authored base is fixed. Splits, base sign and deltas are rolled back on failure. The runtime shader still consumes one base sign and XYZ morph deltas, as in UE's glTF representation. Generated import output changes, so the local candidate bumps both importer identities from 4 to 5 by the existing rule (see the UE mesh builder version cited above).
- Real stable importer, identical exact six tests: **0/6 → 6/6**. Both healthy endpoints are oriented correctly; same-sign targets succeed. The opposite-sign target remains an error at precisely `target_index=1, vertex_index=0`, not at the first target and not ignored. Runtime scoped CPU: **29/31**. The authored-fallback-value and split rollback controls pass. The unrelated old authored fixture failure remains in #143.
- That earlier candidate (`268109540`) still failed the **original two-call** probe for an undefined base expanding into a negative-sign frame. Once the first call publishes the stream, the second call cannot distinguish generated `[1,0,0,+1]` from identical authoring. This is why the follow-up below acts during generation, not during a later fixed-base rebuild. The original comparison stays unchanged.

## Legacy two-call constraint: determine handedness before the fallback is published

The original two tests remain unchanged. The [two added unit controls](../../../zircon_runtime/src/asset/tests/assets/mesh/legacy_morph_generation.rs) use the same `MeshAsset` suite and do not call the newer combined entry point:

- With the base collapsed, two viable mirrored targets should each reconstruct `T=+Y`, `B=+X` under either supported normal policy. The first legacy call may fill the generated base sign while it still knows the basis is missing; it must not publish target deltas. Reconstruct direction from the actual base plus XYZ deltas, not just the admission return value.
- An unindexed, still-collapsed probe in a target has two potential donors at the same position/UV, but their different normals prevent indiscriminate welding. Keeping the imported probe normal selects the mirrored donor; flat reconstruction uses the degenerate face's normal fallback and selects the opposite donor. Those policies cannot share one sign at the probe; the two healthy donors can still use their respective signs, and an incompatible fixed-base rebuild must fail without publishing partial target deltas.

UE selects authored or reconstructed normals at the point where the morphed positions are available (`Engine/Plugins/Interchange/Runtime/Source/Parsers/GLTFCore/Private/GLTFMeshFactory.cpp:515–516,545–550,565–599`). The imported tangent displacement still has no `w` (`GLTF/GLTFMesh.cpp:152–167`). The pinned `bevy_mikktspace` 1.0.0 computes the UV sign for healthy faces but welds positions, normals and UVs before borrowing a neighboring basis for degenerate triangles (`src/mikktspace.rs:93–118,338–355,842–880`). Thus neither the UV determinant alone nor the materialized `+1` fallback is enough for all corners. UE does not expose ZE's two-stage API; these are ZE regressions for that representation boundary, not claims of byte-for-byte UE output.

Native Windows/MSVC baseline, `5bc2a7e6631080f6f02c6c4fc4d80a042642f533` (unchanged production, exact four cases): both original admission probes passed, both new controls failed. The expanded endpoint was admitted under preserved normals but reconstructed `T=(0,1,0)`, `B=(-1,0,0)`. The second control measured `(probe, regular, mirrored)=(+1,+1,+1)` immediately after base generation. Native exit 101; neither failure was in compilation or fixture setup.

The [legacy generator](../../../zircon_runtime/src/asset/assets/mesh/tangents.rs#L25-L86) now samples real existing target frames only when a referenced slot is newly generated and undefined. If viable policies disagree, it leaves that slot at fallback; the fixed-base rebuild still rejects incompatible computed frames. A failed speculative policy does not make the base-only call fail. The probe retains no delta arrays, adds at most two Mikk passes per target on this gated legacy path, and changes neither signatures nor serialized data. This does not guarantee compatibility if the caller edits the morphs or UVs between calls, or if the two normal policies need different signs. Select the [combined operation](../../../zircon_runtime/src/asset/assets/mesh/tangents.rs#L89-L118) when the normal policy is known: both glTF tangent-generation paths do so and calculate only the selected frames.
