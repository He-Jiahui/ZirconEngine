# Skinned material geometry loses its instance when looking up the palette arena

**Problem-only Draft from `e89349ca51b4e9d024c194cd3bdf645bd25b6c37`.** This does not change runtime, shaders, tests, defaults, or merge gates. Not part of [#141 generated Mikk asset frames](https://github.com/He-Jiahui/ZirconEngine/pull/141), [#140 the affine TBN oracle](https://github.com/He-Jiahui/ZirconEngine/pull/140), or [#223 ordinary HZB motion](https://github.com/He-Jiahui/ZirconEngine/pull/223).

## What the user sees

A material-template draw routed to GPU Skinning or Skinned+Morph can fail before it can produce pixels. An existing offscreen product test reaches capture, then fails Base error-proxy admission with `source_validation_failed`. The direct (not skinned) authored-morph control does return matching pixels. This is not an imported morph normal-map sign failure and is not evidence of wrong bone arithmetic after a valid pipeline. The user sees a failed capture/frame, not an allowed lower-quality fallback or a measured deformation error in that frame.

## Actual owner mismatch

- [The palette arena hard-cut plan](../optimize/zircon_runtime/90/2026-08-27-pfo-4d1k-skinned-palette-arena-hard-cut-plan.md#目标架构) moved from per-draw uniform palettes to two existing scene-owned current/previous storage arenas with instance offsets/counts. The [Rust layout](../../../zircon_runtime/src/graphics/scene/gpu_scene/layout.rs#L92-L111) carries four `u32`s. The [stage/commit owner](../../../zircon_runtime/src/graphics/scene/gpu_scene/prev_skinned_palette.rs#L28-L56) stages the span against the stable instance key and [rolls it only on success](../../../zircon_runtime/src/graphics/scene/gpu_scene/prev_skinned_palette.rs#L82-L97). No change to that ownership or the 192-byte instance ABI is proposed.
- [The WGSL producer contract](../../../zircon_runtime/src/graphics/scene/renderer/mesh/shaders/zr_gpu_scene.wgsl#L104-L137) requires `(instance_index)` for both counts and `(instance_index, joint_index)` for current/previous matrix loads. It fetches the appropriate instance (including supported visible-remap) and chooses the current or prior `base + joint_index`. The [entry point](../../../zircon_runtime/src/graphics/shader/wgsl/zr_template_forward.wgsl#L1-L21) passes the real draw instance index to geometry fetches. Existing [fallback geometry](../../../zircon_runtime/src/graphics/scene/renderer/mesh/shaders/fallback_mesh.wgsl#L130-L218) already passes this index to the arena; do not change that working consumer to add compatibility overloads.
- The templated [Skinned](../../../zircon_runtime/src/graphics/shader/wgsl/zr_geometry_skinned.wgsl#L24-L68) consumer discards the index at its entry and still calls the older zero-/one-argument helpers. [SkinnedMorphed](../../../zircon_runtime/src/graphics/shader/wgsl/zr_geometry_skinned_morphed.wgsl#L33-L57) preserves an index for morph data but not for the current/previous skin lookup [after morph](../../../zircon_runtime/src/graphics/shader/wgsl/zr_geometry_skinned_morphed.wgsl#L180-L195). This is a missed consumer migration, independent of the palette layout and authored affine world chain. `source_validation_failed` is the background WGSL validation path, not a missing adapter or a fallback material tint problem ([validation state](../../../zircon_runtime/src/graphics/shader_source_validate_admission.rs#L370-L387), [error-proxy summary](../../../zircon_runtime/src/graphics/mesh_pipeline_cache/material_pipeline_publish.rs#L466-L491)).

## Actual local Unreal source boundary

Physical local Unreal [Build.version](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Build/Build.version#L1-L10>) is 6.0.0 (branch string `UE5`). [`GpuSkinVertexFactory.ush:537–571`](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Shaders/Private/GpuSkinVertexFactory.ush#L537-L571>) constructs bone matrix inputs from actual instance scene data (`SkinningData`, reference pose handling, current/previous slot and buffer); [the vertex stage](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Shaders/Private/GpuSkinVertexFactory.ush#L826-L829>) supplies the actual instance to blend the addressed bones. [`GpuSkinCommon.ush:220–240`](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Shaders/Private/GpuSkinCommon.ush#L220-L240>) combines buffer offset, instance offset and selected slot before the section/joint index. Ordinary GPU skinning also has a [section-based update path](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Engine/Private/SkeletalRenderGPUSkin.cpp#L925-L954>) with explicit current/previous palettes and bone maps; the separate [scene extension](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Renderer/Private/Skinning/SkinningSceneExtension.cpp#L341-L420>) publishes scene-global buffers through RDG. The relevant comparison is **identity and temporal slot must reach the sampler**, not picking UE section layouts, influence counts, compression or normal basis rules for ZE. No Unreal runtime execution.
