# Legacy navigation writes a world-space next position as a local transform

**Draft — Legacy position-only manager behavior, old vs. candidate.** Old production matches main `e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. The production change is only the verified ordinary Legacy position-only writeback. Independent of physics #145 and plugin registration.

1. **Difference.** The navigation runtime plugin's [registered Update system](../../../zircon_plugins/navigation/runtime/src/plugin.rs#L143-L158) calls the agent manager. With no navmesh loaded, it selects the [Legacy tick](../../../zircon_plugins/navigation/runtime/src/agent.rs#L44-L55). That tick starts from [world position](../../../zircon_plugins/navigation/runtime/src/manager/tick.rs#L51-L62), computes a [world displacement and next pose](../../../zircon_plugins/navigation/runtime/src/manager/tick.rs#L201-L235), and writes that pose through a [local-only ECS setter](../../../zircon_runtime/src/scene/world/hierarchy.rs#L132-L150). UE keeps path following and movement in world space until the component setter converts for the attachment.
2. **Impact.** The executed old Legacy manager advanced a child from world X=11 to **22** instead of 12, storing world X=12 as local X. The same requested world step under a sheared parent moved to approximately `(1.4142,0.7071,0)` instead of `(1,0,0)` and changed the original world basis. The root control passed. Downstream stopping/repath effects were not measured.
3. **Cause and Unreal evidence.** The adapter omitted the world-to-local boundary. In local UE, `Engine/Source/Runtime/AIModule/Private/Navigation/PathFollowingComponent.cpp:1117–1161` computes a path velocity as `(CurrentTarget - CurrentLocation) / DeltaTime` in the direct-move branch. `Engine/Source/Runtime/Engine/Private/Components/NavMovementComponent.cpp:132–135` stores that velocity; `Engine/Source/Runtime/Engine/Private/FloatingPawnMovement.cpp:37–64` turns it into a world delta. `Engine/Source/Runtime/Engine/Private/Components/MovementComponent.cpp:532–537,564–579` dispatches to `MoveComponent`; `PrimitiveComponent.cpp:3325,3502–3503` sends the resolved world position to the component setter. The attachment conversion happens before relative state is written in `Engine/Source/Runtime/Engine/Private/Components/SceneComponent.cpp:3293–3356`. This is a space/ownership reference, not a requirement to copy Pawn, sweeps, or UE `FTransform` algebra.
4. **Rust approach.** Keep the world-space navigation query/displacement. The [position-only branch](../../../zircon_plugins/navigation/runtime/src/manager/tick.rs#L207-L242) uses the checked inverse of the actual parent world matrix and [replaces authored local translation only](../../../zircon_plugins/navigation/runtime/src/manager/tick.rs#L255-L286). This preserves existing local rotation, scale and inherited shear. Missing or noninvertible parents use the existing blocked-agent diagnostic path. The [gameplay-host world transform helper](../../../zircon_runtime/src/script/vm/gameplay_host/transform.rs#L308-L361) illustrates the same checked space boundary. The position+facing branch does not change here: first verify representable and nonrepresentable facing in dedicated cases before touching it.
5. **Interface and ECS.** In UE a movement component owns the world move, with attached-relative values written by its scene component. In ZE a registered dynamic NavMeshAgent can be attached under the [checked hierarchy](../../../zircon_runtime/src/scene/world/hierarchy.rs#L96-L129). The agent manager should not write `WorldMatrix` or detach it. Preserve local authoring, full `parent_world * local`, root behavior and the current movement/reporting contracts; no new ECS component, movement service, or Prefab changes. Crowd, off-mesh traversal, the builtin bridge and DesiredVelocity must be individually qualified; this note makes no executed claim about any of them.
6. **Concrete ZE gate.** The [three frozen tests](../../../zircon_plugins/navigation/runtime/tests/legacy_parented_writeback.rs) reuse the [existing manager fixture](../../../zircon_plugins/navigation/runtime/src/tests/test_support.rs#L27-L49) in an ordinary Cargo integration target; no mocks, new harness or manifest change. They extend the [older Legacy manager control](../../../zircon_plugins/navigation/runtime/src/tests/manager.rs#L72-L101) without compiling unrelated stale libtest fixtures. One world-space +1 step is requested with no loaded navmesh at 0.5 s, speed 2, acceleration 4 and no braking/avoidance/facing change. The translated and sheared-parent cases independently require the correct local point, unchanged parent and correct world endpoint; the latter requires exact authored rotation/scale and identical world linear columns. UE reference tests are `System.Navigation.NavMesh.Pathfinding.PathHasPoints` (`Engine/Source/Developer/NavigationTestSuite/Private/NavMeshPathfindingTest.cpp:94–126`, world path endpoints) and `System.Engine.Attachment` (`Engine/Source/Runtime/Engine/Private/Tests/EngineAutomationTests.cpp:2022–2085`, world/relative checks). Neither exercises the combined path. Borrow their assertions, not their infrastructure.
