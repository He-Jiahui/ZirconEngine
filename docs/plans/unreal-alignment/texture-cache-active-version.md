# [Asset/Texture] 同 ID 重建载荷后经典预备纹理缓存不应误命中

**状态：独立问题 Draft 研究稿，仅源码取证。** ZE 固定e89349ca51b4e9d024c194cd3bdf645bd25b6c37；本机UE为6.0.0 / UE5 / CL0，提交未知，下附实际源路径/符号/行及原始SHA，不公开Epic实现正文。未运行测试、构建、GPU或GUI，未提交生产修复；主回归为ZE源码派生，UE原测只作相邻对照。先独立复核和去重，再开问题Draft；之后才同PR补真实RED/可行修复/同oracleGREEN。不要求全局数字修订单调或引入新的异步加载架构。

## 1. 差异与 ZE 自身合同

ZE 已把**持久资源 ID**、**目录内容修订**、**本次已安装载荷身份**明确分开：[ResourceRecord:15–42](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime_interface/src/resource/resource_record.rs#L15-L42>) 规定提交约束 `revision/state`，导入器提供内容身份；[ResourceSnapshot:6–29](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/crates/zr_resource/src/snapshot.rs#L6-L29>) 规定载荷与记录配对；[ResourceActiveVersionKey:10–39](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/crates/zr_resource/src/active_generation.rs#L10-L39>) 明确覆盖 remove/recreate ABA，用保留的 Arc 分配身份相等，而非数字；[geometry_replay:178–205](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/graphics/scene/resources/resource_streamer/geometry_replay.rs#L178-L205>) 明确接受独立 Removed → Added 之后相同或更小的 content revision。**因此不是要求数字跨删除单调，而是要求缓存不能用碰撞的 `(id, revision)` 宣称旧 GPU 内容是当前成功载荷。** UE 相邻 owner 清除旧 UObject 导出并重新解析身份；其 texture reimport 走显式资源失效/重建（见第 3 点），不等于要求 ZE 改为 UObject/DDC。

## 4. 最小 Rust 方向（待实际 RED，不是本轮修改）

修经典 prepared-texture **消费者键**，不要改 importer、watch 策略、磁盘 revision/UUID 或添加 tombstone。优先复用内部 `ResourceActiveVersionKey`（必要时加原有数值 content revision）作为缓存快路键：hit 只接受同一当前载荷发布；更换时使用同一 authority 下配对的数据与身份，例如基于现有 [snapshot_expected:87–116](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/crates/zr_resource/src/manager/payload_ops.rs#L87-L116>)，而不是读完 snapshot 后独立查询一个可能更新的 key。把键随该 `PreparedTexture` 写入，修同一类型的常规/snapshot hit 和 [mip re-publish:35–52、62–99](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/graphics/scene/resources/mip_streaming/frame_apply.rs#L35-L99>) 的继承/确认，保留数值 revision 供现有报告、非本 issue 的消费者使用；对初始 cold、无 active key/已释放 CPU、reload-failure 既有行为先用相邻控制验收，不能让稳定帧持续重读/重传，不能把任何无 key 的旧 GPU 资源当新发布。若 active key 放大无关的 CPU 租约重驻留，限于已证实的经典导入纹理可用其现有目录 content/provenance 作键补充（只在这条路径已有可靠来源时）；仍要求和上传 snapshot 绑定，不用全项目 epoch 强制同批资源全失效。先不扩大到其它 scalar consumers、negative-cache 或 GPU-device recovery。

## 5. API / ECS 边界

UE 是 package/object 路径 + UObject 实例导出、GC/streamable handle、editor texture resource 生命周期；ZE ECS 存稳定 typed `ResourceHandle<TextureMarker>`，目录 UUID/locator/数字 revision 独立于进程内 Arc 发布，经典 renderer 的 GPU upload 仍由现有 frame transaction 记录（[ensure texture:110–172、201–212](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/graphics/scene/resources/resource_streamer/ensure_texture.rs#L110-L212>)）。只修资源 cache admission / replace，不改 `Sprite2dComponent`、顶点、ECS extraction、scene、AssetRegistry 序列化、Core service/FFI、RHI upload ordering 或插件边界；不引入 UObject 式路径重映射、内存地址持久化或额外测试架构。
