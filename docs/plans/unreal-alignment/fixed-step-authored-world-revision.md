## Difference and consequence

ZE [registers a solver step and a scene writeback as fixed stages](../../../zircon_plugins/physics/runtime/src/runtime_system.rs#L47-L60). The [writeback system](../../../zircon_plugins/physics/runtime/src/runtime_system.rs#L139-L155) applies the same-World snapshot under a replacement-epoch guard. Updating a changed pose through the normal [authored transform entry](../../../zircon_runtime/src/scene/world/hierarchy.rs#L132-L150) legitimately changes the [World synchronization revision](../../../zircon_runtime/src/scene/world/generation.rs#L80-L93) and invalidates [affected component/derived state](../../../zircon_runtime/src/scene/world/typed_api/component_mutation_effects.rs#L34-L77). However, the [original fixed stage and commit checks](https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/scene/module/world_driver.rs#L48-L125) compared against the frame's earlier content revision and rejected a normal in-place change as a generation mismatch. Replacement identity and pinned schedule execution are separate concepts. Aborting the time transaction [does not roll back World writes](../../../zircon_runtime/src/scene/world_time/controller.rs#L373-L402).

In real registered ZE/Jolt tests, one root Dynamic sphere (no parent, shear, collider offset, gravity, angular motion, damping or collisions) produced `Stage(FixedPostUpdate)`: **expected world generation 7, found 8, committed steps 0, remaining debt 15.625 ms**. Same failure on local `d935f87262c3c4c318199966a09ab386cf48d7be` (exact #198 producer, original applier) and `74b8dbac9eeb898ee87d05c5f6edbf40169f7d4d` (that producer plus exact #145 applier). The intact root fixture checks the pre-tick valid/centered descriptor. The failure cuts off its post-tick native-pose and clock checks; this is not yet a full native trajectory, acceptance on unchanged main, a scene rollback measurement, or a solver error. Orthogonal parent fixtures on the latter tree likewise report 10→11. The root isolates this question from the separate loss of an otherwise representable pure translation under affine shear.

## Candidate — execution identity, not content identity

The [Level frame admission and clock settlement](../../../zircon_runtime/src/scene/level_system.rs#L235-L321) keep one pinned World/plan lease *and* its captured Level replacement epoch. Before and after each fixed stage, [the driver](../../../zircon_runtime/src/scene/module/world_driver.rs#L48-L123) checks the same execution. The commit checks it again while still holding the World lane, then settles the unchanged active time token using the existing World→clock lock order. Internal Level reset that retains the plan still revokes time settlement, while same-World authored writes do not. A step's revision stamp is observed at admission and shared across its callbacks; it does not authorize a live-content equality check when committing. If the frame is already retired at issuance, the clock attempt is aborted under both locks; no committable token can escape to a later stage even if the old schedule is reattached.

Actual byte-matched candidate `ad7a6f805554016bca5dbb98b6a7efda12e8ae46`: Jolt **3/3**, exit0. With one frame per step or both steps in a single frame, same actual Jolt handle, native and authored pose both reach `(4,0,3)`, two steps committed, debt zero. Authored revision advances **7→9** and cached `WorldMatrix` is correct; resting Simulate remains unchanged. The same Scene library suite is **13/13**, exit0: the authored case now runs all six callbacks and commits both 10 ms steps, `x=2`, revision **4→6**, correct cached transform and zero debt. The schedule-only change and staged Level reset both still retire the old step without consuming 10 ms debt, then retry successfully on a fresh frame. All ten frozen historic controls pass. Two existing checks for paired frame capture under a real reset and committed interpolation endpoints pass **2/2** on both binaries, counted separately.

Original stage ordering, active clock token/explicit error/debt contracts, normal mutation invalidation and strict stale-content publication checks are not relaxed. This does not add per-callback replacement polling, rollback for already executed callbacks/solver writes, or a guarantee about detached and reattached owners that no check observes.
