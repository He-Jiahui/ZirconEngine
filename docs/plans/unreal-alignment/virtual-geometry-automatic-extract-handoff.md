# Scheduled scene Virtual Geometry drops the automatic source before native execution

**Problem-only Draft; separate from ordinary affine #135, moving HZB #223 and skinned templates #226.** No code, fixtures, feature defaults, checks or merge changes. The narrow question is whether the one selected same-frame virtual geometry payload reaches both Runtime and the actual registered executor. Affine bounds and depth position changes are explicitly out of scope for this issue.

## What the user would see, and the evidence boundary

On a supported viewport where Virtual Geometry is enabled and a resident cooked primitive is admitted, the scheduled scene may report an authored payload with no clusters rather than using its discovered automatic mesh source. The indexed material path intentionally refuses whole-mesh replay for a captured but explicitly unbound primitive. This is a source-reachable loss of the requested draw path, not a measured dropped affine fragment, not the intended software fallback, and not evidence that the native plugin cannot render any caller. A new target requirement is to reproduce the real scheduled World → registered native plugin path without replacing the extract in a test or settings panel.

## Two halves of the same frame handoff

1. The [World prepared extractor](../../../zircon_runtime/src/scene/world/render.rs#L152-L179) runs RenderExtract on the real scene input. It constructs [an empty VG `Some` for debug settings](../../../zircon_runtime/src/scene/world/render.rs#L193-L204) while separately publishing the optional debug sideband; an [inactive camera placeholder](../../../zircon_runtime/src/scene/world/render.rs#L765-L780) carries no scene geometry either. This was a known empty-slot convention: an [existing test](../../../zircon_runtime/src/graphics/tests/m5_flagship_slots.rs#L13-L30) contrasts it with the synthetic snapshot adapter's `None`. The [submission owner](../../../zircon_runtime/src/graphics/runtime/framework/extract/submission/build.rs#L180-L203) treats every `Some` as authored topology, builds automatic sources when enabled, then prefers the placeholder. It [binds the authored topology](../../../zircon_runtime/src/graphics/runtime/framework/extract/submission/build.rs#L234-L284); [unbound captured admissions](../../../zircon_runtime/src/graphics/virtual_geometry_runtime_provider/extract_output.rs#L119-L179) keep zero authored rows, which the [indexed draw planner](../../../zircon_runtime/src/graphics/scene/renderer/mesh/mesh_draw/indexed_plan.rs#L133-L164) correctly does not turn into full-mesh commands. Do not loosen this last gate: truly explicit empty author choices are meaningful and must continue to suppress a draw.
2. `None` alone is not a repair. The [chosen extract is a separate context member](../../../zircon_runtime/src/graphics/runtime/framework/extract/submission/build.rs#L438-L443) from the shared submitted frame. [Rendering gets the shared extract](../../../zircon_runtime/src/graphics/runtime/extract/submit/submit_runtime_frame.rs#L349-L358), while renderer [execution data builds an owned author catalog of the chosen extract](../../../zircon_runtime/src/graphics/runtime/framework/extract/submit/debug.rs#L285-L302). The native [node-selection source packer](../../../zircon_plugins/virtual_geometry/runtime/src/executors/selection.rs#L13-L25) instead reads the raw `frame_extract().geometry.virtual_geometry`; it can encounter `VG source extract is absent` or disagree with the chosen catalog indices. This is one source-of-truth fault across admission and execution, not a request to duplicate the raw mesh/cook data in every pass or use the debug output as authority.

Independent archived controls narrow the problem without reproducing the combined path. Seven Windows Runtime CPU selectors confirm the empty World slot, snapshot adapter `None`, and `Some` precedence; two RTX 3060 Laptop/DX12 captures through a direct DTO use a **test provider** and no-op graph executors. The native plugin archive passes one orthogonal bounds/lineage selector and two real hardware kernels (residency/VisBuffer word readback and clip-space raster color); those kernels start from supplied words or pretransformed vertices and do not exercise the handoff. No fresh unchanged-production regression, verified backend for those two plugin kernels, or native scheduled product measurement is claimed here.

## Physical local Unreal comparison

In the local Unreal build 6.0.0 sources (`UE5` branch string, not a binary run), [the deferred renderer](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Renderer/Private/DeferredShadingRenderer.cpp#L1766-L1811>) passes scene, packed view and culling inputs to Nanite, then consumes those raster results in the depth pass. [Nanite instance setup](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Shaders/Private/Nanite/NaniteSceneCommon.ush#L17-L37>) fetches a real `VisibleCluster.InstanceId` and explicit current/previous instance transforms. [Cull](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Shaders/Private/Nanite/NaniteCullingCommon.ush#L527-L532>) uses the chosen instance's current local-to-translated-world matrix; [orthographic support](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Shaders/Private/Nanite/NaniteHZBCull.ush#L414-L439>) uses transformed box center/extent axes. The transferable constraint is coherent instance and payload selection, not GPUScene/Nanite ABI, box size, page streaming, or UE's authored transform model. ZE should retain authored `LocalTransform` and published `parent_world * local_matrix`; the follow-on affine comparison will make its own bounds and depth assertions.
