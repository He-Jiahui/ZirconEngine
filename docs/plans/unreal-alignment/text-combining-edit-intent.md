# [Text/UI] 对照 Unreal：不应丢弃接续前一字素的已准入文本输入

**状态：独立问题 Draft 研究稿，仅源码论证。** 未写入测试或引擎代码，未执行 ZE/UE 测试、构建、GUI 或原生输入实测；没有行为 RED/GREEN。ZE 引用固定在独立基线 [`e89349ca51b4e9d024c194cd3bdf645bd25b6c37`](https://github.com/He-Jiahui/ZirconEngine/tree/e89349ca51b4e9d024c194cd3bdf645bd25b6c37)。UE 是本机参考树，[Build.version:1–10](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Build/Build.version#L1-L10>) 声明 `6.0.0 / BranchName UE5 / CL 0`，提交未知。本机研究稿和 UE 源路径不是 GitHub 可直接读取的证据；仅列路径、符号、行号和文件指纹，不公开 Epic 源码正文。

## 1. 不一致：合法插入能改变原有字素边界

最小见证：一个可见、启用、聚焦、可写的普通 retained `TextInput`，持有字符串 `e`，光标在末尾（UTF-8 字节偏移 `1`），无非空选区、无活动预编辑、无长度上限或限制性字符过滤器。下一条已准入的提交文本只含 **U+0301（组合锐音符）**。期望原样保留分解形式 `e\u{0301}`（UTF-8 `65 CC 81`），光标和折叠选区在字节 `3`。它是一个字素，但编辑差量仍是一次 `Insert`：旧 `1..1`、新 `1..3`。UE Slate 保存字符插入；ZE 将这次编辑路由为 handled，却拒绝提交。

这是 ZE 自身的合同差异，不是要求照搬 UE。普通 [`TextInput` 过滤策略](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/text_constraints.rs#L340-L394>) 允许此标量，且 [Text08 的提交合同](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/docs/plans/zircon_runtime/text/08-ime-and-text-input.md#L486-L516>) 要求发布精确字节差量。一次性把 `e\u{0301}` 输入空字段的起点是字节 `0`，不会触发同一个错误；不能用该控制替代分开输入的见证。

## 2. 实际调用链和有界影响

- **生产入口。** [`RuntimePreparedProject::load_runtime_ui_surfaces`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/dynamic_api/session/project.rs#L376-L410>) 装入项目清单声明、已获准入的 UI。原生运行时 [`RuntimeEntryApp::handle_keyboard_input`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_app/src/entry/runtime_entry_app/keyboard_input/event.rs#L15-L31>) 借用 Winit `KeyEvent.text` 的 [原始字节](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_app/src/entry/runtime_entry_app/keyboard_input/payload.rs#L6-L15>)；[`RuntimeDynamicSession::handle_keyboard`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/dynamic_api/session/events/keyboard_ime.rs#L27-L109>) 解码 UTF-8 并交给 [`RuntimeUiSurfaceSet` 的已聚焦表面](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/dynamic_api/session/runtime_ui/input_routing.rs#L136-L229>)。这是现有键盘文本路径，不依赖某款 IME 分两次提交，也不声称某个操作系统或键盘布局会发出特定按键序列。
- **准入到消费。** [`UiInputManager::dispatch_input_event_with_query`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/dispatch/input_manager/manager.rs#L194-L229>) 携带现有文档会话，[键盘路由](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/keyboard.rs#L27-L67>) 检查焦点所有者后进入文本编辑。普通 [键盘文字提取](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/text_keyboard/payload.rs#L32-L72>) 拒绝控制字符而不拒绝 U+0301，[提交入口](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/editable_text.rs#L173-L192>) 进入共享 `committed_text_state`。另有[直接 Text 事件](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/editable_text.rs#L294-L334>)。若已有匹配且未过期的剪贴板传输，[合法 `ReadText` 完成回执](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/keyboard_clipboard.rs#L162-L274>) 贴入同一后缀也进入这一提交逻辑；这不是原生 Ctrl+V 触发验证，剪贴板不是主见证的前置条件。
- **可见影响。** [`apply_editable_text_state`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/editable_text/mutation.rs#L55-L144>) 先标记处理，再返回 `text_state_transaction_rejected:invalid_edit_intent`。字段仍是 `e`，光标仍是 `1`，不发布这次 `ValueChanged`/`TextEditChange`，不推进这次提交的文档版本或撤销历史；[双准备后才发布](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/editable_text/mutation.rs#L230-L284>)。限定为已准入的非预编辑文本在该接缝的丢失，不宣称数据损坏、字体/整形失败或所有输入法受影响。

## 3. 根因与 UE 的真实处理

**ZE：** [`committed_text_state`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/editable_text/state_transition.rs#L46-L87>) 将清洗后的数据交给 `Insert`。[文本编辑所有者](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/text/edit_state.rs#L211-L229>) 按**旧正文**合法光标生成上述精确差量，新状态的末端光标合法。新正文中的字节 `1` 仍是 UTF-8 标量边界，却不再是扩展字素簇（EGC）边界；[`clamp_grapheme_boundary`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/text/grapheme.rs#L53-L75>) 会回到 `0`。[`CommittedTextEditIntent::is_valid_for_state`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/text/edit_state.rs#L25-L74>) 错把**新正文差量起点**也当作可停光标。[属性预检](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/editable_text/property_transaction.rs#L529-L573>) 因此返回 `InvalidEditIntent`；[独立的交互状态预检](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/surface/input/editable_text/property_transaction.rs#L681-L699>) 在本例通过。这不是过滤器拒绝、旧范围失效或新光标越界。

**UE：** [`FSlateApplication::ProcessKeyCharEvent`](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Slate/Private/Framework/Application/SlateApplication.cpp#L4982-L5029>) 在启用的焦点路径派发；[`SEditableText::OnKeyChar`](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Slate/Private/Widgets/Input/SEditableText.cpp#L281-L296>) 进入 Slate 编辑布局，未装自定义限制时 [`CanTypeCharacter`](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Slate/Private/Widgets/Input/SEditableText.cpp#L702-L709>) 与布局的 [`IsCharAllowed`](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Slate/Private/Widgets/Text/SlateEditableTextLayout.cpp#L106-L118>) 都允许 U+0301。[`HandleKeyChar`](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Slate/Private/Widgets/Text/SlateEditableTextLayout.cpp#L1048-L1087>) 开启事务；[`HandleTypeChar`](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Slate/Private/Widgets/Text/SlateEditableTextLayout.cpp#L1692-L1726>) 调用 [`FTextLayout::InsertAt`](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Slate/Private/Framework/Text/TextLayout.cpp#L2264-L2407>) 更新行正文和 dirty 状态，再推进光标；不以插入段是否恰好与新字素边界重合为准入条件。字素迭代器仍用于[光标导航](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Slate/Private/Widgets/Text/SlateEditableTextLayout.cpp#L3124-L3138>)。[事务结束](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Slate/Private/Widgets/Text/SlateEditableTextLayout.cpp#L3318-L3402>) 保存、广播变化并记录撤销状态。两者的对齐目标是「合法文本编辑不因重新分簇而被拒绝」，不是移植 Slate 的行布局或证明其所有 Unicode 光标规则与 ZE 一致。

## 4. Rust 方案：分开校验精确差量与交互位置

保留旧输入光标/选区的字素边界，以及提交后的光标、选区和活动 composition 的现有边界检查；只在**内部已验证的精确差量**上用有界 UTF-8 字节切片检查（例如 `str::get`）区分非法标量切割与合法字素内部接缝。保持区间顺序、同一起点、长度与种类检查、文档身份和版本、历史来源验证、预算和事务原子性；不开放任意用户提供的字素内部旧位置，也不删除整段校验。Undo 的旧**存储**差量可以位于字素内部，但必须来自当前文档的已验证历史并匹配预期正文，恢复的交互状态仍须合法。

[`TextDocument::prepare_replace`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/text/document/edit.rs#L231-L307>) 和 [`validate_range`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/text/document/storage.rs#L197-L208>) 已支持精确 UTF-8 替换；[字素索引增量路径](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/text/document/index.rs#L58-L108>) 不会把这个非 ASCII 接缝当成可用的 ASCII 快路径。[文档会话](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/dispatch/input_manager/text_document_session/session.rs#L211-L298>) 和 [`UiTextHistoryEntry::transition`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/ui/dispatch/input_manager/text_document_session/history.rs#L86-L133>) 已按精确范围校验并逆用差量。把旧 `1..1` / 新 `1..3` 扩围为整个字素的 `0..1` / `0..3` 会改变回执并把插入误表为替换；不应以 NFC 归一化、无意图直写、全文 diff 或跳过双预检掩盖错误。

## 5. 接口与 ECS 差异

UE 的 `FSlateEditableTextLayout` 与 `FTextLayout` 以 widget、行模型和 `FString`/`TCHAR` 为边界；本例的 BMP 字符使行内偏移从 1 到 2。Slate 使用[旧文本、光标和选区快照](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Slate/Private/Widgets/Text/SlateEditableTextLayout.cpp#L3433-L3495>) 撤销。ZE 以 `UiSurface`、`UiNodeId`、每表面的 `UiInputManager` 和文档 UUID/revision 为权威；中立接口的 [`UiTextChangedRanges` 和 `UiTextByteSelection`](<https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime_interface/src/ui/text.rs#L91-L155>) 把 UTF-8 变化范围与最终选区分开。此处沿用 ZE 的字节差量、配对提交和绑定事件，不改变 DTO/ABI、产品特性、场景 ECS、宿主适配或渲染所有权。
