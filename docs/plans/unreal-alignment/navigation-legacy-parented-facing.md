# Legacy navigation writes an attached agent's world-facing pose as local TRS

**Draft — bounded writeback fix, with old and candidate observations.** This is the ordinary Legacy position-and-facing path intentionally left unchanged by #146 (base `4100e5e5f8a7e366ebfa87c68991f63878557fa4`). Stack on #146 because both changes own the same write boundary. The frozen tests use reachable world `-Z` / `+Z` endpoints and a sufficient angular budget to isolate the parent boundary from #170's yaw sign.

1. **Difference.** ZE's [Legacy tick](../../../zircon_plugins/navigation/runtime/src/manager/tick.rs#L51-L62) starts with the resolved world pose, and [writes world translation/rotation plus projected world scale](../../../zircon_plugins/navigation/runtime/src/manager/tick.rs#L207-L227) through the [authored local-only ECS setter](../../../zircon_runtime/src/scene/world/hierarchy.rs#L132-L150) whenever `update_rotation=true`. UE path movement computes world direction and orientation before the component converts to the attachment's relative space. `update_rotation` defaults to true.
2. **Impact.** The old native manager reported a successful move but the translated child landed at `(20,0,-1)` rather than `(10,0,-1)`. Under a yawed parent both actual position and forward were near `-X` rather than `-Z`. A tilted uniform parent also doubled the authored child scale. Under nested shear with zero angular speed, the old motion landed near `(-1.4142,0,-2.8284)` and changed the full linear basis. These are measured CPU manager results, not editor observations.
3. **Cause and Unreal evidence.** UE `Engine/Source/Runtime/Engine/Private/Components/CharacterMovementComponent.cpp:6624–6670,6755–6777` gets world desired direction from acceleration or requested navigation velocity and steps yaw before `MoveUpdatedComponent`. `PrimitiveComponent.cpp:3325,3502–3503` dispatches to `SceneComponent.cpp:3280–3356`, converting attached world point with the parent inverse and proper rigid rotation with `ParentQ.Inverse() * WorldQ` before setting *only* relative position and rotation. The explicit `SetWorldLocationAndRotation` does likewise (`SceneComponent.cpp:2041–2062`). UE has a separate negative-scale branch and explicitly notes `FTransform cannot represent shear` (`Engine/Source/Runtime/Engine/Private/VisualLogger/VisualLogger.cpp:573–581`); none of these TRS choices are a ZE shear oracle.
4. **Rust change.** The [attached writeback](../../../zircon_plugins/navigation/runtime/src/manager/tick.rs#L249-L323) keeps #146's checked full parent inverse for the point and retains authored local scale. When the prior facing policy produces no turn, the original local rotation is preserved, including under inherited shear. For an actual turn, verify that the parent linear part is a proper rotation times positive uniform scale (Gram check, `1e-5` on normalized columns), and child local scale is positive; only then apply `Q_parent⁻¹ * Q_world`. This follows UE's attachment setter where applicable, and [Three.js r180 Object3D](https://github.com/mrdoob/three.js/blob/r180/src/core/Object3D.js) separates matrix-inverse `worldToLocal` from `lookAt`, which explicitly does not support nonuniform parent scale. The active-turn path for other parents/signed child scale intentionally retains old behavior, including its incorrect position possibility, until that separate contract has evidence.
5. **Interfaces and ECS.** Keep the existing NavMeshAgent, derived `WorldMatrix`, local authoring and single `parent_world * child_local` chain. This review does not introduce any state, transforms, wrappers, alternate movement implementation or prefab change. Ordinary Legacy only: no Crowd, Off-mesh, builtin bridge, DesiredVelocity, hosted module admission or editor claims. Controls must still call the real plugin manager, not a standalone math simulation.
6. **Concrete gate.** The [frozen Legacy target](../../../zircon_plugins/navigation/runtime/tests/legacy_parented_facing.rs) adapts the pose/parent assertions from local UE `System.Engine.Attachment` (`Engine/Source/Runtime/Engine/Private/Tests/EngineAutomationTests.cpp:1543–1556,2045–2085`, attach/detach rather than navigation) and the forward-vector assertion used in `System::Core::Math::Vector Register Abstraction Test` (`Engine/Source/Runtime/Core/Tests/Math/UnrealMathTest.cpp:3858–3875`). It reuses the existing real manager fixture. Native Windows/MSVC on identical test, fixture, lockfile and dependency features: old `71adabea220e386ca9d91b209d9ca6ac65b93c31` **1 passed / 5 failed** (exit 101), candidate `4983563de9473b9b6677176d57f5c5124256517f` **6 passed / 0 failed** (exit 0). All three unchanged #146 position-only controls pass on both. All five failing moves had already reported `scanned/moved/blocked=1/1/0`. No hosted `Update`, Unreal executable, editor or GPU ran for this CPU state boundary.

**Active affine boundary, not a policy change:** with parent linear map `A=Ry(45°)·diag(2,1,1)`, inverse-mapped world X/Z axes have dot `3/8`, so an orthogonal upright world orientation cannot be realized through any local TRS for that case. The geometric forward direction alone can be satisfied without rewriting authored scale. These are different contracts; do not use a lossy world quaternion to claim an exact turn. The frozen regressions do not define how a requested nonrepresentable active turn should be reported.
