# Edit Scene picking can miss a rendered mesh under orthographic camera scale

**Problem-only Draft.** This isolates the Edit viewport's renderer-visible spatial ray, not its mesh frustum, render transform, or Play/SIE GPU HitProxy. No new ZE test result, hardware repro, or production change is included.

1. **Reachable split in camera coordinates.** The Edit [camera seed/reset](../../../zircon_editor/src/scene/viewport/controller/scene_viewport_controller_camera.rs#L10-L58) reads the [active Scene camera world transform](../../../zircon_editor/src/scene/viewport/controller/scene_viewport_controller_camera.rs#L132-L158). `SetProjectionMode(Orthographic)` changes the lens mode, not this pose. Use `User` orientation: non-User alignment can replace the pose with a new unit-scale look-at. In this Edit path the Editor owns the lens; it uses a half-size of `5` by default, not the authored component's orthographic size. Its [prepared render extraction](../../../zircon_editor/src/scene/viewport/controller/build_render_snapshot.rs#L24-L66) passes that camera through `request.camera=Some`. Runtime rendering uses [projection × inverse of the represented transform](../../../zircon_runtime/src/core/framework/render/view_matrix_pair.rs#L12-L32); Editor [screen projection does the same for ordinary orthographic input](../../../zircon_editor/src/scene/viewport/projection.rs#L19-L47). However the [cursor ray](../../../zircon_editor/src/scene/viewport/projection.rs#L88-L119) reconstructs its offset using quaternion `right()` / `up()` and direction using `forward()`, discarding the scale that is still in the displayed view.
2. **Why a regular Edit click is affected.** After a Scene submit the [retained host adopts the renderer's spatial snapshot for that leaf](../../../zircon_editor/src/ui/retained/app/host_lifecycle/render_submission.rs#L118-L152). The [adoption](../../../zircon_editor/src/scene/viewport/pointer/overlay_router/visible_spatial_query.rs#L14-L44) removes the static renderable candidates. A new stable Move or Down calls [the shared dispatcher](../../../zircon_editor/src/scene/viewport/pointer/overlay_router/build_dispatcher.rs#L20-L45); its [one spatial query](../../../zircon_editor/src/scene/precision/renderer_visible_spatial_pick_source.rs#L88-L123) must first find the visible owner, before a correctly projected circle can accept its center. The [renderer query](../../../zircon_runtime/src/graphics/visibility/spatial_query.rs#L180-L233) rejects finite spheres not intersected by the supplied ray. The Edit click [records the Down target and commits on Up](../../../zircon_editor/src/scene/viewport/controller/handle_input.rs#L268-L322); an empty target is a background selection, not an opportunity to retry a GPU pick. The [native Play picker](../../../zircon_editor/src/ui/retained/app/play_viewport_pick.rs#L75-L122) explicitly requires a Simulate session and different gateway/frame identity. This is the normal admitted Edit CPU path, not a `CpuFallback` mode of a GPU pick. One stable session, selection, world, extract, camera and size are enough; reconciling stale displayed images is not needed to show the discrepancy.
3. **Separated numerical input.** Square 256×256 Edit view, half-size `5`, identity local camera under `Sx=0.25` with world X range `[-1.25,1.25]`, world cube center `(0.625,0,-5)` with side `0.4`. The finite cube sphere radius is `sqrt(3)*0.2≈0.346410`. The current and correct frustum both retain the cube (`|2.5| < 5 + 0.346410` in the old view slab), so [#218](https://github.com/He-Jiahui/ZirconEngine/pull/218) is not required. It projects to `(192,128)`; the correct parallel ray crosses world `x=0.625`, but the old rotation-only ray goes down `x=2.5`, missing even the sphere by a lateral offset of `1.875`. The point is the center of the object, not a picking-threshold or silhouette edge. [Three r180 Raycaster](https://github.com/mrdoob/three.js/blob/0af9729d0c143a86a1d725d6e2c3ad83301f3f34/src/core/Raycaster.js) and [Vector3.unproject](https://github.com/mrdoob/three.js/blob/0af9729d0c143a86a1d725d6e2c3ad83301f3f34/src/math/Vector3.js) executed twice on the pinned core: all **16/16** projected samples hit the actual front face in Three, **0/16** after supplying the legacy ZE formula as a reference ray. At unit camera scale both hit **16/16** at the separately projected location `(144,128)`. A literal center cube and empty pixels are independent controls. Negative `Sx` mirrors the geometric location to `(64,128)` in Three; this is not ZE render-winding or reflection acceptance.
4. **Actual local Unreal and managed Unity comparisons.** Local UE `Engine/Source/Editor/EditorViewport/Public/ViewportClick.h:19–41` obtains screen coordinates from the view and uses that view's clip-to-view and view-to-world matrices, with separate perspective/orthographic ray origins. `Engine/Source/Runtime/Engine/Private/SceneView.cpp:1506–1559,1562–1603` supplies the general inverse and homogeneous divide, explicitly subtracts the view rect origin, and normalizes the direction. `Engine/Source/Editor/UnrealEd/Private/LevelEditorViewport.cpp:2841–2863,2902–2943` routes normal actor/element selection through the hit proxy rather than this geometric ray alone. The usable contract is projection and unprojection from the same resolved view, not UE reverse-Z, integer cursor rounding, selection policy, rigid camera or `FTransform`. [Unity 6 managed `HandleUtility`](https://github.com/Unity-Technologies/UnityCsReference/blob/78530831f091cf6d811fd020ed7ad652f10af6fa/Editor/Mono/Handles/HandleUtility.cs#L842-L929) converts GUI points to pixels, subtracts `camera.pixelRect`, uses inverse `projectionMatrix` for the view-space point and `cameraToWorldMatrix` for the orthographic ray; its source comments assume no scale when interpreting depth, and native camera matrix construction is not established by that managed file. Three's camera does invert its full matrix-world. None of these references authorize changing ZE's existing optics.
5. **Bounded ownership and proof.** Keep the correction private to the Edit projection owner and reuse its existing projection/cache/viewport, with finite/invertible handling; do not widen circles, add event-time matrix inversion/scans, change selection priority, alter authored transforms/ECS/user lens, or add an ABI. [#135](https://github.com/He-Jiahui/ZirconEngine/pull/135)/[#144](https://github.com/He-Jiahui/ZirconEngine/pull/144) address mesh affine/bounds transfer, [#206](https://github.com/He-Jiahui/ZirconEngine/pull/206) is Play local writes/gizmo, and #218 is a different visibility rejection. First freeze exact CPU forward-projection/ray-round-trip tests with unit and invalid controls; then use the actual Edit controller/state with the same admitted renderer snapshot from a warm real offscreen submission. Prove finite prepared bounds, stable owners, same viewport/size/scene/submit generation, actual offset cube color, the correct scalar ray hitting its known sphere, center and background controls, and no static-layout fallback, overlays or selection-domain substitution. One stable `Down`→`Up` in Select mode must select the offset cube. A pixel-only or direct math assertion may not be called a complete Edit click repro. First native GPU witness can use positive X scale, no HZB/history or custom projection-matrix override (the normal Edit camera packet remains), and no pan/slot replacement, shear, perspective corrections, or exact triangle/HitProxy policy changes. Run untouched production first; publish any qualifying late RED before modifying production, rerun identical selectors, and leave required checks untouched.
