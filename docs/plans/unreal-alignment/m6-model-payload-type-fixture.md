# M6 model resolution: distinguish a rejected replacement from an incompatible read

**Draft — existing CPU test only.** The test compiled on the local integration candidate with [#137](https://github.com/He-Jiahui/ZirconEngine/pull/137); its remaining failure is independent of that fixture's lifetime repair.

1. **Difference.** The [ZE fixture](../../../zircon_runtime/src/graphics/scene/resources/tests/model_geometry_resolution.rs#L152-L181) expects a registered `MeshAsset` to be replaced by a `u8` under the same identity. UE checks the existing named object's class before attempting replacement (`Engine/Source/Runtime/CoreUObject/Private/UObject/UObjectGlobals.cpp:3518–3544`). This is a test expectation contrast, not a demonstrated runtime divergence.
2. **Effect.** The test stops at `register_ready(...).unwrap()` with `PayloadTypeConflict`, before the resolver's intended `KindConflict` assertion and the true-absence control. The early abort was reproduced in the unchanged CPU executable; no rendered behavior was measured.
3. **Cause and UE evidence.** ZE's [commit preflight](../../../zircon_runtime/crates/zr_resource/src/manager/commit.rs#L48-L86) now preserves concrete payload identity; the [typed read](../../../zircon_runtime/crates/zr_resource/src/manager/payload_ops.rs#L87-L116) independently validates version, kind and downcast. The UE source case rejects an incompatible replacement before allocation. The existing UE `FObjectProperty::CheckValidAddress` test (`Engine/Source/Runtime/CoreUObject/Tests/ObjectPropertyTest.cpp:53–76`) accepts a valid reference and rejects an incompatible one; it is an analogous consumer type guard, not a model-generation or identical-input port.
4. **Rust approach.** Check that the failed replacement leaves the same active generation and the same typed payload reachable. To cover the read-side error, put the deliberately wrong first payload in a different manager and read a fresh capture of that resource.
5. **Interface/ECS boundary.** UE uses `UClass` compatibility and an allocation error; ZE uses exact Rust payload identity and `Result` over captured active generations. Preserve both checks, the stale capture and last-known-good behavior, and reserve inline fallback for actual absence. No ECS, resource contracts or Prefab changes.
6. **Concrete change.** The existing M6 fixture now checks the failed write, the exact unchanged active generation and typed payload, and then the resolver's independent `KindConflict` on a different manager. True absence still exercises inline fallback. No production changes.

The same 12 Windows/MSVC CPU cases went from **9 passed / 3 failed** to **11 passed / 1 failed** with this fixture repair and [#140](https://github.com/He-Jiahui/ZirconEngine/pull/140). All eight model-resolution cases passed; the remaining independent generated tangent failure is tracked in [#141](https://github.com/He-Jiahui/ZirconEngine/pull/141). The local integration candidate includes [#137](https://github.com/He-Jiahui/ZirconEngine/pull/137), which remains a separate build prerequisite touching a different hunk in the same test file. No GPU, UE binary, or editor product result.
