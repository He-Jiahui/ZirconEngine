# Navigation: preserve the affine world center of authored obstacles

**Problem-only Draft.** Base `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. No test changes, behavioral measurements, or implementation yet. Independent of #181 link anchors, #173 bake source triangles, and #158 registry admission. UE citations below refer to the actual local `dev/UnrealEngine` tree.

1. **Difference.** [Plugin obstacle collection](../../../zircon_plugins/navigation/runtime/src/runtime_obstacles.rs#L160-L197) and [built-in obstacle rows](../../../zircon_runtime/src/navigation/runtime/world_scan.rs#L294-L322) both interpret the descriptor's `center` as a local point but transform it after reconstructing a matrix from projected world TRS. Actual Unreal `Engine/Source/Runtime/Engine/Private/Components/ShapeComponent.cpp:168–188` exports dynamic shapes as area modifiers; `Engine/Source/Runtime/Engine/Private/AI/Navigation/NavigationModifier.cpp:539–572` resolves the local box corners before choosing AABB or convex placement.
2. **Expected consequence, to be measured.** This can translate the entire obstacle independently of its shape approximation. An intended world-centered box that spans a walkway can miss it, turning the agent's native path from blocked to passable. The built-in fallback can instead omit steering away from the same nearby authored center. It does not have the plugin's TileCache carve contract.
3. **Cause and Unreal contract.** ZE [already retains the affine world matrix](../../../zircon_runtime/src/scene/world/derived_state.rs#L450-L462); the point is evaluated after a lossy round trip. Unreal `Engine/Source/Runtime/NavigationSystem/Private/NavMesh/RecastNavMeshGenerator.cpp:5501–5524` constructs and passes the resolved box center/extents into Detour marking. `Engine/Source/Runtime/Engine/Private/AI/Navigation/AvoidanceManager.cpp:14–37` receives a resolved world origin independently of radius and height (`Engine/Source/Runtime/Engine/Private/Components/CharacterMovementComponent.cpp:4253–4261`). UE's FTransform is not a shear oracle; ZE's hierarchy uses full matrix composition as in [Three.js](https://github.com/mrdoob/three.js/blob/r180/src/core/Object3D.js) and [Unity Entities](https://docs.unity3d.com/Packages/com.unity.entities@1.3/manual/transforms-concepts.html).
4. **Rust direction only after qualified RED.** Use the same matrix point operation but read the authoritative `WorldMatrix`; preserve per-consumer authored local fallback. Do not change extents, radius, axis alignment, cylindrical anchoring, ABI, obstacle sync/policy, broadphase or writeback rotation. Each changed consumer must first show its own behavior failure. Do not modify any component or registration just to expose diagnostics.
5. **Interface/ECS.** Keep [authored obstacle descriptor](../../../zircon_runtime/src/core/framework/navigation/obstacle.rs#L18-L50) unchanged. The plugin collects and submits world-space carving AABB; built-in projects typed rows for planar avoidance. Unreal has navigation-relevant component/modifier and RVO origin interfaces rather than ZE's dynamic descriptors; the shared precedent is correct point placement before querying or marking, not identical navigation policies.
6. **Frozen verification plan.** Migrate the flat reachable path expectations from actual Unreal `Engine/Source/Developer/NavigationTestSuite/Private/NavMeshPathfindingTest.cpp:58–92`, the forbidden area distinction from `NavigationAreaTest.cpp:32–51` (`UNavArea_Null`, not merely high-cost `UNavArea_Obstacle`), and the scalar matrix-point comparison from `Engine/Source/Runtime/Core/Tests/Math/UnrealMathTest.cpp:3051–3098`. Reuse [ZE live carve/remove test pattern](../../../zircon_plugins/navigation/runtime/src/tests/manager.rs#L362-L470), [native flat Detour control](../../../zircon_plugins/navigation/native/src/tests/tile_cache.rs#L22-L59), and [built-in targeted avoidance pattern](../../../zircon_runtime/src/navigation/runtime/tests/cases.rs#L24-L65). The compensated shear hierarchy uses nonzero X and Z authored offsets with the same true obstacle center as the rigid control. Require plugin agent passage before carving and after removal, and actual no-path with carve enabled; require built-in to steer away vs. approach when avoidance is toggled. Do not read the projected center as the oracle; the true point is fixed analytically. No exact matching UE dynamic shear automation or executed Unreal binary is claimed.
