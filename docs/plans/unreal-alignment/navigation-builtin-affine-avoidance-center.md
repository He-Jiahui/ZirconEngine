# Navigation: preserve the authored obstacle point in built-in avoidance

**Problem-only Draft.** Explicitly based on the verified but unmerged [#183](https://github.com/He-Jiahui/ZirconEngine/pull/183) `a1f32df76c262eaf938ac52828c430f853081229` so both sides can reach the actual tick after the cold-route guard release. This Draft changes only the problem note relative to that prerequisite. It does not inherit [#182](https://github.com/He-Jiahui/ZirconEngine/pull/182)'s plugin TileCache changes. No tests, native measurement, or production changes here yet. UE sources below are from the actual local `dev/UnrealEngine` tree.

1. **Difference.** The [built-in dynamic-obstacle row](../../../zircon_runtime/src/navigation/runtime/world_scan.rs#L294-L322) transforms `NavMeshObstacleDescriptor.center` as a local point using a matrix recomposed from projected world TRS. UE `Engine/Source/Runtime/Engine/Private/AI/Navigation/AvoidanceManager.cpp:14–37` consumes a resolved world origin independently from size/radius, and `:429–448` subtracts obstacle/agent world centers before filtering and accumulating avoidance.
2. **Predicted consequence.** Changing only hierarchy shear can displace the apparent obstacle outside planar avoidance distance and cause an approaching agent to continue toward its true center rather than steer away. This is built-in lightweight avoidance, not Detour carving. The historical cold-tick timeout occurred before avoidance and is not evidence of this behavior.
3. **Cause and Unreal contract.** A cached hierarchy matrix is already authoritative. `world_transform` decomposes it before evaluating the obstacle offset. UE `Engine/Source/Runtime/Engine/Private/Components/CharacterMovementComponent.cpp:4253–4261` supplies feet origin separately from scaled radius, while `AvoidanceManager.cpp:429–448` expects those origins in the same space. This is a coordinate precedent, not UE's steering algorithm or inherited-shear support. Keep the ZE full hierarchy affine point as in [Three.js](https://github.com/mrdoob/three.js/blob/r180/src/core/Object3D.js) and [Unity Entities](https://docs.unity3d.com/Packages/com.unity.entities@1.3/manual/transforms-concepts.html).
4. **Rust direction only after a genuine steering RED.** Change only the obstacle-row point read to the authoritative world matrix and retain the existing authored-local fallback for unavailable world transforms. Keep planar broadphase, radius scalar, candidate budgets/order, path, projection reuse/invalidation and writeback exactly as before. Do not bring in plugin, cold-route, collider shape or service semantics.
5. **Interface/ECS.** ZE's built-in rows use the same obstacle authoring descriptors as plugin but interpret them only for lightweight avoidance; UE's RVO object need not be a ZE obstacle or make the same turn. No API/registration/schema changes. The intended invariant is the existing offset before the existing solver, with whatever compact shape the solver currently uses.
6. **Frozen witness intent.** Reuse [the targeted tick and existing obstacle steering fixture](../../../zircon_runtime/src/navigation/runtime/tests/cases.rs#L24-L65) and the earlier plugin affine point setup (not its native carving assertions). A rigid offset and two analytic compensation cases under `S(.25,1,4)*Ry(45°)` map nonzero local offsets to common center zero. Use the real loaded flat mesh and targeted root agent `(-.35,0,.08)→(4,0,0)`, `0.1 s`, radius `.3`, obstacle radius `.35`, `carve=false`. While the same route remains active, disabled avoids no obstacle and moves closer, enabled must steer farther away, disabling again must restore the same clear result. Adapt UE `Engine/Source/Developer/NavigationTestSuite/Private/NavMeshPathfindingTest.cpp:94–126` real path/endpoint readiness and `Engine/Source/Runtime/Core/Tests/Math/UnrealMathTest.cpp:3051–3098` independent point witness; no matching UE inherited-shear avoidance test or UE binary run claimed. Prove the expected movement with fresh/invalidation controls, not a synthetic index or old view.
