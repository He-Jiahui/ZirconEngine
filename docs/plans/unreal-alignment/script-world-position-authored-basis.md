# Gameplay world-position writes must not re-author local rotation and scale

**Frozen regression and measured RED — production unchanged.** The initial problem-only Draft is `5788b98378b2e023f2877407e4645174349d9e7a`; the exact executed freeze `2b8bd7b83e9c85a61594eee0197fe14ebaa117ee` adds only the test mount and fixture over that note. Production is byte-identical to `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. This is independent of native physics pose writeback and generated tangent work.

1. **Difference.** Registered `set_position`, `set_position_json`, `translate` and other point-only gameplay helpers converge on [the Script position writer](../../../zircon_runtime/src/script/vm/gameplay_host/transform.rs#L152-L185). [The writer](../../../zircon_runtime/src/script/vm/gameplay_host/transform.rs#L307-L362) correctly starts with the full affine matrix and replaces its origin, but sends even a point-only request through the same local-matrix decomposition as a whole-pose request. This reconstructs *three* authored fields rather than writing just one.
2. **Consequence.** The finite legal root `q=I`, `s=(-2,-3,+0.5)` can be reconstructed as `q=Rz(π)`, `s=(+2,+3,+0.5)`. The linear matrix is unchanged, so a geometry-only test cannot detect the change. The [`World::update_transform` comparison](../../../zircon_runtime/src/scene/world/hierarchy.rs#L132-L151) is on authored values: even an exact no-op point request could report a write, change the synchronization revision and alter values available to persistence, inspectors or subsequent R/S edits. This does not assert a visible change in the first frame.
3. **Reason and local Unreal comparison.** Matrix decomposition cannot uniquely infer signed per-axis R/S. In the supplied local `dev/UnrealEngine`, `Engine/Source/Runtime/Engine/Private/Actor.cpp:6801–6804,5060–5073` delegates actor position to `RootComponent->MoveComponent(Delta, GetActorQuat(), ...)` (not to the component setter). The Blueprint component route `.../Components/SceneComponent.cpp:4352–4355` instead calls `SetWorldLocation`; `:1919–1931` converts an attached world **point** to relative location; `Engine/Source/Runtime/Engine/Classes/Components/SceneComponent.h:1735–1747` passes the existing relative rotation when setting location. The later movement internals (`SceneComponent.cpp:1723–1756,3293–3356`) can sweep, notify and separately handle mirrored `FTransform` conversions. This is an ownership comparison, not proof of a UE bit-level invariant, an Unreal run, or a reason to copy its compact parent transform, collision or socket semantics.
4. **Rust approach to validate.** For a current parent affine matrix `P=[A,b]`, authored local basis `B=R*S`, and intended world position `x`, solve only `t=A⁻¹(x−b)` and retain `B` through the original local R/S values: `P*[B,t]=[AB,x]`. A root just uses `x`. Preserve the existing inverse/error and authoring routes; explicitly distinguish invalid inputs, singular parent and static entity from a real write. Do not let a position-only operation relax the existing whole-pose representability check.
5. **ECS/interface boundary.** Only the Script host's position-only conversion owns this change. `LocalTransform` is authoritative for the fields; derived `WorldMatrix` remains `parent_world * local_matrix` including shear and reflection. Do not touch the matrix cache directly, prefab format, public host names/capabilities, collision behavior, `face_direction`, `set_scale`, or camera whole-pose semantics.
6. **Measured original.** The [8 new registered host tests](../../../zircon_runtime/src/script/vm/gameplay_host/tests/world_position.rs) ran on the unchanged Windows/MSVC `zircon_runtime --lib` test build, defaults off, only `script` enabled: **4 passed, 4 failed, none ignored**, native exit 101. All four position rows have the correct post-propagation `WorldMatrix` origin and unchanged linear columns, but replace `(q=I, s=(-2,-3,+0.5))` with `(q=Rz(π), s=(+2,+3,+0.5))`. Same-point root `(4,-3,1)` returned `Bool(true)` and advanced revision `2→3`. Moving root reached `(-5,7,2)`; positive/reflected sheared parents (immediate X·Y≈−1.5) reached `(13.414213,-0.8786793,14)` / `(6.5857863,-0.87868,14)`, so failure is not an incorrect point or fixture definition. The ordinary case, static/singular rejection and existing nonfinite diagnostics passed. The [six original pose/position/camera controls](../../../zircon_runtime/src/script/vm/gameplay_host/tests/spawn_transform.rs) separately passed **6/6**, exit 0. UE's plain `MoveComponentImpl` can report success on a no-op (`SceneComponent.cpp:3471–3478`); the no-op Bool/revision test is ZE's authored-state contract, not UE API parity.
