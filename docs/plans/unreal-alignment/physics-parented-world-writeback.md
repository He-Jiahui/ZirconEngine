# Physics step writes a world-space body pose into a parented local transform

**Problem-only Draft.** Source-confirmed path on ZE main `e89349ca51b4e9d024c194cd3bdf645bd25b6c37`; the runtime consequences below are predictions until the fixed-step witness runs. No engine code, public interface, ECS, or prefab change in this Draft.

1. **Difference.** ZE's [physics snapshot](../../../zircon_runtime/src/core/framework/physics/body_sync_state.rs#L11-L20) carries world-space body poses. [Fixed-step writeback](../../../zircon_plugins/physics/runtime/src/runtime_system.rs#L139-L155) sends them via [`apply_synchronized_bodies_to_scene`](../../../zircon_plugins/physics/runtime/src/manager/world_sync.rs#L238-L263) to [`World::update_transform`](../../../zircon_runtime/src/scene/world/hierarchy.rs#L132-L150), which stores a `LocalTransform`. Unreal converts a solver result at the component writeback boundary before storing the relative values.
2. **Impact.** The scene correctly publishes [`parent_world * child_local`](../../../zircon_runtime/src/scene/world/derived_state.rs#L656-L680). With a parent translated +10 X and a child starting at local +2 X, a step moving the child +1 X predicts a world physics snapshot of 13 and a scene world X of **23** after writeback. A root or identity parent hides the mistake; more general parent transforms can also affect orientation and scale. This numerical trace is source-derived, not an executed observation.
3. **Cause and Unreal reference.** The ownership/conversion step is missing at the ZE adapter, not in hierarchy propagation. In the checked-out Unreal source, `Engine/Source/Runtime/Engine/Private/PhysicsEngine/Experimental/PhysScene_Chaos.cpp:2542–2565` takes the particle world pose, compares against the component world pose, and queues a world delta/rotation; `:2767–2778` calls `MoveComponent` with `MOVECOMP_SkipPhysicsMove`. `Engine/Source/Runtime/Engine/Private/Components/PrimitiveComponent.cpp:3284–3325` forwards world location and rotation to the component setter. `Engine/Source/Runtime/Engine/Private/Components/SceneComponent.cpp:3293–3356` converts through the attachment socket into relative space before writing, with an explicit mirrored-scale branch. This is an ownership/space reference, not an endorsement of Unreal `FTransform` shear handling or a same-input UE binary result.
4. **Rust approach.** For a parented results row, read the authoritative parent matrix; use a checked affine inverse and solve `local = inverse(parent_world) * requested_world`. Convert to local TRS only when recomposition agrees with the requested affine matrix; reject singular parents and unrepresentable local shear without silently approximating or detaching. Nonuniform or negative scale is not by itself disallowed. Check application order when parent and child both receive solver rows. If the outbound rigid pose is already a lossy shear projection, keep that distinct from the full scene world matrix. Decide and test the narrow physics-boundary policy before changing it.
5. **Interface and ECS.** ZE admits a Dynamic body on a movable child through [`set_parent_checked`](../../../zircon_runtime/src/scene/world/hierarchy.rs#L96-L129) and [`set_rigid_body`](../../../zircon_runtime/src/scene/world/component_access.rs#L69-L88). Unreal may detach components when simulation is enabled (`Engine/Source/Runtime/Engine/Private/PhysicsEngine/BodyInstance.cpp:2670–2687`); do not copy that admission policy. The solver snapshot remains world space; authored ECS transforms remain local; the derived matrix cache remains authoritative. Builtin integration space, collider representation, navigation, reflection and prefabs are outside this change.
6. **Proposed ZE change and exact gate.** The owner is the plugin's private [writeback boundary](../../../zircon_plugins/physics/runtime/src/manager/world_sync.rs#L238-L263). Extend the existing [manager harness](../../../zircon_plugins/physics/runtime/src/manager/tests/cases.rs#L77-L119), not a standalone inverse-math proof. With a static transform-only parent at X=10, child at local X=2, Dynamic velocity X=64, no gravity/damping, builtin Simulate at 64 Hz, run exactly one real manager step. Before writeback require `local.x=3` and the same handle's snapshot `world.x=13`. After the production applier require `local.x=3`, `world.x=13`, original parent retained and parent still at X=10. Freeze before changes; add root and nonrepresentable-relative-pose controls, and rerun the same inputs in both builds. No tests have run for this issue yet.
