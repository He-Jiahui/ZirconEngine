# Physics step writes a world-space body pose into a parented local transform

**Draft with Windows/MSVC RED/GREEN.** Source-confirmed path on ZE main `e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. The six unchanged fixtures ran against old production at `40a40d47d` and the local candidate at `806502cd3`. Production changes are confined to the physics plugin writeback; no public interface, ECS or prefab change.

1. **Difference.** ZE's [physics snapshot](../../../zircon_runtime/src/core/framework/physics/body_sync_state.rs#L11-L20) carries world-space body poses. Before the fix, [fixed-step writeback](../../../zircon_plugins/physics/runtime/src/runtime_system.rs#L139-L155) handed those world values directly to [`World::update_transform`](../../../zircon_runtime/src/scene/world/hierarchy.rs#L132-L150), which stores a `LocalTransform`. Unreal converts a solver result at the component writeback boundary before storing the relative values.
2. **Impact.** The scene correctly publishes [`parent_world * child_local`](../../../zircon_runtime/src/scene/world/derived_state.rs#L656-L680). With a parent translated +10 X and a child starting at local +2 X, an executed step moved the child +1 X and produced a world snapshot of 13; old writeback put its scene world X at **23**. A root hides the mistake; a separate signed nonuniform-parent fixture also reproduced a wrong child pose.
3. **Cause and Unreal reference.** The ownership/conversion step is missing at the ZE adapter, not in hierarchy propagation. In the checked-out Unreal source, `Engine/Source/Runtime/Engine/Private/PhysicsEngine/Experimental/PhysScene_Chaos.cpp:2542–2565` takes the particle world pose, compares against the component world pose, and queues a world delta/rotation; `:2767–2778` calls `MoveComponent` with `MOVECOMP_SkipPhysicsMove`. `Engine/Source/Runtime/Engine/Private/Components/PrimitiveComponent.cpp:3284–3325` forwards world location and rotation to the component setter. `Engine/Source/Runtime/Engine/Private/Components/SceneComponent.cpp:3293–3356` converts through the attachment socket into relative space before writing, with an explicit mirrored-scale branch. `SceneComponent.cpp:1018–1026` also updates attached children after a parent moves, without forwarding the parent's skip-physics flag to them. These are references for the ownership, change detection, and relative-space boundary. They do not imply UE orders a batch by ZE entity depth or provides a full-affine shear oracle.
4. **Rust approach.** Apply roots and ancestors first (stable entity IDs are not topology). Read the actual parent's affine matrix through the dirty-aware scene accessor, then solve `local = inverse(parent_world) * requested_world` with a checked inverse. Accept local TRS only when both local and world recompositions agree within the per-column `1e-5` relative tolerance; a large translation does not hide a basis error. Negative/nonuniform scale and even a sheared parent are supported when the requested local pose is representable. An unchanged lossy solver projection is an echo, not a request to replace the scene matrix. A refused pose leaves the previous local transform and still syncs valid body properties.
5. **Interface and ECS.** ZE admits a Dynamic body on a movable child through [`set_parent_checked`](../../../zircon_runtime/src/scene/world/hierarchy.rs#L96-L129) and [`set_rigid_body`](../../../zircon_runtime/src/scene/world/component_access.rs#L69-L88). Unreal may detach components when simulation is enabled (`Engine/Source/Runtime/Engine/Private/PhysicsEngine/BodyInstance.cpp:2670–2687`); do not copy that admission policy. The solver snapshot remains world space; authored ECS transforms remain local; the derived matrix cache remains authoritative. Builtin integration space, collider representation, navigation, reflection and prefabs are outside this change.
6. **ZE change and exact gate.** Only the plugin's private [writeback boundary](../../../zircon_plugins/physics/runtime/src/manager/world_sync.rs#L241-L375) changes. The [existing manager harness](../../../zircon_plugins/physics/runtime/src/manager/tests/cases.rs#L81-L407) verifies the behavior, not a standalone inverse-math proof. With an unmoving transform-only parent at X=10, child at local X=2, Dynamic velocity X=64, no gravity/damping, builtin Simulate at 64 Hz, run exactly one real manager step. Before writeback require `local.x=3` and the same handle's snapshot `world.x=13`. After the production applier require `local.x=3`, `world.x=13`, original parent retained and parent still at X=10. We froze and ran the six cases before the production edit, then reran them unchanged. Roots, nonrepresentable relative poses, a moved mirrored parent, a representable goal under a sheared parent, and an unchanged sheared echo are separate controls.

## Existing Unreal tests and port boundary

- `System.Engine.Attachment` (`Engine/Source/Runtime/Engine/Private/Tests/EngineAutomationTests.cpp:1543–1556,2022–2085,2102–2163`) sets up a real parent/child and asserts the child world transform and unchanged parent across attachment rules. Its relative-value assertion is after detach; it does not step physics or write an attached body's result. Carry the distinct world/local and unchanged-parent assertions into this existing ZE suite, not Unreal's `FTransform` arithmetic or detach policy.
- `EngineInterface.SimRoundTrip` (`Engine/Source/Programs/HeadlessChaos/Private/HeadlessChaosTestPhysicsScene.cpp:1205–1235`) disables gravity, advances one single-threaded real solver frame and asserts the returned position and velocity. Use the same one-step/same-body oracle with exact binary-friendly `1/64 s` and ZE units. `SetKinematicTargetWriteBackEnabled/Disabled` (`:1345–1507`) tests GT/PT particle data, not local component pose. Base `FChaosScene::OnSyncBodies` (`Engine/Source/Runtime/PhysicsCore/Private/ChaosScene.cpp:391–395`) does not execute the derived scene component writeback.
- Searched the relevant Engine automation, PhysicsEngine, Plugins/Tests, HeadlessChaos and ChaosPhysicsTests suites. No case was found that exercises the same retained-parent solver-to-local path. This is a ZE manager integration regression borrowing the existing Unreal assertions and checked against the Unreal production conversion; it is not an executed Unreal binary or a literal port of one test. The nonrepresentable relative shear control is a ZE requirement, not a behavior copied from UE.
