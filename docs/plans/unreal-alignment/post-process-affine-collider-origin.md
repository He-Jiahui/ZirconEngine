This is a scene extraction point issue, not #154's LUT color domain, #179's Sprite2D graph, or a general affine volume-distance feature. 1. **Difference.** The [local volume producer](../../../zircon_runtime/src/scene/world/render_post_process.rs#L134-L145) transforms a [collider's authored local translation](../../../zircon_runtime/src/scene/world/render_post_process.rs#L230-L252) with world TRS components that have already been decomposed from the true matrix. 2. **Predicted consequence.** With parent scale `(2,1,1)`, child `Ry(45°)`, collider offset `8X`, the real world center is `(8√2,0,−4√2)`. A compact sphere with radius `.25` before scaling and zero fade may fail to apply any override when the camera is placed at that exact point. The existing [fog AABB midpoint](../../../zircon_runtime/src/scene/world/render_post_process.rs#L148-L183) uses the same extracted center, but no fog rendering failure is claimed here.
3. **Cause and UE contract.** The exact `WorldMatrix` exists before consumption; reconstructing from `world_transform` throws away inherited shear. Actual UE `Engine/Source/Runtime/Engine/Private/Volume.cpp:84–110` gets world distance to the bound shape, then `World.cpp:10742–10803` applies volume weight to the view. That provides the point-before-influence precedent, not a shear oracle or permission to change ZE's fade. ZE uses the complete hierarchy matrix, as in [Three.js](https://github.com/mrdoob/three.js/blob/r180/src/core/Object3D.js) and [Unity Entities](https://docs.unity3d.com/Packages/com.unity.entities@1.3/manual/transforms-concepts.html).

Retain the compact box orientation/extents and sphere max-radius policy, priorities, layer filtering, blending, fog AABB shape policy, shaders and graph. A full affine ellipsoid or parallelepiped distance API would be a different task.
5. **Interface/ECS.** [Local PostProcessVolumeComponent](../../../zircon_runtime/src/scene/components/scene/post_process.rs#L46-L96) uses a same-entity collider; UE has actor/shape or brush volume interfaces.
