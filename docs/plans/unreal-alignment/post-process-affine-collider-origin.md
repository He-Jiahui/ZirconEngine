# Graphics: preserve the world point of a local post-process collider origin

**Problem-only Draft.** Base `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`; no tests changed, observations, or implementation yet. This is a scene extraction point issue, not #154's LUT color domain, #179's Sprite2D graph, or a general affine volume-distance feature. UE references name files in the actual local `dev/UnrealEngine` tree.

1. **Difference.** The [local volume producer](../../../zircon_runtime/src/scene/world/render_post_process.rs#L134-L145) transforms a [collider's authored local translation](../../../zircon_runtime/src/scene/world/render_post_process.rs#L230-L252) with world TRS components that have already been decomposed from the true matrix. UE `Engine/Source/Runtime/Engine/Private/Components/SphereComponent.cpp:25–33` resolves local sphere bounds to scene space; `PostProcessComponent.cpp:272–303` measures against the resolved sphere center or primitive shape, not the untransformed local offset.
2. **Predicted consequence.** With parent scale `(2,1,1)`, child `Ry(45°)`, collider offset `8X`, the real world center is `(8√2,0,−4√2)`. A compact sphere with radius `.25` before scaling and zero fade may fail to apply any override when the camera is placed at that exact point. The existing [fog AABB midpoint](../../../zircon_runtime/src/scene/world/render_post_process.rs#L148-L183) uses the same extracted center, but no fog rendering failure is claimed here.
3. **Cause and UE contract.** The exact `WorldMatrix` exists before consumption; reconstructing from `world_transform` throws away inherited shear. Actual UE `Engine/Source/Runtime/Engine/Private/Volume.cpp:84–110` gets world distance to the bound shape, then `World.cpp:10742–10803` applies volume weight to the view. That provides the point-before-influence precedent, not a shear oracle or permission to change ZE's fade. ZE uses the complete hierarchy matrix, as in [Three.js](https://github.com/mrdoob/three.js/blob/r180/src/core/Object3D.js) and [Unity Entities](https://docs.unity3d.com/Packages/com.unity.entities@1.3/manual/transforms-concepts.html).
4. **Rust direction after both native REDs.** Project only the existing collider translation via the authoritative world matrix, with the prior identity fallback. Retain the compact box orientation/extents and sphere max-radius policy, priorities, layer filtering, blending, fog AABB shape policy, shaders and graph. A full affine ellipsoid or parallelepiped distance API would be a different task.
5. **Interface/ECS.** [Local PostProcessVolumeComponent](../../../zircon_runtime/src/scene/components/scene/post_process.rs#L46-L96) uses a same-entity collider; UE has actor/shape or brush volume interfaces. Preserve the existing scene/renderer shape snapshot and collider authoring. Fix the producer rather than adding a new effect or marker to the scene.
6. **Frozen verification.** Adapt actual UE `Engine/Source/Runtime/Core/Tests/Math/UnrealMathTest.cpp:3051–3098` (independent scalar point comparison) and `Engine/Plugins/Tests/RHITests/Source/RHITests/Private/RHIClearTextureTests.cpp:963–989` (map and compare actual frame regions with a control). Reuse [existing CPU volume extraction and resolution](../../../zircon_runtime/src/scene/tests/render_post_process_extract.rs#L314-L448) and [actual final-frame vignette witness](../../../zircon_runtime/src/graphics/tests/render_product_post_process_volume.rs#L16-L92). Use a real Level, active Core3D camera, true World ID, same-world layers, parented sphere above, fixed camera clear and no test-injected volume snapshot.
