# BD02: keep the mesh frame's world transform and bounds coherent

**Draft — prepared World, ordinary mesh path.** The problem note and tests preceded the production change. The existing frame owns the shared transform, and no new scene or GPU layout is introduced.

1. **Difference.** In ordinary Unreal static meshes, component transform supplies both the render matrix and bounds. ZE's World and persistent RenderScene retained `WorldMatrix`, while the old [mesh extraction path](../../../zircon_runtime/src/scene/world/render.rs) projected it back to TRS before [CPU bounds projection](../../../zircon_runtime/src/graphics/visibility/culling/mesh_bounds.rs) and [model-matrix preparation](../../../zircon_runtime/src/graphics/mesh/build/extend_pending_draws_for_mesh_instance.rs).
2. **Effect.** The local tests-only combination of this PR and [the compilation prerequisite (#137)](https://github.com/He-Jiahui/ZirconEngine/pull/137) reproduced three symptoms: opposite shear matrices shared a stable key and revision; the CPU culler lost an instance with an in-frustum vertex on full and sparse frames; and both ordinary geometry paths uploaded a different matrix than World published. This is not a measurement of editor pixels or performance.
3. **Cause and Unreal reference.** TRS decomposition loses shear, and a sphere scaled by the largest column length is not conservative for arbitrary shear. Unreal `GetRenderMatrix` (`Engine/Source/Runtime/Engine/Private/Components/PrimitiveComponent.cpp:1267–1270`), `CalcBounds` (`Engine/Source/Runtime/Engine/Private/Components/StaticMeshComponent.cpp:665–679`), and the update payload (`Engine/Source/Runtime/Renderer/Private/RendererScene.cpp:1630–1641`) derive and carry matrix and bounds together. The proxy stores both and compares the matrix itself (`Engine/Source/Runtime/Engine/Private/PrimitiveSceneProxy.cpp:905–971`). Ordinary UE attachment is TRS (`Engine/Source/Runtime/Engine/Private/Components/SceneComponent.cpp:727–748`), so it is not a shear parity oracle. The affine bounds reference is `TBox::TransformBy(TMatrix)` (`Engine/Source/Runtime/Core/Public/Math/Box.h:870–918`).
4. **Rust representation.** The existing [geometry frame domain](../../../zircon_runtime/src/core/framework/render/frame_extract/geometry.rs#L78) keeps one finite affine override per entity only when the snapshot TRS cannot reproduce the World matrix bit-for-bit. All its primitives share the matrix and its content revision. The projected TRS and revision guard against a stale override if a derived frame publicly edits or replaces its snapshot. Callers editing the public DTO still own its revision contract.
5. **Interface and ECS boundary.** The [prepared World producer](../../../zircon_runtime/src/scene/world/render.rs#L152) collects this in the same traversal as mesh snapshots, independent of journal upserts. Hierarchy, mesh DTO fields, shared-frame ownership, and the GPU instance layout stay unchanged. Legacy editor packets and cubemap captures, VG/GI, and other TRS-only consumers are not migrated. Prefab remains untouched.
6. **Concrete ZE change.** CPU projects the local AABB using the same override as ordinary draw preparation and uses its enclosing sphere; missing/invalid bounds fail open, and the existing no-override TRS path remains. The existing wireframe and selection bounds use the same matrix lookup (UE `PrimitiveSceneProxy.cpp:1747–1762` draws local bounds with the proxy matrix); no new direct-mesh overlay path. The published matrix fingerprint also feeds the existing static shadow revision consumer.

## Historical HZB

1. **Difference.** ZE selected the previous matrix but guarded nonorthogonality only with current flags. UE's temporal Nanite pass projects the previous box using the actual previous transform and view (`Engine/Shaders/Private/Nanite/NaniteCullingCommon.ush:623–642`).
2. **Effect.** A previous-shear/current-TRS fixture on DX12 dropped its indirect draw (`0` instead of `1`), although a point in the previous local sphere was in front of the occluder.
3. **Cause and Unreal reference.** Largest column length is not the operator norm of a sheared transform; UE projects the full box with the selected transform (`Engine/Shaders/Private/Nanite/NaniteHZBCull.ush:414–528`).
4. **ZE approach.** For its existing sphere, use the largest absolute row sum of `A^T A` to bound squared scale. This reduces to the previous formula when columns are orthogonal, while remaining conservative for finite ordinary affine transforms in real arithmetic.
5. **Interface and scope.** Use the selected GPUScene matrix without changing ABI, normal flags, HZB texture/history, or introducing Nanite's post-pass. This does not prove the existing screen-space sphere approximation conservative for all perspective projections.
6. **Concrete ZE change.** The [existing shader](../../../zircon_runtime/src/graphics/scene/renderer/hzb/shaders/hzb_occlusion_cull.wgsl#L56) derives radius from the selected matrix and retains draws on invalid/overflowed projection; a normal previous-TRS occluded control must still be culled.

- The [same-key revision and sparse-frame visibility fixtures](../../../zircon_runtime/src/graphics/scene/tests/component_projector_cases.rs#L517) exercise the existing prepared-World path. The [AABB control](../../../zircon_runtime/src/core/framework/render/mesh/tests/bounds.rs#L69) ports the forward case from the local Unreal checkout, `Engine/Source/Programs/HeadlessChaos/Private/HeadlessChaosTestAABB.cpp:23–38,114–124`, with its eight-corner reference. It does not run Unreal or assert shear parity for UE attachments.
- Standalone PR validation attempted `zircon_runtime` libtest on Windows/MSVC with defaults off and `native-host,graphics` enabled. It failed **before any test ran**: the unchanged [model resource test](../../../zircon_runtime/src/graphics/scene/resources/tests/model_geometry_resolution.rs#L305-L315) on the base branch borrows a temporary registry (Rust `E0716`). This is a separate compile prerequisite, not BD02 RED and not included in this PR.
- The local, unpushed combination of the two draft heads, including the refined tests-only commit, compiled and ran all 18 CPU cases without a production change: **12 passed, 6 failed, 0 ignored**. The bounds control passed; both BD02 regressions failed at their behavior assertions. The other four failures are three unchanged `WorldMismatch` fixtures and an unchanged mirrored TBN expectation.
- The [existing offscreen HZB case](../../../zircon_runtime/src/graphics/scene/renderer/hzb/tests/cases.rs#L47) completed on DX12 and read back an indirect draw count. The new test varies only the selected previous transform and its sphere; the current transform is ordinary TRS. It is based on the principle shown in Unreal `Engine/Shaders/Private/Nanite/NaniteCullingCommon.ush:623–642`: the bounds tested against previous HZB must be projected with the actual previous transform. ZE uses the existing ordinary-mesh HZB path, not Nanite's box culling or its post-pass.
- The [ordinary draw upload regression](../../../zircon_runtime/src/graphics/scene/renderer/core/renderer/tests/renderer.rs#L258) submits real prepared World frames to the existing offscreen SceneRenderer, then reads both matrix fields from the actual GPUScene instance buffer. It uses direct and built-in model geometry plus a subsequent ordinary-TRS frame; it does not replay the CPU shadow as GPU evidence. This test follows the same UE render update contract above, not UE's instance packing format.
- With the initial BD02 patch, the same 18 CPU cases were **14 passed, 4 failed, 0 ignored**. The DX12 cases changed from **1 passed, 2 failed** to **3 passed, 0 failed** without changing either fixture. This verifies both uploaded matrix fields through the ordinary direct/model paths and an actual indirect HZB dispatch, not rendered pixels.
- The tighter [perspective regression](../../../zircon_runtime/src/graphics/scene/tests/component_projector_cases.rs#L716-L798) passed the geometric enclosure guard but returned no visible child with the old culler and the BD02 patch. With [BD01 (#138)](https://github.com/He-Jiahui/ZirconEngine/pull/138), the same child stays visible and the far instance is still culled, with the same radius (`1.10494351`). Between these two candidates only the BD01 culling owner changed; all test bytes were unchanged. This is why the two production changes must land in order, not why the sphere should be enlarged.
- On the local combined candidate, non-test `zircon_runtime` lib check passed; the exact 31 CPU cases went from **23 passed, 8 failed** to **26 passed, 5 failed** when BD01 was added. The remaining failures are the four unchanged BD02 controls and the old static-index prefilter assertion from #138. All three actual DX12 offscreen cases passed again.
