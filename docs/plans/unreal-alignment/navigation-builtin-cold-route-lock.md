# Built-in navigation: release the route-cache guard before a cold query

**Problem-only Draft.** Base `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. No change to tests or production yet. Independent of #182's TileCache obstacle-center patch and #158's plugin module admission. UE citations refer to the actual local `dev/UnrealEngine` tree.

1. **Difference.** In the [built-in agent tick](../../../zircon_runtime/src/navigation/runtime.rs#L354-L377), the cache check calls `self.lock_state()` directly in the Rust `if let` condition. Its `None` branch tries to select navmesh data by taking the same guard again. UE `Engine/Source/Runtime/NavigationSystem/Private/NavigationSystem.cpp:1887–1936` resolves missing query nav data and dispatches the query; a cold/default-data route is expected to return.
2. **Observed symptom, separate from #182 affine results.** The preceding native Windows investigation passed its rigid plugin TileCache case, but the initial rigid built-in steering control never completed before the 180-second native process deadline. No built-in affine or steering assertion ran. The dedicated baseline must localize the failure after a successful flat path and actual tick entry; the previous attempt did not record this stage boundary.
3. **Cause to verify.** [Workspace edition 2021](../../../Cargo.toml#L22-L26) extends the `if let` scrutinee's temporary guard through the `else`. The [manager uses a std Mutex](../../../zircon_runtime/src/navigation/runtime.rs#L34-L55); a freshly spawned agent [has no cached route](../../../zircon_runtime/src/navigation/runtime/state.rs#L110-L144). Both the targeted and full tick enter the same miss branch. This is a host lock lifetime, not a path geometry or transform issue.
4. **Rust direction after observed RED only.** Express the cache lookup as a separate `Option<Vec3>` statement so the existing guard ends before mesh selection. Keep the exact same generation/route keys, budgets, snapshots, lookup/update policy, and callbacks. Do not add a reentrant lock, runtime deadline, or new service.
5. **Interface/ECS.** No authoring schema, actor writeback, service registration, or navigation ABI changes. The test uses an existing root agent ECS component, real loaded mesh and manager. Unreal has `ANavigationData`/`FPathFindingQuery` rather than ZE's built-in cache; use it for the observable cold query/navigation expectation, not a claim that UE has this Rust cache.
6. **Frozen verification.** Adapt actual UE `Engine/Source/Developer/NavigationTestSuite/Private/NavMeshPathfindingTest.cpp:58–126` (flat straight line, success and real endpoints) and `:12–29` (same-point control). Reuse [ZE targeted tick fixture](../../../zircon_runtime/src/navigation/runtime/tests/cases.rs#L24-L65) and [existing stable destination cache test](../../../zircon_runtime/src/navigation/runtime/tests/cases.rs#L467-L486); no new test architecture. Record `Complete` before the cold agent tick, require first and subsequent ticks to move and keep one path query, and verify an already-arrived agent needs neither. Use a bounded test-only worker so a self-lock produces a logged failure without hanging the whole runner. No Unreal binary execution or equivalent UE lock-lifetime automation is claimed.
