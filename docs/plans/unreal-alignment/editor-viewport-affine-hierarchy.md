# Keep the authored affine hierarchy through the live editor viewport

**Draft, stacked on [#135](https://github.com/He-Jiahui/ZirconEngine/pull/135).** Unity and Three.js are the reference for hierarchy math, not Unreal's `FTransform` composition.

1. **Difference.** ZE already computes `parent_world * local_TRS_matrix` on the [dirty read](../../../zircon_runtime/src/scene/world/derived_state.rs#L503-L531) and [published WorldMatrix path](../../../zircon_runtime/src/scene/world/derived_state.rs#L656-L682). That is the same matrix order as [Three.js Object3D r180](https://github.com/mrdoob/three.js/blob/r180/src/core/Object3D.js#L1121-L1155). Its [WebGL renderer](https://github.com/mrdoob/three.js/blob/r180/src/renderers/WebGLRenderer.js#L2004-L2009) consumes `matrixWorld`; [Unity Entities LocalToWorld](https://docs.unity3d.com/Packages/com.unity.entities@1.3/manual/transforms-concepts.html) is likewise a rendering matrix and can carry nonuniform scale and shear. The old ordinary ZE editor viewport went through a packet that stores only projected TRS.
2. **Effect.** The authored test cube under `S(4,1,1)` followed by `Rz(π/4)` projects to `|x|/4 + |y| ≤ 1/√2`. A patch known to lie inside that silhouette but outside the TRS reconstruction drew **0/16** changed pixels on the old editor entry, with **16/16** at the center and **0/16** in a far background patch. Opposite inherited shear matrices with exactly equal projected TRS also produced the same revision, `8087597793426439401`, under the same stable mesh key.
3. **Cause and reference.** The old [controller](../../../zircon_editor/src/scene/viewport/controller/build_render_snapshot.rs#L24-L49) constructed the compatibility packet; its [mesh visit](../../../zircon_runtime/src/scene/world/render.rs#L115-L140) collected no affine rows on that path, so `from_snapshot` could not recover them. The local Unreal [attachment path](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Engine/Private/Components/SceneComponent.cpp#L727-L748>) combines `FTransform`s. Its [vectorized multiply](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Core/Private/Math/TransformVectorized.cpp#L295-L345>) recomposes quaternion, translation and scale, so it is **not** a reference for inherited shear. Unreal *does* pass the already-resolved `FMatrix` to the renderer: [RendererScene](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Renderer/Private/RendererScene.cpp#L1630-L1639>) gathers it and [PrimitiveSceneProxy](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Engine/Private/PrimitiveSceneProxy.cpp#L905-L916>) stores it directly. [GetRenderMatrix](<E:/Git/ZirconEngine/dev/UnrealEngine/Engine/Source/Runtime/Engine/Private/Components/PrimitiveComponent.cpp#L1266-L1270>) shows where the normal Unreal path obtains that matrix; this does not imply Unreal's attachments propagate shear.
4. **Rust approach.** Keep the current viewport's mesh visit, layer/camera filtering and preview data. At the live Rust entry, enable the existing private affine collector during the same visit and transfer it to `GeometryExtract` with the matching matrix revision. Existing [bounds lookup](../../../zircon_runtime/src/graphics/context/history/collect_batching_result.rs#L76-L89) and [mesh draw lookup](../../../zircon_runtime/src/graphics/mesh/build/extend_pending_draws_for_mesh_instance.rs#L89-L100) then see the same matrix. The standalone packet/`from_snapshot` APIs still do not synthesize affines.
5. **Interface/ECS boundary.** No new ECS component, serialized field, plugin/C ABI or GPU instance layout. Local authoring remains TRS; `WorldMatrix` remains protected and derived. Keep the current cache key, overlay sharing, preview settings and editor's legacy generation tag (used by the spatial snapshot router); do not attach the full World journal or switch to the complete Runtime producer and enable unrelated rendering domains. This does not change reparenting semantics, exact picking, Prefab, physics, navigation or reflection-capture packets. [Three.js `attach`](https://github.com/mrdoob/three.js/blob/r180/src/core/Object3D.js#L837-L858) also distinguishes preserve-world reparenting from routine affine propagation.
6. **Concrete ZE change and gate.** The [narrow viewport-frame producer](../../../zircon_runtime/src/scene/world/render.rs#L73-L102) [installs the mesh sideband](../../../zircon_runtime/src/core/framework/render/frame_extract/frame.rs#L147-L155) before publishing the frame. The [controller](../../../zircon_editor/src/scene/viewport/controller/build_render_snapshot.rs#L35-L50) caches that frame without doing a lossy roundtrip. The frozen test set includes a port of [Three.js `localToWorld`](https://github.com/mrdoob/three.js/blob/r180/test/unit/src/core/Object3D.tests.js#L515-L543), editor cache and projection controls, and [actual offscreen DX12 view extraction/submission](../../../zircon_editor/src/tests/editing/state/viewport/affine_hierarchy.rs). The same nine CPU cases went **5 passed / 4 failed → 6 passed / 3 failed**: the affine revision witness turned green and the three unrelated failures stayed unchanged. On discrete RTX 3060 Laptop / DX12, the old frame drew **0/16** of the right-edge patch and the candidate drew **16/16** with the same **16/16 center** and **0/16 outside** controls. The non-test `zircon_editor` library check also passed. Evidence is local, with frozen fixtures from `24a220cc3`; the only production changes are those reviewed in `4a97ded98`. The matching local verification pins were `20758d809` (old) and `761a9cd7b` (candidate). Do not merge in the absence of the real required checks.

The old comparison did not count the first project-less GPU setup failure as RED. The frozen fixture opens a fresh test-only project before constructing the production renderer, without touching an authoring project. Tests do not claim a UE binary result or a packaged editor-window result.

The three pre-existing controls stay in the paired invocation: [the source guard](../../../zircon_editor/src/ui/workbench/state/tests/editor_state_render.rs#L21-L30) reads the old implementation owner; [the replacement reset fixture](../../../zircon_editor/src/scene/viewport/controller/tests/reset_from_scene.rs#L11-L35) asks for a default camera instead of the scene camera and stops before reset; [the highlight fixture](../../../zircon_editor/src/ui/workbench/state/tests/editor_state_render.rs#L44-L65) replaces the already-bound gateway before attempting scene access. Those assertions are not retired, skipped, or repaired by the affine change.
