# Navigation bake loses attached source geometry shear before Recast

**Draft — native old RED, production unchanged.** Both branches in the same geometry collector are present on `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. This is independent of #158 navigation host admission and #146/#172 agent writeback. The problem-only Draft preceded the test commits.

1. **Difference.** ZE's [render mesh and collider branches](../../../zircon_plugins/navigation/runtime/src/manager/bake/geometry.rs#L166-L216) rebuild a matrix from `World::world_transform` before transforming geometry. UE's Recast exporter consumes the resolved source-to-world mapping for each emitted vertex. ZE's hierarchy authority is the [affine matrix](../../../zircon_runtime/src/scene/world/derived_state.rs#L503-L531), not the decomposed TRS projection; the consumer can already accept a matrix.
2. **Impact.** A rectangle rotated below a nonuniformly scaled parent is a true world parallelogram. Old ZE baked nonempty output from 4 vertices / 2 triangles for both sources, yet returned no sample at `(41.76955, 2.75, -17.142136)` and hit a premature wall near `(30.68525, 2.78135, -13.81685)`. Both rigid controls reached their expected endpoint, and center/outside checks on all four runs behaved as intended. The verdict is the actual published bake footprint, not triangle count.
3. **Cause and Unreal evidence.** [ZE's world TRS read](../../../zircon_runtime/src/scene/world/derived_state.rs#L450-L462) decomposes the matrix, discarding the actual shear. UE `Engine/Source/Runtime/NavigationSystem/Private/NavMesh/RecastNavMeshGenerator.cpp:743–766` transforms custom mesh vertices and accumulates world bounds before Recast consumption; `844–877` composes the collision box local matrix with the component mapping before emitting vertices (UE row-vector order). UE still passes `FTransform` there; this is an export boundary comparison, not UE support for parent shear. The fixture uses positive determinant and does not introduce a winding or normal policy.
4. **Rust direction.** After true old RED for a source, feed that source's existing `Mat4` path directly from `World::world_matrix`. Keep `node_world * collider_local`, shape semantics, [render primitive priority and typed leases](../../../zircon_plugins/navigation/runtime/src/manager/bake/geometry_provider.rs#L17-L89), area assignment, and vertex validators. If only one source is demonstrated, do not change the other based on that result alone.
5. **Interface and ECS.** Existing [direct apply](../../../zircon_plugins/navigation/runtime/src/manager/bake.rs#L109-L145) captures a `LevelSystem` snapshot and publishes with its World, project and navigation-generation fences. No new ECS state, renderer/GPU dependency, hierarchy or ABI change. Do not bypass host registration, alter live collision or rewrite selection/volume/carving code; those have separate contracts.
6. **Concrete gate.** [Four frozen integration cases](../../../zircon_plugins/navigation/runtime/tests/bake_affine_geometry.rs) reuse UE's static floor (`Engine/Source/Developer/NavigationTestSuite/Private/NavMeshTestWorld.cpp:63–77,204–221`), projection negative controls (`NavMeshProjectionTest.cpp:10–49`) and returned world-endpoint assertions (`NavMeshPathfindingTest.cpp:94–126`). ZE uses its [existing manager and Level fixture](../../../zircon_plugins/navigation/runtime/src/tests/test_support.rs), actual `bake_surface`, published asset and sample/raycast. A Box with a local offset has no renderer; the ready typed `MeshAsset` has no collider. Only comparing `Some` is insufficient: Detour can return the closest point of a candidate whose bounds intersect the extent. The tests assert coordinates, nonempty real output and whether a wall was hit.
