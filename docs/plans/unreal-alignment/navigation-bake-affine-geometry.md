# Navigation bake loses attached source geometry shear before Recast

**Problem-only Draft.** Both branches in the same geometry collector are present on `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. This is independent of #158 navigation host admission and #146/#172 agent writeback. No tests, production changes or measured native result yet.

1. **Difference.** ZE's [render mesh and collider branches](../../../zircon_plugins/navigation/runtime/src/manager/bake/geometry.rs#L166-L216) rebuild a matrix from `World::world_transform` before transforming geometry. UE's Recast exporter consumes the resolved source-to-world mapping for each emitted vertex. ZE's hierarchy authority is the [affine matrix](../../../zircon_runtime/src/scene/world/derived_state.rs#L503-L531), not the decomposed TRS projection; the consumer can already accept a matrix.
2. **Potential impact.** A rectangle rotated below a nonuniformly scaled parent is a true world parallelogram, but the bake can receive different vertices, bounds and walkable edges. Two triangles and a nonempty navmesh do not certify that the correct world point can be sampled or reached. This is a source prediction; native tests must keep controls viable and distinguish an actual wrong projected point or boundary from quantization and missing setup.
3. **Cause and Unreal evidence.** [ZE's world TRS read](../../../zircon_runtime/src/scene/world/derived_state.rs#L450-L462) decomposes the matrix, discarding the actual shear. UE `Engine/Source/Runtime/NavigationSystem/Private/NavMesh/RecastNavMeshGenerator.cpp:743–766` transforms custom mesh vertices and accumulates world bounds before Recast consumption, and `8838–8868` supplies collision and shape exports from the same mapping. UE still passes `FTransform` there; this is an export boundary comparison, not UE support for parent shear. The fixture uses positive determinant and does not introduce a winding or normal policy.
4. **Rust direction.** After true old RED for a source, feed that source's existing `Mat4` path directly from `World::world_matrix`. Keep `node_world * collider_local`, shape semantics, [render primitive priority and typed leases](../../../zircon_plugins/navigation/runtime/src/manager/bake/geometry_provider.rs#L17-L89), area assignment, and vertex validators. If only one source is demonstrated, do not change the other based on that result alone.
5. **Interface and ECS.** Existing [direct apply](../../../zircon_plugins/navigation/runtime/src/manager/bake.rs#L109-L145) captures a `LevelSystem` snapshot and publishes with its World, project and navigation-generation fences. No new ECS state, renderer/GPU dependency, hierarchy or ABI change. Do not bypass host registration, alter live collision or rewrite selection/volume/carving code; those have separate contracts.
6. **Concrete gate.** Adapt UE `System.Navigation.NavMesh.Pathfinding.PathHasPoints` (`Engine/Source/Developer/NavigationTestSuite/Private/NavMeshPathfindingTest.cpp:94–126`, real world endpoints) and the UE test floor export fixture (`Engine/Source/Developer/NavigationTestSuite/Private/NavMeshTestWorld.cpp:63–77`). Reuse [native ZE manager and Level fixture](../../../zircon_plugins/navigation/runtime/src/tests/test_support.rs#L27-L55), then actual `bake_surface`, published asset and sample/raycast. Compare unit/rigid controls, a known inside center, a far outside point, and a point inside only the full-matrix footprint. One test source has a real Box collider with local offset and no render attachment; the other has a real typed ready `MeshAsset` and no collider. Assert the *returned coordinates* and wall behavior, not just `Option::Some`: Detour can return the closest point of a polygon whose bounds intersect the search box. No new test framework and no compile/setup failures counted as RED.
