# Skeletal physics projects the bone chain before resolving world target points

**Draft — paired native skeletal regression.** Independent of #145's parented post-solver writeback. The problem-only Draft preceded the test commit, and qualified behavioral RED on `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37` was published here before any production change.

1. **Difference.** Old ZE [profile spawn](../../../zircon_plugins/physics/runtime/src/skeletal/profile.rs#L271-L335) and [animated drive](../../../zircon_plugins/physics/runtime/src/skeletal/runtime.rs#L193-L231) started with projected skeleton world TRS and composed successive bone/offset TRS. UE resolves the live bone's world transform before submitting it to the body or kinematic target. ZE uses that world-target boundary but must keep its full affine hierarchy, not UE's TRS restriction.
2. **Impact.** Old ZE put a profile-generated root at `(11.107976,0,-4.060660)` instead of `(11.414213,0,-3.707107)` below the sheared skeleton. A nonzero child body offset ended at `(12.414213,0,-3.414214)` both at spawn and when driven, not `(12.414213,0,-2.707107)`, even with a root skeleton entity. On animated release the old velocity was `(2.215952,0,-2.121321) m/s` rather than `(2.828427,0,-1.414214) m/s`; the transition retained the already incorrect last world point.
3. **Cause and Unreal evidence.** [ZE world TRS](../../../zircon_runtime/src/scene/world/derived_state.rs#L450-L462) is a reduction of the true matrix, and componentwise bone composition could not carry the shear to a later offset. UE `Engine/Source/Runtime/Engine/Private/SkeletalMeshComponentPhysics.cpp:919–928,1071–1084` supplies `GetBoneTransform` to `InitBody`; `Components/SkinnedMeshComponent.cpp:2441–2450,2508–2514` uses the resolved component-to-world transform. The adjacent *matrix* getter (`2391–2432`) composes the bone and component matrices before returning. In `PhysicsEngine/PhysAnim.cpp:683–711` the world bone pose reaches `SetKinematicTarget_AssumesLocked` or `SetGlobalPose_AssumesLocked`; `Experimental/PhysScene_Chaos.cpp:1782–1787` forwards the target. UE's deferred branch resolves the same world pose but currently writes `SetX/SetR` directly (`Experimental/PhysScene_Chaos.cpp:2211–2278`), so not all its animated updates synthesize target velocity. UE also warns on nonuniform scale and approximates body scale (`PhysAnim.cpp:616–622,713–730`); this is not proof that UE physics or `FTransform` supports shear.
4. **Rust change.** A [private bone placement](../../../zircon_plugins/physics/runtime/src/skeletal/runtime.rs#L105-L147) propagates the full affine matrix for points, while separately composing the old approximate rigid rotation and scale. Use `skeleton_world * bone_chain` at the offset's local origin. Store each bone, not its offset body, for descendants. The old finite checks, topological order and release difference calculation stay in place; only the world points in its existing history are corrected. Do not reinterpret this as verifying angular velocity, a sheared primitive, a manually reparented body or the reverse simulated-pose feed.
5. **Interface and ECS.** [Profile configuration](../../../zircon_plugins/physics/runtime/src/skeletal/profile.rs#L412-L460) uses independent ECS bodies and joint metadata, not scene parenting of bones. [Runtime animated drive](../../../zircon_plugins/physics/runtime/src/runtime_system.rs#L91-L109) precedes the physics step. Validate the real profile and driver in existing unit tests, not a parallel runtime or ABI. Prefab, live solver, ECS hierarchy, public profiles and #145 stay unchanged.
6. **Concrete gate.** Extend the existing skeletal unit test module and preserve its [spawn/control](../../../zircon_plugins/physics/runtime/src/skeletal/tests/cases.rs#L28-L95) and [no-pop/release](../../../zircon_plugins/physics/runtime/src/skeletal/tests/cases.rs#L126-L174) assertions. Port the position-and-velocity observation from local UE HeadlessChaos `EngineInterface.SetKinematicTargetWriteBackEnabled/Disabled` (`Engine/Source/Programs/HeadlessChaos/Private/HeadlessChaosTestPhysicsScene.cpp:1387–1419,1432–1458,1498–1508`). Assert real spawned root points, parent bone vs parent **body offset** distinction, animated drive positions, unchanged last point on release, and `Δworld / Δt` separately. [Four frozen cases](../../../zircon_plugins/physics/runtime/src/skeletal/tests/affine_points.rs) measure scene shear, an independent sheared bone-chain offset at spawn and at drive, and release with two fixed-time samples. The Chaos test is a position/difference oracle, not an assertion that UE's skeletal switch computes release velocity. A direct driver unit test is not a hosted Update or Chaos/Jolt solver run.

The old executable reached the intended coordinate/velocity assertions, not a compile or setup fault. The first external log validator over-specified the numeric output of decomposing a sheared matrix. Qualification reran the identical SHA-256 old executable against a wrong-point margin and the unchanged world geometry oracle. Tests and non-owner code were byte-identical across the pair. Existing fixture checks also cover the body staying a root, joint linkage, no release jump, collider configuration, and the prior rigid rotation/scale in the offset case. This compares profile spawn and two directly driven animation samples before the solver; it does not claim a hosted animation graph, live solver, UE binary, GPU, or packaged editor run.
