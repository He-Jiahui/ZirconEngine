# Runtime ordinary-mesh HZB: a previous occlusion result can hide the current pose

Status: **problem only**. The unchanged ZE product has **not** yet run the proposed motion regression. This note, a numerical reference, and existing tests of the HZB kernel or history machinery are not its RED or acceptance.

## User-visible contract

With a stationary camera and wall, an already resident opaque object can move out from behind the wall. The first frame at the exposed pose must show it, regardless of whether the object itself or an ancestor changed. The old depth image can prove that the *old object pose* was hidden; on its own it cannot prove the current pose is hidden. The risk is one-frame pop-in during manipulation, animation or simulation, not inaccurate authoring transforms or a need to turn off occlusion for every Dynamic object.

Independent of [#135](https://github.com/He-Jiahui/ZirconEngine/pull/135): that Draft preserves the published affine through the renderer and makes **the selected previous matrix** yield a conservative sphere radius even when only it has shear. Its real DX12 kernel control injects an old-pose point in front of the wall and requires that the shader retain it. Here the old pose is genuinely hidden, including its complete inflated bound; the current pose is exposed. The stale decision also occurs with a plain unit parent and no shear or reflection. [#144](https://github.com/He-Jiahui/ZirconEngine/pull/144) covers Edit color of affine mesh geometry, not position validity for prior depth. A change of target position is not an [orthographic camera visibility](https://github.com/He-Jiahui/ZirconEngine/pull/218) or [Edit click ray](https://github.com/He-Jiahui/ZirconEngine/pull/220) defect.

## ZE: the decision and its authority are in different spaces

Baseline `e89349ca51b4e9d024c194cd3bdf645bd25b6c37`; behavior also source-reachable on the isolated affine comparator `3e6e9746590b4d5db33d5f95e4c46ecc5203ff23`.

1. ECS writes a Dynamic parent's local pose and publishes the child's world pose; static authoring writes are rejected by [the hierarchy API](../../../zircon_runtime/src/scene/world/hierarchy.rs#L132-L195). The Level-to-Frame consumer is [real world extraction](../../../zircon_runtime/src/scene/level_system_render_extract.rs#L7-L17), not a renderer re-authoring ECS. Preserve `parent_world * local` and never decompose an affine to qualify history.
2. [GPUScene sync](../../../zircon_runtime/src/graphics/scene/renderer/mesh/build/gpu_scene_sync.rs#L83-L111) gets the previous matrix for the same stable instance and writes it alongside the current float32 matrix. It writes the transform revision, but does not use either the revision or the matrix pair to qualify HZB. [`previous_world_from_local` and its success roll](../../../zircon_runtime/src/graphics/scene/gpu_scene/prev_transform.rs#L17-L43) provide previous submitted instance data; [commit](../../../zircon_runtime/src/graphics/core/render/commit_compiled_scene_frame_success.rs#L103-L117) rolls the history after the successful scene submission chain. Rely on queue order, not implicit CPU proof of GPU completion.
3. [Local bounds qualification](../../../zircon_runtime/src/graphics/scene/renderer/mesh/build/gpu_scene_sync.rs#L135-L168) only incorporates [bounds validity](../../../zircon_runtime/src/graphics/scene/renderer/mesh/build/gpu_scene_bounds.rs#L22-L41) and [deformation stability](../../../zircon_runtime/src/graphics/scene/renderer/mesh/build/pending_mesh_draw.rs#L94-L108). Stable local geometry is not stable in world space. Ordinary non-skinned instances advertise the [velocity previous-transform bit](../../../zircon_runtime/src/graphics/scene/renderer/mesh/build/gpu_scene_sync.rs#L244-L260) even on first-frame current-matrix fallback, so that bit alone is not proof of previous committed pose. The path uses standard [indexed indirect batching](../../../zircon_runtime/src/graphics/scene/mesh/mesh_pass/indirect_draw_batcher.rs#L157-L176) with no mobility gate. Local GPUScene bind-group override and external/virtual-geometry draws are not this scope.
4. [Global history key](../../../zircon_runtime/src/graphics/runtime/history/validation_key.rs#L47-L64) keys the world identity, camera structure and features, not its local content generation. HZB is a [separate texture domain](../../../zircon_runtime/src/graphics/core/render/bind_compiled_scene_graph_resources.rs#L89-L109) from TAA. The [shader](../../../zircon_runtime/src/graphics/scene/renderer/hzb/shaders/hzb_occlusion_cull.wgsl#L65-L111) first checks **current** flags, then selects the old matrix, projects it in the old view and samples [one furthest HZB texel](../../../zircon_runtime/src/graphics/scene/renderer/hzb/shaders/zr_hzb.wgsl#L2-L17). Shader compaction output governs [current-frame replay](../../../zircon_runtime/src/graphics/scene/renderer/mesh/mesh_pass/replay.rs#L316-L366); there is no current-pose verification in that replay. This is the V1 one-pass tradeoff, not an implementation of [the explicitly deferred two-pass retest](../zircon_runtime/render/04-visibility-culling.md#L224-L229).

## Local Unreal source and an independent optical control

Physical reference: `dev/UnrealEngine`, file layout of local 6.0.0, branch string `UE5` (not executed). In `Engine/Source/Runtime/Renderer/Private/SceneVisibility.cpp:2793–2812`, the classic renderer admits HZB feedback only for the matching query frame, and at **2911–2979** it expands and queries the world box only when eligible. At **5573–5594**, a camera reset or large camera movement sets `bIgnoreExistingQueries`. `Engine/Shaders/Private/HZBOcclusion.usf:17–38` projects the entire box and rejects testing a near-plane-crossing footprint; `Engine/Shaders/Private/Nanite/NaniteHZBCull.ush:135–201` samples the projected footprint and uses reversed Z. This is not proof that classic UE never suffers delayed visibility for moved objects. An explicit example of distinct ownership is **Nanite**: `Engine/Source/Runtime/Renderer/Private/Nanite/NaniteCullRaster.cpp:7108–7169` rebuilds a HZB from this pass's available depth and re-tests prior-occluded instances/clusters, with a post raster pass. Do not import UE's reverse-Z compare, texture layout, query objects, or Nanite's second raster path into this ZE fix.

Pinned [Three.js r180](https://github.com/mrdoob/three.js/tree/0af9729d0c143a86a1d725d6e2c3ad83301f3f34) ran two identical references using `Object3D` current `matrixWorld`, single-sided `Mesh` ray intersections and a separate shader-equation/analytic depth-tile model. At 256², rigid orthographic half width/height **5**, near/far **0.1 / 10**, wall front `z=−2.4` on left half, a cube of side `.15` at `z=−7.5` moves by its parent from **x=−2.5** to **x=+2.5**. With both cubes purely TRS, old-left probe is wall **16/16**, prior-right is clear, current-right shows the cube **16/16**. Old sphere calculation at the left gives nearest `.584095 > .232323` even with padding, so it correctly rejects **the previous location**. On the right, the old depth texture's independent modeled tile is clear (`1`). In a second reference with **prior shear → current orthogonal**, the #135 radius gives nearest `.421715 > .232323`, still old-location occluded. Frustum intersection, radius conservatism and stale pose are three different questions. Three is a geometry/appearance oracle here, not an implementation of ZE or UE HZB. No engine result is inferred from the model.

Existing isolated DX12 HZB rows showed the old-matrix radius fault and #135 fix. Existing archived GPUScene history-roll controls also pass, and an archived perspective wall test reported no hidden culls; that test's projection/depth margin is different. An independent archived general camera-cut consumer assertion fails; it does not exercise this fixed-camera condition and cannot be used as evidence here. A fresh product without admitted real HZB, matching diagnostics or ready assets would be a setup failure, not this RED.

## Narrow proposed acceptance, in order

- Open this documentation-only Draft. Freeze unchanged-production CPU and DX12 tests after independent owner/fixture review. CPU contract: the exact current and prior *effective draw* matrix pair from the registered instance, reviewed together with local bounds stability. Distinguish changed ordinary rigid geometry (including parent-only translation), stable Dynamic, deforming/invalid, and real-vs-fallback prior history without rewriting velocity eligibility. Require controls with unchanged matrix despite an unrelated world-generation update. Use real sync or its validated lower-level inputs; a source-string assertion alone is not a RED. Keep the tests in a new dedicated child owner; the existing low-level mirrored tangent tests remain owned by [#140](https://github.com/He-Jiahui/ZirconEngine/pull/140).
- DX12 hardware, real active Project, Level `WorldMatrix` after schedule, registered ordinary opaque resident cube, unchanged camera/wall/material/shader/LOD, same world uid, viewport and stable mesh key. Use the pure parent translation above as the primary late oracle. Use no deform/VG/layer toggles/AA. A no-HZB control with only the built-in occlusion feature removed must show all 16 red pixels first exposed. In the measured lane prove the old left is wall, actual previous depth history is bound (not neutral white), ordinary indirect phase was dispatched, and the target is inside CPU visibility before compaction. A separate unchanged opaque target fully behind the wall must still compact away; establish this via source-frame-matched stats plus independently verified stable identities/candidate counts, never via hidden color alone. Opt in to diagnostics; prior/latest totals without their source-frame numbers do not count. Content must be ready before the history seed; do not repeat the transition frame until it looks correct. Seek true old `0/16` and fixed `16/16` on that *first* exposed frame, with the identical selectors and evidence controls. Archive captures independently of receipts. Prior-shear variant can verify composition with #135 after a primary RED.
- Only after the genuine RED is published, consider OR-ing the existing `FORCE_HZB_VISIBLE` for a changed same-instance submitted matrix at the GPUScene producer that already owns both matrices. Do not change velocity's previous matrix, its flags, shader ABI or #135 radius. Prefer exact effective-float comparison for known history; do not invalidate all objects for a world-generation edit or disable stable Dynamic occlusion. Check steady fade-out of the guard, reuse/failed submissions and the no-history behavior deliberately. No new public interface needed.
- Camera movement, moved/removed occluders, missing/reused history across viewport/stack routes, conservative projected extent/sampling, and visibility provenance/performance beyond this witness are separate. Do not claim that a moved-occludee guard fixes those. Packaged UI, CI, Unreal runtime parity and merge are not part of this problem-only submission.
