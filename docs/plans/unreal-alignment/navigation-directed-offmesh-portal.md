# Navigation: follow the selected entry of a bidirectional off-mesh link

**Problem-only Draft**, directly based on `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. No test, native behavioral result, or production edit yet. This is not [#181](https://github.com/He-Jiahui/ZirconEngine/pull/181) (affine authored endpoints), [#187](https://github.com/He-Jiahui/ZirconEngine/pull/187) (coincident entry metadata), [#188](https://github.com/He-Jiahui/ZirconEngine/pull/188) (ordinary false adjacency), or [#189](https://github.com/He-Jiahui/ZirconEngine/pull/189) (cached agent eligibility).

1. **Difference.** ZE [selects only the link ID from the first two path points](../../../zircon_plugins/navigation/runtime/src/manager/traversal/selection.rs#L4-L14), forwards [the asset link and current agent position](../../../zircon_plugins/navigation/runtime/src/manager/traversal/mod.rs#L53-L66), and [orients the bidirectional stage by nearest authored endpoint](../../../zircon_plugins/navigation/runtime/src/manager/traversal/state.rs#L26-L64). The route's marked entry point can be the opposite of the endpoint closest by straight-line distance.
2. **Possible consequence.** The approach can move toward the other island while still on ordinary walking, before any jump, and then start and land in the wrong direction despite a valid ordered native route. A correct start for the current direction is not the same as a correctly transformed endpoint. Both effects must be measured, not inferred from a path-only log.
3. **Cause and actual Unreal source.** Local `dev/UnrealEngine/Engine/Source/Runtime/AIModule/Private/Navigation/PathFollowingComponent.cpp:903–928,950–965,1466–1478` takes the start, refs, end and custom link from the selected segment and dispatches `StartUsingCustomLink(CustomNavLink, SegmentEnd)`. ZE's vendor `getPortalPoints` already derives the off-mesh point from the actual `from` polygon link on entry. The loss is in the Rust handoff, not a reason to copy UE motion or native wire format.
4. **Rust follow-up after measured RED.** Preserve the marked entry when selecting the ID. Use it only for a determinate direction, retain authored endpoints/identity, leave one-way behavior and active traversal/capacity unchanged. Ambiguous snapping, repeated identical IDs and geometry changes are separate from this measurable entry-selection case. Prefer no ABI or new path schema; do not guess that a path destination is the authored link landing.
5. **Interface/ECS.** Path metadata records the actual native entry, while the asset owns authored endpoints and the stage event carries the actual agent/mesh/link/owner and directed endpoints. Keep planner/filtering, writeback and shape/transform contracts unchanged; an observed `Complete` alone cannot show a traversal actually happened.
6. **Frozen gate.** Adapt the existing runtime two-island ground and [native jump-stage tests](../../../zircon_plugins/navigation/runtime/src/tests/off_mesh.rs#L14-L40). Native disjoint long islands have A=(1,0,−5) on left, B=(7,0,+5) on right. An interior left start (0,0,+5) is closer to B (distance² 49) than A (101), despite the path first entering A. The opposite case mirrors this. Both use explicit TileCache, area-masked and local endpoint controls so the ordinary reverse phantom edge cannot qualify. Require real agent first-step direction, approach staying on the start island, Started/Completed and arc/landing, plus normal nearer-entry and one-way controls. Use UE `Engine/Source/Developer/NavigationTestSuite/Private/NavMeshPathfindingTest.cpp:94–126` for successful start/end predicate precedent, not a claim of an identical local UE automation or executed UE binary.
