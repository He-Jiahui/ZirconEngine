# Navigation facing yaw reflects the requested X direction

**Draft — verified old behavior.** The problem-only Draft preceded the frozen tests. With ZE production unchanged at `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`, unparented Legacy agents reproduced the yaw reflection independently of the position-only parent write in #146 and of host admission in #158.

1. **Difference.** ZE's [navigation movement-facing routine](../../../zircon_plugins/navigation/runtime/src/manager/agent_motion.rs#L104-L136) reads local `-Z` through the current quaternion to obtain forward. Both horizontal headings use `atan2(+x, -z)`, but the result is then used as a right-handed rotation around `+Y`. UE's orient-to-movement routine derives a target `Rotation()` from requested velocity or acceleration; after the optional axes policy, it steps toward that orientation, not toward a reflection of the direction. Compare the actual rotated forward vector in each engine's coordinate system, not Euler-angle signs.
2. **Impact.** The native old Legacy manager moved `+X` while facing `-X`, and `-X` while facing `+X`. Starting 30 degrees left of forward with a 45-degree cap, the old X component was about `-0.258819` instead of `+0.258819`; the expected crossing to the right of forward did not happen. Movement positions were correct in every test. `update_rotation` is true in the [default descriptor](../../../zircon_runtime/src/core/framework/navigation/agent.rs#L65-L87), so a position-only control cannot rule this out.
3. **Cause and Unreal evidence.** ZE [math aliases](../../../zircon_runtime/crates/zr_math/src/lib.rs#L49-L57) are glam; the locked `glam 0.32.1` `from_rotation_y` formula takes a positive angle around `+Y` (`src/f32/sse2/quat.rs:175–180`), and quaternion/vector multiplication uses `axis.cross(vector)` (`src/f32/sse2/quat.rs:876–892`). It maps `-Z` to `(-sin(yaw),0,-cos(yaw))`, so the inverse heading sign must agree. In the local Unreal tree, `Engine/Source/Runtime/Engine/Private/Components/CharacterMovementComponent.cpp:6624–6639` uses `RequestedVelocity.GetSafeNormal().Rotation()` or acceleration, and `6755–6777` uses `FMath::FixedTurn` for the capped yaw before moving the component. `AIModule/Private/AIController.cpp:445–478` separately derives a world facing from `FocalPoint - PawnViewLocation`; it does not define ZE's shared movement or axis policy.
4. **Rust direction.** After a frozen old behavioral failure, align extraction of the *current* and *target* horizontal heading with the same existing quaternion convention (for `-Z` forward and `+Y` yaw, both use the inverse sign for `x`). Preserve the shortest-arc wrap and configured angular limit, and do not change movement vectors, parent-space writes, rotations unrelated to movement, or the vertical/no-movement rules. Do not negate just one of the two headings to make a cardinal case pass.
5. **Interfaces and ECS.** Keep `NavMeshAgentDescriptor`, authored axes, root transforms, World hierarchy, prefab and registries unchanged. The helper is shared by the [ordinary Legacy and direct-traversal writes](../../../zircon_plugins/navigation/runtime/src/manager/tick.rs#L201-L267) and [Recast Crowd transform writer](../../../zircon_plugins/navigation/runtime/src/agent/writeback.rs#L54-L79); a Legacy observation alone does not certify the other routes or any parent-space facing behavior. [Builtin's analogous expression](../../../zircon_runtime/src/navigation/runtime/math.rs#L1-L5) has a different motion route without this helper; it is a separate source concern, not a tested part of this Draft.
6. **Concrete gate.** The [six frozen cases](../../../zircon_plugins/navigation/runtime/tests/legacy_facing.rs) port the assertion style from local UE `System::Core::Math::Vector Register Abstraction Test` (`Engine/Source/Runtime/Core/Tests/Math/UnrealMathTest.cpp:2357,3858–3875`): rotate the engine-forward basis and compare its measured direction. They reuse the [real plugin manager fixture](../../../zircon_plugins/navigation/runtime/src/tests/test_support.rs#L27-L49) and #146's one agent, zero meshes, 0.5-second frame and actual Legacy displacement assertions. The mirror `+X/-X` and first capped step are the old RED. Straight movement, disabled facing, and zero angular speed are the old passing controls; the last two still move one world unit. Compile/setup failures, raw quaternion-component matches, and substitutes for the host are not acceptance.

Windows/MSVC baseline `a43b10650d52a3e2c830e680e85017625f512677`: **3 passed, 3 failed, 0 ignored**, native exit 101. All three failures followed the real `scanned/moved/blocked=1/1/0` movement; assertions tested the sign of the resulting world forward axis. No UE binary, packaged editor, hosted scene `Update`, Crowd, or Off-mesh case ran.
