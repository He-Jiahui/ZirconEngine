# Jolt: top-level collider center must reach native geometry, not move the body origin

**Problem-only Draft**, independent on `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. No new tests, native execution or production edit. [#194](https://github.com/He-Jiahui/ZirconEngine/pull/194) only corrects World-to-physics affine point publication to Builtin; no dependency on it.

1. **Difference.** [Native Jolt body creation](../../../zircon_plugins/physics/runtime/src/backend/jolt/runtime.rs#L297-L367) receives separate `BodyDesc.body.transform` and `collider.transform` but supplies the body pose plus the unplaced shape to JoltC. A valid nonzero collider center can therefore be ignored even with identity scale and no hierarchy shear. The failure to preserve a simple local point precedes the wider affine-shape question.
2. **Effect to prove.** With a small static floor whose body origin is at x0 but authored collider center at x8, a sphere falling above x8 should settle and one above x0 should fall. Step the actual native physics system and collect native body positions/velocities, not CPU manager raycasts or shared-geometry contact events. Equivalent zero-offset and translated-body floors must retain their existing physical response.
3. **Actual UE.** Local `dev/UnrealEngine/Engine/Source/Runtime/Engine/Private/PhysicsEngine/Experimental/ChaosInterfaceUtils.cpp:148–176` constructs its box with resolved local translation (transformed shape if rotated, translated bounds otherwise), separately from the body. `Engine/Source/Programs/HeadlessChaos/Private/GeometryCollection/GeometryCollectionTestSimulation.cpp:32–103` advances a real solver and checks falling/resting dynamic positions. These are source contracts, not an executed UE result or evidence of UE FTransform shear fidelity.
4. **Rust approach after RED.** Resolve only the world-space center difference into the native body's rotation frame and place the native shape locally, without teleporting body origin, changing the shared shape or silently changing shape rotation/scale. Verify the exact locked JoltC API and reference ownership first; preserve zero-offset and existing density/mass paths. Actual radius/extents, nonuniform/signed affine shape support, native querying and mass-center/joint policies are separate boundaries, not inferred fixes.
5. **Interface/ECS.** Existing [BodyDesc](../../../zircon_plugins/physics/runtime/src/backend/types.rs#L19-L48) already owns body and collider descriptors; manager need not consult mutable ECS during native construction. Keep public ABI and authoring format unchanged. [Active Jolt collider readback](../../../zircon_plugins/physics/runtime/src/manager/jolt_world.rs#L259-L286) can separately overwrite snapshot metadata; do not fix it here or use the snapshot as native narrow-phase evidence.
6. **Test-first.** Extend [existing real Jolt tests](../../../zircon_plugins/physics/runtime/src/backend/tests/jolt_contract.rs) using their native shape/body/step/readback framework. Freeze original-source center-offset and rotated-body cases, zero/translated controls, original stack/mass/pendulum controls. Build only `zircon_plugin_physics_runtime --lib`, defaults off, explicit `backend-jolt` + runtime native-host/physics-contracts, Windows/MSVC test profile; no fallback if linking/initialization fails, no such failure counts as RED. Publish actual measured RED before any production change. No GPU needed for native CPU solver response.
