# Runtime Sprite2D vertices lose the parent hierarchy's shear

**Problem-only Draft.** Baseline `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. No tests, observed result or production change yet. This is Level → runtime sprite draw, not #135 ordinary mesh visibility or #144 editor mesh viewport extraction.

1. **Difference.** The [ZE sprite producer](../../../zircon_runtime/src/scene/world/render.rs#L408-L463) reduces the hierarchy to `World::world_transform`, and the [sprite emitter](../../../zircon_runtime/src/graphics/scene/renderer/sprite/build_sprite_vertices.rs#L92-L118) builds a new matrix from that TRS. Unreal Paper2D uses the resolved scene proxy draw matrix when submitting the sprite batch. That is the relevant consumer boundary; Unreal attachment is not the shear oracle.
2. **Potential impact.** A centered 2×2 quad with `Sx(2) * Rz(45°)` should have XY corners `(±2√2,0),(0,±√2)`. A test point near `(2.50,0)` has real area inside the affine quad independently of raster quantization. The compatibility reconstruction can move these corners and miss the fringe even when the center, sprite count and Ready texture look correct. This is a source prediction, pending a measured CPU and GPU pair.
3. **Cause and Unreal evidence.** [ZE's affine hierarchy](../../../zircon_runtime/src/scene/world/derived_state.rs#L503-L531) is already available, but reducing it to a quaternion and three scales before a vertex projection discards shear. UE `Engine/Plugins/2D/Paper2D/Source/Paper2D/Private/PaperSpriteComponent.cpp:75–87` submits the sprite draw record to the proxy; `PaperRenderSceneProxy.cpp:369–378,409–419` feeds local vertices and `GetLocalToWorld()` to the dynamic mesh path. `Engine/Source/Runtime/Engine/Private/DynamicMeshBuilder.cpp:876–894` writes that matrix to the primitive uniform. Paper2D's prebuilt buffer uses the same primitive proxy (`PaperRenderSceneProxy.cpp:465–497` and `PrimitiveSceneProxy.cpp:905–926`). That does not remove UE `FTransform` hierarchy limitations.
4. **Rust direction.** Only after genuine RED, retain `WorldMatrix` in the existing frame flow until the common sprite vertex projector. Keep the newly supplied affine frame-owned, select it only for its matching compatibility snapshot, and obtain one matrix before quad/slice traversal. Do not silently attach an old matrix to a replaced sprite or break raw/synthetic TRS callers. No requirement to change the world's serialized sprite component, UVs, sorting, material, particles or batching.
5. **Interface/ECS.** [LevelSystem](../../../zircon_runtime/src/scene/level_system_render_extract.rs#L7-L17) prepares the ECS frame, then [shared SpriteExtract](../../../zircon_runtime/src/core/framework/render/frame_extract/scene_payload.rs#L7-L21) supplies sprite indices to the [same batched Core2d consumer](../../../zircon_runtime/src/graphics/scene/renderer/sprite/prepared_batches.rs#L46-L82) and per-sprite vertex path. Preserve camera masks, frame sharing and anchor/atlas conventions. UE attaches the mapping to a primitive proxy rather than using ZE's owned snapshot. The old Editor compatibility adapter is not the sprite runtime route.
6. **Concrete gate.** Port the checked-in UE independent scalar point comparison in `System::Core::Math::Vector Register Abstraction Test` (`Engine/Source/Runtime/Core/Tests/Math/UnrealMathTest.cpp:525–540,2357,3051–3098`) and the parent/child control in `System.Engine.Attachment` (`Engine/Source/Runtime/Engine/Private/Tests/EngineAutomationTests.cpp:1543,2045–2065`). No Paper2D-specific affine automation was identified locally. Reuse ZE's [sprite vertex cases](../../../zircon_runtime/src/graphics/scene/renderer/sprite/tests/cases.rs) and [product submit](../../../zircon_runtime/src/graphics/tests/render_product_sprite.rs#L190-L252). Require actual vertex coordinates with rigid/synthetic controls and a DX12 offscreen image with a real Ready sprite texture, expected center, far outside and fringe pixels. Missing assets, wrong camera, GPU validation errors, or build failures are not behavioral RED.
