# Runtime Sprite2D vertices lose the parent hierarchy's shear

**Draft — frozen CPU behavioral RED; no production change.** Baseline `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. This is Level → runtime sprite draw, not #135 ordinary mesh visibility or #144 editor mesh viewport extraction. The problem-only review was published before test changes. Full hardware pixel validation is pending an independently observed Core2D depth-attachment issue; no GPU affine result is claimed.

1. **Difference.** The [ZE sprite producer](../../../zircon_runtime/src/scene/world/render.rs#L408-L463) reduces the hierarchy to `World::world_transform`, and the [sprite emitter](../../../zircon_runtime/src/graphics/scene/renderer/sprite/build_sprite_vertices.rs#L92-L118) builds a new matrix from that TRS. Unreal Paper2D uses the resolved scene proxy draw matrix when submitting the sprite batch. That is the relevant consumer boundary; Unreal attachment is not the shear oracle.
2. **Potential impact.** A centered 2×2 quad with `Sx(2) * Rz(45°)` should have XY corners `(±2√2,0),(0,±√2)`. A test point near `(2.50,0)` has real area inside the affine quad independently of raster quantization. The old compatibility reconstruction produced corners `(-2.215953,0.094632)` and `(2.215953,-0.094632)` where `(-2.828427,0)` and `(2.828427,0)` were required; the maximum over all six draw vertices was `0.8073049` world units. This proves the vertex difference, not a measured fringe: on current production the proper Core2D graph rejects a separate depth attachment access before rasterization.
3. **Cause and Unreal evidence.** [ZE's affine hierarchy](../../../zircon_runtime/src/scene/world/derived_state.rs#L503-L531) is already available, but reducing it to a quaternion and three scales before a vertex projection discards shear. UE `Engine/Plugins/2D/Paper2D/Source/Paper2D/Private/PaperSpriteComponent.cpp:75–87` submits the sprite draw record to the proxy; `PaperRenderSceneProxy.cpp:369–378,409–419` feeds local vertices and `GetLocalToWorld()` to the dynamic mesh path. `Engine/Source/Runtime/Engine/Private/DynamicMeshBuilder.cpp:876–894` writes that matrix to the primitive uniform. Paper2D's prebuilt buffer uses the primitive proxy (`PaperRenderSceneProxy.cpp:465–497`); `Engine/Source/Runtime/Renderer/Private/RendererScene.cpp:3341–3355` reads that proxy's `LocalToWorld` into the primitive parameters. The source primitive still starts from `GetComponentTransform().ToMatrixWithScale()` (`Engine/Source/Runtime/Engine/Private/Components/PrimitiveComponent.cpp:1267–1270`); this is not evidence of shear-preserving UE attachment.
4. **Rust direction.** Only after genuine RED, retain `WorldMatrix` in the existing frame flow until the common sprite vertex projector. Keep the newly supplied affine frame-owned, select it only for its matching compatibility snapshot, and obtain one matrix before quad/slice traversal. Do not silently attach an old matrix to a replaced sprite or break raw/synthetic TRS callers. No requirement to change the world's serialized sprite component, UVs, sorting, material, particles or batching.
5. **Interface/ECS.** [LevelSystem](../../../zircon_runtime/src/scene/level_system_render_extract.rs#L7-L17) prepares the ECS frame, then [shared SpriteExtract](../../../zircon_runtime/src/core/framework/render/frame_extract/scene_payload.rs#L7-L21) supplies sprite indices to the [same batched Core2d consumer](../../../zircon_runtime/src/graphics/scene/renderer/sprite/prepared_batches.rs#L46-L82) and per-sprite vertex path. Preserve camera masks, frame sharing and anchor/atlas conventions. UE attaches the mapping to a primitive proxy rather than using ZE's owned snapshot. The old Editor compatibility adapter is not the sprite runtime route.
6. **Concrete gate.** Port the checked-in UE independent scalar point comparison in `System::Core::Math::Vector Register Abstraction Test` (`Engine/Source/Runtime/Core/Tests/Math/UnrealMathTest.cpp:525–540,2357,3051–3098`) and the parent/child control in `System.Engine.Attachment` (`Engine/Source/Runtime/Engine/Private/Tests/EngineAutomationTests.cpp:1543,2045–2065`). For actual pixel validation, adapt channel-wise comparison from Unreal `Engine/Plugins/Tests/RHITests/Source/RHITests/Private/RHIClearTextureTests.cpp:686–744`. No Paper2D-specific affine automation was identified locally. Reuse ZE's [sprite vertex cases](../../../zircon_runtime/src/graphics/scene/renderer/sprite/tests/cases.rs) and [product submit](../../../zircon_runtime/src/graphics/tests/render_product_sprite.rs#L190-L252). Require actual vertex coordinates with rigid/synthetic controls and a DX12 offscreen image with a real Ready sprite texture, expected center, far outside and fringe pixels. Missing assets, wrong camera, GPU validation errors, or build failures are not behavioral RED.

## Native baseline (production unchanged)

- Windows/MSVC `zircon_runtime --lib`, defaults off, explicit `native-host,graphics`. [Frozen cases](../../../zircon_runtime/src/graphics/scene/renderer/sprite/tests/affine_cases.rs) plus existing checks: **5 passed / 1 failed** (101), only the sheared vertex assertion. Batch and per-sprite vertices agree, rigid and raw same-TRS replacement retain their expected coordinates, and atlas/triangle, selection and batching controls are unchanged. The build comparison uses just the known #137 test-lifetime file locally in addition to this Draft's tests; it does not go into this PR.
- The actual RTX 3060 Laptop DX12 backend initialized. The first two attempts did **not draw**: an empty viewport was given a premature Core2D override and then a test-generated World ID did not match its existing journal. The final fixture uses the default pipeline chosen from the real submitted camera and the real world identity with unchanged inputs, probes and geometric assertions; it does not clear or substitute the journal.
- The final baseline enters the real render graph for the **rigid** frame and fails before any pixel assertion: `opaque-sprite` did not declare `Read` access for `scene-depth`. This is not shader coverage, not missing texture evidence and not an affine GPU RED; no image is claimed. The independent attachment-access investigation must produce a qualified graph baseline before comparing these same frozen GPU pixels on the old versus candidate affine code. No production modification to the sprite or renderer yet.
