## 2. 有界实际影响

采用两个正常关节、单位旋转/缩放、单一 Skin，源序 `[Child, Root]`、父槽 `[Some(1), None]`，`JOINTS_0=0` 的顶点以 `WEIGHTS_0=1` 绑定 Child。仅 X 平移，绑定 `(Root=10, Child-local=1)`、姿态 `(Root=14, Child-local=3)`，Child 的绑定/姿态同空间坐标为 `11/17`，故槽 0 应为 `+6`、槽 1 为 `+4`，顶点 `x=11` 应到 `17`。这是可判定的源码与算术预期，不是本轮运行实测；纯平移 fixture 可使导入逆绑定值与基线从绑定 TRS 推导值一致，不混入逆绑定来源问题。调色板在第一个槽就失败，直接 Mesh 的 `.ok()` 吞掉错误，无 morph 时去 [普通 prepared draw:171–195](https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/graphics/mesh/build/extend_pending_draws_for_mesh_instance.rs#L171-L195)：可见但未随骨骼变形；存在 morph 时可能仍 morph 而不蒙皮（[448–477](https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/graphics/mesh/build/extend_pending_draws_for_mesh_instance.rs#L448-L477)）。Model 的对应候选可落到 [skinned=false、无 palette:283–335](https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_runtime/src/graphics/mesh/build/extend_pending_draws_for_mesh_instance.rs#L283-L335)。错误在 CPU 顶点与 GPU 调色板分流前，切换 GPU 选项不能补救。父先子后的资产不因本根因受影响；不声称项目存量或真实角色渲染已复现。

## 3. 根因与 UE 解决

ZE 把**持久化的源关节槽号**当作**父依赖已经求值的顺序**。UE 普通 glTF Skeletal Mesh 则区分二者：翻译器保存源序 joint 名及 influence slot；工厂从根开始先加入父骨，再遍历子骨，随后把 source slot 映射到目标 RefSkeleton bone index 并写入权重。`FReferenceSkeleton::Add` 在通常单根契约中显式验证 `parent < child`，不是让运行时顺序循环接受杂序 RefSkeleton。播放期动画组件据已排好的 required bones 得到 component-space pose，UE 渲染以逆绑定和该 pose 形成 `ReferenceToLocal` 供 CPU/GPU 使用。下列是本机 UE 证据定位与原始字节 SHA256；不复制源码。

## 4. Rust 沿用 UE 的哪条规则

只沿用「先解父依赖，再合成子骨，绘制读取仍指向同一关节」规则；不把 UE 进口期改排和权重重映射照搬到 ZE。遍历用一套父先子后的计算次序，同时解绑定与动画姿态，**写回原始骨骼槽**。UE 行向量的 local × parent、inverseBind × posed 对应 ZE 列向量的 `parent * local`、`posed * inverse(bind)`；全程保留 `Mat4`，不分解 TRS、不引入引擎 World transform。ZE 编辑器的 [reference_matrix:32–62](https://github.com/He-Jiahui/ZirconEngine/blob/e89349ca51b4e9d024c194cd3bdf645bd25b6c37/zircon_editor/src/core/editing/skeleton_reference/space.rs#L32-L62) 已按真实父链迭代、保持源序，可作本土语义对照；它只求一个骨骼，不应直接用作整帧的 O(深度×骨数) 循环。
