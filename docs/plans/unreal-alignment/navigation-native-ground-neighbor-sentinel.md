# Navigation: preserve missing ground neighbors in ordinary Detour input

**Problem-only Draft.** Based directly on `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`; no test or production edit, and no qualified isolated RED yet. Separate from [#187](https://github.com/He-Jiahui/ZirconEngine/pull/187) straight-path metadata and [#181](https://github.com/He-Jiahui/ZirconEngine/pull/181) link endpoint placement. Unreal references are from the actual local `dev/UnrealEngine` tree.

1. **Difference.** [Ordinary Detour input](../../../zircon_plugins/navigation/native/native/detour_query.cpp#L366-L439) initially fills the ground-neighbor indices with `0`; only a reversed shared vertex-index pair writes a neighbor. UE's actual `Engine/Source/Runtime/NavigationSystem/Private/NavMesh/RecastNavMeshGenerator.cpp:4800–4814,4960–5009` builds a tile-cache polymesh whose standard `Runtime/Navmesh/Private/DetourTileCache/DetourTileCacheBuilder.cpp:2265–2274` row initializes both halves to `0xffff` before matching adjacency/portals.
2. **Consequence.** In #187's earlier native diagnostic, the two separate ground islands `x=[−1,1]` and `[7,9]` run from the right interior straight to the left interior with two corridor entries and no authored jump mark. Forward and TileCache controls actually use the jump, three entries. A nonexistent ground edge can bypass the only link in one direction. A near-coincident endpoint, Rust graph fallback, or `Complete` alone does not establish this bug.
3. **Cause and UE contract.** UE `Engine/Source/Runtime/Navmesh/Private/Detour/DetourNavMeshBuilder.cpp:658–682` translates input `0xffff` to a border but valid source index `0` to `neis=1`; `Private/Detour/DetourNavMesh.cpp:1465–1477` skips `neis=0` and subtracts one for internal references. ZE's vendored consumer has the same meaning. The ordinary ZE producer accidentally creates edges pointing to source polygon zero. Merely swapping polygon records, not geometry, is predicted to reverse which direction is broken.
4. **Rust/native approach after real RED.** Reuse existing raw-Detour test owner and test only the ordinary input builder. Set unused slots to the documented null index before matching; preserve real zero-index adjacency. Keep native/Rust status mapping, filtering, triangulation, TileCache, off-mesh points, straight-path funnel, and ABI as-is.
5. **Interface/ECS.** ZE marshals a portable `NavMeshAsset` (ground topology, areas, authored links); UE usually produces native tile-poly data directly. This correction would only translate absent adjacency, not change asset serialization, world matrices, ECS, ownership registration, or runtime traversal.
6. **Freeze before any fix.** Reuse [existing two-island geometry](../../../zircon_plugins/navigation/native/src/tests/support.rs#L6-L68), native unit tests and raw path in [the linkage suite](../../../zircon_plugins/navigation/native/src/tests/linkage.rs). Require both directions in both polygon orders to be disconnected with no link, and after masking the single jump with the same native owner. Verify both local endpoints remain usable, raw status/message means no complete corridor, unmasked links have actual markers, and legitimate shared edge into polygon zero remains usable. Explicit TileCache or raw TileCache controls should not show the asymmetry. Adapt UE `Engine/Source/Developer/NavigationTestSuite/Private/NavMeshPathfindingTest.cpp:94–126` route/endpoint checks; no exact UE false adjacency test or UE executable run claimed. The test helper may need the same import-only migration as #187, not its production change or path tests.
