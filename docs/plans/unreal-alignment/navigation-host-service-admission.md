# Navigation plugin declares a Driver → Manager dependency before the scene can tick

**Problem-only Draft.** Source reviewed against ZE main `e89349ca51b4e9d024c194cd3bdf645bd25b6c37` and the local Unreal checkout. The expected Core refusal is not yet an executed reproduction. Do not conflate plugin host admission with #146, whose actual Legacy manager was constructed directly by its existing fixture.

1. **Difference.** The ZE [production plugin descriptor](../../../zircon_plugins/navigation/runtime/src/plugin.rs#L199-L214) contributes [one implementation Driver](../../../zircon_plugins/navigation/runtime/src/lib.rs#L68-L95) that explicitly depends on `AssetModule.Manager.ProjectAssetManager`. Its scene Driver and public Manager both view that implementation. UE uses an instance attached to a world, and selects/configures it before initializing navigation for that same world; its navigation-data readiness follows the instance, not a service-kind edge equivalent to ZE's.
2. **Impact to verify.** ZE's extension catalog can describe the navigation module and the `navigation.agent_tick` anchor while the Core registered graph is unable to accept the module. If reproduced, neither typed service view nor the scheduled Update can become usable through the normal host path. The directly constructed manager can still pass #146; that is not host acceptance. Do not infer a crash, an affected executable, or UE parity from source alone.
3. **Cause and Unreal evidence.** ZE's [descriptor admission](../../../zircon_runtime/src/core/runtime/handle/registration/validation.rs#L17-L40) [requires Driver dependency targets to be Drivers](../../../zircon_runtime/src/core/runtime/handle/registration/validation.rs#L88-L102), independent of `Lazy`. In the local Unreal tree, `Engine/Source/Runtime/Engine/Private/AI/NavigationSystemBase.cpp:74–115` selects configuration, installs its instance in the world and optionally initializes it. `Engine/Source/Runtime/Engine/Private/World.cpp:2487–2499` may install without initializing; `Engine/Source/Runtime/Engine/Private/GameInstance.cpp:521–530` initializes PIE navigation after actor initialization. `Engine/Source/Runtime/NavigationSystem/Private/NavigationSystem.cpp:1355–1413` sets up the current world and registers its nav data. This references service availability, operation timing and ownership; UE does not expose ZE's Driver/Manager hierarchy.
4. **Rust feasibility.** Keep one authoritative navigation implementation and the existing Core dependency contract; do not delete the descriptor edge while secretly fetching the same Manager in its Driver factory. Read-only project asset access is needed for baking, including source geometry leases and generation-fenced publication ([bake preparation](../../../zircon_plugins/navigation/runtime/src/manager/bake.rs#L388-L423), [publication](../../../zircon_plugins/navigation/runtime/src/manager/bake.rs#L508-L568)). Verify where a legal existing owner can supply that dependency before proposing a fix. [The audio module](../../../zircon_plugins/sound/runtime/src/module.rs#L24-L69) is a ZE example of a pure Driver with asset-dependent Manager above it; it is not an interchangeable navigation implementation.
5. **Interface and ECS.** Preserve the public `NavigationManager` and `SceneNavigationRuntime` views, their shared loaded-mesh state, and project/world generation guards unless a separate, specifically justified change is approved. Neither UE's `UWorld` instance life cycle nor registry policy requires creating per-ECS-entity navigation owners. Do not change navmesh bake geometry, movement writeback, hierarchy, Prefab, or Core-wide service validation in this issue.
6. **Concrete ZE gate.** Reuse the intent of the [existing registration fixture](../../../zircon_plugins/navigation/runtime/src/tests/registration.rs#L25-L108), but first register prerequisites and the real exported plugin module before any activation (the first activation freezes the graph). Require registration, activation, and the declared service views, with the existing flat-navmesh query control; keep a separate genuine builtin-nav module control. No duplicate implementation or altered descriptor. The local UE test `System.Navigation.NavMesh.Pathfinding.StraightLine` (`Engine/Source/Developer/NavigationTestSuite/Private/NavMeshPathfindingTest.cpp:58–91`) obtains the real navigation instance for a fresh world, initializes data using `NavMeshTestWorld.cpp:146–221` and queries it. Borrow the availability→data→query assertions, not UE's editor fixture or the creation of a new ZE test framework. A compile/setup failure or `ModuleGraphFrozen` would not demonstrate the stated failure. If the old behavior is reproduced but no legal thin fix is established, retain a tests-and-evidence Draft; do not relax Core or declare host Update repaired.
