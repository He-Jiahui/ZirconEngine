# Physics: resolve the authored collider point through the actual affine hierarchy

**Draft — measured original-production ray-hit RED**, directly based on `main@e89349ca51b4e9d024c194cd3bdf645bd25b6c37`. Tests frozen; production still unchanged. Scope is the collider's local-origin translation during scene-to-physics sync; opposite-direction body writeback [#145](https://github.com/He-Jiahui/ZirconEngine/pull/145), skeletal points [#176](https://github.com/He-Jiahui/ZirconEngine/pull/176), navigation [#182](https://github.com/He-Jiahui/ZirconEngine/pull/182) and render volumes [#184](https://github.com/He-Jiahui/ZirconEngine/pull/184) are independent.

1. **Difference.** [Current World physics projection](../../../zircon_plugins/physics/runtime/src/manager/world_sync.rs#L37-L100) uses the projected `world_transform` for the entity and then [composes the nonzero collider-local point through its TRS](../../../zircon_plugins/physics/runtime/src/manager/world_sync.rs#L311-L317). `WorldMatrix` contains the real `parent * local` affine chain; the compatibility TRS cannot reconstruct it under inherited shear.
2. **Effect to prove.** [The real scene tick](../../../zircon_plugins/physics/runtime/src/manager/service.rs#L121-L156) publishes a synchronized collider snapshot and [actual manager ray queries](../../../zircon_plugins/physics/runtime/src/manager/query.rs#L18-L57) read it. A small sphere at an authored nonzero offset may hit at the projected position and miss at the actual affine position. Query hit identity, distance, position and normal must demonstrate the defect, not a hand-built sync or an unsynchronized empty query. No native Jolt invocation follows from the shared Builtin query API.
3. **Actual Unreal contract.** Local `dev/UnrealEngine/Engine/Source/Runtime/Engine/Private/PhysicsEngine/BodySetup.cpp:2032–2051,2072–2086` resolves primitive-local sphere center separately from radius. `Engine/Source/Runtime/Engine/Private/PhysicsEngine/Experimental/ChaosInterfaceUtils.cpp:137–146` passes those values to the actual sphere constructor. This supplies the local-point/shape boundary, not UE FTransform as a shear oracle. UE sphere radius uses a different nonuniform policy; that is not part of this change.
4. **ZE/Rust after actual RED.** Keep compact rotation/scale and validation/fallback behavior; replace only collider world translation with the authoritative matrix's `transform_point3(local_center)` when available. [ZE matrix hierarchy](../../../zircon_runtime/src/scene/world/derived_state.rs#L668-L680), [Three.js matrixWorld](https://github.com/mrdoob/three.js/blob/r180/src/core/Object3D.js) and [Unity Entities local-to-world](https://docs.unity3d.com/Packages/com.unity.entities@1.3/manual/transforms-concepts.html) provide the affine chain semantics. No radius, orientation, ellipsoid, dynamic body integration or body-origin change.
5. **Interface/ECS.** Authoring remains `ColliderComponent.local_transform`; physics retains its existing compact `PhysicsColliderSyncState` ABI. The consumer should see the correct point from World publication without querying mutable ECS or adding another transform owner. No new public matrix/TRS schema, no project/prefab format migration.
6. **Tests first.** Extend [the existing world-sync tests](../../../zircon_plugins/physics/runtime/src/manager/tests/world_sync.rs), use real `tick_scene_world` and public manager raycast after verifying the synchronized snapshot. Freeze sheared and mirrored-shear nonzero points plus rigid/zero-offset controls and filter/world checks. Adapt actual UE `Engine/Source/Programs/HeadlessChaos/Private/HeadlessChaosTestRaycast.cpp:25–86` sphere hit/miss, distance, position and normal predicates, not a new test framework or a claim of having executed UE. No GPU is needed for a CPU scene-to-physics query contract.
