# BD01: use world distance for perspective sphere culling

**Draft — scoped CPU fix.** The opening commit described the independent prerequisite for [BD02 (#135)](https://github.com/He-Jiahui/ZirconEngine/pull/135), then the tests were committed separately and run before the production change.

1. **Difference.** Before the fix, ZE's [ordinary CPU culling](../../../zircon_runtime/src/graphics/visibility/culling/is_mesh_visible.rs#L64-L88) compared world-space sphere radius to the raw lateral coordinate excess at the center's depth. Unreal extracts unit-normal frustum planes before comparing world-space signed distance to radius; its ordinary primitive visibility uses a box test, with an optional sphere-first rejection (`Engine/Source/Runtime/Renderer/Private/SceneVisibility.cpp:604–627`).
2. **Effect.** A visible mesh can disappear near a perspective edge. The BD02 review exposes an additional source-level counterexample at 90° and aspect 1: center `(6.3,0,-5)`, parent scale `(1,3,1.2)`, child rotation `Y=-45°`, local triangle `(-1,0,0), (1,.01,0), (1,-.01,0)`. The new affine box sphere is about `1.105`, so the old test rejects `6.3 > 5 + 1.105`; a real transformed vertex is about `(5.593,0,-5.849)`, inside the right plane. The old, looser sphere is about `3`, hiding the defect. The local #135 combination later verified this witness: it was culled with the old side-plane equation and retained after BD01, at the same measured radius `1.10494351`.
3. **Cause and Unreal source.** Local Unreal `Engine/Source/Runtime/Core/Public/Math/Matrix.inl:755–766,794–835` normalizes side-plane coefficients including the offset. `Engine/Source/Runtime/Engine/Private/ConvexVolume.cpp:310–348,728–749` rejects a sphere only if a plane's signed distance exceeds its radius. ZE omitted the side plane normal length; increasing the geometry bound to mask this would not fix the culler.
4. **Rust direction.** For symmetric perspective, use horizontal `hypot(tan(fov_y/2) * aspect, 1)` and vertical `hypot(tan(fov_y/2), 1)` radius allowances once per view. This is the same half-space test in unnormalized coordinates, not a convex volume/SIMD port. Retain the existing conservative near clamp and orthographic path.
5. **Boundary.** Ordinary CPU sphere visibility only. No ECS changes, arbitrary projection update, virtual geometry change, new bounding-volume owner, HZB change, or Prefab change. Existing sphere data and worker paths stay unchanged.
6. **Concrete ZE change and gate.** Only [BoundsVisibilityTest](../../../zircon_runtime/src/graphics/visibility/culling/is_mesh_visible.rs#L14-L89) changed. The [four-sided signed-distance comparison at three aspect ratios](../../../zircon_runtime/src/graphics/visibility/culling/tests/is_mesh_visible.rs#L38) and [prepared triangle against its far control](../../../zircon_runtime/src/graphics/visibility/context/history/construct/tests/cases.rs#L743) were frozen and rerun unchanged. These compare with UE's signed-distance formula, not a copied or executed UE automation test.

On a local candidate with the separate [#137](https://github.com/He-Jiahui/ZirconEngine/pull/137) compile repair, the exact 15 Windows/MSVC CPU cases changed from **12 passed, 3 failed** to **14 passed, 1 failed**. The two target cases passed, the existing static prefilter assertion remained unchanged, and the non-test runtime library check passed. No GPU, UE binary, or editor product test was run for the independent #138 verification. Combined CPU/DX12 evidence is recorded in [#135](https://github.com/He-Jiahui/ZirconEngine/pull/135); GitHub's required `editor-compile-gate` must still pass before merging.
