# BD01: use world distance for perspective sphere culling

**Draft — tests only.** The opening commit described the independent prerequisite for [BD02 (#135)](https://github.com/He-Jiahui/ZirconEngine/pull/135). The following commit transfers two existing investigation tests without editing engine code.

1. **Difference.** ZE's [ordinary CPU test](../../../zircon_runtime/src/graphics/visibility/culling/is_mesh_visible.rs#L52-L76) compares world-space sphere radius to the raw lateral coordinate excess at the center's depth. Unreal extracts unit-normal frustum planes and compares world-space signed distance to radius.
2. **Effect.** A visible mesh can disappear near a perspective edge. The BD02 review exposes an additional source-level counterexample at 90° and aspect 1: center `(6.3,0,-5)`, parent scale `(1,3,1.2)`, child rotation `Y=-45°`, local triangle `(-1,0,0), (1,.01,0), (1,-.01,0)`. The new affine box sphere is about `1.105`, so the old test rejects `6.3 > 5 + 1.105`; a real transformed vertex is about `(5.593,0,-5.849)`, inside the right plane. The old, looser sphere is about `3`, hiding the defect. This specific combined case has not been executed in ZE.
3. **Cause and Unreal source.** Local Unreal `Engine/Source/Runtime/Core/Public/Math/Matrix.inl:755–766,794–835` normalizes side-plane coefficients including the offset. `Engine/Source/Runtime/Engine/Private/ConvexVolume.cpp:310–348,728–749` rejects a sphere only if a plane's signed distance exceeds its radius. ZE omitted the side plane normal length; increasing the geometry bound to mask this would not fix the culler.
4. **Rust direction.** For symmetric perspective, use horizontal `hypot(tan(fov_y/2) * aspect, 1)` and vertical `hypot(tan(fov_y/2), 1)` radius allowances once per view. This is the same half-space test in unnormalized coordinates, not a convex volume/SIMD port. Retain the existing conservative near clamp and orthographic path.
5. **Boundary.** Ordinary CPU sphere visibility only. No ECS changes, arbitrary projection update, virtual geometry change, new bounding-volume owner, HZB change, or Prefab change. Existing sphere data and worker paths stay unchanged.
6. **Concrete ZE change and gate.** Before changing production, run the [four-sided signed-distance comparison at three aspect ratios](../../../zircon_runtime/src/graphics/visibility/culling/tests/is_mesh_visible.rs#L38) and [prepared triangle against its far control](../../../zircon_runtime/src/graphics/visibility/context/history/construct/tests/cases.rs#L743). A historical investigation obtained behavior RED and then GREEN in a different worktree; this PR has not run. Freeze fresh tests-only inputs on a buildable candidate with [#137](https://github.com/He-Jiahui/ZirconEngine/pull/137), then change only `BoundsVisibilityTest` and rerun.
