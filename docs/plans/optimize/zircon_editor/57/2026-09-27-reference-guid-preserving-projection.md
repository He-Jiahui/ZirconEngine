# Editor57 reference GUID preserving projection

## Defect and contract

`catalog_generation/details.rs` and `record.rs` previously looked up a reference UUID and, on a miss, resolved its locator without checking how that UUID was created. If explicit UUID A had disappeared and asset B occupied the old locator, both the details row and `direct_reference_uuids` silently changed A to B. The details row was marked `known_project_asset`, making B reachable through the reference pointer route and drag payload.

Both projections now use one private catalog lookup in `record.rs`. A registered UUID wins even when its locator hint names another asset. A missing explicit UUID remains the original UUID and locator, with no known-project pointer target. Locator fallback is retained only when the UUID equals the exact stable-label identity generated by `AssetReference::from_locator` for that locator. The resolved row must exist in the catalog for both projections.

This preserves the Editor's existing locator-only reference behavior. It does not broaden Runtime registry semantics: `AssetRegistryIndex::resolve_asset_id_for_reference` remains strictly UUID based. The synthetic identity rule comes from `zircon_runtime_interface/src/resource/asset_reference.rs`, not from an added public compatibility layer. Existing capacity changes in `details.rs` were preserved.

## Behavioral evidence

The tests were authored before the production lookup change. Dynamic RED/GREEN execution is deferred to the grouped managed Editor batch.

- `editor57_reference_identity_rejects_missing_explicit_uuid_at_an_occupied_locator` rejects substitution of B for missing explicit A.
- `editor57_reference_identity_allows_only_the_exact_locator_derived_uuid_to_fall_back` preserves a valid synthetic reference, rejects a synthetic UUID derived from a different locator, and keeps an absent target unresolved.
- `editor57_reference_identity_prefers_a_registered_uuid_over_an_occupied_hint` checks UUID priority, including a registered UUID that also matches the hint's synthetic identity.
- `editor57_reference_identity_details_and_catalog_drive_the_same_pointer_target` runs the actual catalog-row and details projections, installs the results in `AssetWorkspaceState`, and dispatches a click through `AssetReferenceListPointerBridge`. Explicit missing identity produces `ListSurface` and retains source selection; valid synthetic and registered identities produce the correct item route and navigation. It also asserts agreement between details and `direct_reference_uuids`.

This is a correctness repair with no new timing claim. Registered UUID lookup still returns before deriving the synthetic identity. Editor57-G37 native 100,000-asset navigation/selection/action p95/p99, G30 generation-coherent publication, global reference repair, and typed unresolved-reference diagnostics remain open.
