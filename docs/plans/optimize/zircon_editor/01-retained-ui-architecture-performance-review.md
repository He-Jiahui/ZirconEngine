## 3. 参考引擎结论与适用边界

Unreal Slate 的 `FSlateInvalidationRoot`/fast path把widget更新限制到失效集合，`FHittestGrid`在paint时记录paint-space geometry；`SListView`从当前scroll offset开始生成并在viewport填满后停止，复用已有item widget。Slint repeater同样分离model row count、visible offset、cached item height与instances。Zircon应吸收的是单一publication authority、dirty propagation边界、逻辑集合/实例集合分离、可见集合和事件期只读查询，不复制Slate历史兼容层、UObject所有权或另一棵平行row tree。

renderer生命周期同样必须显式。`FSlateApplication::InitializeRenderer`在初始化阶段建立renderer，`DestroyRenderer`在shutdown释放；窗口变化通过既有renderer的viewport resize合同处理。它没有在每个输入/tick中先销毁renderer再探测依赖是否就绪。Zircon的runtime RenderFramework是异步解析，因此需要额外的Pending状态和有界poll，但可用fallback presenter必须持续拥有surface，直到共享renderer已确认ready并进入一次性交接。

Unreal的native reshape边界也不是“每条size消息都重建UI”。Windows `WM_ENTERSIZEMOVE`使Slate进入responsive mode，`WM_EXITSIZEMOVE`退出；`WM_SIZING`只要求flush旧viewport命令，`FSlateViewportInfo::ResizeViewport`只在extent/HDR/fullscreen真变化时刷新projection并调用RHI resize。这一实现仍有flush/viewport成本，不能用来证明“resize必然廉价”；它只证明两个应吸收的合同：交互reshape期禁止无关昂贵任务，surface extent变化与widget invalidation分层。Zircon现有80 ms retained-reflow事务已经符合后一条，Softbuffer候选也改为冻结首张raster并直接缩放写surface；仍须用timeline验证两种backend的present admission，不应再加第二套layout或每事件重建。

Unreal进一步把窗口surface与device故障分层：`FSlateViewportInfo`按窗口保存独立viewport/extent，`CreateViewport`、`RequestResize`和`OnWindowDestroyed`只操作对应窗口，并在native window销毁前等待in-flight present完成；D3D12 RHI在queue/fence层检查device removed reason并集中输出DRED、breadcrumb和page-fault证据。当前参考版本遇到GPU crash会进入明确终止路径，并不能证明“Unreal会自动恢复device”。Zircon应吸收的是分层owner、单次状态转换和可诊断失败；Editor若要进程内恢复，必须由RenderFramework建立device generation与重建协议，不能把真正device loss伪装成可无限重试的surface acquire，也不能让每个窗口自行创建平行device/cache。

Slate的render cache边界也比当前Zircon完整：invalidation root保存per-widget cached element list、只把`ListsWithNewData`交给batcher重编译，并长期保留cached batches；当帧仍按batch数提交，但不会为全部widget重新hash、克隆和展开draw payload。Slint用item-local cache index + backend generation与property tracker表达同一原则。Zircon现有`UiSurfaceFrame`应扩展为唯一generation publication，multi-surface composite只能引用其segment handles；不能在Runtime set、Editor host和renderer各自再建一份cache。

Unreal Content Browser把thumbnail集合限制在真实visible items与有界offscreen range，复用`RelevantThumbnails`，`SListView`的`FWidgetGenerator`则从当前scroll offset开始生成、填满viewport后停止，并在generation pass末尾回收未见widget；其 `ListItemsSource` 是外部稳定item source，selection由table/list selection set另外维护，不把selected bit复制进每个source row。Slint repeater以共享model、model row count、visible offset、cached item height和instances表达同一边界；Fyrox `ListView`仍保留全量child vector，只作为Rust所有权对照而不是规模目标。`FAssetThumbnailPool`的 `FThumbId(ObjectPath, Width, Height)`以完整元组相等性区分对象和目标尺寸、按具体dirty asset刷新且限制每tick生成时间，其XOR只用于哈希，不替代typed equality。Zircon现已用稳定slot + 算术rebind消除全部filtered assets的template-node物化，把像素materialization限制到visible paint，并让Asset Workspace发布共享immutable item generation与选择overlay；下一步是per-asset delta、后台预算和稳定GPU handle，而不是在layout层增大全局cache常量。

Hierarchy hard-cut前的current-source复核给出直接依据。`workbench_scene_tree_panel.zui`只声明10个authored row，但旧 `virtual_rows` repeat会扫描surface、克隆prototype并为每个overflow逻辑行插入真实child；`sync_scene_entries`随后遍历全部control并写visibility、text、depth、indent、entity、parent、subtree hash、expanded和selected，旧 `SceneHierarchyProjectionState`又克隆全部control id建立双向map。与之相反，native painter只访问 `visible_hierarchy_row_range`，`HierarchyPointerBridge`只保存layout/state/row metrics并用算术求 `item_index`；click、drag/reparent直接把index映射到 `scene_entries`/entity，inline rename使用固定 `HierarchyInlineRename` control加目标entity id，不依赖逐行control。Unreal `SListView.h:1524-1705`从 `CurrentScrollOffset` 求 `StartIndex`、生成到viewport填满并复用已生成widget，`:1029-1077`在generation末释放未见row；Slint `repeater.rs:176-360`以 `offset + instances`随机跳转、按viewport补齐并删除不可见实例，`:445-523`只把落在实例窗内的row delta应用到实例。本轮已删除overflow template物化，把完整逻辑行留在generation-owned投影/native model，并保留native paint/input的算术可见窗权威。后续current-source复审又收口了full reflow内部的重复identity projection：行查找只保存无序标量索引，不再拥有`display_name`；selection-only delta直接复用共享presented row，只有真实content change才携带replacement。该改动不取消full reflow对N行展示模型的一次线性发布，动态门仍要求把index、presentation与allocator成本分别计数。

布局current-source已经比早期审查继续推进：增量pass删除预先收集整个root subtree和全量geometry snapshot，使用dirty-to-root dependency paths、增量post-order measure、arrange-time geometry delta与可复用scratch；`UiLayoutCache.measure_valid`也已替代零frame哨兵，合法零尺寸viewport不再被误判为首次prepass。2026-08-27产品入口复核发现剩余卡顿并不在增量pass内部：`rebuild_incremental`先把 `root_size_changed` 合入layout dirty，然后在没有节点级dirty来源时把 `layout_dirty_node_count` 扩成全树，`should_use_full_layout_rebuild`又直接因resize返回true，导致每次窗体尺寸变化都在进入已有 `pure_root_resize`、尺寸依赖索引与 `arrange_resized_root` 前退化为全量measure/arrange。后半链还把任意同帧 `dirty.input` 作为禁止局部arranged patch的条件，resize + hover/press会继续全量重建arranged/hit/render；resize + render-only dirty则误走纯geometry command patch，存在视觉payload漏刷风险。当前候选在合入resize前保存真实layout dirty状态，布局预算只统计layout域节点；输入字段、resize geometry、hit route/cell与render command在同一受影响节点集合内顺序patch，任一步验证失败仍完整fallback。纯resize的dirty count保持0并交给增量authority，未归因的真实layout失效仍按全树处理，大脏集仍按预算回退。Unreal `SWidget.cpp:674-684`只在显式 `bNeedsPrepass` 时执行fast-update prepass，Fyrox `fyrox-ui/src/lib.rs:1830-1844`则以measure validity与available-size key共同控制early-out；两者都支持“尺寸是缓存输入，不是无条件全树失效”的边界。10,000节点、200步、1 root + 1尺寸依赖child + 1交互dirty的确定性模型将measure探测从2,000,000降至0、arrange探测从2,000,000降至400（5,000倍），arranged/hit/render三域总patch work从6,000,000降至1,800（约3,333倍），但该数字不是CPU/RSS/p95实测，Cargo与产品resize timeline仍待managed validation。

Console复核说明“有容量上限”和“已虚拟化”不是同一结论。旧实现虽由`ConsoleOutputSnapshot`与`EditorConsoleHistory`把逻辑历史限制到256行，仍按全部行clone prototype并为severity/message生成最多512个完整template node；paint只画可见范围，且曾为每次查询生成新的row索引向量。当前候选已按同一 `SListView`/Slint repeater边界把逻辑快照和实例集合解耦：metadata拥有逻辑行authority，retained tree只生成viewport + 双侧overscan稳定环形槽，paint/hit按相同line-index映射读取payload和frame，静态控件命中只遍历前缀/后缀且所有paint行访问均不分配row vector。pointer主链继续读取published authority且同hover不触发redraw；下一缺口不是再次改变命中几何，而是让输出append在跨presentation generation时复用logical descriptors并只更新entered/expired slot，同时取得current-source allocator/CPU/RSS/p95证据。

后台物化的直接依据也来自同一产品链：`SAssetView.cpp:1293-1295`创建共享thumbnail pool并把offscreen池限制为64，`:5369-5370`与`:5445-5446`只把可见row标记为pending update，`:5573-5658`围绕可见集合维护relevance并利用队列次序优先处理可见项；`AssetThumbnail.h:234`把pool默认预算限制为每tick 5 ms、每帧最多3个realtime thumbnail；`AssetThumbnail.cpp:2114-2267`在tick中执行expensive-task throttle和frame-time allowance，`:2775`之后重新提升可见thumbnail优先级。Zircon没有照搬Slate tick对象，而是复用现有受限job system、cache epoch与winit wake；仍缺少的是类似5 ms tick预算的queue-age/可见优先级证据，以及由resource-to-frame反向索引驱动的局部damage。

Slint/Fyrox用于交叉核对缓存与Rust所有权边界：缓存按资源generation与内容身份复用，布局/命中状态由发布代际拥有，事件不承担全场景重建。参考只用于确认契约，不以API名称映射代替本地生产链证据。

文本输入与无障碍同样要求“平台桥接器围绕单一retained authority工作”。Unreal `ITextInputMethodContext`要求editable owner同时提供composition状态、selection、range读写、text bounds和screen bounds，并由focus生命周期Register/Activate/Deactivate；不是把IME commit降级成普通字符追加。Slate无障碍则缓存稳定widget/id、只在dirty时重建，默认每tick最多处理100个widget，并在整轮完成前继续向平台暴露上一代children数组。Zircon已有更适合不可变publication的Surface frame，因此应吸收完整上下文与代次提交原则，不复制Unreal的全局singleton或game-thread同步等待。

## 4. 实现顺序

1. 稳定输入与窗口底座：合并后台事件native wake；移除event-loop原生metrics轮询；修复runtime presenter升级状态机；保留可用fallback并建立readiness/backoff/单次handoff计数。在不改变80 ms retained-reflow边界的前提下，把native resize snapshot提升为backend-neutral合同：Softbuffer专用override与纯像素/首帧冻结/source wiring测试候选已完成。专用resize gate现已接入 `presentation_rebuild_count`、shell-presentation/host-scene/pane-projection build、structure-generation、layout probe、GPU/SVG cache与shell geometry patch等真实authority，当前全presentation rebuild会明确RED。当前最高优先级是把pure `WINDOW_METRICS`切到单一authority上的geometry-only publication，保持pane model与structure generation，并新增独立正数 `geometry_patch_count`；topology key或breakpoint变化才以typed `geometry_only_fallback_count`及原因升级全结构rebuild。只有该算法、专用gate、managed focused回归和200-step产品profile同时通过后，才允许根据剩余GPU/forced-softbuffer timeline决定是否引入latest-wins present admission。
2. 接通真实按钮提交：静态候选已让bridge pending node patch在dispatch boundary提升为typed Workbench projection commit，允许与render/paint域合并命中已有changed-row patch，并消费 `sync_viewport_chrome`；热路的pending判定为 `O(1)`，首次full projection及projection/hit miss仍完整fallback。下一门是managed Rust与1000次tool/button click产品profile，必须证明Full target/full redraw为0并核对old/new damage、structure generation和render submission；之后才按数据决定是否继续做changed-row generation/delta、有序trie cursor与publication-time compaction。
3. 收口事件期只读命中：Console static hit的前缀/后缀零分配迭代候选已完成静态格式/source guard，下一门是managed focused回归；随后以borrowed generation/row handle替代稳定pointer move中owned `TemplateNodePointerHit`字符串复制，hover identity比较不得物化callback payload，visible hit只迭代算术range。最后完成Runtime projected hit grid的下层受管验证并验证Editor popup产品路径；各路径都不得在事件期lazy扫描tree/render commands。
4. 统一焦点导航publication：projected hit下层动态通过后，在同一Surface frame generation构建navigation index；先用相关dirty整批重建移除事件期全树扫描，再依据publication profile决定是否做changed-node patch。control-anchored popup必须使用最终投影geometry，不能建立tree-local cache或lazy event rebuild。
5. 消除伪虚拟化：hierarchy先删除逐逻辑行template镜像、repeat reconcile和entity/control双向字符串map，structural template只保留viewport anchor；selection/rename/drag/reparent直接复用既有native `O(V)` paint、`O(1)` arithmetic pointer与entity authority。Runtime Tree的selection/rename事件期全量`Vec`/`HashSet`物化问题、目标authority和复杂度预算见[Tree logical-index input review](./02-tree-logical-index-input-review.md)：稳定generation下single/additive/rename必须为`O(1)`，range只访问实际跨度`O(Delta)`，仅identity/generation不一致允许计数化全扫描fallback。旧的 `WorkbenchSceneVirtualItem*` dispatch/snapshot/fragment测试应替换为“10,000逻辑行、template row节点为0、selection/rename/drag等价、1000次scroll无reconcile/property write”的产品合同，不能为了保住测试而保留影子树；键盘导航/accessibility需单独建立logical-row adapter，不得重新物化N个隐藏节点。Inspector先修复当前dead scroll contract：property generation、logical extent、offset与visible slot window同代发布，paint/hit共享变换；再用visible + overscan稳定slot替代全量row，slot按field id重绑并保护active edit identity。最后扩展Runtime model-count/logical-extent/visible-materializer合同。
6. 收敛Asset Browser item/thumbnail与preview raster product：stable slot、generation-owned logical paint source以及Asset Workspace state-owned `Arc<[AssetItemSnapshot]>` + UUID index已完成静态实现；selected UUID为独立overlay，Activity/Explorer和相邻selection快照共享allocation，registry投影也复用同一双代际缓存。同步SVG/image miss已移入既有并发上限2的Thumbnail后台队列，并具备同键合并、cache epoch拒绝旧结果和独立completion wake；CPU cache继续按RGBA bytes预算，GPU继续使用既有device registry。下一步以per-asset delta替换catalog/resource单项变化导致的全源重建，补可见优先级/queue-age门和resource-to-frame damage聚合；最后让decode/raster generation直接发布带预计算content key的共享product，继续删除paint热路剩余的resource key/command DTO构造。
7. 消除其它逻辑集合复制：Console的256行bounded snapshot、64行chunk source generation、shell-owned Activity Log projection与visible+overscan环形instance pool已完成静态增量链；append跨generation复用未变source chunks，payload不flatten全文，pane cache只patch变化control与source identity变化的slots，同generation多消费者零重绑，entered/expired/rebound与generation reuse计数已接入。下一门是managed focused Rust和1000次产品追加/滚动profile，必须证明格式化/slot patch与delta/viewport同阶且RSS有界；通过后再按shell drag、asset family、menu、Welcome顺序验证固定authority候选。
8. 收敛布局与paint publication：auto-layout现已具备dirty-to-root依赖路径、显式measurement validity与generation-owned child order；纯root resize也已接通responsive/尺寸依赖索引和局部arrange，不再默认完整reflow。下一门是managed产品resize证明measure probe为0、arrange probe与root + 尺寸依赖节点同阶，并验证breakpoint、clip与大脏集仍正确保守回退；随后验证viewport toolbar点击不重排、tab/header authored-frame局部dirty rebuild，以及damage paint索引复用generation内稳定顺序。rich-table必须在同一阶段建立generation-owned `TrackMetrics`：列/行extent、含gap origin和prefix sum只计算一次，provisional、box与final cell三条路径共享消费，禁止每个cell重复slice sum或让origin与span使用不同gap语义。
9. 收敛Surface frame与render publication：顶层frame保持单一原子generation，layout/hit/navigation/render/a11y改为分域immutable handles，focus/window-only变化复用未变域；Surface render frame已发布64-command leaves + 32路持久目录，并从局部rebuild接收exact ranges。Runtime/RenderFramework/one-slot queue现已传共享persistent extract/submission handles，multi-surface以ordered segment + 惰性node-id namespace组合，删除changed-Surface command clone/global-id rewrite；Editor HUD等flat fixture只在显式兼容入口一次转换。下一门是让renderer按persistent segment identity只recache changed segments并组合cached batches；framebuffer background ordering、draw-range rebasing、text/image prepare owner必须先有下层等价回归，owned DTO只保留冷路径兼容。
10. 校准文本和GPU：文本cache稳定命中的owned key分配与2048项clear-all已独立收口；待glyph owner稳定后，把layout artifact改为相对坐标并在draw应用最终origin/subpixel phase，删除pure translate/resize中的绝对x/y cache miss。先批量提交GPU present profile counters以降低观测扰动；在上述结构性工作归零后，用profile决定text raster与damage/present剩余长尾。SVG/GPU只验证失效与residency，不重复建立平行cache。
11. 完成RHI故障域：先在 `zr_rhi` 定义可区分surface retry、device unavailable和terminal failure的结果，再由RenderFramework实现唯一device generation/recovery owner，最后让多窗口presenter按新generation各重建一次surface/pipeline/text/image/retained资源并请求一次full redraw。该项是故障隔离与工程完整性门，不作为稳态按钮卡顿的替代解释，也不与前十步的动态profile混成同一收益结论。
12. 收口平台可访问性：先为Editor focused text建立完整IME session回归并删除append-only事件降级，再把Runtime accessibility snapshot变成publication-owned cache，最后为每native window接入OS adapter。两项都先证明产品event/action闭环，再做大树/长composition压力；不得用每帧全树snapshot换取功能表面可用。

每一步必须从最低共享层focused回归开始；一项候选未得到current-source动态证据时，不与下一项算法重写混成同一验收结论。

Unreal Slate复核进一步限定了native hard cut。`FSlateFontCache::GetShapedGlyphFontAtlasData`先读shaped glyph自身的atlas-data weak cache，miss才查跨sequence的`ShapedGlyphToAtlasData`，最终才raster/add entry；`FSlateFontCache::UpdateCache`独立推进异步SDF完成和atlas texture dirty update。Zircon当前相反地由`NativeBitmapAtlasFrame`同时拥有source images、retry/report与`GlyphAtlasBitmapRenderSubmissionPlan`，后者的run又拥有`GlyphAtlasSet`；`TextRenderState::prepare_bitmap_atlas`每帧`mem::take` atlas，frame handoff后`finish_bitmap_atlas_frame`再取回。renderer即使instance bytes未变也必须先遍历/构造完整plan、对全部instance做BLAKE3并clone draw commands，所有权耦合使“缓存整个frame”既冻结worker/upload，又无法安全保留atlas。

M2b3目标因此拆为四个authority，而不是给现有frame加一个布尔命中。第一，segment product保留immutable glyph dependency与ordered logical geometry，并建立`GlyphRasterKey -> segment/local instance`反向索引。第二，source-cache update每帧先drain completion、处理face/invalidation并对active unique keys做LRU touch，发布typed readiness generation和exact changed-key receipt；effective exact/approximate/missing或persistent binding变化才进入receipt，普通touch不推进，近似subpixel lookup的邻接key必须扩张失效。第三，atlas residency/slot/page update独立持有`GlyphAtlasSet`并发布mapping generation、changed-key与upload delta，retry placeholder另有可见代次；draw product不再拥有atlas。第四，`D(readiness) union M(mapping) union R(retry)`通过反向索引只patch受影响segment，局部plan变化只重建对应segment；renderer接收segment draw-product identity，未变段不hash、不write buffer、不clone commands，而texture upload无条件消费本帧delta。face/font generation、viewport或缺receipt保守全重建。
