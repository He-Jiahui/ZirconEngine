# UI Architecture Audit and Optimization Plan

Date: 2026-08-26
Scope: `zircon_runtime`, `zircon_runtime_interface`, `zircon_editor`, and the local reference engines under `dev/`.

## Executive Finding

The editor is not slow because of one missing cache. The current retained UI path still materializes several independent, scene-sized authorities for a single update:

```text
UiTree
  -> layout/cache state
  -> arranged tree
  -> base hit grid
  -> projected popup hit grid
  -> render extract + render cache
  -> UiSurfaceFrame domain clones
  -> runtime project aggregate command stream
```

The dirty flags select some local patch paths, but several fallback boundaries are still whole-surface rebuilds. A small change can therefore become O(N) layout work, render extraction, navigation-index rebuild, or frame-domain cloning. M2.46 closes one narrower downstream case: after scroll/layout has produced final geometry, arranged and hit-test authorities patch the exact changed clipping subtree instead of rebuilding the complete arranged tree and hit grid. SVG/GPU image caching reduces repeated asset work, but it cannot compensate for the remaining structural walks. Broad layout dirtiness still takes one full layout publication instead of probing incremental layout and then falling through the derived-domain rebuilds a second time.

This audit intentionally does not claim a product CPU/RSS/p50/p95/p99 improvement yet. Dynamic validation is still pending a managed editor/runtime build that is independent of the unrelated current-source blockers. The static evidence and complexity claims below are source-derived.

## Current Pipeline and Hot Boundaries

### Dirty rebuild

`zircon_runtime/src/ui/surface/surface/rebuild.rs` (`rebuild_dirty`) computes a dirty summary, runs incremental layout, and then attempts local patches. When a patch is ineligible or returns an error it falls back to:

- `build_arranged_tree(&self.tree)` and index refresh;
- `UiHitTestIndex::rebuild_arranged_indexed` over the arranged draw order;
- `rebuild_render_extract_with_text_frame` over the arranged draw order;
- `rebuild_navigation_index` over the full tree.

The layout branch now consults the rebuild-owned navigation candidate map before rebuilding the full index. M2.44 extends that authority from geometry/input-only checks to style, text, and visible-range changes: stable local semantics are compared against retained signatures in O(D * H), while changed focus/tab/group/directional/modal facts, navigation-bearing inserted or removed subtrees, popup projection/stack changes, missing authority, and unknown dirty sets remain conservative rebuild triggers. A bounded layout budget chooses the full layout route before incremental probing when the layout dirty set exceeds one quarter of the surface or 256 nodes, whichever is smaller; root-size changes and unknown global layout dirtiness are full-layout cases as well.

### Frame publication

`zircon_runtime/src/ui/surface/surface/frame_publication.rs` stores independent `layout`, `render`, `hit_test`, `focus`, and `pipeline` domains. `surface_frame()` is lazy: after a dirty mark, the first snapshot/debug consumer clones changed arranged nodes, render commands, hit entries/cells, and pipeline data into a new `Arc<UiSurfaceFrame>`. Snapshot construction remains O(changed domain size), but M2.13 removes it from the production runtime render path: rendering now reads the retained `UiSurface::render_extract` authority directly and keys its segment cache with the retained invalidation render generation.

The existing counters (`ui.surface_frame.publication_build_count`, `arranged_node_clone_count`, `render_command_clone_count`, `hit_entry_clone_count`, `hit_cell_entry_clone_count`, and `pipeline_stage_build_count`) remain useful for explicit debug/snapshot consumers. Production pointer dispatch queries the retained projected-hit authority, and production runtime rendering queries the retained render authority; neither hot path materializes a frame. Retained/chunked public snapshots are still a later milestone for diagnostics that request immutable history.

### Hit testing and popup projection

The base hit grid and projected popup grid are separate retained spatial indexes, but M2.38 makes them share one frame-owned route authority. Each spatial entry carries a checked dense route index instead of its own inherited policy and bubble-route `Vec`; full publication resolves ancestry once, geometry-only patches reuse the route allocation, and only the selected hit materializes a path. For an ordinary zero-radius pointer query, the hot path resolves one 64 px cell and walks that cell's entries in rebuild-time z/paint order. It performs no arranged/render scan and no event-time sort. Radius queries can span multiple cells and deduplicate/sort their local candidates through retained scratch; that is a separate accessibility/tolerance path rather than the normal mouse-move cost. Popup transforms remain publication-time work and use the same route authority to recognize popup subtrees.

### Render extraction and image assets

`surface/render/extract.rs` walks arranged draw order and resolves visual style, text, and image commands. `surface/render/cache.rs` retains commands by node/command index, but an ineligible local patch returns to full extraction. Before M2.37, full extraction also re-walked each node's parent chain separately for command admission, owner-text prewarm, overlap admission, and popup-trigger visibility. The surface now publishes one inherited arranged-visibility index with its arranged node indexes; those stages query the retained authority by node ID, while standalone one-shot extraction builds one explicit fallback index and records that fallback. The GPU image bind-group cache prevents repeated upload/bind-group construction for stable image keys; it does not remove the surrounding command traversal.

### Editor template projection

`zircon_editor/src/ui/retained_host/ui/apply_presentation/pane_conversion.rs` can convert several pane kinds in one host recompute. Before the current slice, the template pane path projected the same document and built its shared surface through separate old-template instantiations. The stable document projection and old-template instance are now retained by `EditorUiHostRuntime`; pane payload attributes and hybrid slot anchors are applied to a per-call projection copy. Registration, binding, component, and plugin-document changes clear both caches. This keeps dynamic state out of the immutable cache and makes the steady-state projection path allocation-visible through hit/miss counters rather than hidden repeated instantiation.

## Reference Engine Comparison

| Engine | Relevant mechanism | Gap in Zircon today |
| --- | --- | --- |
| Unreal Slate | `WidgetUpdateFlags` separates prepass, repaint, render-transform, volatile paint, and active-tick work. `SlateInvalidationRoot` maintains update/prepass/post lists and a stable hit-test grid. `FSlateDrawBuffer` retains one `FSlateWindowElementList` per window, while `FSlateCachedElementData` keeps per-widget cached element lists and only tracks lists with new data. `SListView::ReGenerateItems` starts at the scroll offset, generates only until the viewport is filled, and `FWidgetGenerator` releases rows no longer seen in the generation pass. | Zircon has dirty domains, M2.44 bounds stable local navigation semantics, and M2.46 patches arranged/hit geometry for an exact changed clipping subtree. Its generic virtual list still retains every logical child and has no model-to-row generation authority. M2.39/M2.41 retain ordered surface segments and one complete renderer plan; partial plan reuse after one changed segment is still deferred. |
| Fyrox UI | Widget state tracks independent measure/arrange/visual validity and previous geometry. `DrawingContext` reuses one `RenderData` allocation and transfers its vectors with `append` when ownership can move. | Zircon now has explicit measurement validity, but arrangement, hit, render, and navigation still frequently cross a whole-surface fallback boundary. Its independently retained `Arc` surface segments cannot use Fyrox's single-producer move without changing the renderer submission contract. |
| Slint | Partial renderer tracks property dependencies and dirty regions, retaining item geometry/transform and repainting affected regions. Its ListView repeater keeps a logical model row count plus a persistent offset/cached-height state, splices only the visible instance range, and removes instances outside that range. | Zircon retains commands/assets but lacks both a shared dirty-region/chunk authority and a generic logical-model-to-bounded-instance authority. |
| Bevy UI | ECS `Changed` queries feed a Taffy-backed `UiSurface`; entity-to-layout mappings are retained and updated independently from rendering systems. | Zircon's tree is retained, yet derived arranged/hit/render/navigation indexes are rebuilt as separate vectors/maps without a common stable chunk/index layer. |

The closest implementation model is Unreal's `dev/UnrealEngine/Engine/Source/Runtime/SlateCore/Private/FastUpdate/SlateInvalidationRoot.cpp` plus `FastUpdate/WidgetProxy.cpp`: the invalidation root processes a sorted affected-widget list and falls back to slow paint only when required, while render-transform updates patch the widget subtree's cached geometry and `FHittestGrid` in place. `FastUpdate/WidgetProxy.h` stores `FSlateInvalidationWidgetVisibility` as direct and ancestor visibility flags, and `SlateInvalidationWidgetList.cpp` propagates parent visibility while updating retained proxies instead of recomputing ancestry in each paint consumer. `Input/HittestGrid.h` stores a weak widget, cell bounds, sort keys, and user index per `FWidgetData`; it does not copy a parent path into every spatial entry. `FHittestGrid::GetBubblePath` selects the best hit first and only then follows `Advanced_GetPaintParentWidget()` to create one route. Fyrox likewise chooses a hit node before `bubble_message` walks ownership at dispatch, while Slint builds one `item_stack` during the current front-to-back input traversal and aborts after acceptance. The important property is shared retained authority: a local update does not first clone an immutable copy of every paint and hit record, or repeatedly derive the same inherited state, merely to feed the renderer.

## Complexity Targets

For a surface with N nodes, R render commands, H hit entries, K navigation candidates, L logical list items, V visible-plus-overscan row slots, and T retained nodes per row template:

- current zero-radius pointer query: O(C + P), where C is occupancy of the addressed hit-grid cell and P is the selected bubble-route depth; it is independent of total H unless cell occupancy degenerates;
- current local layout candidate: layout remains O(D + ancestor/sibling propagation) when eligible and generic virtual-list layout still visits all retained children; after layout, M2.46 patches arranged nodes and hit entries/cells in O(G + affected cells) for the exact geometry-affected clipping subtree G. Render-command topology or other ineligible domains can still produce O(N + H + R + K) fallback work;
- current generic virtual-list materialization: retained tree memory is O(L * T), measurement can visit the retained row subtrees, and scroll arrangement validates and visits all L direct row children even though only V receive non-zero geometry. The target is O(V * T) live row nodes, O(V) fixed-extent window/rebind/layout work, O(changed slots * T) derived updates, and O(L) only for the external logical model that already owns the data;
- explicit immutable frame publication after a dirty mark: O(N_layout_changed + R_render_changed + H_hit_changed) cloning, with domain-specific full copies when the domain changed wholesale; M2.13 removes this operation from the runtime render hot path but not explicit debug/snapshot consumers;
- current runtime aggregate rebuild after one local surface update: O(R_changed) local-to-global node-id remapping plus O(S) ordered segment-handle publication for S surfaces; stable frames return the submission `Arc` and do neither;
- current runtime screen-space planning: an unchanged submission/viewport/background/font-generation key performs an O(1) retained-plan identity check; a miss rebuilds O(R_total + planned payload). The same prepared-plan identity skips stable vertex hashing, while downstream text/image preparation, draw traversal, and GPU recording remain per-frame work;
- current navigation rebuild: O(N + K log K) due full traversal and candidate sorting;
- retired full-extract visibility classification: O(V * N * depth * log N) parent-index work for V visibility stages over a depth-bounded tree; M2.37 replaces this with one O(N log N) retained-index publication and O(V * N * log N) node-ID queries, and a stable arranged tree performs no visibility rebuild;
- retired hit publication: O(H * depth * log N) repeated ancestor lookup work plus O(H * depth) retained route-node payload and one `Vec` header/allocation per hit entry; M2.38 performs one O(N) iterative inherited-route publication, O(H) indexed entry admission, O(A log A) dependency-ordered no-op/input precomputation for A affected descendants, O(G) geometry patching for G changed entries, O(N) shared route payload, and O(P) route materialization only for the selected hit path. A true inherited-semantic mutation may additionally clone O(N) route records when an immutable projected/frame snapshot still shares the previous `Arc`; ordinary state-only input patches prove zero route-table clones;
- desired bounded update: O(D + changed commands + affected hit cells + affected navigation scopes), with an explicit threshold before a full rebuild. Runtime project publication now reaches O(R_changed + S), and stable renderer planning is O(1) before its unchanged downstream preparation/recording work. A changed submission still rebuilds the complete O(R_total + planned payload) screen-space plan; partial segment-plan composition needs an explicit cross-segment background/order contract before it can be safe.

The important metric is not only total frame time. Every rebuild report must expose whether work was local or fallback, and the ratio of visited nodes/commands/cells to the declared dirty set.

## Optimization Plan

### M1: Make authority and invalidation explicit

1. Keep pointer and render product paths on their retained hit/render authorities; reserve `surface_frame()` materialization for explicit immutable snapshot consumers.
2. Keep layout, hit, render, focus, and pipeline generations separate and record the publication generation that consumed each domain.
3. Add source contracts proving that pointer routing queries the published projected authority and never scans arranged/render collections.
4. Add pressure fixtures for one-node style, geometry, input, popup, and window-resize updates; record fallback ratios and domain clone counts.

### M2: Retained chunks and scoped indexes

1. Partition arranged/render/hit data into stable subtree or paint chunks keyed by node identity and draw-order generation.
2. Patch only changed chunks and their affected spatial cells; rebuild a surface only when ordering/topology changes or the changed ratio exceeds a documented threshold.
3. Replace unconditional navigation rebuilds with scope-local updates for unchanged modal/focus scopes, retaining sorted candidate runs and position maps.
4. Treat popup projection as an overlay chunk whose stack/order key is separate from base content and whose subtree entries are replaced atomically.
5. Replace generic retained-child "virtualization" with one model-backed row materializer: preserve the serialized geometry config, keep logical count/data outside `UiTree`, retain only V stable row slots, and publish slot-to-logical-key mappings as the input/accessibility identity authority.
6. Keep row-slot render command topology stable across ordinary scroll. A variable-length command splice is a conservative fallback for genuine structure changes, not the primary virtual-scroll algorithm.

### M3: Product profiling and acceptance

1. Run managed `zircon_editor` scenarios (`idle_hover`, `click`, `drawer_resize`, `window_resize`, `hierarchy_scroll`, and `viewport_pointer`) with the existing PowerShell evidence tools, writing only to `E:\zircon-profiles`.
2. Compare median, p95, and p99 interaction CPU time, peak private/working-set memory, publication clone counters, full-fallback counts, and SVG/GPU cache hit ratios before/after.
3. Accept only if event routing has no rebuild/publication work on a clean frame, local updates scale with the dirty set, and resize remains below the configured interaction CPU gate.

## Immediate Implementation Slice

M1.1 established rebuild-boundary frame publication and independent domain generations. M2.13 supersedes its render-consumer call: full rebuild/layout construction can still publish immutable snapshots, but incremental runtime rendering now stays on retained render authority. This remains an algorithmic change until managed product measurements quantify editor latency and memory.

M1.2 is also implemented in the current slice: incremental layout geometry now consults the rebuild-owned navigation candidate map before rebuilding the full navigation index. M2.44 removes the remaining unconditional style/text/visible-range trigger by comparing local resolved semantics with the retained index; geometry changes confined to non-navigation nodes and semantic-stable local updates skip the O(N + K log K) navigation walk.

The skip path records `ui.navigation_index.geometry_skip_count`, so the next managed profile can report avoided navigation rebuilds directly instead of inferring them from total build counts.

M1.3 is implemented as a retained template projection slice. `EditorUiHostRuntime` caches one immutable `RetainedUiProjection` and one `Arc<UiTemplateInstance>` per document identity. `project_pane_body` clones the cached projection only to apply payload-specific attributes and slot anchors; `build_shared_surface` reuses the cached old-template instance. Cache invalidation is centralized at template/component/binding registration and plugin document replacement. The source-level target is one cold projection/instance build per document generation, then zero further template instantiations on warm pane conversions; dynamic pane data remains per-call work.

M2.1 is implemented as the first stable render-segment boundary. Each runtime UI surface retains its globalized command segment keyed by `(viewport_size, render_generation)`. A changed surface rebuilds only its own segment; unchanged surfaces reuse their remapped commands while the existing public `UiRenderExtract.list.commands` remains flat and behavior-compatible. `ui.project_extract.segment_cache_hit_count`, `segment_cache_miss_count`, and `segment_command_projection_clone_count` expose the avoided remapping directly. Final flat-list cloning is intentionally still measured as a remaining M2 interface gap.

M2.2 is implemented in the screen-space planner: `UiRenderCommand::fill_paint_elements` fills one planner-owned scratch vector per frame while preserving the cached paint generation metadata consumed by text route planning. This removes one temporary `Vec<UiPaintElement>` allocation per visible command without changing the retained/debug vector APIs or text cache-generation semantics.

M2.3 is implemented in `zircon_runtime/src/ui/surface/surface/rebuild.rs`: layout updates are classified before the incremental solver starts. The incremental budget is `min(max(1, N / 4), 256)`; a broad or root-size update calls `compute_layout` once and returns through the normal frame publication path. If a layout flag arrives without a reliable node set, the implementation treats the whole tree as dirty instead of paying an incremental probe followed by a full fallback. `ui.layout.full_rebuild_threshold_count` records this route for managed profiling. This is a scheduling optimization, not a claim that the full layout algorithm itself is faster.

M2.4 is implemented in `zircon_runtime/src/ui/layout/pass/engine.rs` and `incremental.rs`: the incremental arrangement context now builds `required_children_by_parent` once from the required node set. Sparse independent containers read their already-grouped child IDs instead of scanning every required node and querying the tree for every parent. The old shape was O(P * D * log N) for P sparse parents and D required nodes; the new shape is O(D * log N + P * log N + D) and preserves the previous node-ID order. This is the first change in this audit that removes a multiplicative traversal rather than only reusing an allocation.

M2.5 is implemented in `zircon_runtime_interface/src/ui/surface/hit.rs` and `zircon_runtime/src/ui/tree/hit_test.rs`: a retained bubble route now has a direct `UiHitPath::from_bubble_route` constructor. The event path copies the cached route once to produce the root-to-leaf view and no longer builds a second route for `with_route` validation followed by another reverse collection. Query semantics and `virtual_pointer` provenance are unchanged; this removes redundant route allocation from every pointer hit result.

M2.6 is implemented in `zircon_editor/src/ui/template_runtime/runtime/pane_payload_projection.rs`: component projection patches are grouped by `control_id` and applied during one preorder walk of the retained projection. The old path performed one recursive search per patch, O(P * N); the indexed path is O(P + N) for grouping and traversal, preserves patch order for duplicate controls, continues walking after a match so sibling/child controls are still patched, and stops only after all buckets are consumed. Unmatched patches remain no-ops.

M2.7 is implemented in `zircon_editor/src/ui/template_runtime/runtime/runtime_host/dynamic_control_state.rs`: applying the same component attributes to a mutable `UiSurface` and to the retained host model now builds `control_id -> node ids/indexes` once, then resolves each requested control from that index. Missing and duplicate control diagnostics are unchanged, while both old O(P * N) scans become O(N + P). The rebound action path also passes an empty ownership map after `rebind_pane` has registered the canonical table, removing a full `control_attributes.clone()` for every binding.

M2.8 is implemented in the pane projection path: the payload attribute map is built once per projection and moved into the optional hybrid slot anchor after cloning the same values into the root attributes. The anchor no longer reruns the full payload-to-TOML conversion, so one pane conversion has one payload materialization instead of two.

M2.9 is implemented in `zircon_editor/src/ui/template_runtime/runtime/projection.rs`: template action resolution now indexes control positions and resolves bindings in a read-only pass before mutating them. Expressions read the authoritative node attributes through the index, preserving the prior last-duplicate-wins behavior without cloning every control's full attribute map into a temporary table. A static guard also covers the two-phase writeback boundary so a control match cannot invalidate the read snapshot.

M2.10 is implemented in `zircon_runtime/src/ui/surface/frame_hit_test.rs`: projected popup entries now receive an explicit stable z layer derived from popup stack order plus the popup subtree's source z/paint order. The layer rank is saturating, so an unusually large subtree cannot wrap an `i32` z value; the existing paint-order rank remains as the deterministic tie/fallback key. The lower-layer overlapping-child regression now checks both relative z and cross-popup ordering.

M2.11 is implemented in `zircon_runtime/src/ui/surface/navigation_index.rs` and `surface/rebuild.rs`: input-only invalidation now checks the retained index's focus-candidate and modal-activation semantics before rebuilding navigation. Pointer policy and hover state therefore skip the full candidate traversal and sorting; focusability, enabled/visibility changes, modal activation, missing nodes, and unknown dirty sets remain conservative rebuild cases. `ui.navigation_index.input_semantics_skip_count` exposes the avoided rebuilds for the managed profile.

M2.12 corrects the geometry invalidation authority in `navigation_index.rs` and `surface/rebuild.rs`. The navigation index retains all tree nodes for routing metadata, so the previous `self.nodes.contains_key(node_id)` condition classified every local geometry change as navigation-relevant and defeated the intended M1.2 skip path. The index now keeps a separate `geometry_authority_node_ids` set containing focus candidates, active MUI modal roots, and explicit modal-group roots. It also retains each authority's published `(frame, z, paint)` geometry and compares that subset after a projected hit-grid change; a non-candidate hit entry can no longer force a navigation rebuild through the projected-grid branch. Candidate addition/removal, modal roots, missing state, and changed published candidate geometry remain conservative. `ui.navigation_index.projected_geometry_skip_count` exposes the second-stage skips.

M2.13 removes immutable frame publication from `zircon_runtime/src/dynamic_api/session/runtime_ui.rs`'s render hot path. The aggregate renderer previously called `publish_surface_frame_after_rebuild()` and `surface_frame()` for every surface, so a local render/hit change cloned the changed frame domains before the renderer immediately cloned/remapped render commands again. It now rebuilds retained surfaces, compares `invalidation_generations().render`, and passes `&surface.render_extract` directly into the existing per-surface remapped-command cache. `UiSurfaceFrame` remains the immutable debug/snapshot contract; its cost is no longer mandatory for runtime rendering.

M2.14 closes the immutable-snapshot sharing proof. `UiSurfaceFrame` stores arranged, render, hit, focus, layout-report, and pipeline domains behind independent `Arc` values, while `UiSurfaceFramePublication::shared_domain` reuses every clean domain and advances a separate domain generation only when that authority changed. Window-only publication therefore copies no heavy domain elements; render-only publication copies the render extract but retains arranged, hit, focus, layout-report, and pipeline identities. This is deliberately separate from M2.13: M2.13 removes publication from normal rendering, while M2.14 bounds the remaining explicit snapshot/debug cost by the changed domains.

M2.15 removes business-payload collection from the final native window-resize reflow. Continuous resize events were already correct: `events/resize.rs` defers retained reflow for 80 ms, `redraw.rs` suppresses frame updates during that transaction, and the GPU presenter reuses one generation-bound command snapshot while only reconfiguring the latest surface size. The remaining accepted `WindowMetrics` recompute moved committed layout/model/chrome but then unconditionally reread preset names, all visible editor pane presentations, runtime diagnostics, module/plugin data, build/export data, and all template pane snapshots. `CommittedShellState` now retains the payload bundle behind `Arc`; the pure metrics snapshot moves that identity through recompute, while a full recompute replaces it. Successful shell-content and scoped-view patches invalidate the retained bundle so a later metrics reflow cannot reuse stale business data. Hit/miss counters are emitted as `ui.window_metrics.pane_payload_cache_{hit,miss}_count` and are exported by the window-resize evidence gate.

M2.16 removes maintenance polling from the pointer-to-present critical path. Previously every pointer result that requested a frame update reached `UiHostContext::invoke_frame_requested`, which synchronously ran the complete retained-host tick before present: job/event pumps, recovery, heartbeat I/O, autosave, imports, save/export polling, plugin lifecycle, hierarchy/runtime consumers, settings/notification sync, and asset refresh all preceded the actual UI recompute and render submission. `HostRedrawRequest` now retains an explicit `interactive_frame_update` authority through redraw merging. Pointer-origin updates and the final debounced native-resize reflow mark that authority; their dedicated callback runs only the already-invalidated `sync_shell_size`, `recompute_if_dirty`, and `submit_render_frame_if_dirty` commit. It then schedules an immediate lifecycle wake, so the unchanged full maintenance tick runs from `about_to_wait` after the interactive frame has presented. Present retries clear the authority, and maintenance-only redraws retain the original full-tick route. This improves response ordering; it does not claim that background maintenance CPU work disappeared.

M2.17 removes three false global-presentation promotions from common workbench interaction paths. Opening the componentized context menu already refreshes the retained template surface and leaves exact changed projection rows; `apply_dispatch_effects` detects that pending projection, so the additional `request_presentation()` forced the invalidation decision from `WorkbenchProjection` back to a full shell recompute. The menu now commits only the changed rows. Resolving a notification-center decision likewise relies on the existing end-of-dispatch notification projection instead of promoting the decision button to a whole-shell presentation. Toast creation no longer marks presentation globally in the event bridge. `publish_activity_toasts` makes the host-aware choice: the active componentized workbench synchronizes its notification controls through the same changed-row projection, while a non-workbench activity document explicitly retains the `PRESENTATION_DATA` fallback. Dispatch batches enqueue all toasts and refresh the notification projection once after their other side effects, avoiding the previous immediate snapshot collection followed by an unconditional second collection. External asynchronous toast publication retains immediate refresh. Business effects such as project save still request their own required presentation work independently. Product-host regressions require context-menu visibility, pending-projection consumption, decision-modal closure, and unchanged slow-path rebuild counts.

M2.18 removes idempotent asset-control events before they enter the invalidation pipeline. Asset folder/item/reference selection, search, kind filter, surface view mode, and utility-tab setters now return whether their authoritative state actually changed. `execute_asset_event` uses that result instead of hard-coding `changed=true`; a repeated control value produces no `PresentationChanged`, details refresh, or visible-preview refresh effect. Error paths that update the global status line still use the original forced-presentation helper. This gate is intentionally upstream of Asset Browser projection: the shared asset state can affect both `Assets` and `AssetBrowser`, while the existing `ViewPresentation` fast path supports only UI Asset Editor panes and shell-content reuse holds an old chrome snapshot. Narrowing these events to the clicked pane would leave other asset views stale. The safe current optimization is therefore O(1) idempotence rejection; multi-view asset projection remains a separate architectural milestone.

M2.19 applies the same authoritative-change rule to other common controls that already returned a reliable boolean. Re-selecting the current hierarchy node and no-op hierarchy edits no longer request presentation/reflection work. Clearing an already empty console and selecting the already-active message/source filter no longer request presentation. A shared const-generic `effects_when` gate returns an allocation-free empty vector for no-op events and materializes the fixed effect array only for real changes. Menu branches that update a status line or trigger external business work remain unchanged. Viewport toolbar commands are also excluded from this slice: their executor currently classifies several command kinds as structurally changed before consulting detailed feedback, so they require a separate state-authority correction rather than reusing this boolean gate blindly.

M2.20 closes that viewport authority gap. `SceneViewportController::apply_command` now performs O(1) equality checks at the owned setting slot and publishes `ViewportFeedback::settings_changed`; projection updates retain their camera-side effect only on a real projection change. Snap setters use the existing `SettingsAuthority::set` result and return whether it produced a persisted change instead of forcing a downstream refresh for an identical value. `execute_viewport_event` consumes that feedback and no longer treats transform-space, projection, display, grid, snap, preview, or gizmo setters as structural merely because of their enum variant. Commands with action semantics (`AlignView`, resize, overlay toggle, frame selection, release, and scene-mode activation) remain conservative. A product-path regression dispatches the same grid setting twice and requires the second host effect bundle to stay presentation/layout/render clean.

M2.21 removes complete binding-inspector projection from seven UI Asset Editor interaction entry points. Binding selection now validates against the selected node's binding count; event and action-kind dropdowns index their fixed option authorities; route/action/payload suggestion actions resolve only the requested suggestion before cloning the document; payload-row selection flattens the payload once and moves the selected key instead of formatting every row and parsing the selected display string back with `split_once`. The prior path called `build_binding_fields`, which also formatted all bindings and payload rows, generated every suggestion group, and rebuilt schema projection for a single index check. Invalid indices still return the same typed errors, and valid no-op mutations still return `Ok(false)`. The display/presentation path continues to build the complete fields when it actually needs to render the Inspector.

M2.22 removes binding receipt preparation from empty-target pointer events. Component events may carry compiled template actions without any binding mutation targets; the previous target filter still started a timer, cloned the binding identifier, copied the asset identifier, loaded the compiled binding twice, and then returned the event unchanged. `binding_target_event_profile` now resolves the event authority once before `Instant::now` and returns both receipt generation and executable state; a resolved compiled binding with an empty target list returns the passthrough result in O(1), and an event with no compiled handle passes through only when raw legacy metadata also has no targets. This shared resolution avoids adding a third compiled-binding lookup to real targeted interactions. Stale handles, endpoint mismatches, raw legacy targets, and executable target transactions retain the existing diagnostic/receipt path. Receipt constructors now borrow event/registry identifiers directly and remain the one bounded-string allocation authority. `ui.binding.target_passthrough_count` exposes the avoided work in profiling builds.

M2.23 removes recursive payload-value cloning from complete binding Inspector projection. The retired display path first cloned the complete payload into a synthetic TOML root and then cloned each flattened entry's complete `Value` subtree before immediately formatting it; schema projection separately cloned every top-level value subtree before recursively reading it. The flattening authority now owns only the path strings that the UI fields require and borrows each payload `Value` from the selected binding, while schema projection iterates borrowed top-level entries and owns only keys admitted to its deduplication set. Top-level `BTreeMap` order and recursively sorted TOML table order remain unchanged. Each projection is now O(P) value visits with zero value clones instead of O(P * d) copied value nodes for P nested nodes at depth d. Editing paths that intentionally materialize a next payload map retain their owned copies.

M2.24 batches workbench pointer feedback at the event boundary. ## Product Surface Pipeline Attribution

The reference review shows that retained rendering alone is not enough; the profiler must expose the owner boundary where retained state is validated or rebuilt. Unreal Slate records root tick/input, prepass, invalidation paint/FastPath, window draw, and painted/ticked widget counts at the invalidation-root and widget-proxy boundaries. Slint's partial renderer similarly separates dirty-region traversal from actual render while retaining item geometry and property tracking. Zircon's equivalent authority is `UiSurface`, not an Editor pane or button bridge.

The previous `UiSurfaceRebuildReport` measured layout, arranged-tree, base hit-grid, and render-extract phases, but those values were only embedded in the latest immutable frame report. They were not emitted into the product timeline, and projected popup hit-grid synchronization, navigation-index rebuild, and frame publication occurred outside those four elapsed fields. A WPR trace could therefore show main-thread CPU without allowing the source-bound capture artifact to distinguish layout from popup projection, navigation sorting, or immutable frame materialization.

The profiling build now exports one counter stream at the owning boundaries. `ui.surface_rebuild.*` records total elapsed time, only the stages that actually ran, dirty-node count, outer traversal work, and render reuse/rebuild counts. `ui.surface_projected_hit.*` distinguishes full rebuild, local patch, affected entries, and fallback. `ui.navigation_index.rebuild_elapsed_us` covers both successful and error exits. `ui.surface_frame.publication_elapsed_us` includes changed-domain sharing/cloning and retained-frame construction. All timing and pre-move work-count evaluation is compiled only with the `profiling` feature; normal builds do not start timers or evaluate these counters.

`tools/ui-profile-surface-pipeline-metrics.ps1` converts the runtime counter stream into `ui_surface_pipeline_metrics.json`, with sample count, nearest-rank p50/p95, max, sum, and mean for each stage and work counter. Missing stages remain `sample_count=0` with null percentiles instead of becoming fabricated zero-cost samples. The module is included in `Get-ZirconProfileCaptureToolPaths`, so its source hash is bound into every capture manifest. This closes the attribution gap; it does not yet prove that a product interaction meets its latency, CPU, or memory budget. That proof still requires a current-source managed profiling build and the real click/resize/scroll scenarios under the machine gate above.
