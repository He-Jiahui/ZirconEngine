# ZirconEngine 第一方源码中文注释审查规范

任务 ID：`source-comment-audit-20261012`。审查不修改程序行为、公共 API、字符串常量、测试断言、条件编译、宏语义或资源载荷。覆盖账本与问题账本独立于编号计划保存，逐项证据不塞入计划正文。

## 范围与内容身份

覆盖产品、公共接口、Runtime、Editor、第一方插件、Hub、入口、工具、示例、测试、着色器与可执行文本资源。排除 `dev/` 参考仓库、第三方/vendor、明确生成的代码/资源和构建缓存。`zircon_runtime/build` 是第一方规范源码，不能按目录名排除。模板、夹具、嵌入代码与无常规扩展名的执行文本也须分类；二进制和纯数据的排除须有依据。

初始清单采用跟踪文件及未被忽略的第一方源码候选。读取失败、reparse point、嵌套 Git 和生成属性不明分别登记，不能静默略过。SHA256 按实际文件字节计算，不归一化行尾。最终验收再次盘点增删文件，并核对最终内容哈希。

## 中文注释

- Rust 用 `//!` 说明模块职责、入口与边界，用 `///` 说明声明的职责、调用时机与约束，用 `//` 说明私有不变量、非显然顺序和设计理由。其他语言采用其有效文档/普通注释语法。
- 文档级注释包含 Markdown 概述；按对象需要补充 `# 使用时机与生命周期`、`# 参数`、`# 返回值`、`# 约束`、`# 参考`。解释字段、泛型、关联类型、回调和返回错误的实际语义。无参数或无返回值不添加空章节，但不能漏掉生命周期和调用前提。
- 参考指向具体调用者、类型、trait、测试或契约。可解析 Rust 符号采用有效 rustdoc 链接，跨 crate 私有项使用代码标识与路径说明。不新增可执行 doctest，不制造失效链接。
- 保留现有注释，在旁补足中文解释。用途清楚且说明已足够的对象可不新增注释，仍须记录逐对象审查证据。不复述命名、赋值或逐行实现，不粘贴通用说明来提高覆盖数。
- 只写调用证据能证明的事实；推测和证据缺口进入 TODO。注释不得改变 token、宏输入、shebang、预处理指令、注释指令或可执行文本载荷。

## 逐项审查

每项先定位声明、直接调用、trait 实现、宏生成、动态注册和 FFI 入口，再读取调用上下文、状态、契约及相关测试。证据说明具体符号之间的关系，不能只列文件名。未找到直接调用时检查导出、注册、生成和测试；确属未使用也记录检索依据。

每个声明、数据结构、实现项、宏、关联项与语句块都须审查。语句块记录进入条件、状态变化和后续可观察影响，重点核对错误路径、重入、释放顺序、异步完成和跨边界所有权。大文件按符号组拆分；不能只读头部或只审公共函数后标为完成。

## 问题编号

编号使用 `ZCA-<agent 分配前缀>-NNN`，全任务唯一。

- `BUG: [编号] 触发条件；可观察影响；证据` 写在错误调用附近，必须有最小复现或完整可证明路径，主审复核后才可交付。
- `TODO: [编号] 待确认问题；证据缺口；下一步验证` 用于未证实风险或意图。没有看见测试不能单独证明缺陷。
- `SAFETY:` 只写已证实的 unsafe 前提，说明谁建立前提、有效期和释放边界；无法证明时留下具体 TODO。
- 每个新 BUG/TODO 与问题账本的路径、符号、证据和动作一致。历史标签保留并作初始记录；历史无编号标签不能冒充本任务已复核结果。此任务只记录问题，不顺带修复行为。

## 所有权、复核和验证

主审分配互不重叠的精确文件清单。agent 可跨仓只读追踪调用方，只编辑分配文件与自己的证据文件；记录 before/after 哈希。既有 dirty 或外来占用路径列为 waiting-foreign-owner。意外变化停止该文件，独立模块继续。

三名 `gpt-6-luna max` 并行处理模块，一名 `gpt-6.1-sol max` 处理核心与决策，含主审最多五并发。大型子树继续拆批并复用四名 agent，不再增加并发。相关测试随模块归属；顺序为公共契约与核心、Runtime、Editor、插件、Hub/入口/工具/示例。

每批主审逐文件独立核对新增注释、调用证据、问题级别及完整覆盖记录；核对精确归属 diff、SHA256、语言格式/解析、可执行结构不变和标签一致。生成型验证和必要票据由 Jenkins 执行；纯注释不例行宽泛 Cargo 测试，待回执不称通过。

Jenkins 按用户授权提交精确归属批次并附带企业微信自动通知；返回 SHA、实际文件/hash 和验证证据。首次提交前诊断索引锁及索引所有权，不删除锁、不混入既有改动、不由 agent 运行 Git 写操作、建立源码副本或恢复退役协调器。
