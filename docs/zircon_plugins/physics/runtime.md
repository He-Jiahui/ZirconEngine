# Physics Runtime Plugin

`zircon_plugins/physics/runtime` owns the concrete physics runtime after the hard cutover. The crate provides the canonical `physics.runtime` descriptor, the plugin-local `PhysicsDriver`, a typed `PhysicsBackend` contract with generation-checked shape/body/constraint handles, the `BuiltinPhysicsBackend`, the feature-gated `JoltPhysicsBackend`, the `DefaultPhysicsManager`, and the two runtime scene systems that step and write back physics.

`zircon_runtime` no longer exports `zircon_runtime::physics` and does not depend on the plugin crate. Runtime keeps only neutral contracts under `zircon_runtime::core::framework::physics`, manager service names/resolvers under `zircon_runtime::core::manager`, scene ECS state, and the generic runtime scene-system scheduling protocol.

The current backend option decision is recorded in [Physics Plugin Options](../physics-plugin-options.md): builtin remains the default no-feature backend, Jolt is executable when the plugin's `backend-jolt` feature is enabled, feature-off Jolt remains explicitly unavailable, and Rapier is not introduced on the primary path.

## Runtime Boundary

- The plugin descriptor embeds `module_descriptor_with_manager(...)`; `RuntimePluginRegistrationReport` registers that lifecycle module once, then `RuntimePluginRegistrationBuilder::new(registry).module(PLUGIN_RUNTIME_MODULE_NAME)` opens the same owner scope for the query interface and runtime system contributions.
- The plugin contributes two scheduled systems through `RuntimePluginModuleRegistration::runtime_scene_system(...)`: `physics.step` in `SystemStage::FixedUpdate` and `physics.sync_to_scene` in `SystemStage::FixedPostUpdate`, both in `physics.main`. The runtime-system owner no longer receives `PluginModuleId` or calls `RuntimeExtensionRegistry::register_runtime_scene_system(...)` directly.
- D8 runtime registration builder original evidence paths are locked by `review_d8_runtime_registration_builder_original_evidence_paths_use_sdk_builder` and status `d8_runtime_registration_builder_original_paths_static_passed_cargo_deferred`.
- D10 animation/physics bridge call migration exports the runtime-owned `physics.query.v1` bridge interface from this plugin. `PhysicsRuntimePlugin::register(...)` creates a shared `DefaultPhysicsManager`, registers it as the module manager, and exports it as `Arc<dyn PhysicsQueryInterface>` through `RuntimePluginModuleRegistration::export_interface::<dyn PhysicsQueryInterface>(...)`; module activation borrows `&CoreHandle` and stores only `CoreWeak`, upgrading it at the settings-persistence boundary. The registry-owned manager therefore cannot retain the Runtime root through `ServiceEntry.instance`. Guard `review_d10_animation_physics_tests_use_sdk_bridge_call` records status `d10_animation_physics_bridge_call_static_passed_cargo_deferred` and locks consumers to `WeakBridge<dyn PhysicsQueryInterface>`.

## Backend Selection

The current runtime has two executable backends when built with `backend-jolt`: `builtin` and `jolt`. Without that feature, only `builtin` is linked and the Jolt setting remains a typed unavailable state.

- `backend = "builtin"` with `simulation_mode = Simulate` runs fixed-step writeback, syncs the world snapshot, and produces fallback query/contact data.
- Builtin and Jolt both drain external body commands only when a real FixedUpdate step is about to run. Query-only ticks retain queued writes until simulation resumes; disabled, unavailable, cleared, or backend-switched worlds discard stale commands.
- `backend = "builtin"` with `simulation_mode = QueryOnly` syncs the sanitized world snapshot for ray/contact queries but records a zero-step plan and does not move rigid bodies.
- `backend = "jolt"` with `backend-jolt` enabled creates a persistent native world, supports Box/Sphere/Capsule/Cylinder/ConvexHull/Compound plus registered TriangleMesh/HeightField shapes, applies body commands, steps Jolt, and writes active state back through the shared sync snapshot. Resource-mesh shapes are static-only, including when nested in Compound.
- `backend = "jolt"` without the plugin feature reports `PhysicsBackendState::Unavailable` with a feature-specific detail.
- Unknown, blank, or `unconfigured` backends report `PhysicsBackendState::Unavailable` and clear the manager's synchronized world/contact state for the tick instead of using builtin as an accidental downgrade path.
- `simulation_mode = Disabled` reports `PhysicsBackendState::Disabled` and records no executable backend.

## Framework Contract

Runtime framework contracts are intentionally concrete-free:

- `PhysicsManager::tick_scene_world(...)` defines the manager-side scene tick capability.
- `PhysicsSceneStepResult` returns the step plan and contact events without exposing plugin-owned implementation details.
- `PhysicsWorldStepPlan` carries `steps`, `step_seconds`, `remaining_seconds`, and `interpolation_alpha`; the alpha is neutral visual interpolation metadata for runtime/editor consumers and is zero when the backend cannot step.
- `PhysicsQueryFilter` is now the shared query filter for ray, shape-overlap, and shape-cast queries. It carries collision mask, sensor inclusion, excluded entities, and required collision group.
- `PhysicsQueryMode::{First, Closest, All}` is shared by all three query families. `Closest` is the serde-compatible default for existing documents, `First` preserves synchronized insertion order, and `All` returns deterministic distance-ordered results with entity-id tie breaking. Overlap hits do not expose a distance field, so their ordering uses collider-center distance to the query transform.
- `PhysicsColliderShape` covers primitive, convex, asset-backed mesh/heightfield, and recursive compound contracts. `PhysicsMeshAsset` is the backend-neutral validated payload used to resolve asset references without moving Jolt or concrete mesh objects into Runtime.
- `PhysicsMassProperties` selects authored explicit mass with an optional positive-definite inertia tensor or automatic shape-volume mass from density. Primitive and compound volumes resolve in the backend; the current JoltC ABI can realize an explicit tensor only when it is a uniform scale of the analytic primitive inertia, and returns typed `Unsupported` for rotated/non-uniform tensors instead of silently discarding them.
- `PhysicsCcdMode::{Disabled, LinearCast}` and `PhysicsSleepPolicy::{Allow, Never}` are shared scene-authoring and sync contracts. Runtime body commands update Jolt motion quality and sleeping permission without handle replacement. Scene reflection and property paths expose these typed values directly; the retired `can_sleep` boolean has no production alias or dual-write path.
- `PhysicsRayCastQuery` uses the shared filter instead of duplicating query fields. `PhysicsShapeOverlapQuery` and `PhysicsShapeCastQuery` expose the same filter and query-mode semantics for broader query families.
- `PhysicsManager::ray_cast(...)` and `PhysicsManager::shape_cast(...)` return hit vectors so `All` is represented without a second API. `PhysicsManager::shape_overlap(...)` remains a vector query. Default manager capabilities return empty vectors.
- The builtin fallback manager answers all query families from its synchronized collider snapshot. Shape cast now performs a conservative continuous sweep by casting the query shape's oriented AABB center against each collider AABB expanded by the query half extents; initial overlap remains a zero-distance hit. The returned sweep position follows the query-center path and is intentionally not advertised as an exact manifold contact point for non-box convex shapes.
- `PhysicsQueryInterface` is the plugin-to-plugin bridge contract for ray, shape-overlap, and shape-cast queries. Its `PHYSICS_QUERY_INTERFACE_ID` is `physics.query.v1`, and linked plugins should consume it through `WeakBridge<dyn PhysicsQueryInterface>` instead of resolving `DefaultPhysicsManager`.
- `PhysicsContactEvent` and `PhysicsTriggerEvent` are registered by the Physics runtime module as `physics.events.contact` / `physics.events.trigger`, with payload schemas `physics.contact_event.v1` / `physics.trigger_event.v1`. `physics.step` publishes every drained event into the scene `EventStore` and retains the same frame batch in `LevelSystem` diagnostics; consumers use ordinary event subscriptions and do not depend on `DefaultPhysicsManager`.
- JoltC 0.3.1 exposes narrow-phase ray cast but not shape-cast/collide-shape entry points through its C ABI. Until that ABI grows, manager queries deliberately use the backend-neutral synchronized collider snapshot; no native Jolt shape sweep is claimed.
- `PhysicsJointType`, scene `JointKind`, and scene-asset `SceneJointKindAsset` now share the same fixed/distance/hinge/slider/cone-twist/Generic6Dof vocabulary. The plugin maps those scene values into `PhysicsJointSyncState`.
- `PhysicsJointConstraintMetadata` and `PhysicsJointDrive` carry per-axis linear/angular limits, per-axis drives, break thresholds, and projection tolerances through scene ECS, scene assets, project IO, and the synchronized physics snapshot.
- `PhysicsSkeletonJointBinding` links a joint to a skeleton entity and bone path for physical-bone or ragdoll authoring metadata. Dynamic scene remapping updates the skeleton entity alongside the joint's connected entity.
- The builtin fallback validates finite ordered limits, non-negative drive/break/projection values, and non-empty bone paths before accepting a joint into synchronized state. Native Generic6Dof solving remains backend-dependent; the plugin-local `skeletal/` owner now supplies backend-neutral profile generation, mode switching, animation target drive, and simulated-pose writeback without putting ragdoll state into Runtime.
- `PHYSICS_MANAGER_NAME` remains the stable service name consumed by runtime/editor callers.

Native Jolt query/event/constraint breadth remains explicit follow-up work behind the same plugin-owned boundary; the ragdoll orchestration layer consumes whichever backend owns the synchronized bodies and does not reintroduce `zircon_runtime::physics`.
