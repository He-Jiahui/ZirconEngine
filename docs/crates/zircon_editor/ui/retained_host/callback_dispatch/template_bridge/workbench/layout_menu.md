# Workbench Layout Menu

## Purpose

`layout_menu.rs` is the narrow adapter from the componentized Workbench Layout popup to the existing editor layout reset command. It does not own layout persistence, preset registration, popup geometry, or menu selection state.

## Behavior

Reset Layout maps to the canonical `MenuAction::ResetLayout` binding. The normal editor event executor invokes `LayoutCommand::ResetToDefault`, so the menu row reaches the same layout manager, event journal, invalidation effects, and status feedback as other reset entry points. Before dispatch, the leaf restores the popup surface `value` and `value_text` to Default Layout and refreshes the host projection; Reset remains a command and cannot become a false persistent layout selection even if business dispatch later fails.

Gameplay Layout and Rendering Layout are disabled because this surface does not yet receive registered preset names or identities. They cannot change the popup value or dispatch an event. Default Layout remains a disabled+checked current-state indicator rather than duplicating the destructive Reset command.

The menu is intentionally a mixed command menu, not a single-choice popup. Selecting Reset therefore preserves the authored Default Layout check instead of moving it to the command row.

## Ownership

- `layout_menu.rs` owns the Reset row-id to canonical binding map.
- `workbench_window.zui` owns row availability and visual flags.
- `control.rs` merges real event effects after generic popup selection.
- the editor event executor and `EditorUiHost` own reset execution.
