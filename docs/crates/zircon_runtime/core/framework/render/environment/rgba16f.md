# Environment RGBA16F Encoding

## Purpose

`rgba16f.rs` owns the CPU-side RGBA16F byte layout used by environment cubemap artifacts and source containers. It exists so `.zribl` PMREM/IEM payloads and `.zcube` source cubemap payloads cannot drift into subtly different half-float encodings.

The module is backend-free. It performs no file IO and creates no GPU resources. Callers pass typed texel arrays and receive little-endian bytes, or decode already-sized byte ranges after their own container/header validation.

## Behavior Model

`encode_rgba16f_texels(...)` and `append_rgba16f_texels(...)` pack `[f32; 4]` texels as four IEEE-754 binary16 channels in little-endian order. Negative values are clamped to zero because current environment radiance, PMREM, source cubemap, and IEM payloads are non-negative HDR color data.

`append_rgb_as_rgba16f_texels(...)` packs `[f32; 3]` texels with a caller-provided alpha value. `IblBakeArtifactPayload` uses this for optional IEM cube sections, writing alpha as `1.0` while preserving RGB irradiance.

`decode_rgba16f_texels(...)` and `decode_rgb_from_rgba16f_texels(...)` convert exact RGBA16F byte ranges back to CPU texels. Container layers are responsible for validating byte lengths before calling these helpers; the helpers intentionally process complete 8-byte texel chunks only.

## Design and Rationale

The code stays inside `core::framework::render::environment` because the layout is an environment contract, not a generic image library. It is shared upward through the render facade only for environment-adjacent asset code such as `.zcube`. General texture upload still has its own readiness and format negotiation path.

Keeping the conversion dependency-free avoids a workspace dependency change for a narrow byte layout. If future image or GPU tooling introduces a common half-float crate, this module can become the single replacement point.

## Test Coverage

The RGBA16F helpers are validated through their consumers:

- `.zribl` artifact tests round-trip PMREM/IEM payloads and decode them back into source-cubemap artifact application.
- `.zcube` source-cubemap tests round-trip source mips and compare them to `SourceCubemapMipChain::source_texels()` within FP16 precision.
