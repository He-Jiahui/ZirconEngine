# Font Artifact Cache Payload

`zircon_runtime::asset::artifact::cache_payload::font` owns the binary cache representation of `FontAsset`. It separates the authoring document schema from the sequential bincode wire schema used by compressed `.zasset` files.

## Ownership Boundary

`FontAsset` remains the TOML-facing authoring type. Its optional values, empty collections, default face index, default render strategy, family members, variable instances, parsed face metadata, metrics, variation axes, and cmap ranges may use `skip_serializing_if` to keep human-readable documents compact.

`ArtifactCacheFontAsset` and its child DTOs always serialize every field. `cache_payload.rs` only routes `ImportedAsset::Font` through the cache DTO and converts it back after reading. The cache child module contains no authoring omission rule, runtime fallback, compatibility alias, or legacy cache reader.

The hard cut intentionally invalidates font artifacts written with the old direct-`FontAsset` wire shape. Library artifacts are derived cache data and must be regenerated by the current importer rather than decoded through a second architecture path.

## Conversion Contract

The cache payload explicitly maps the following authoring families in both directions:

- root font source, family, render mode, face selection, fallbacks, composite font, render strategy, and optional metadata;
- family members and variation coordinates;
- named variable instances and variation axes;
- parsed faces, line metrics, underline/strikeout values, and cmap coverage.

Shared enum values and `CompositeFontDescriptor` remain values inside the cache DTO because their current serde definitions serialize all fields. Any future authoring omission rule in those types requires a cache-local replacement before it can enter the artifact wire.

## Validation

The original project-manager font regression failed at `ArtifactStore::read(...)` with `ArtifactCacheDeserialize(UnexpectedEof)`. The public integration contract now writes a representative font containing default-skipped fields, composite sub-font routing, variable coordinates, parsed metadata, optional names, line metrics, variation axes, and cmap ranges; it verifies the `ZRARTZ01` artifact header and exact `ImportedAsset::Font` roundtrip.

On 2026-07-11, the current production library passed `cargo check -p zircon_runtime --lib --no-default-features --features core-min --locked --jobs 1` in 4m59s with 52 existing warnings. The same generated `core-min` rlib compiled the integration contract with `rustc --test` in 7.6s, and the executable passed 1/1 in 0.03s.

The default-feature lib-test remains pending because the active text-layout refactor currently leaves six unrelated rich-text import/type errors. The `core-min` unit-test target is also independently blocked by repository-wide test feature-gating gaps, and Cargo integration-test orchestration reaches an ungated `zircon_host_reflection_docs` binary. These external package/test-target failures do not replace the focused font cache pass and are not reported as a full Runtime test pass.
