# Web Native Handoff Matrix

This matrix is the handoff boundary between the browser workbench prototype and the Rust-owned retained editor path. The browser prototype is still the fastest place to assemble and validate component grammar. The retained/Taffy path is the implementation target for native editor behavior. Promotion from web-only to native-covered requires evidence, not a matching label.

The accepted shell direction remains the shared workbench shell represented by `ai-gameplay-effect-layout.png`; other AI images contribute function grouping and module vocabulary, not another outer shell.

## Retained/Taffy Migration Gates

Use these gates before moving any browser surface into the native-covered column:

1. The browser component or module must pass `node verify-interaction-contract.mjs`.
2. Browser and native action IDs must pass `node verify-action-naming-contract.mjs` so action payloads use dotted functional paths instead of CamelCase, slugs, or slash namespaces.
3. The browser runtime must pass `node validate-control-routes.mjs` and show the target control or module in the driven interaction path.
4. The responsive shell must pass `node validate-responsive.mjs` at the reference and compact viewports.
5. The component family must pass `node verify-native-component-contract.mjs` if it relies on a low-level painter/input/render-extract family, and its `.zui` assets must stay under the functional `components/` subfolders rather than the root.
6. A promoted core module must pass `node verify-native-module-contract.mjs` with matching `.zui` workspace, binding, preview action, and route evidence.
7. Recorded native-extension workspace evidence must pass `node verify-native-extension-module-contract.mjs` while the extension row remains prototype-only.
8. Recorded generated-bottom visible shell bottom drawer pane body evidence must pass `node verify-native-generated-bottom-contract.mjs` while module lifecycle remains the action/state owner.
9. The matrix itself must pass `node verify-web-native-handoff.mjs`.

Do not promote prototype-only extension modules into native-covered status until matching .zui workspace, binding, preview action, and retained route evidence exist.

Native-extension workspace evidence may be recorded before promotion when it is intentionally scoped to one More Editors surface. That evidence must keep ZUI binding ids under `WorkbenchExtension/*`, register preview action payload ids and ZUI route symbols as dotted functional paths under `workbench.extension.*`, use split extension binding/navigation/feedback files, pass `node verify-native-extension-module-contract.mjs`, and keep the module row prototype-only until the broader promotion contract is completed.

Generated-bottom visible shell drawer body evidence may be recorded before full action/state consolidation when it is intentionally scoped to a bottom-drawer activity view that mounts the shared generated panel through `pane.generated_bottom.body`. That evidence must keep ZUI binding ids under `WorkbenchGeneratedBottom/*`, route/action symbols under `workbench.generated_bottom.*`, shared panel content visible by default while leaving module overlay collapse state on `WorkbenchGeneratedBottomDrawer`, use split generated-bottom drawer/panel/body/binding/action/lifecycle/navigation/feedback files, pass `node verify-native-generated-bottom-contract.mjs`, and keep this family out of full native-covered status until the shell pane and module lifecycle contracts are unified.

When a prototype-only extension graduates, update this file, `verify-web-native-handoff.mjs`, `verify-native-extension-module-contract.mjs`, `reference-samples.js` role metadata if needed, and the native module verifier in the same slice. The change should be treated as a retained/Taffy implementation slice, not a browser-only breadth pass.
