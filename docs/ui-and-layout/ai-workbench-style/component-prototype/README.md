# Workbench Component Prototype

This prototype rebuilds `E:/Git/ZirconEngine/docs/ui-and-layout/workbench.png` as a component stack inside the normalized `ai-workbench-style` design workspace instead of wrapping the reference PNG.

2. `src/foundation/layout.js` and `src/foundation/layout.css` provide reusable box, stack, cluster, and grid primitives for direction, wrapping, columns, shared gaps, left/center/right placement, and cross-axis alignment.
3. `src/foundation/icons.js` defines local inline SVG icons, so buttons and tree/list rows are not dependent on an icon package.
4. `src/components/inputs/atoms.js` and `src/components/inputs/atoms.css` are only the public input-family export/base-style entries. Concrete low-level controls live in `src/components/inputs/{buttons,fields,selection-controls,tabs,dropdowns,sliders}.js` with matching `.css` files, plus `input-utils.js` for shared escaping. Button leaves are further split under `src/components/inputs/buttons/{button,icon-button}.js`, so text buttons and icon buttons do not share an implementation file. Field leaves are likewise split under `src/components/inputs/fields/{input,search-input,number-field}.js`, so plain text input, search input, and numeric field markup stay in separate files. ## Component Families

The prototype follows the same bottom-up grouping used by mature component libraries such as Material UI, but keeps the implementation local and dependency-free:

- Foundation and layout: tokens, box, stack, cluster, grid, window shell, drawers, panels, tab strips, toolbars, and status regions.
- Inputs: buttons, icon buttons, fields, selects, number fields, checkboxes, radios, switches, tabs, segmented controls, and sliders.
- Data display: scene tree rows, inspector property rows, table rows, list rows, and menu rows.
- Feedback: alerts, tooltip, toast, focused/selected/checked/disabled states, and popup placement.
- Surface chrome: top bar, activity rail, module tabs, module toolbar, module left drawer, module main editor, module right details window, module bottom output drawer, popup layer, and status bar.

Module layout styles also follow functional paths: `src/modules/module-layouts.css` is only an import entry, while the shared editor grid, native core module grid variants, More Editors library grid, and extension module grids live under `src/modules/layouts/{base,core,library,extensions}.css`.
