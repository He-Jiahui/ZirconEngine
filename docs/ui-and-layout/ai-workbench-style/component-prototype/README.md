# Workbench Component Prototype

This prototype rebuilds `E:/Git/ZirconEngine/docs/ui-and-layout/workbench.png` as a component stack inside the normalized `ai-workbench-style` design workspace instead of wrapping the reference PNG.

## Build Order

1. `tokens.css` extracts the fixed dark editor palette, 1672x941 reference dimensions, compact 30 px controls, 1 px separators, low radii, and teal active states.
2. `layout.js` and `layout.css` provide reusable box, stack, cluster, and grid primitives for direction, wrapping, columns, shared gaps, left/center/right placement, and cross-axis alignment.
3. `icons.js` defines local inline SVG icons, so buttons and tree/list rows are not dependent on an icon package.
4. `atoms.js` and `atoms.css` provide buttons, icon buttons, inputs, checkboxes, radio buttons, switches, tabs, segmented controls, selects, number fields, and sliders.
5. `collections.js` and `collections.css` compose tree view, table view, list view, popup menu, alerts, tooltip, and toast. List, table, and menu rows are real buttons with stable action identities, so the same collection grammar can be used inside fixed side menus, data tables, and transient popup menus.
6. `surfaces.js` and `surfaces.css` compose the top toolbar, left rail, legacy scene drawer/viewport, inspector window, UI component drawer, and status bar through explicit `workbenchWindow`, drawer/window surface, and panel-view helpers.
7. `module-components.js` contains the shared module surface primitives: left/main/right/bottom regions, cards, panel tabs, settings rows, list/tree/table rows, graph nodes, timelines, preview tiles, tags, and placeholder output panels. Module table rows derive their `data-action` and `aria-label` from the first readable content cell instead of a row index, so response hashes and accessible names stay meaningful across repeated tables.
8. `modules.js` and `modules.css` add the active editor-module layer. The default Gameplay Effect module follows the approved shell direction from `ai-gameplay-effect-layout.png`; Scene, Gameplay Ability, Gameplay Tags, AI Perception, Material, Behavior Tree, Render Pipeline, Asset Browser, VFX, and HUD Editor reuse the same left/main/right/bottom workbench regions while borrowing only the core function grouping from their AI reference images. The module main, left, and right regions use shell-bound stretch constraints at desktop widths, while HUD and Perception editor grids make their primary canvas card a fill container instead of a fixed-height preview.
9. `reference-samples.js` classifies the 59 PNG samples in the parent AI reference directory: 11 native-synced core module references, 44 prototype-only extension references, and 4 supplemental workbench/style references.
10. `extension-modules.js` generates the 44 prototype-only More Editors panels from that reference manifest. It keeps the shared workbench shell but assigns category recipes for world, rendering, animation, UI, production, diagnostics, online, simulation, data, gameplay, runtime, and VFX editors so the module panels are not just one copied layout with different titles.
11. `routes.js` maps prototype commands to module and panel destinations. Global commands can still jump across modules, while generic toolbar labels such as Compile, Preview, Build, Validate, Play, and Debug first resolve through the active module so repeated controls land on the matching output/details panel. Prototype-only extension commands also route by command verb to their own Output, Validation, or References bottom panel.
12. `app.js` mounts the window helper and wires small interactions for module navigation, URL hash deep links for modules, panels, and the latest command response, browser history restore, command routing, command feedback, tab switching, panel view switching, tree/list/table selection, keyboard activation for non-native button rows, toggles, dropdown popup placement, and popup menu selection/close feedback.

## Component Families

The prototype follows the same bottom-up grouping used by mature component libraries such as Material UI, but keeps the implementation local and dependency-free:

- Foundation and layout: tokens, box, stack, cluster, grid, window shell, drawers, panels, tab strips, toolbars, and status regions.
- Inputs: buttons, icon buttons, fields, selects, number fields, checkboxes, radios, switches, tabs, segmented controls, and sliders.
- Data display: scene tree rows, inspector property rows, table rows, list rows, and menu rows.
- Feedback: alerts, tooltip, toast, focused/selected/checked/disabled states, and popup placement.
- Surface chrome: top bar, activity rail, module tabs, module toolbar, module left drawer, module main editor, module right details window, module bottom output drawer, popup layer, and status bar.

Layout corrections should start by choosing the right foundation primitive and shared token. Per-control pixel adjustments are a late polish step, not the primary way to make repeated controls consistent.

## Fidelity Rules

- UI chrome and controls are HTML/CSS/SVG components.
- The whole `workbench.png` is not embedded as a screenshot.
- The central scene viewport is also HTML/CSS: it uses layered DOM elements for hangar bands, side walls, left stair/rack detail, rear-wall detail lines, an octagonal door, floor grid, floor grate, floor seam, floor reflection, lightwash overlays, shadow overlays, handrails, wall columns, amber beacons, selected prop, transform axes, cargo silhouettes with inner frames, lights, and the orientation gizmo instead of a cropped raster reference.
- The 1672x941 viewport is the strict reference size for visual QA. Smaller viewports use responsive media queries while preserving the same component hierarchy.

## Preview

Open `index.html` directly or serve this directory with a static server. No build step, CDN, web font, or third-party runtime is required.

The default view is the Gameplay Effect editor module. The top module tabs and left rail switch between the native-synced core modules: Scene, Gameplay Effect, Gameplay Ability, Gameplay Tags, AI Perception, Material, Behavior Tree, Render Pipeline, Asset Browser, VFX, HUD Editor, and the More Editors library. `reference-samples.js` keeps every PNG sample in the AI reference directory classified, so the prototype does not silently ignore a newly added sample image. More Editors exposes 44 prototype-only panels from that reference layout set, including Terrain Editor, Lighting Bake, Sequencer, Montage Editor, Physics Collision, NavMesh AI, Data Table, Console Diagnostics, Shader Editor, Source Control, UI Binding, Weather Editor, and World State, without changing the outer shell. Each module has a shareable hash route such as `index.html#module=gameplay-effect`, `index.html#module=editor-library`, `index.html#module=shader-editor`, or `index.html#module=weather-editor`; unknown module hashes normalize back to `gameplay-effect`. Module tabs, rail items, extension cards, and routed commands update the hash, so browser Back/Forward restores the visible module state.

Panel tabs and routed commands can also store a panel target through `panel=<data-panel-tab>`, for example `index.html#module=gameplay-effect&panel=module-bottom-gameplay-effect%3Acompile-log`, `index.html#module=asset-browser&panel=asset-right%3Ametadata`, and `index.html#module=shader-editor&panel=shader-editor-right%3Aresources`. Invalid panel hashes are removed instead of forcing an unrelated panel open.

Ordinary control responses also store the latest response through `command=<id>` without changing the layout, for example `index.html#module=gameplay-effect&command=save`, `index.html#module=gameplay-effect&command=tree-ge-healthregen`, `index.html#module=gameplay-effect&command=row-healthregen`, or `index.html#module=gameplay-effect&command=edit-search-assets`. Loading one of these URLs restores the visible module and records the last prototype response in browser history; it does not execute engine behavior.

Controls do not execute engine behavior yet, but every module tab, rail item, extension card, global toolbar command, module toolbar command, panel tab, list row, tree row, table row, text field, toggle, dropdown, popup menu row, graph node, asset tile, map point, HUD widget, and visible panel button produces a visible response and shareable command state. Non-native interactive rows such as module table rows also respond to Enter and Space through the same delegated click path. Popup menu rows are native `<button>` controls, use the same `data-action` path as other controls, preserve their readable menu identity through `data-menu-item`, and close the transient popup after selection. Top-level module toolbar commands are audited as complete sets across Scene, Gameplay Effect, Gameplay Ability, Gameplay Tags, AI Perception, Material, Behavior Tree, Render Pipeline, Asset Browser, VFX, HUD Editor, and More Editors. Prototype-only extension modules are also audited as complete internal surfaces across left, main, right-panel, and bottom-panel controls instead of a representative sample. Common commands route through the active module before using global fallbacks: Browse opens Asset Browser, Gameplay Effect Compile opens its compile log, Material Compile/Preview/Build stay in Material and activate shader output, preview variants, or warnings, Behavior Tree Play/Validate stay in Behavior and activate execution or validation issues, Asset Browser Validate/Build stay in Assets and activate validation or cook output, VFX Compile stays in VFX compile output, Compile Ability opens the Ability compile log, Validate Tags opens the Tags validation log, Validate Query opens the Perception validation panel, Compile Pipeline opens Render Pipeline compile output, Preview HUD opens the HUD preview log, Texture Sample stays in Material, More Editors returns to the extension library, VFX simulation points to the VFX module, and every prototype-only extension toolbar command stays inside its selected extension module while activating Output, Validation, or References by command verb.
